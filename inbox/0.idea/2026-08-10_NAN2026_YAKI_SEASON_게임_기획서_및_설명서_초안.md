### 한 줄 소개

> 할아버지의 낡은 야키토리 노포를 물려받아, 꼬치를 직접 만들고 숯불에 양면을 구우며 손님들의 저녁을 다시 이어 가는 손맛 경영 게임.

### 핵심 제안

`YAKI SEASON`은 음식을 버튼 하나로 생산하는 경영 게임이 아니다. 플레이어는 주문을 읽고 재료를 끼우며, 여러 꼬치의 앞뒤 익힘을 각각 판단하고, 생맥주의 비율을 맞춘 뒤 알맞은 손님에게 제공한다. 작은 조작 실수가 대기 시간과 품질, 매출과 손님의 반응으로 연결되기 때문에 “내가 가게를 운영했다”는 감각을 만든다.

## 2. 세계관과 감정적 목표

도시 생활에 지친 주인공은 할아버지가 40년간 운영한 골목 야키토리집 `炭火やきとり とり暦(스미비 야키토리 토리코요미)`의 열쇠와 얼룩진 레시피 노트를 물려받는다. 읽을 수 있는 첫 페이지는 네기마뿐이다. 플레이어는 하루만 문을 열어 보려 하지만, 오래된 단골과 퇴근길 손님들이 하나씩 돌아오면서 이곳이 단순한 가게가 아니라 사람들이 다시 만나는 저녁의 자리였음을 알게 된다.

중심 문장은 다음과 같다.

> 물려받은 것은 낡은 가게가 아니라, 사람들이 다시 돌아올 수 있는 저녁의 자리였다.

비주얼은 따뜻한 저녁 골목, 숯불의 주황빛과 손으로 그린 듯한 질감을 지향한다. 이야기는 영업을 방해하는 긴 컷신보다 영업 전후의 짧은 장면, 손님의 재방문과 레시피 노트의 변화로 전달한다.

## 3. 핵심 재미

### 손맛 — Craft

- 주문 순서에 맞춰 닭고기와 대파를 꼬치에 조립한다.
- 꼬치마다 앞면과 뒷면을 독립적으로 굽고 적정 시점에 뒤집고 회수한다.
- 생맥주를 따르며 맥주와 거품의 비율을 맞춘다.
- 조작 정확도는 품질과 손님 반응으로 즉시 돌아온다.

### 압박 — Rush

- 여러 손님이 서로 다른 주문과 대기 시간을 가진다.
- 조립, 그릴, 드링크와 손님 화면을 오가는 동안 조리 상태가 이어진다.
- 먼저 준비된 음식과 음료를 부분 제공해 대기를 관리할 수 있다.
- 익힘, 제공 순서와 좌석 정리를 동시에 판단하는 멀티태스킹이 긴장감을 만든다.

### 성장 — Grow

- 영업 후 매출과 품질을 정산하고 다음 영업일로 넘어간다.
- 레시피 복원으로 모모, 타레 등 새 메뉴와 공정이 열린다.
- 그릴 칸, 직원, 장비와 가게의 이야기가 장기 성장 축으로 확장된다.

## 4. 게임 진행 구조

```text
프롤로그: 가게 상속
→ 영업 준비
→ 손님 입장·주문
→ 조립·굽기·드링크
→ 부분 제공·최종 서빙
→ 좌석 정리
→ 영업 마감·정산
→ 레시피/기능 해금
→ 다음 영업일
```

현재 구현은 공개 시작 화면에서 새 게임 또는 이어하기를 선택하고, S0 프롤로그를 거쳐 D1 영업으로 진입하는 흐름을 갖는다. 저장·복구 기반과 D2·D3 영업일, D4 예고 연결도 코드와 자동 테스트 이력으로 확인된다. 다만 30일 전체 캠페인과 모든 정식 아트는 목표 범위이며, 제출 빌드의 실제 노출 범위는 최종 검수 후 별도 표기한다.

## 5. 대표 플레이 시나리오 — 첫 영업일

1. 불 꺼진 `とり暦`에 도착해 열쇠와 레시피 노트를 확인한다.
2. 첫 손님 츠키오카가 네기마 2개와 생맥주 1잔을 주문한다.
3. 생맥주를 먼저 만들어 부분 제공한다.
4. 주문서에 맞춰 네기마 두 꼬치를 각각 조립한다.
5. 시작 그릴 두 칸에 꼬치를 올리고 각 꼬치의 양면을 독립적으로 굽는다.
6. 완성된 네기마를 회수해 츠키오카에게 최종 제공한다.
7. 손님 반응과 짧은 대사를 확인한 뒤 좌석을 정리한다.
8. 직장인 손님들의 겹친 주문을 처리하며 첫 러시를 경험한다.
9. 영업을 마감하고 정산한 뒤 모모 레시피를 복원해 다음 날로 넘어간다.

| 생맥주 제조 | 화면 안내에 따른 클릭·드래그 | 잔·레버를 조작해 맥주 제조 |
| 제공 | 완성품 선택 후 손님 선택 | 주문과 일치하는 음식/음료 제공 |
| 화면 이동 | 화면 내 스테이션 내비게이션 | 손님·조립·그릴·드링크 화면 전환 |

### 그릴 판정 이해하기

- 꼬치를 올린 직후에는 생것이며 시간이 흐르면서 서서히 익은 색으로 변한다.
- 너무 일찍 누르면 진행되지 않고 안내가 표시된다.
- 적정 구간에 누르면 앞면은 뒤집히고, 뒷면은 완성품으로 회수된다.
- 오래 방치하면 품질이 떨어지거나 타서 실패한다.
- 여러 꼬치의 타이머는 서로 독립적이므로 각 꼬치의 상태를 따로 확인해야 한다.

## 7. 차별점

### 1) 상태가 보이는 직접 조리

Three.js와 GLSL 셰이더로 하나의 승인된 꼬치 원본 위에 익힘 정도를 연속적으로 표현한다. 단순 타이머 바가 아니라 음식 자체가 익는 색을 보고 판단하도록 설계했다.

### 2) 손님 중심의 부분 제공

완성품을 생산 순서대로 자동 소모하지 않는다. 플레이어가 준비된 음식이나 음료를 선택하고, 해당 주문을 가진 손님에게 직접 제공한다. 생맥주를 먼저 내어 대기를 관리하거나 특정 손님을 우선하는 운영 판단이 생긴다.

### 3) 이야기와 시스템의 같은 방향

레시피 노트 복원은 이야기 소품이면서 메뉴 해금 장치다. 반복 영업은 단순 스테이지 클리어가 아니라, 가게의 불을 다시 밝히고 단골과 관계를 쌓는 과정이 된다.

### 4) AI 결과물을 게임 품질로 바꾸는 제작 체계

생성 이미지와 코드는 바로 게임에 넣지 않는다. 기획 원본, 요구사항, 구현 태스크, 테스트, 에셋 provenance와 사람 승인을 연결해 어떤 결과가 왜 채택되었는지 추적한다. 생성 속도와 함께 일관성, 재현성과 안전한 통합을 해결하는 것이 프로젝트의 기술적 특징이다.

## 10. 실행 방법

### 심사자용

1. [배포 URL]에 접속한다.
2. 가로 화면을 권장하며 PC에서는 Chrome 또는 Edge를 사용한다.
3. `새 게임`을 선택해 프롤로그부터 진행하거나, 제공되는 심사용 바로가기 [있다면 입력]를 사용한다.
4. 음향이 포함된 최종 빌드라면 브라우저의 오디오 재생 권한을 허용한다.

### 로컬 실행

```bash
cd app
npm install
npm run dev
```

브라우저에서 `http://127.0.0.1:8777/src/public-shell.html`을 연다.

전체 검증 명령은 다음과 같다.

```bash
npm run verify
```

## 12. 개발 확장 계획

### 본선 48시간 우선순위(제안)

1. 제출 빌드의 한 개 완결 루트를 고정하고 시작부터 정산까지 무중단 플레이를 보장한다.
2. AI를 게임 안의 새로운 경험으로 보여 줄 기능을 대회 주제 공개 후 핵심 루프에 결합한다.
3. 정식 아트·오디오의 누락을 사용자 시야에 보이는 순서대로 마감한다.
4. 실제 기기 성능, 첫 로딩, 터치 조작과 오디오 정책을 검증한다.
5. 자동 테스트와 사람 플레이테스트를 통과한 동일 빌드로 영상·문서를 갱신한다.

### 장기 방향

- D30까지 이어지는 30일 캠페인과 단골 서사
- 메뉴·공정, 손님 성격과 러시 패턴 확장
- 직원과 자동화를 통한 운영 빌드 다양화
