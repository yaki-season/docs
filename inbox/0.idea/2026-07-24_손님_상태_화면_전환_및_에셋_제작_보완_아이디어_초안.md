## 1. 기준 화면 확정

- 기준 화면은 `16:9`, `1920×1080 FHD` 모니터다.
- 기준 브라우저는 데스크톱 Chrome이다.
- 화면 구성, 정보 밀도, 카메라 프레이밍과 에셋 제작은 이 환경을 우선한다.
- 모바일 전환과 모바일 최적화는 가장 후순위로 기획한다.

## 2. 손님 상태 흐름

손님 화면에서 각 손님은 다음 네 가지 상태를 가진다.

```text
[주문 전]
  4~6초 동안 메뉴 고민
  머리 위에 "..." 표시
        ↓
[주문 중]
  주문 결정 완료
  머리 위에 클릭 가능한 주문서 아이콘 표시
        ↓ 플레이어가 주문서 아이콘 클릭
[주문 수령 대기]
  주문 내용 확인 및 조리 진행
  머리 위 남은 시간 게이지 감소
  음식이 나올 때마다 부분 서빙 가능
        ├─ 남은 시간 소진 → 실망하거나 화를 내며 퇴장
        └─ 모든 주문 음식 전달
                    ↓
[주문 수령]
  식사 및 음주 애니메이션 재생
  일정 시간이 지난 뒤 빈 그릇과 빈 컵을 남기고 퇴장
```

### 2.1 주문 전 상태

- 손님이 자리에 앉은 뒤 메뉴를 고민하는 상태다.
- 고민 시간은 `4~6초` 사이의 딜레이로 설정한다.
- 손님 머리 위에는 메뉴를 고민하고 있음을 보여주는 `...` 아이콘 또는 애니메이션을 표시한다.
- 이 상태에서는 아직 플레이어가 주문을 받을 수 없다.

### 2.2 주문 중 상태

- 손님이 주문할 메뉴를 모두 결정한 상태다.
- 손님 머리 위에 주문서 모양의 클릭 가능한 아이콘을 표시한다.
- 플레이어가 주문서 아이콘을 클릭하면 주문 내용을 확인하고, 손님은 주문 수령 대기 상태로 전환된다.

### 2.3 주문 수령 대기 상태

- 플레이어가 주문을 확인한 뒤 요리와 음료를 준비하는 상태다.
- 손님 머리 위에는 남은 시간이 줄어드는 시간 게이지를 표시한다.
- 남은 시간 안에 모든 주문 음식을 전달하지 못하면 손님은 실망하거나 화를 내며 가게를 떠난다.
- 주문한 모든 음식을 한 번에 전달할 필요는 없다. 완성된 음식부터 차례로 전달할 수 있다.
- 주문한 음식이 하나 전달될 때마다 손님의 남은 시간 게이지가 일정량 회복된다.
- 일부 음식만 전달된 동안에는 주문 수령 대기 상태를 유지하며, 전달 완료된 음식과 남은 주문을 구분해서 표시한다.
- 모든 주문 음식이 전달되면 주문 수령 상태로 전환된다.

### 2.4 주문 수령 상태

- 손님이 주문한 모든 음식과 음료를 전달받은 상태다.
- 손님은 음식과 주류를 먹고 마시는 모습을 애니메이션으로 보여준다.
- 식사 시간은 고정하지 않고 일정 범위 안에서 무작위로 정한다.
- 식사가 끝나면 손님은 빈 그릇과 빈 컵 등을 바 테이블 위에 남기고 퇴장한다.
- 남겨진 식기와 좌석 정리가 완료될 때까지 해당 자리는 빈 좌석으로 사용할 수 없는 상태가 될 수 있다.

## 3. 조리 화면 상단 주문서

- 조리 화면 상단에는 손님 좌석 순서와 대응하는 영수증 형태의 주문서 카드를 일렬로 표시한다.
- 각 주문서 카드에 반드시 표시할 정보는 다음 두 가지다.
  - 해당 손님에게 아직 전달하지 않은 주문 내용
  - 해당 손님의 남은 시간 게이지
- 부분 서빙한 음식은 완료 처리하여 미완료 주문 목록에서 제거하거나 완료 상태로 명확히 구분한다.
- 모든 주문을 전달한 손님의 주문서 카드는 완료 상태로 전환하며, 조리에 필요한 활성 주문 목록에서는 제외할 수 있다.
- 조리 화면의 주문서는 조리에 필요한 요약 정보이며, 손님 정보 화면 자체를 조리 화면 안에 중복해서 표시하지 않는다.

## 4. 손님 입장과 좌석 배치

- 플레이어는 손님을 직접 좌석으로 안내하거나 좌석을 선택하지 않는다.
- 시스템은 전체 남은 자리 수와 빈자리의 연속 여부를 함께 확인한다.
- 1인 손님은 빈자리 하나가 있으면 입장할 수 있다.
- 단체 손님은 인원수만큼의 빈자리가 있더라도 서로 붙어 있지 않으면 입장할 수 없다.
- 단체 손님의 입장 여부는 필요한 수만큼 연속된 빈 좌석이 있는지를 기준으로 결정한다.
- 손님이 입장하면 시스템이 조건에 맞는 연속 좌석에 자동으로 배치한다.

## 5. 준비 음식과 제공 대상 선택

- 일반 주문으로 만든 음식과 음료는 해당 주문과 손님에게 명확히 연결한다.
- 일반적인 경우 플레이어가 제공 대상을 다시 직접 선택하게 하지 않는다.
- 플레이어가 제공할 음식 또는 대상을 직접 선택하는 예외는 손님이 `맥주와 "아무거나"`를 주문한 경우에만 적용한다.
- `"아무거나"` 주문은 플레이어가 준비 가능한 음식 중 제공할 메뉴를 선택하는 특수 주문으로 취급한다.
- 부분 서빙 시에는 전달된 메뉴만 주문 완료 처리하고, 나머지 메뉴는 미완료 주문으로 유지한다.

## 6. 스테이션 단계별 전환

- 손님 테이블, 꼬치 조립, 굽기, 주류 등 각 화면은 일렬로 연결된 독립 스테이션으로 구성한다.
- 현재 화면의 양옆에 좌·우 이동 버튼을 배치한다.
- 플레이어는 좌·우 버튼을 클릭하여 인접한 이전 또는 다음 스테이션으로 이동한다.
- 손님 테이블 화면으로 이동하는 경로에는 주문 내역 하단의 `테이블 보기` 버튼도 제공한다.
- 좌·우 이동은 주인공이 실제 작업 공간에서 고개나 시선을 옮기는 방향과 일치해야 한다.

## 7. 퀵 전환

- 화면 우측 상단에 퀵 전환 버튼을 배치한다.
- 퀵 전환 버튼을 누르면 현재 플레이어가 볼 수 있는 모든 화면을 한 번에 표시한다.
- 목록에서 손님 테이블 또는 원하는 조리 스테이션을 선택하면 중간 화면을 거치지 않고 바로 이동한다.
- 잠겨 있거나 아직 사용할 수 없는 스테이션은 목록에서 숨기거나 비활성 상태로 구분한다.
- 단계별 좌·우 전환과 퀵 전환은 동일한 화면 상태를 공유하며, 어느 방식으로 이동해도 진행 중인 조리와 주문 상태가 유지된다.

## 8. 공통 원근감 확보를 위한 AI 에셋 제작 가설

공통 공간 배치도, 카메라 높이, 화각, 화면별 카메라 회전값과 소실점을 수치로 먼저 확정하는 방식은 현재 단계에서 사용하기 어렵다.

대신 다음과 같은 제작 방식을 검토한다.

1. AI가 손님 테이블과 모든 조리 스테이션을 포함하는 전체 장면을 한 번에 그린다.
2. 전체 장면에서 바 테이블, 손님, 음식, 불판, 주류 도구와 배경 등 필요한 요소를 하나씩 에셋으로 분리한다.
3. 분리한 에셋은 원본 장면에서의 위치, 크기, 각도와 겹침 관계를 유지하여 다시 배치한다.
4. 개별 화면용 에셋을 따로 생성하면서 발생하는 소실점, 원근과 화풍의 차이를 줄인다.

이 방식의 핵심은 모든 화면과 에셋이 하나의 통합된 원본 장면을 공유하게 하는 것이다. 다만 AI가 한 번에 생성한 장면만으로 서로 다른 시선 방향까지 자연스럽게 확보할 수 있는지는 실제 생성 결과로 검증해야 한다. 검증 시에는 다음 항목을 확인한다.

- 손님 정면, 아래쪽 불판과 옆쪽 주류 화면이 같은 가게 공간으로 이어져 보이는가
- 바 테이블의 높이와 깊이, 에셋의 크기 비율이 화면마다 유지되는가
- 에셋을 분리한 뒤에도 가려졌던 부분과 접촉면을 자연스럽게 복원할 수 있는가
- 분리한 2D 에셋과 직접 조작하는 3D 오브젝트의 투영이 어긋나지 않는가

## 9. 후속 정제 시 남은 항목

- 주문 전 고민 시간 `4~6초`의 무작위 분포
- 손님 유형별 기본 대기 시간과 시간 게이지 감소 속도
- 음식 하나를 전달했을 때 회복되는 시간 게이지의 양
- 주문 수령 후 식사 및 음주 시간의 무작위 범위
- 시간 초과 퇴장의 만족도, 명성 및 매출 처리
- 빈 그릇과 빈 컵을 정리하는 조작 방식
- `"아무거나"` 주문에서 선택 가능한 메뉴 범위와 선택 UI
- 통합 장면 생성 및 에셋 분리 방식의 실제 원근감 검증 결과
