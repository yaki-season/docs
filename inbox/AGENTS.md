# inbox AI 작업 지침

## 목적

개발 전뿐 아니라 `app` 구현 중이나 구현 후 발견된 개선사항, 수정사항, 결함과 새 아이디어를 빠짐없이 수집한다.

## 기록 규칙

- 빠른 메모는 형식을 강제하지 않는다.
- AI 파이프라인으로 처리할 항목은 가능하면 `template/inbox_변경요청_템플릿.md`를 사용한다.
- 현상과 원하는 결과를 구분한다.
- 관련된 `app` 기능 또는 파일 경로를 알면 기록하되 소스코드를 복사하지 않는다.
- 하나의 문서에는 하나의 핵심 변경사항을 기록한다.
- 최초 상태는 `접수`로 기록한다.

개발 중·개발 후 사람이 발견한 개선사항, 버그와 모순은 `99.change-request/`에 기록한다. 해당 디렉토리의 입력은 하위 `AGENTS.md`에 따라 처리한다.

## AI 처리 규칙

AI는 `inbox/` 문서를 직접 구현 지시로 사용하지 않는다. 관련 자료와 현재 `spec/`, `epic/`을 비교한 뒤 다음 중 하나로 판단한다.

- `반영`: 요구사항과 작업에 적용할 수 있음
- `질문 필요`: 결정에 필요한 정보가 부족함
- `중복`: 이미 같은 요구사항 또는 작업이 있음
- `보류`: 현재 범위나 우선순위에 포함되지 않음
- `기각`: 프로젝트 방향 또는 제약과 충돌함

처리 결과에는 관련 `spec/`, `epic/` 경로와 판단 근거를 원문에 남긴다.
