# 변경 요청 AI 처리 지침

## 처리 대상

`spec/meta/inbox_처리_이력.md`에 같은 경로와 SHA-256 지문 조합이 아직 기록되지 않은 사람 입력 파일을 처리한다. 같은 경로라도 지문이 달라졌다면 사람이 갱신한 새 원본 리비전으로 처리한다. `README.md`와 `AGENTS.md`는 운영 지침이므로 처리 대상에서 제외한다.

## 처리 순서

1. 사람의 원본을 읽기 전용으로 취급하며 수정·이동·이름 변경·삭제하지 않는다.
2. 원본 내용 전체의 SHA-256 지문을 계산하고 기존 처리 이력과 비교한다.
3. 현상, 기대 결과, 변경 이유와 영향 영역을 구분한다.
4. 관련 `spec/`과 모든 `epic/` 태스크를 검색한다.
5. 중복, 충돌, 모순과 필요한 질문을 판별한다.
6. 반영 가능한 내용은 관련 `spec/` 상세 설계서에 근거 경로·지문과 변경 이력을 남기며 생성하거나 갱신한다.
7. 새 `spec/`은 `v1.0.0`으로 만들고 기존 문서 변경 시 버전을 올린다.
8. 변경된 요구사항을 참조하는 `대기`·`진행 중` 태스크에 즉시 반영하고 태스크 문서 버전을 올린다.
9. 기존 태스크로 처리할 수 없는 범위는 담당 개발자에게 `v1.0.0`의 새 순번 태스크로 생성한다.
10. `epic/작업_현황.md`의 작업 수, 버전, 현재 작업, 대기·보류·완료 목록을 갱신한다.
11. 판단, 원본 지문, 반영된 `spec/`·`epic/` 경로와 버전을 `spec/meta/inbox_처리_이력.md`에 기록한다.

## 처리 판단

- `반영 완료`: `spec/`과 필요한 `epic/`에 반영함
- `질문 필요`: 정보가 부족해 확정할 수 없음
- `중복`: 이미 같은 내용이 반영되어 있음
- `보류`: 현재 범위나 우선순위에서 처리하지 않음
- `기각`: 프로젝트 기준과 충돌해 반영하지 않음

판단이 무엇이든 원본에는 표시하지 않고 `spec/meta/inbox_처리_이력.md`에만 기록한다.

## 저장소 경계

이 파이프라인에서는 문서만 갱신한다. 구현, 테스트, 빌드, 배포와 운영 소스는 `app` 저장소에서만 변경한다.
