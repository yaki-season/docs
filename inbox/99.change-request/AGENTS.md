# 변경 요청 AI 처리 지침

## 처리 대상

이 디렉토리에서 상태가 `접수`인 변경 요청을 처리한다. `README.md`와 `AGENTS.md`는 입력 문서가 아니므로 처리 대상에서 제외한다.

## 처리 순서

1. 사람의 원문을 보존하고 문장 표현만으로 의미를 임의 변경하지 않는다.
2. 현상, 기대 결과, 변경 이유와 영향 영역을 구분한다.
3. 관련 `spec/`과 모든 `epic/` 태스크를 검색한다.
4. 중복, 충돌, 모순과 필요한 질문을 판별한다.
5. 반영 가능한 내용은 관련 `spec/` 상세 설계서에 근거 경로와 변경 이력을 남기며 갱신한다.
6. 변경된 요구사항을 참조하는 `대기`·`진행 중` 태스크에 즉시 반영한다.
7. 기존 태스크로 처리할 수 없는 범위는 담당 개발자에게 새 순번의 태스크로 생성한다.
8. `epic/작업_현황.md`의 작업 수, 현재 작업, 대기·보류·완료 목록을 갱신한다.
9. 원본 변경 요청에 판단, 반영된 `spec/`, 반영된 `epic/`과 남은 질문을 기록한다.

## 상태 변경

- 분석을 시작하면 `분석 중`
- 정보가 부족하면 `질문 필요`
- 문서 반영이 끝나면 `반영 완료`
- 이미 반영된 내용이면 `중복`
- 현재 처리하지 않으면 `보류`
- 프로젝트 기준에 맞지 않으면 `기각`

## 저장소 경계

이 파이프라인에서는 문서만 갱신한다. 구현, 테스트, 빌드, 배포와 운영 소스는 `app` 저장소에서만 변경한다.
