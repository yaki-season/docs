# D1 완료 tray·음식 원근/톤 보정 — PM 보고 및 지시 초안

- 생성 주체: AI (Artist 1)
- 상태: 미정제 변경 요청 초안 — 사용자 또는 PM의 별도 지시 전까지 spec·epic·runtime 기준이 아님

## 관찰된 문제

`SCR-SVC-GRILL-FINISHED-PROPER-SIX-SLOT R2` 소비 화면 후보에서 완료 네기마와 완료 tray가 `CM-GRILL-STATION-QUEUED-SELECTION R3`의 고정 카메라와 다른 정면 2D 인상으로 보인다.

- `ST-GRILL-FINISHED-TRAY R1`은 upper-right FHD anchor `(1534, 130, 218, 342)`를 지키지만, station 안에서 깊이감 없이 정면 평면처럼 읽힌다.
- `MDL-NEGIMA-GRILL-PROPER-SECOND-FACE`의 현행 shape/shader는 master의 고기 덩어리감, 외곽선, 숯불 반사와 일치하지 않는다.
- 두 요소를 함께 놓으면 tray와 꼬치가 master의 상단 우측 공간에 속하지 않고 별도 정면 UI처럼 보인다.

`CM-GRILL-STATION-EMPTY-BASE R1`의 카메라·원근·구도·조명·색조는 사용자 승인 상태이며 수정 대상이 아니다. 현재 소비 화면 R2도 승인된 바 없고, 이 관찰을 해결하기 전 finalizer·runtime handoff·manifest 등록을 금지한다.

## PM에게 요청할 다음 음식 작업 지시

다음 네기마 또는 후속 음식 model/shader 작업을 시작할 때, 기존의 음식 단일 상태 검수에 아래 공통 gate를 추가해 한 묶음으로 처리한다.

1. `CM-GRILL-STATION-QUEUED-SELECTION R3`의 고정 camera/perspective를 음식 모델의 유일한 소비 카메라로 삼는다. 정면 아이콘/orthographic 상품 컷을 완료 tray 또는 석쇠 소비 화면의 기준으로 사용하지 않는다.
2. `MDL-NEGIMA-GRILL-*`의 raw·first-face·second-face·proper·burnt를 같은 3/4 상부 시점에서 비교한다. 꼬치의 두께, 닭·대파의 부피, 잉크 외곽, 석쇠/숯불에 따른 따뜻한 반사광을 master와 비교해 승인받는다.
3. proper는 실제 익은 닭 속살의 밝고 먹음직스러운 회갈색, 절제된 진갈색 sear, 대파의 익은 녹색을 유지한다. raw와 같은 분홍색 또는 평면적인 정면 실루엣으로 읽혀서는 안 된다.
4. 180° 뒤집기, 면별 시간, `contactFace`, 회수/재투입/복구 보존이라는 기존 gameplay state contract는 유지한다. 시각 보정이 state 의미를 바꾸거나 별도 raster/GLB 사본을 만들 근거가 되지 않는다.
5. 새 음식 후보는 먼저 master 위의 해당 station 위치에 한 상태만 합성한 FHD/720 소비 검수로 사용자의 원근·톤 승인을 받는다. 음식 단독 checkerboard 승인만으로 station 소비 승인으로 간주하지 않는다.

## Artist 1의 즉시 분리 범위

음식 model/shader 보정은 위 PM 묶음으로 보류한다. Artist 1은 그 전에 **음식 없는 완료품 rack**만 별도 후보로 제작·검수한다.

- 유지: approved base, FHD anchor `(1534, 130, 218, 342)`, runtime registration 금지.
- 제작: 승인 `ST-GRILL-WAITING-RACK R2`의 얕은 cavity·가까운 쪽 rim·top-down material language를 직접 참조하는 작은 empty completed-food rack. 독립된 비스듬한 UI 카드나 새 소품으로 해석하지 않는다.
- 제외: 네기마, 꼬치, shader 수정, 음식 raster/texture/GLB, 집게, 버튼, 텍스트, 서빙 접시, finalizer.
- 승인 뒤에도 음식이 수정되기 전에는 tray에 네기마를 다시 합성하지 않는다.
