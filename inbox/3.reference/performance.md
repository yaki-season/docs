# 성능 예산 스펙

## 목적 (Why)

웹 제출(GitHub Pages) 특성상 심사관이 **모바일 브라우저**로 열 가능성이 높다.
"열자마자 부드럽게 도는 것"이 첫인상의 절반이므로, 성능은 사후 최적화가 아니라
**개발 전 과정에서 지켜야 하는 예산**으로 관리한다.
모든 AI 코드 생성 세션의 컨텍스트에 이 문서를 포함할 것.

## 기준 환경 (Baseline)

| 항목 | 기준 |
|---|---|
| 기준 기기 | 중급 Android (Galaxy A3x~A5x급) + Chrome 최신 |
| 보조 확인 | iPhone SE급 + Safari (iOS WebGL 특이사항 확인용) |
| 데스크톱 | 개발 편의용일 뿐, **성능 판정 기준이 아님** |
| 목표 프레임 | 기준 기기에서 **30fps 고정** (데스크톱 60fps) |
| 프레임 예산 | 33ms — JS 로직 ≤8ms / 렌더 ≤20ms / 여유 ≥5ms |

## 예산 수치 (Hard Budget)

위반 시 PR 리뷰에서 반려한다. "일단 넣고 나중에 최적화"는 금지.

### 렌더링

| 항목 | 상한 | 비고 |
|---|---|---|
| 드로우콜 | ≤ 30 | 배경 계층은 합쳐서 1~3콜 목표 |
| 삼각형 | ≤ 50,000 | 인터랙티브 메시는 개당 ≤2,000 |
| 실시간 광원 | ≤ 3 | 숯불 point + ambient + 보조 1 |
| 반투명 오버드로우 | 같은 픽셀 위 ≤ 3겹 | 연기/김/글로우가 주범. 겹침 설계 필수 |
| 풀스크린 포스트 패스 | **0** | 블룸 금지 → 글로우 스프라이트로 대체 |
| 그림자 | 실시간 그림자 맵 금지 | 접지감은 blob shadow(원형 반투명 쿼드) |

### 파티클 / 이펙트

| 항목 | 상한 | 비고 |
|---|---|---|
| 동시 파티클 총량 | ≤ 200 | InstancedMesh 필수, 개별 Mesh 생성 금지 |
| 숯불 불씨 | ≤ 80 | |
| 연기 | 큰 쿼드 ≤ 6장 | 셰이더 UV 스크롤로 흐름 표현 |
| 판정/타격 이펙트 | 이벤트당 ≤ 30, 수명 ≤ 1s | |

### 메모리 / 로드

| 항목 | 상한 | 비고 |
|---|---|---|
| 초기 로드 (gzip) | ≤ 5MB | 첫 인터랙션까지 ≤ 5초 (4G 기준) |
| 텍스처 메모리 | ≤ 64MB | 배경 2048², 오브젝트 ≤1024², UI 아틀라스 1장 |
| 텍스처 포맷 | 배경 JPG/WebP, 알파 필요 시 WebP | PNG 남발 금지 |
| 오디오 | 지연 로드, 초기 번들 제외 | |
| 런타임 GC | 게임 루프 내 객체 생성 금지 | Vector3/배열 재사용, 풀링 필수 |

## 동작 규칙 (Rules)

1. **품질 2단계 폴백**: 시작 시 기기 감지(디바이스 픽셀 비율·GPU 문자열·첫 3초 fps 측정)
   → LOW 모드에서는 파티클 총량 50%, 연기 쿼드 3장, renderer pixelRatio 1.0 고정.
2. **pixelRatio 상한 1.5**: 고해상도 폰에서 필레이트 폭발 방지. 데스크톱은 2.0 허용.
3. **일시정지 시 렌더 루프 정지**: 탭 비활성/메뉴 화면에서 requestAnimationFrame 중단.
4. **로직/렌더 분리 유지**: 게임 시스템(TypeScript 모듈)은 renderer를 import하지 않는다.
   성능 문제 발생 시 렌더러만 교체 가능해야 한다.

## 측정 (How we verify)

| 도구 | 용도 | 주기 |
|---|---|---|
| Chrome DevTools Performance | 프레임 타임, JS/렌더 분해 | 주요 기능 머지 전 |
| Spector.js | 드로우콜·오버드로우 검사 | 렌더링 변경 시 |
| `renderer.info` HUD | 드로우콜/삼각형 실시간 표시 (디버그 빌드) | 상시 |
| 실기기 테스트 | 기준 기기 30fps 확인 | 주 2회 이상 |

측정 스크린샷은 `docs/inbox/perf-logs/`에 날짜별 저장 → **AI 활용 기술 문서의
before/after 근거 자료**로 사용한다.

## 완료 조건 (Acceptance Criteria)

- [ ] 기준 기기 Chrome에서 러시 상황(손님 2팀 + 꼬치 4개 + 숯불/연기) 30fps 유지
- [ ] 초기 로드 gzip ≤ 5MB, 첫 플레이 가능까지 ≤ 5초 (4G 스로틀링)
- [ ] Spector.js 캡처: 드로우콜 ≤ 30, 최대 오버드로우 ≤ 3겹
- [ ] iPhone SE Safari에서 크래시/블랙스크린 없음
- [ ] LOW 폴백 모드 진입 및 동작 확인
- [ ] 게임 루프 1분간 GC 스파이크(>5ms) 0회

## 열린 질문 (Open Questions)

- [ ] LOW 모드 자동 판정 임계값 — 첫 3초 평균 fps 몇으로? (초안: <25)
- [ ] 배경 슬라이스 패럴랙스가 LOW 모드에서도 유지되는가? (측정 후 결정)
- [ ] 본선(48h)용 예산은 이 문서를 그대로 상속할지, 완화 버전을 만들지
