# inbox 운영 원칙

`inbox`는 사람이 게임 개발에 필요한 자료를 정리하거나 정제하기 전에 원본 그대로 넣는 공간이다.

`app`에서 태스크를 개발하는 중이거나 완료한 뒤 발견한 개선사항, 수정사항과 결함도 다시 이곳에 기록한다.

## 핵심 원칙

### 1. 지저분해도 된다

형식, 파일명, 완성도는 강제하지 않는다. 한 줄 메모, 불완전한 문장, 아직 검증되지 않은 생각도 보관한다.

정리하려고 기다리다가 자료가 사라지는 것보다, 미완성 상태로라도 남기는 편이 낫다.

### 2. 여기 있는 것은 전부 아직 확정이 아니다

`inbox`의 모든 내용은 초안이다. 승인된 요구사항도 아니고, 구현 기준도 아니다.

코드 구현은 `inbox`가 아니라 정제된 `spec/`과 `epic/`을 기준으로 시작한다. AI에게도 `inbox` 자료만 보고 구현하도록 지시하지 않는다.

### 3. 사람이 정제하지 않는다

회의록, 메신저 대화, 관찰 기록, 스케치와 참고자료는 원문 그대로 넣어도 된다. 내용이 여러 주제를 섞고 있거나 중복·모순되어도 괜찮다.

AI가 원본에서 필요한 사실과 결정을 추출하고 관련 카테고리의 `spec/` 문서로 정제한다. 원본은 출처 추적을 위해 `inbox/`에 그대로 보존한다.

## 기존 aidd-input 분류의 새 위치

| 기존 분류 | 새 위치 |
|---|---|
| `00-basic-design` 게임 컨셉, 코어 루프, 기획, 시나리오 | `inbox/0.idea/`, `inbox/1.design/`, `spec/scenario/` |
| `01-spec` 판정 규칙, 동작 정의, 데이터 구조 | `spec/gameplay/`, `spec/system/`, `spec/data/` |
| `02-ui` 화면 구성, 연출, UX 아이디어 | `spec/ui/`, `inbox/1.design/` |
| `03-difficulty` 난이도, 밸런싱 수치 | `spec/gameplay/`, `spec/data/` |
| `04-art-reference` 레퍼런스 아트, 컨셉 이미지, 에셋 | `inbox/2.art-concept/`, `inbox/3.reference/`, `spec/art/` |
| `05-performance` 성능 목표, 최적화 메모 | `spec/system/` |
| `06-constraints` 일정, 플랫폼, 기술적 제약 | `spec/qa/`, `spec/system/` |

## 파일 작성 권장 방식

파일명과 형식은 자유다. 날짜나 출처를 알고 있으면 함께 남기되 필수는 아니다.

마크다운 상단에는 가능하면 날짜와 출처를 적는다.

```md
2026-07-17 / 회의 중 기록

손님 인내심 이야기가 나왔고 15초 안과 20초 안이 모두 제안됨.
```

## 이미지와 에셋

이미지와 에셋은 필요하면 그대로 커밋한다. 단, 이미지에는 같은 이름의 설명 파일을 함께 둔다.

```text
grill-ref-01.png
grill-ref-01.md
```

설명 파일은 사람이 알고 있는 맥락을 자유롭게 적는다. 정제된 반영 기준은 `spec/art/`에 별도로 작성한다.

## 개발 중 변경사항

개발 중 발견된 변경사항은 가능하면 `template/inbox_변경요청_템플릿.md`로 기록한다. 기록 후에는 `template/AI_변경사항_반영_파이프라인.md`를 실행해 `spec/`과 `epic/`을 먼저 갱신하고, 갱신된 작업을 기준으로 `app` 구현을 계속한다.
