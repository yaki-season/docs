---

## 1. 목적

메뉴 항목을 **카테고리**로 정리한다. 카테고리는 세 가지를 동시에 규정한다.

- 손님이 **무엇을 주문하는가** (주문 단위)
- 요리사가 **어디서 만드는가** (스테이션)
- 한 손님이 **몇 번 시킬 수 있는가** (중복 주문 규칙)

별도의 공정 축이나 음료/안주 이분 플래그를 두지 않는다. 카테고리 하나가 이 셋을 모두 담는다.

---

## 2. 카테고리 정의

메뉴 항목은 **카테고리 하나**를 가진다. 카테고리는 **스테이션과 1:1**로 대응한다.

| 카테고리 | 만드는 곳(스테이션) | 중복 주문 | 성격 | 대표 메뉴 | 현재 구현 |
|---|---|---|---|---|---|
| **음료** | 드링크 | 가능 | 주력 | 생맥주, 하이볼, 사와 | ❌ 스테이션 미구현 |
| **꼬치** | 꼬치(조립+구이) | 가능 | 주력 | 네기마, 모모, 츠쿠네, 카와 | ✅ 네기마 |
| **튀김** | 튀김 | 1회 | 특선 | 가라아게 | ❌ |
| **사시미** | 사시미 · 플레이팅 | 1회 | 특선 | 사시미 모듬 | ❌ |
| **사이드** | 즉시제공 | 1회 | 사이드 | 양배추 | ❌ |

---

## 3. 중복 주문 규칙 (주력 vs 특선)

한 손님이 같은 카테고리를 몇 번 주문할 수 있는지는 카테고리 속성으로 정한다.

- **주력(음료·꼬치)**: 밤새 계속 시켜 먹는 회전 메뉴. 한 손님의 주문에 **여러 번** 올 수 있다.
- **특선/사이드(튀김·사시미·사이드)**: 튀김·사시미는 한 접시 시켜 나눠 먹는 메뉴, 사이드는
  오토시성 한 접시(양배추 = 생양배추). 성격상 **한 번만** 낸다. 한 손님의 주문에 최대 1회.
- 이 규칙이 손님별 주문량 차이를 만든다(주력을 여러 번 넣으면 많이, 안 넣으면 소량).

---

## 4. 메뉴 매핑 (기획서 5장 기준)

| 메뉴 | 카테고리 | 해금 |
|---|---|---|
| 네기마 (대파 닭꼬치) | 꼬치 | 시작 |
| 모모 (닭다리살) | 꼬치 | 시작 |
| 생맥주 | 음료 | 시작 |
| **양배추** (즉시제공) | 사이드 | 확장 |
| 츠쿠네 | 꼬치 | Lv2 |
| 카와 / 난코츠 | 꼬치 | Lv2 |
| 삼겹살말이 | 꼬치 | Lv3 |
| 하이볼 | 음료 | Lv3 |
| 가라아게 | 튀김 | Lv4 |
| 사시미 모듬 | 사시미 | Lv5 |
| 오니기리 · 츠키미 츠쿠네 등 | 복합 | Lv6+ |

> 변경: 기획서의 즉시제공 메뉴 **에다마메 → 양배추**로 교체한다. 오토시(생양배추) 역할로
> "노력 0, 회전율용" 성격은 동일하다.

## 5. 카테고리 설정 (구현 참조)

```js
const CATEGORY = {
  음료:   { station: '드링크',   repeatable: true  },
  꼬치:   { station: '꼬치',     repeatable: true  },
  튀김:   { station: '튀김',     repeatable: true  },
  사시미: { station: '사시미',   repeatable: false },
  사이드: { station: '즉시제공', repeatable: false },
};
```

메뉴 항목은 `{ name, category }`를 가지며, `category`가 `CATEGORY`의 키를 참조한다.
스테이션 라우팅과 중복 규칙은 전부 `CATEGORY`에서 파생한다.

---

## 6. 주문 규칙과 손님 시스템 연계

주문 자체의 표현(순서열)과 손님 유형별 주문 내용은 **짝 문서(손님 유형과 상태 머신 설계)**가 다룬다.
본 문서가 제공하는 것은 그 순서열이 지켜야 할 규칙이다.

- 주문 = **카테고리의 순서열**. 카테고리가 주문의 단위다.
- **중복 규칙**(3장)이 순서열 안에서 한 카테고리가 여러 번 올 수 있는지를 정한다.
  주력은 여러 번, 특선·사이드는 최대 1회.
- 순서열 작성 시 이 규칙을 검증한다(특선·사이드가 2회 이상 나오면 무효).

---

## 7. 서빙 접점에서의 카테고리

요리사가 완성한 접시가 손님으로 넘어갈 때 **어느 카테고리인지**를 함께 넘긴다.
손님은 현재 대기 중인 슬롯의 카테고리와 일치할 때만 수령한다.

```
serve payload = { category, recipeMatched, frontResult, backResult }
```

상세 계약과 판정은 짝 문서 6장 참조.

---

## 8. 현재 구현 현실

- 실제 구현된 스테이션은 **꼬치 하나**뿐이다. `음료·튀김·사시미·사이드`는 스테이션이 없어
  현재는 주문·서빙이 불가능하다.
- 따라서 지금 단계에서 유효한 주문은 사실상 `꼬치`뿐이며, 나머지 카테고리는 **선행 설계**다.
- 드링크 스테이션 도입 시점이 음료 카테고리 활성화의 전제다(퇴근직장인·취객 주문에 영향).
