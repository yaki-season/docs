# 그릴 꼬치 익힘 상태 UI 설계 초안

> 문서 상태: 초안 v0.1 · 작성일 2026-07-30 · 대상: 프로덕션 영업 그릴 화면(`SCR-SVC-GRILL`)
>
> 근거: `spec/gameplay/GPL-004 조리 스테이션과 품질 서빙`(면별 익힘·품질), `spec/gameplay/GPL-001`(면별
> 판정·뒤집기/회수 규칙), `spec/ui/UI-003 전체 게임 상세 화면 설계`(영업 shell·그릴 화면), `spec/data/DAT-001`
> (네기마 면별 적정 8초·과다 16초·탄 21초).
>
> 성격: 그릴에서 굽는 중인 각 꼬치의 **익힘 정도를 플레이어가 UI로 읽을 수 있게** 하는 표시 계약 초안이다.
> 확정 spec이 아니라 spec 개정을 위한 구체화 단계다.

---

## 1. 목적

지금은 그릴 칸 꼬치의 익힘이 **셰이더 색(마이야르·그을음)** 으로만 드러난다. 색 변화는 미묘하고
절대적 판정(덜 익음/적정/과다/탄)이나 **뒤집기·회수 적기**를 명시적으로 알려주지 않아, 초심자는 언제
뒤집고 언제 빼야 하는지 판단하기 어렵다.

굽는 중인 각 꼬치에 대해 **현재 면·익힘 단계·적정 구간까지의 진행도**를 UI로 표시해, 색 관찰에만
의존하지 않고 조리 타이밍을 읽을 수 있게 한다.

## 2. 현재 상태 (구현 현실)

- `SCR-SVC-GRILL`은 N개의 칸을 가지며 각 칸이 앞·뒤 독립 타이머로 굽는다(`cookStations`).
- 칸 상태는 `slotViews`가 제공한다: `status`(`empty|front|back`), `doneness`(`under|perfect|over|burnt`),
  `faceElapsedSec`(현재 면 경과), `cooking`.
- 면별 임계값(콘텐츠 구동): **덜 익음 [0,8초) · 적정 [8,16초) · 과다 [16,21초) · 탄 [21초~)**.
- 뒤집기·회수는 **적정 또는 과다**일 때만 허용(`canAdvance`), **탄** 면이 있으면 칸 폐기.
- 익힘값은 셰이더 색으로만 표시되고, 별도 판정·게이지 UI는 없다.

## 3. 요구 사항

굽는 칸(`status=front|back`)마다 다음을 화면에서 확인할 수 있어야 한다.

1. **현재 면**: 앞면 / 뒷면.
2. **익힘 단계**: 덜 익음 · 적정 · 과다 · 탄 (텍스트 + 색).
3. **진행 게이지**: 현재 면의 경과를 임계 구간(덜 익음→적정→과다→탄) 위에 표시. 적정 구간을 강조해
   "지금 뒤집기/회수 적기"를 시각적으로 드러낸다.
4. **행동 신호**: 적정 진입 시 "뒤집기 가능"(앞면) / "회수 가능"(뒷면)을 강조, 탄 임박(과다 후반)엔 경고.
5. 빈 칸(`empty`)에는 표시하지 않는다. 그릴 화면일 때만 보인다(다른 화면 카메라에 걸쳐 보이지 않게).

## 4. 표시 설계

### 4-1. 배치
- 각 그릴 칸 위에 **DOM 오버레이**를 띄운다(좌석 말풍선·대기 게이지와 동일 패턴, `bubbleLayer`류).
- 칸의 월드 좌표를 화면 좌표로 투영해 칸 바로 위에 정렬. 그릴 화면 진입 시만 표시.

### 4-2. 익힘 게이지
- 가로 막대. 전체 길이를 **탄(21초)** 기준으로 정규화하고, 구간 경계(8·16·21초)를 눈금으로 표시.
- 채움 = `faceElapsedSec / 21`. 채움 끝(현재 위치)에 마커.
- 구간 색:
  | 단계 | 구간 | 색 | 의미 |
  |---|---|---|---|
  | 덜 익음 | 0~8초 | 회색/차분 | 아직 이르다 |
  | 적정 | 8~16초 | 녹색 | **뒤집기/회수 적기** |
  | 과다 | 16~21초 | 주황 | 가능하나 품질↓ |
  | 탄 | 21초~ | 적/검정 | 폐기 임박·경고 |
- 적정 구간은 배경을 옅게 강조해 "목표 창"을 항상 보이게 한다.

### 4-3. 라벨·신호
- 상단 라벨: `앞면 · 적정` 형태(면 + 단계). 색은 단계색.
- 적정/과다 진입 시(=canAdvance) 라벨에 액션 힌트: 앞면→`뒤집기`, 뒷면→`회수`.
- 과다 후반·탄에서는 라벨을 붉게 깜빡여 경고(대기 게이지 긴급 표시와 톤 일관).

### 4-4. 접근성
- 색만으로 구분하지 않는다. 단계는 항상 텍스트로 병기. 게이지 눈금·마커로 위치를 이중 표현.

## 5. 데이터 계약

표시는 `slotViews(now)`의 파생만 사용한다(새 상태 없음).

```
slotView = { index, status, doneness, faceElapsedSec, cooking }
파생: stageColor(doneness), actionable = canAdvance(doneness),
      progress = faceElapsedSec / burntSec, faceLabel = status==='front' ? '앞면' : '뒷면'
```

임계값은 `recipe.COOK_THRESHOLDS_SEC`(콘텐츠 구동)를 그대로 참조한다. 매직 넘버를 UI에서 다시 정의하지 않는다.

## 6. 명시적 제외

- 조리 자동화·직원 효과(굽기 자동)와는 무관. 표시만 다룬다.
- 셰이더 색 규칙 변경 없음(게이지는 색 관찰을 **보완**한다).
- 부채 강화(fan-boost)로 인한 경과 가속의 시각화는 후속(강화 사용 시 게이지가 앞당겨지면 자연 반영).

## 7. 검증 관점

- 굽는 칸마다 게이지·라벨이 뜨고, 빈 칸엔 안 뜬다.
- 경과에 따라 단계 색·라벨이 덜 익음→적정→과다→탄으로 바뀐다.
- 적정/과다에서 액션 힌트(뒤집기/회수)가 뜨고, 덜 익음에선 안 뜬다.
- 그릴 화면에서만 보이고 다른 화면에선 숨는다.

## 8. 열린 과제

- [ ] 게이지를 칸 위 DOM으로 둘지, 3D 빌보드로 둘지(현재 좌석 말풍선은 DOM → 일관성상 DOM 제안).
- [ ] 남은 초(카운트다운) 수치까지 노출할지, 구간·색만 둘지(초심자 vs 숙련자).
- [ ] 다중 칸이 많아질 때(그릴 6칸) 오버레이 밀집 처리.
