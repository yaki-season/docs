# 게임용 이미지 생성 규격화 요구사항 초안

- 생성일: `2026-08-23`
- 생성 주체: `AI (Codex)`
- 상태: `미정제 원본 / 요구사항 초안`
- 작성 근거: 사용자와의 아트 규격화 대화 및 현재 게임 manifest·런타임 에셋·소비 코드 확인
- 확정 범위: 영업 화면 좌석 인물, 스토리 장면의 이미지 구성, 꼬치·음료 이미지와 공통 생성 절차

> 이 문서는 사용자의 명시적 요청으로 `inbox`에 작성한 AI 초안이다. 아직 정식 구현 요구사항이 아니며, 사용자가 별도로 지시하기 전까지 `spec`, `spec/meta`, `epic`과 `app`에는 반영하지 않는다.

## 1. 작성 목적

현재 게임에 들어간 인물 이미지는 쓰임새가 같아도 원본 크기, 화면 속 인물 크기, 배치, 그림체와 픽셀 밀도가 서로 다르다. 이미지 생성 프롬프트에 단순히 “츠키오카 이미지를 기준으로 한다”고 적는 것만으로는 다른 캔버스, 다른 인물 크기와 다른 배치가 반복해서 생성된다.

앞으로는 다음을 목표로 한다.

1. 이미지를 생성하기 전에 실제로 사용될 게임 화면과 용도를 먼저 정한다.
2. 같은 용도의 이미지는 동일한 캔버스, 앵커, 픽셀 밀도와 화면 검수 조건을 사용한다.
3. 현재 승인된 게임 이미지를 직접 참조해 처음부터 게임에 넣을 수 있는 최종 크기로 생성한다.
4. 인물의 외형과 체형은 다양하게 표현하되, 실제 좌석과 화면에 사용할 수 없는 자세와 배치는 차단한다.
5. 스토리 장면은 일반 배경 위에 작은 전신 초상을 얹는 방식이 아니라, 장면 맥락이 담긴 완성 일러스트로 보여준다.

## 2. 현재 우선 규격화 대상

### 2.1 영업 화면 좌석 인물

- 카운터 좌석에 앉아 정면을 바라보는 손님 이미지
- 대기, 주문, 음식 먹기, 맥주 마시기와 반응 상태
- 여러 손님이 동시에 앉았을 때 서로 겹치지 않고 좌석에 맞게 보이는 인물 레이어

### 2.2 스토리 장면

- 영업 전, 영업 종료 후, 회상과 사건 장면에 사용하는 완성 일러스트
- 한 명이 등장하는 장면, 두 인물이 대화하는 장면과 인물이 없는 서술 장면
- 같은 장면 안에서 말하는 인물을 강조하고 듣는 인물을 낮추는 화자 전환

### 2.3 별도 대화 초상 카테고리

현재 화면의 `일반 배경 + 투명 전신 인물 한 장` 구성은 앞으로의 목표가 아니다. 별도의 미래 UI가 구체적으로 요구되지 않는 한 `대화용 초상`, `스토리용 전신 투명 컷아웃`을 독립 아트 카테고리로 제작하지 않는다.

스토리에서 인물 레이어를 기술적으로 분리하더라도, 최종 화면은 반드시 하나의 맥락 있는 완성 장면으로 보여야 한다.

### 2.4 꼬치 이미지

- 재료 조립 과정, 조립 완료 대기, 그릴 조리 상태와 손님 제공 상태
- 주문표, 재고와 완성품 목록에 사용하는 꼬치 아이콘
- 현행 게임에 승인 등록되어 실제 코드가 소비하는 네기마·모모를 우선 기준으로 삼는 신규 꼬치 규격

### 2.5 음료 이미지

- 현행 게임이 실제 소비하는 맥주 제조 화면, 주문 아이콘과 손님 제공 맥주 이미지
- 앞으로 추가할 하이볼, 레몬사와와 그 밖의 음료가 공유할 화면 레이어·아이콘·제공 이미지 계약
- 음료마다 달라지는 제조 장비, 잔, 재료, 장식과 제조 상태를 독립적으로 확장할 수 있는 메뉴별 음료 모듈

## 3. 모든 이미지에 적용할 공통 원칙

### 3.1 기준 화면

| 구분 | 기준 |
|---|---|
| 1차 제작·승인 화면 | PC `1920×1080` |
| 추가 축소 검수 | PC `1280×720` |
| 한 화면 최대 표시 좌석 | `6석` |
| 모바일 | 이번 초안에서 제외하고 이후 별도 규격화 |

최종 이미지는 `1920×1080` 화면에서 사용할 실제 크기와 배치를 기준으로 만든다. `1280×720`에서는 새 구도를 만들지 않고 같은 화면을 축소했을 때 인물 식별, 픽셀 밀도, 겹침과 크롭이 유지되는지 확인한다.

8석·12석 확장에서는 인물을 축소해 한 화면에 모두 넣지 않는다. 카운터를 최대 6석 단위의 구역으로 나누고 좌우 화면 전환으로 이동한다. 모든 구역은 같은 인물 크기, 좌석 간격과 픽셀 밀도를 사용한다.

### 3.2 공통 화풍과 톤앤매너

- 내부 스타일 기준은 `YS-HANDCRAFTED-NIGHT-v1`, 작업명은 `손끝이 남은 따뜻한 밤`을 사용한다.
- 연필 밑그림, 불균일한 잉크선, 여러 번 덧칠한 과슈 색면과 제한된 종이 질감이 보여야 한다.
- 실내의 호박색·황갈색 빛과 밤의 남색·인디고 환경색을 함께 유지한다.
- 인물 피부, 옷, 목재, 음식과 배경이 서로 다른 렌더링 방식처럼 보이지 않게 한다.
- 플라스틱처럼 매끈한 피부, 균일한 벡터 선, 사진 같은 PBR 광택, 과한 렌즈 효과를 사용하지 않는다.
- 특정 작가, 스튜디오나 기존 작품의 고유 화풍을 복제하지 않는다.
- 가짜 문자, 워터마크, 서명, 설명 화살표, UI와 의미 텍스트를 이미지에 굽지 않는다.

### 3.3 픽셀 밀도

- `640×360` 같은 단일 저해상도 논리 격자를 모든 이미지에 강제하지 않는다. 츠키오카 기준 이미지는 하나의 고정 픽셀 크기가 아니라 용도에 따라 밀도가 달라지는 혼합형 표현이다.
- 아래 수치는 원본 캔버스 픽셀이 아니라, 최종 `1920×1080` 화면에서 보이는 화면 픽셀 기준이다.
- 인물의 외곽과 형태를 결정하는 주요 윤곽선은 대체로 `2~4px` 굵기를 목표로 한다.
- 머리카락, 옷 주름, 명암과 과슈 색면의 대표 군집은 대체로 `3~6px` 단위로 읽히게 한다.
- 눈매, 안경, 입, 손가락과 표정선은 필요한 곳에 `1~2px` 세부를 허용한다.
- 종이결과 연필 흔적의 `1~2px` 표현은 주변과 명도 차가 작은 재질 정보일 때만 허용한다. 형태와 무관한 고대비 `1px` 점, 자동 디더링과 불규칙한 픽셀 얼룩은 허용하지 않는다.
- 픽셀은 단순 다운샘플 필터가 아니라 형태, 명암과 재료를 설명하는 덩어리여야 한다.
- 서로 다른 종류의 에셋도 실제 화면에 합성했을 때 픽셀 군집의 보이는 크기가 같아야 한다.
- 최종 파일은 브라우저에서 흐릿하게 보간하지 않고 최근접 보간(`nearest`) 또는 동등한 픽셀 보존 방식으로 표시한다.

`3px 스타일`, `4px 스타일`처럼 숫자만 프롬프트에 적은 결과를 규격 준수로 인정하지 않는다. 수치 구간을 맞췄더라도 기준 이미지와 다르게 보이면 통과가 아니다. 같은 화면 크기로 나란히 비교했을 때 선 굵기, 얼굴 정보량, 과슈 색면과 픽셀 군집이 츠키오카 기준 이미지와 한 세트로 읽혀야 한다.

### 3.4 실제 화면 비교 테스트에 따른 결정

`2026-08-23`에 현재 승인된 츠키오카, `3px 의도` 직접 생성본과 `4px 의도` 직접 생성본을 동일한 영업 화면의 같은 크기와 앵커에 합성해 `1920×1080`, `1280×720`에서 비교했다.

- 승인된 츠키오카는 작은 표정선, 안경, 머리카락, 옷의 잉크선과 과슈·종이 질감이 함께 유지됐다.
- `3px 의도`와 `4px 의도` 생성본은 픽셀 밀도 차이가 육안으로 거의 구분되지 않았다.
- 두 생성본 모두 승인본보다 선과 재질이 매끈하고 단순해졌으며 얼굴, 머리 크기와 체형도 달라졌다.
- 생성 지시의 출력 크기와 실제 생성 파일 크기도 일치하지 않았다.

따라서 단일 `3px`, `4px` 또는 `640×360` 논리 격자는 공통 규격으로 채택하지 않는다. 픽셀 수치는 위 혼합 밀도 구간으로 관리하고, 승인 여부는 반드시 실제 게임 화면의 동일 크기 비교로 결정한다. 생성 파일이 요청한 캔버스와 포맷을 지키지 않으면 합성 전에 규격 미달로 처리하며, 임의 확대본을 최종 에셋으로 승인하지 않는다.

## 4. 생성 전에 반드시 준비할 기준 묶음

텍스트로 “츠키오카와 같게” 또는 “네기마·모모와 같게”라고 적는 것만으로는 기준을 전달한 것으로 보지 않는다. 매 생성 작업에는 다음 자료를 실제 이미지 입력으로 함께 제공한다.

1. 같은 쓰임새의 승인된 런타임 이미지 원본 1장 이상
2. 해당 파일을 등록한 런타임 manifest와 실제 소비 코드의 캔버스·앵커·배치값
3. 현재 런타임 리비전과 일치하는 기존 승인 화면 자료가 있을 때는 그 자료
4. UI 안전 영역, 좌석 또는 인물 앵커와 가림선을 표시한 배치 가이드
5. 대상 인물의 승인된 얼굴, 머리, 체형, 복장과 대표색 기준
6. 만들 상태 하나와 그 상태에서 허용되는 손·팔·소품 동작 설명

원본 크기와 화면 배치를 프롬프트 문장만으로 설명하지 않고 실제 기준 파일과 코드의 계약값을 제공한다. AI가 임의로 재구성한 화면, 검수용 원화 합성판과 현재 리비전을 확인하지 않은 새 캡처는 규격 근거로 사용하지 않는다. 화면 자료가 필요하면 현재 승인 리비전과 결선된 기존 자료를 우선 사용하며, 새 런타임 캡처는 사용자가 별도로 요청한 경우에만 보조 검수 자료로 만든다.

## 5. 기본 제작 방식

### 5.1 현재 기본 방식: 최종 사용 크기로 바로 생성

현재는 게임에 들어간 승인 이미지와 실제 화면 캡처가 충분히 존재한다. 따라서 큰 원화를 먼저 만든 뒤 축소·픽셀화하는 방식을 기본 절차로 사용하지 않는다.

1. 사용할 화면과 상태를 먼저 고른다.
2. 같은 용도의 승인 런타임 이미지, manifest와 실제 소비 코드의 배치값을 기준으로 고른다.
3. 최종 런타임 캔버스, 앵커와 픽셀 밀도를 처음부터 적용해 생성한다.
4. 임의로 화면을 재구성하지 않고 현재 승인 런타임의 실제 결선 경로에 바로 대입한다.
5. 사람이 현재 게임을 직접 확인해 승인한 결과만 최종 기준으로 삼는다. 새 캡처 파일은 사용자가 별도로 요구할 때만 보조 자료로 남긴다.

### 5.2 기준 이미지가 전혀 없을 때만 사용하는 예외 방식

참고할 승인 이미지가 없는 새로운 종류의 장면이나 에셋에만 큰 원화 제작을 제한적으로 허용한다.

1. 기존 게임 화면, 공통 화풍과 가장 가까운 승인 이미지를 반드시 참고한다.
2. 큰 원화는 새로운 화풍을 탐색하기 위한 자유 원화가 아니라 기존 게임의 시각 언어를 확장하는 기준 원화여야 한다.
3. 사람이 원화의 화풍, 인물 정체성, 구도와 게임 적합성을 검사하고 승인한다.
4. 승인 전에는 원화 일부를 후속 이미지의 기준으로 사용하지 않는다.
5. 승인 후에도 최종 게임 이미지는 각 실제 화면의 캔버스, 앵커와 픽셀 밀도로 별도 제작하고 다시 화면 검사를 받는다.

## 6. 영업 화면 좌석 인물 규격

### 6.1 최우선 기준 이미지

| 항목 | 기준 |
|---|---|
| 런타임 ID | `D1-TSUKIOKA-WAITING` R3 |
| 기준 파일 | `app/public/assets/core/customer/d1-tsukioka-waiting-r3-b1.png` |
| 캔버스 | `1920×1080` |
| 포맷 | `sRGB 8-bit RGBA PNG`, straight alpha, 무손실 |
| 현재 츠키오카 앵커 | `logical-seat-anchor-fhd: (1086, 594)` |
| 앞으로의 공통 제작 앵커 | `seatHipAnchor: (960, 594)` |

앞으로 좌석 인물 생성에서 “츠키오카를 기준으로 한다”는 말은 위 파일의 얼굴을 복제하라는 뜻이 아니다. 다음 항목을 같은 수준으로 맞추라는 뜻이다.

- 최종 캔버스와 알파 처리
- 실제 화면 속 인물의 정보량과 픽셀 군집 크기
- 카운터 뒤에 앉은 깊이와 하체 가림
- 좌석과 맞닿는 엉덩이 기준 앵커
- 정면 중심 시선과 제한된 자세 범위
- 인물과 배경이 공유하는 선, 채색, 재료와 조명

### 6.2 파일과 앵커

- 좌석 인물의 최종 납품본은 `1920×1080` 투명 전체 화면 캔버스를 기본으로 한다.
- 생성 단계에서는 인물의 엉덩이를 화면 중앙의 `seatHipAnchor: (960, 594)`에 맞춘다.
- 실제 좌석에서는 이미지 크기를 바꾸지 않고 `seatHipAnchor`의 가로 위치만 해당 좌석 중심으로 이동한다.
- 인물의 위치는 머리 높이가 아니라 엉덩이가 좌석에 닿는 `seatHipAnchor`로 정렬한다.
- `seatHipAnchor`와 실제 불투명 영역의 외곽 범위를 부가 정보에 기록한다.
- 같은 인물의 모든 상태는 동일 캔버스와 동일 `seatHipAnchor`를 유지한다.
- 인물마다 키를 맞추기 위한 개별 확대·축소를 하지 않는다.
- `1280×720`에서는 인물만 따로 줄이지 않고 전체 `1920×1080` 화면을 같은 비율로 축소한다.
- 카운터, 좌석, 좌석 번호, 주문 UI, 접시와 테이블 표면을 인물 이미지에 굽지 않는다.
- 음식이나 맥주를 실제로 손에 들고 있는 상태에서는 그 행동에 필요한 소품만 인물 상태에 포함할 수 있다.

### 6.3 신체 다양성과 화면 배치

- 공통 제작 앵커 `(960, 594)`를 기준으로 인물과 손에 든 소품의 불투명 영역은 가로 `x=820~1100` 안에 둔다.
- 좌석 인물 한 명의 불투명 영역 최대 폭은 `280px`, 앵커 좌우 각각 최대 `140px`다.
- 6석의 최소 좌석 중심 간격 약 `296px`에서 인접 인물 사이에 최소 `16px`의 투명 간격을 남긴다.
- 머리 꼭대기는 FHD 기준 `y=180~300` 범위에 둔다.
- 고정된 엉덩이 기준 `y=594`에서 머리 꼭대기까지의 허용 높이는 `294~414px`다.
- 인물의 최소 폭은 정하지 않는다.
- 모든 인물의 머리 꼭대기, 눈높이, 키와 전체 배율을 동일하게 맞추지 않는다.
- 키, 앉은키, 머리 크기, 목 길이, 어깨 폭, 몸통 길이와 체형 차이를 유지한다.
- 짧은 인물을 억지로 확대하거나 큰 인물을 축소해 머리 높이를 맞추지 않는다.
- 좌우 폭은 인접 인물, UI와 주문 표시를 침범하지 않는 범위에서 넓게 허용한다.
- 어깨, 외투, 머리카락과 자연스러운 팔 실루엣 때문에 폭이 넓어지는 것은 허용한다.
- 가장 폭이 넓은 인물끼리 인접 좌석에 앉힌 실제 화면 검사를 통과해야 한다.
- 키 차이 때문에 말풍선 위치가 달라질 수 있으므로 말풍선은 고정 머리 높이가 아니라 인물별 머리 외곽 범위에서 계산하거나 별도 앵커를 둔다.
- 한 화면에는 최대 6석만 표시한다.
- 8석·12석 확장에서는 6석 단위의 카운터 구역을 좌우로 전환하며, 좌석 수에 맞춰 인물을 축소하지 않는다.
- 대기·먹기·마시기 등 모든 상태는 손, 팔과 들고 있는 음식·맥주잔까지 `x=820~1100`을 벗어나지 않는다.

### 6.4 기본 자세

- 기본 대기·주문 상태는 몸통과 얼굴이 정면 중심을 향한다.
- 작은 고개 기울기, 자연스러운 어깨 높이 차이와 표정 변화는 허용한다.
- 옆을 보거나 대각선으로 앉아 인물의 좌석 방향이 달라 보이는 자세는 금지한다.
- 기본 상태에서 손, 팔이나 팔꿈치를 카운터·책상 위에 올려두지 않는다.
- 손은 무릎 위, 몸 가까이, 자연스럽게 내린 위치 또는 허용된 소품을 드는 위치에 둔다.
- 카운터 밖으로 몸을 과하게 내밀거나 다른 좌석 영역으로 팔을 뻗지 않는다.

### 6.5 행동 상태에서 허용되는 손과 팔

다음 행동은 당연히 허용한다.

- 꼬치나 음식을 손에 들기
- 음식을 입으로 가져가거나 먹기
- 맥주잔을 들기
- 맥주를 마시기
- 주문에 필요한 작은 손짓과 물건 수령 동작

금지 대상은 손이나 팔 자체가 아니라, 기본 대기·주문 이미지에서 손·팔·팔꿈치를 카운터 위에 기대어 올려놓는 자세다.

### 6.6 상태 제작 순서

1. 인물마다 정면 대기 기본 상태 한 장을 먼저 만든다.
2. 기본 상태를 실제 영업 화면에 합성해 사람이 승인한다.
3. 먹기, 맥주 마시기, 만족과 다른 상태는 승인된 기본 상태를 편집해 한 상태씩 만든다.
4. 후속 상태를 새 인물처럼 처음부터 다시 생성하지 않는다.
5. 후속 상태에서도 얼굴, 체형, 복장, 캔버스, `seatHipAnchor`, 픽셀 밀도와 광원을 유지한다.
6. 여러 자세를 한 시트에 한꺼번에 생성하지 않는다. 한 번의 생성·검수 단위는 한 인물의 한 상태다.

최소 우선 상태는 다음 세 가지다.

1. 정면 대기
2. 음식 먹기
3. 맥주 마시기

추가 상태는 실제 게임 상태표에 연결된 용도가 확인된 뒤 같은 방식으로 확장한다.

## 7. 스토리 장면 규격

### 7.1 좋은 기준과 사용하지 않을 기준

| 판정 | 현재 예시 | 앞으로의 사용 방식 |
|---|---|---|
| 좋은 기준 | `IL-D1-PREOPEN-TSUKIOKA`, `app/public/assets/core/s0/story/d1-preopen-tsukioka-full-scene-r1-b1.png` | 장소, 조명, 인물과 행동이 한 장면으로 읽히는 완성 일러스트 |
| 사용하지 않을 구성 | `BG-INTERIOR-BASE` 위에 `CH-TSUKIOKA-STORY`를 작게 중앙 배치한 영업 종료 후 화면 | 일반 배경과 독립 전신 컷아웃이 서로 따로 보이는 구성 |

영업 종료 후 장면도 예외가 아니다. 장면의 시간, 장소, 인물의 위치, 행동과 감정이 함께 표현된 완성 일러스트를 사용한다.

### 7.2 장면 교체 단위

- 대사 한 줄이나 화자가 바뀔 때마다 새 일러스트를 만들지 않는다.
- 같은 장소, 행동, 시간대, 감정 흐름과 카메라가 이어지는 동안 하나의 완성 장면을 유지한다.
- 장소 이동, 핵심 행동, 감정의 큰 전환, 시간대 또는 카메라 의미가 실제로 바뀔 때만 새 장면을 만든다.
- 이 단위를 스토리 장면 단위(`storyBeat`)로 기록하고, 같은 장면 단위 안에서는 화자 강조 상태만 바꾼다.

### 7.3 두 인물 대화 장면의 구도

- 두 인물은 같은 공간 안에 실제로 함께 있는 완성 구도로 그린다.
- 화면 왼쪽 인물은 오른쪽 인물을, 화면 오른쪽 인물은 왼쪽 인물을 바라보게 한다.
- 얼굴이 읽히지 않는 완전한 옆모습보다 서로를 바라보면서 관객에게도 표정이 보이는 안쪽 `3/4` 방향을 기본으로 한다.
- 두 인물의 거리, 시선 높이와 주변 소품은 대화 관계가 자연스럽게 보이도록 구성한다.
- 인물을 각각 다른 조명과 원근으로 생성해 배경 위에 붙인 것처럼 보이게 하지 않는다.

### 7.4 화자 강조 상태

같은 스토리 장면 단위에서 화자만 바뀌면 다음 초기 공통값으로 강조 상태를 전환한다.

| 상태 | 크기 | 밝기 | 채도 | 설명 |
|---|---:|---:|---:|---|
| 말하는 인물 | `103%` | `100%` | `100%` | 본래 색과 밝기를 유지하며 조금 앞으로 나와 보이게 함 |
| 듣는 인물 | `97%` | `72%` | `90%` | 조금 뒤로 물러나고 어둡게 보여 화자에게 시선이 가게 함 |

- 확대·축소 기준점(`focusAnchor`)은 화면 중앙이 아니라 각 인물의 발, 엉덩이 또는 장면 내 접촉점으로 둔다.
- 강조 전환 때문에 발이 바닥에서 뜨거나 의자에서 엉덩이가 움직여 보이면 안 된다.
- 화자 전환 시간은 `160~220ms` 범위의 짧고 부드러운 전환을 초기값으로 사용한다.
- 확대된 화자가 상대 인물, 화면 가장자리, 대사 영역과 겹치지 않아야 한다.
- 듣는 인물의 레이어만 어둡게 처리한다. 배경이나 화면 한쪽 전체를 함께 어둡게 만들지 않는다.
- 화자가 없는 서술 장면에서는 인물 강조를 끄고 장면 원래 색과 크기를 사용한다.
- 위 수치는 최초 공통값이다. 실제 화면 사람 검사를 거쳐 조정한 뒤 프로젝트 전체 공통값으로 잠근다. 장면마다 임의로 다르게 바꾸지 않는다.

### 7.5 스토리 파일 구성

스토리 장면은 처음부터 최종 `1920×1080`, 16:9 구도로 제작한다.

| 산출물 | 규격 | 용도 |
|---|---|---|
| 완성 장면 기준본 | `1920×1080`, sRGB, 불투명 무손실 PNG | 장면 전체의 화풍·구도·광원 승인과 회귀 비교 |
| 배경 레이어 | `1920×1080`, 불투명 PNG | 같은 스토리 장면 단위의 고정 공간 |
| 인물 A 레이어 | `1920×1080`, straight-alpha RGBA PNG | 화자·비화자 강조 전환 |
| 인물 B 레이어 | `1920×1080`, straight-alpha RGBA PNG | 화자·비화자 강조 전환 |
| 합성 검수본 2장 | `1920×1080` | A가 말할 때와 B가 말할 때의 실제 화면 비교 |

- 먼저 최종 크기의 완성 장면을 하나의 일러스트로 승인한 뒤, 같은 결과에서 배경과 인물을 마스크로 분리한다.
- 레이어 분리를 위해 인물을 각각 새로 다시 생성하지 않는다.
- 분리 뒤 생긴 빈 배경, 머리카락·옷 가장자리와 접지 그림자를 사람이 보정한다.
- 배경과 인물 레이어를 다시 합성했을 때 승인된 완성 장면과 시각적으로 같아야 한다.
- 독립 인물 레이어만 떼어 다른 일반 배경에 재사용하지 않는다. 해당 스토리 장면 단위의 구성 요소로만 사용한다.
- 레이어 분리를 쉽게 하려고 두 인물을 부자연스럽게 멀리 떼거나 접촉·가림 관계를 없애지 않는다.

## 9. 실제 화면 승인 조건

### 9.1 좌석 인물

- [ ] `1920×1080` 실제 영업 화면에서 엉덩이가 좌석 기준에 맞고 카운터 가림이 자연스럽다.
- [ ] `1280×720`에서 얼굴, 안경, 표정과 행동 소품을 식별할 수 있다.
- [ ] 인물마다 키와 체형 차이가 보이며 머리 높이를 억지로 맞추지 않았다.
- [ ] 같은 인물의 상태를 바꿔도 얼굴, 체형, 복장, 앵커와 화면 속 크기가 튀지 않는다.
- [ ] 가장 넓은 인물끼리 인접 좌석에 놓아도 서로의 얼굴, 몸과 UI가 겹치지 않는다.
- [ ] 기본 상태의 손, 팔과 팔꿈치가 카운터 위에 올라가 있지 않다.
- [ ] 먹기·마시기 상태의 손과 소품 접촉이 자연스럽고 손가락·관절 오류가 없다.
- [ ] 카운터, 좌석, 테이블, UI와 의미 문자가 인물 래스터에 들어 있지 않다.
- [ ] 츠키오카 기준 이미지와 비교했을 때 선, 색면과 픽셀 군집 크기가 같은 세계로 읽힌다.

### 9.2 스토리 장면

- [ ] 장면만 보고 장소, 시간대, 인물 관계와 핵심 상황을 이해할 수 있다.
- [ ] 일반 배경과 독립 전신 초상이 따로 노는 형태로 보이지 않는다.
- [ ] 같은 스토리 장면 단위에서 화자가 바뀌어도 배경, 카메라와 인물 위치가 불필요하게 바뀌지 않는다.
- [ ] 말하는 인물은 본래 색으로 조금 강조되고 듣는 인물은 조금 작고 어둡게 보인다.
- [ ] 화자 전환 중 발, 엉덩이와 접촉 그림자가 움직이거나 떠 보이지 않는다.
- [ ] A 화자·B 화자 합성본 모두에서 얼굴, 시선, 대사 영역과 화면 가장자리가 겹치지 않는다.
- [ ] 분리 레이어 재합성이 승인된 완성 장면과 같은 광원, 원근, 픽셀 밀도로 보인다.
- [ ] 영업 전뿐 아니라 영업 종료 후 장면도 맥락에 맞는 완성 일러스트를 사용한다.

## 10. 현재 정식 문서와 런타임에서 추후 재검토할 충돌

이 항목은 이번 초안 작성만으로 수정하지 않는다. 사용자가 정식 반영을 지시할 때 영향 범위를 확인하기 위한 메모다.

1. `ART-003`에는 모든 좌석 상태 이미지의 눈높이와 화면 배율을 같게 한다는 내용이 있다. 새 방향은 눈높이를 고정하지 않고 `seatHipAnchor`만 고정한다.
2. `ART-003`에는 `CH-*-PORTRAIT`와 좌석 인물 이미지·대화 초상 일치 규칙이 있다. 새 방향에서는 독립 대화 초상을 기본 카테고리에서 제외하고 맥락 있는 스토리 완성 일러스트를 사용한다.
3. 현재 영업 화면 배치 코드에는 “츠키오카와 같은 머리 높이”라는 전제가 있다. 새 방향은 인물별 키와 앉은키 차이를 보존해야 한다.
4. 현재 일부 스토리 대사는 화자별로 완성 일러스트를 교체하고, 영업 종료 후 장면은 일반 배경 위에 투명 전신 인물을 배치한다. 새 방향은 스토리 장면 단위의 완성 장면을 유지하고 화자 강조만 전환한다.
5. 기존 문서의 `2048×1152` 기본 배경과 현재 승인 이미지의 `1672×941`, `1920×1080` 규격이 섞여 있다. 새 방향은 실제 FHD 화면에 즉시 사용하는 이미지의 기준 캔버스를 `1920×1080`으로 통일하는 안이다.
6. 현재 네기마·모모는 그릴의 `109×494` 상태 파일이 일치하고, 모모 조립 단계도 같은 캔버스를 사용한다. 그러나 네기마 조립 트레이 `128×512`, 네기마 주문 아이콘 `192×192`, 네기마 제공 접시 `1000×600`과 모모의 아이콘·접시 규격은 서로 다르다. 신규 메뉴부터 12절의 계약을 적용하고 기존 두 메뉴의 변환은 별도 작업으로 다룬다.
7. 현재 손님 화면은 메뉴별 제공 접시 한 장만 선택하며 실제 제공 수량 `1`과 `2 이상`을 이미지로 구분하지 않는다. `served-1`, `served-2` 결선에는 제공 수량을 읽어 텍스처를 선택하는 후속 구현이 필요하다.
8. 현재 주문표, 그릴 대기와 완성품 목록이 같은 꼬치 아이콘 파일을 일관되게 재사용하지 않는다. 신규 `256×256` 공통 아이콘을 모든 해당 UI에 연결하는 작업은 정식 문서 반영 뒤 별도 구현 범위로 잡는다.

## 11. 아직 별도로 정하지 않은 범위

- 모바일 전용 크롭, 캔버스와 터치 UI 안전 영역
- 세 명 이상이 동시에 등장하는 대화 장면의 강조 방식
- 영업 좌석 인물과 스토리 장면 이외의 배경, 꼬치 이외 음식, 도구, 꼬치 주문 아이콘 이외의 UI 아이콘별 세부 캔버스
- 최종 파일 용량 최적화와 PNG에서 WebP 등으로 변환하는 배포 규칙

이 범위는 현재 확정한 좌석 인물, 두 인물 스토리 장면과 꼬치 이미지의 제작을 막지 않는다. 실제 사용 화면이 정해질 때 각각 별도 규격으로 확장한다.

## 12. 꼬치 이미지 계약

### 12.1 기준과 적용 범위 — 확정

꼬치 이미지는 빈 꼬치, 재료 조립 중, 조립 완료 대기, 그릴 조리 상태, 주문 아이콘과 손님 제공 접시까지 실제 플레이에서 이어지는 한 메뉴의 이미지 묶음을 대상으로 한다. 메뉴 도감의 큰 소개 일러스트는 정보량과 목적이 달라 이 계약에서 제외한다.

신규 꼬치의 정본 기준은 임의로 만든 화면 캡처가 아니라, 현재 manifest에 승인 등록되고 실제 코드가 소비하는 아래 네기마·모모 파일과 배치 계약이다.

| 용도 | 현행 기준 |
|---|---|
| 네기마 그릴 | `app/public/assets/core/cooking/spr-negima-grill-*-r1-b1.png` |
| 모모 그릴 | `app/public/assets/campaign/d2/spr-momo-grill-*-r1-b1.png` |
| 모모 조립 단계 | `app/public/assets/campaign/d2/spr-momo-assembly-progress-*-r1-b1.png` |
| 네기마 주문 아이콘 | `app/public/assets/core/ui/order-icon-negima-r1-b1.png` |
| 모모 주문 아이콘 | `app/public/assets/campaign/d2/order-icon-momo-r1-b1.png` |
| 네기마 제공 접시 | `app/public/assets/core/customer/pr-served-negima-plate-r2-b1.png` |
| 모모 제공 접시 | `app/public/assets/campaign/d2/pr-served-momo-plate-r1-b1.png` |

현행 네기마의 `128×512` 조립 트레이, `192×192` 주문 아이콘과 현행 모모의 `2048×1024` 제공 접시는 기존 결선을 깨지 않기 위한 예외로 유지한다. 신규 꼬치부터 아래 통일 규격을 적용하며, 이 초안만으로 기존 파일을 변환하거나 런타임 결선을 변경하지 않는다.

### 12.2 그릴 꼬치 한 개의 공통 파일 계약 — 확정

| 항목 | 확정값 |
|---|---|
| 캔버스 | `109×494px` |
| 포맷 | `sRGB 8-bit straight-alpha RGBA PNG`, 무손실 |
| 제작 배율 | 최종 사용 크기 `100%`에서 직접 제작 |
| 기본 방향 | 세로, 뾰족한 끝이 위 |
| 길이 중심축 | `x=54` |
| 위·아래 투명 여백 | 각각 `4~6px` |
| 최대 가시 가로 범위 | `x=4..104` 안쪽 |
| 가로 실루엣 | 재료 종류에 따라 자유, 고정 폭 없음 |

- 현행 `raw` 기준 네기마의 알파 영역은 `x=4..104`, `y=4..489`, 모모는 `x=14..95`, `y=6..487`이다. 이 차이는 메뉴의 재료와 굵기를 보여주는 정상적인 다양성이다.
- 모든 익힘 상태는 같은 캔버스, 중심축, 꼬치 끝과 손잡이 위치를 유지한다.
- 익으면서 재료가 조금 수축하거나 가장자리 형태가 변하는 표현은 허용하지만, 꼬치 전체가 이동·확대·축소되면 안 된다.
- 한 상태 이미지에 접시, 트레이, 석쇠, 불, 연기, 집게, 손, UI와 문자를 함께 넣지 않는다.
- 큰 원화를 축소하거나 후처리로 픽셀화하지 않고 처음부터 `109×494` 최종 파일로 제작한다.

### 12.3 조립 단계와 조립 완료 대기 — 확정

- 조립 이미지는 그릴과 동일한 `109×494px` 세로 원본을 사용한다.
- 재료 수가 `N`개이면 `0`부터 `N`까지 총 `N+1`개 논리 상태가 필요하다.
- `0단계`는 재료가 없는 빈 꼬치다.
- `1~N단계`는 손잡이 쪽부터 재료가 하나씩 추가된 상태다.
- 먼저 꽂힌 재료는 다음 단계에서 위치가 움직이지 않는다.
- `N단계`는 그릴 `raw`와 픽셀 위치 및 내용이 동일해야 하며 같은 PNG를 재사용한다.
- 조립 완료 대기 트레이도 별도 이미지를 만들지 않고 같은 `raw` PNG를 재사용한다.
- 조립 지그와 트레이에서 필요한 가로 방향, 기울기, 크기와 쌓임 위치는 런타임 배치가 처리한다. 가로로 돌린 별도 PNG를 납품하지 않는다.
- 현행 네기마의 `128×512` 조립 트레이 파일은 기존 예외로만 유지한다.

논리 상태 연결은 다음과 같다.

`조립 N단계 = 조립 완료 대기 = 그릴 raw`

### 12.4 익힘 상태와 앞뒤 처리 — 확정

메뉴 하나의 그릴 상태 이미지는 아래 총 `5장`이다.

| 상태 | 표현 |
|---|---|
| `raw` | 재료 본래색과 촉촉한 표면 |
| `cooking` | 약한 호박색과 초기 갈변 |
| `proper` | 따뜻한 황갈색과 읽을 수 있는 그릴 자국 |
| `overcooked` | 더 어둡고 건조하며 낮아진 채도 |
| `burnt` | 진한 갈색이지만 유지되는 재료 구분과 실루엣 |

- 앞면과 뒷면 전용 이미지 열 장을 따로 만들지 않는다.
- 게임 로직은 양면의 조리 시간을 독립적으로 계산하되, 화면에는 현재 보이는 면의 익힘 단계에 해당하는 공통 상태 이미지를 사용한다.
- 뒤집기에는 같은 상태 이미지를 런타임에서 반전해 사용한다.
- 탄 상태를 식별할 수 없는 검은 덩어리로 만들거나, 적정 상태를 균일한 주황색 광택 덩어리로 만들지 않는다.
- 연기, 불씨, 기름 튐과 순간적인 윤기는 이미지에 넣지 않고 별도 VFX로 처리한다.
- 파일명은 현행 패턴인 `spr-{menuId}-grill-{state}-r{sourceRevision}-b{runtimeBuild}.png`를 따른다.

### 12.5 픽셀 밀도와 톤 — 확정

- 고정된 제한 색상표를 강제하지 않는다. 현행 네기마와 모모처럼 작은 캔버스 안에서 재료의 결, 단면과 익힘 차이를 표현할 수 있는 색을 사용한다.
- 주요 외곽선은 짙은 갈색 `1~2px`을 기준으로 한다.
- 고기 결, 채소 단면과 그릴 자국은 `1~4px` 크기의 읽을 수 있는 덩어리로 표현한다.
- 검은색 외곽선을 두껍게 두르거나, 형태와 무관한 자동 디더링·고대비 점 노이즈를 만들지 않는다.
- 반투명 픽셀은 가장자리 정리에만 제한적으로 사용한다. 흰색 또는 검은색 알파 테두리가 남으면 반려한다.
- 런타임은 최근접 보간을 사용하고 밉맵을 생성하지 않는다.
- 신규 `raw`를 현행 네기마·모모 `raw`와 `100%` 크기로 나란히 놓았을 때 외곽선, 재료 세부와 픽셀 덩어리의 밀도가 같은 범위로 보여야 한다.
- 익힘 단계가 진행될수록 `본래색 → 호박색·초기 갈변 → 황갈색·그릴 자국 → 어둡고 건조함 → 진한 갈색`의 순서를 유지한다. 재료가 닭과 파가 아니어도 같은 명도·건조 변화의 방향을 따른다.

### 12.6 주문·재고·완성품 아이콘 — 확정

| 항목 | 확정값 |
|---|---|
| 캔버스 | `256×256px` |
| 포맷 | `sRGB 8-bit straight-alpha RGBA PNG`, 무손실 |
| 파생 원본 | 해당 메뉴의 확정된 그릴 `raw` |
| 중심 | `(128,128)` |
| 방향 | 손잡이 왼쪽 아래, 뾰족한 끝 오른쪽 위 |
| 회전 | 세로 원본에서 시계 방향 약 `36°` |
| 목표 가시 영역 | 약 `x=40..216`, `y=20..236` |

- 주문 아이콘을 새로 해석해 그리지 않고 그릴 `raw`에서 파생한다.
- 모든 메뉴는 아이콘 안에서 비슷한 전체 길이로 보이게 한다. 재료의 굵기와 실루엣 차이는 유지한다.
- 주문표, 재고와 완성품 목록에서 같은 아이콘 파일을 재사용한다.
- 현행 네기마 `192×192`, 현행 모모의 반대 대각선과 넓은 여백은 기존 예외로만 유지한다.

### 12.7 손님 제공 접시 — 확정

| 항목 | 확정값 |
|---|---|
| 캔버스 | `1000×600px`, `5:3` |
| 포맷 | `sRGB 8-bit straight-alpha RGBA PNG`, 무손실 |
| 접시·음식 전체 영역 | `x=174..686`, `y=256..414` |
| 접시 중심 | 약 `(430,335)` |
| 꼬치 방향 | 손잡이 왼쪽, 뾰족한 끝 오른쪽 |
| 꼬치 가로 길이 범위 | 약 `x=205..545` |

- 실제 런타임 표시 영역 `260×156`과 같은 `5:3` 비율을 사용한다.
- 접시를 캔버스 왼쪽에 배치하고 오른쪽은 현행 맥주잔이 놓일 공간으로 비워둔다.
- 접시, 그림자, 원근, 광원과 위치는 모든 메뉴에서 동일하게 유지하고 음식만 교체한다.
- 제공 꼬치는 해당 메뉴의 `proper` 상태를 가로로 돌려 파생한다.
- `served-1`은 꼬치 한 개를 중심선 `y=335`에 둔다.
- `served-2`는 꼬치 두 개를 중심선 `y=300`, `y=355`에 평행하게 둔다.
- 제공 수량이 `0`이면 접시를 표시하지 않고, `1`이면 `served-1`, `2` 이상이면 `served-2`를 표시한다.
- 세 개 이상의 정확한 수량은 주문 UI 숫자로 표현하며 접시 이미지에는 최대 두 개만 그린다.
- 현행 모모 `2048×1024` 제공 접시는 기존 예외로만 유지한다.

### 12.8 메뉴 하나의 필수 산출물 수 — 확정

재료가 `N`개인 신규 꼬치 메뉴의 서로 다른 최종 PNG는 총 `N+8장`이다.

| 묶음 | 서로 다른 PNG 수 | 설명 |
|---|---:|---|
| 조립 `0..N-1` | `N` | 빈 꼬치부터 마지막 재료 직전까지 |
| 그릴 상태 | `5` | `raw`, `cooking`, `proper`, `overcooked`, `burnt` |
| 주문·재고 아이콘 | `1` | 그릴 `raw` 파생 |
| 제공 접시 | `2` | `served-1`, `served-2` |

`조립 N단계`, `조립 완료 대기`와 `그릴 raw`는 같은 PNG 한 장을 공유하므로 중복 계산하지 않는다. 앞뒤 전용 이미지, 별도 트레이 이미지와 가로 회전 복제본도 만들지 않는다. 재료가 다섯 개인 메뉴는 총 `13장`이다.

### 12.9 파일 승인 조건

- [ ] 모든 그릴·조립 원본이 `109×494px`, sRGB straight-alpha RGBA PNG다.
- [ ] 모든 원본의 중심축이 `x=54`이고 위·아래 투명 여백이 각각 `4~6px`다.
- [ ] 조립 단계에서 이미 꽂힌 재료가 다음 단계에 이동하지 않는다.
- [ ] `조립 N단계`, 조립 완료 대기와 그릴 `raw`가 같은 픽셀 내용을 사용한다.
- [ ] 다섯 익힘 상태에서 꼬치 끝, 손잡이, 중심축과 전체 화면 속 크기가 움직이지 않는다.
- [ ] 익힘 단계가 색만 덮은 것처럼 보이지 않고 재료의 결, 건조와 그릴 자국 변화가 읽힌다.
- [ ] 아이콘이 `256×256`, 제공 접시 두 장이 각각 `1000×600` 규격을 지킨다.
- [ ] 제공 접시의 음식과 접시가 맥주잔 공간을 침범하지 않는다.
- [ ] 최근접 보간에서 흰색·검은색 알파 테두리, 자동 디더링과 흐릿한 축소 흔적이 없다.
- [ ] 신규 꼬치를 현행 네기마·모모와 원본 `100%` 크기로 비교했을 때 픽셀 밀도와 톤이 같은 게임의 음식으로 읽힌다.
- [ ] 임의 재구성 화면이나 현재 리비전과 무관한 새 캡처가 승인 근거에 포함되지 않았다.

## 13. 음료 이미지 계약 — 확정

### 13.1 규격화 범위와 확장 원칙

음료는 맥주 전용 파일 목록을 다른 메뉴에 복사하는 방식으로 확장하지 않는다. 모든 음료는 공통 레이어 역할과 검수 절차를 따르되, 제조 장비, 잔, 재료, 장식, 제조 순서와 상태 수는 `drinkModule` 단위로 분리한다.

각 음료 모듈은 아래 항목을 반드시 기록한다. 이 표의 이름은 역할명이며 새 런타임 ID를 미리 확정하는 것이 아니다.

| 항목 | 내용 |
|---|---|
| `menuId` | 맥주, 하이볼, 레몬사와 등을 구분하는 메뉴 식별자 |
| `screenId` | 실제 제조 화면 식별자 |
| `referenceStatus` | `approved-runtime` 또는 `concept-required` |
| `background` | 고정 카메라의 제조 화면 배경 |
| `stationStates` | 장비의 중립·조작 상태 목록 |
| `vesselStates` | 빈 잔과 메뉴에 필요한 잔 상태 목록 |
| `ingredientStates` | 얼음, 주류, 탄산, 레몬 등 단계별 재료 목록 |
| `liquidRenderMode` | `realtime` 또는 승인된 래스터 단계 방식 |
| `vfx` | 따르기, 거품, 넘침 등 순간 효과 목록 |
| `orderIcon` | 주문표·재고·제조 완료 목록이 공유하는 아이콘 |
| `servedDrink` | 손님 테이블에 표시하는 완성 음료 이미지 |
| `screenBounds` | 각 레이어의 FHD 화면 좌표와 앵커 |

- 같은 카메라와 작업대를 그대로 사용하는 음료만 승인된 배경을 공유할 수 있다.
- 장비나 작업대 배치가 달라지는 새 제조 화면은 기존 참고 화면이 없는 것으로 보고 전체 화면 콘셉트부터 만든다.
- 전체 화면 콘셉트는 기존 게임 톤을 참고해 사람에게 먼저 승인받고, 승인 전에는 개별 잔·장비·재료를 최종 에셋으로 분해하지 않는다.
- 맥주의 레버 3상태, 맥주잔과 거품 규칙을 하이볼이나 레몬사와에 강제하지 않는다.
- 서로 다른 음료는 잔 높이와 실루엣이 달라도 된다. 동일하게 고정하는 것은 캔버스, 화면 속 접지 앵커, UI 안전 영역과 같은 메뉴 내부의 상태 정렬이다.

### 13.2 공통 화면 레이어 규격

| 항목 | 확정값 |
|---|---|
| 기준 화면 | `1920×1080px` |
| 축소 검수 | `1280×720px`, 전체 화면을 정확히 `2/3` 축소 |
| 화면 고정 레이어 캔버스 | 모두 `1920×1080px` |
| 불투명 배경 | `sRGB 8-bit RGB PNG`, 무손실 |
| 투명 레이어 | `sRGB 8-bit straight-alpha RGBA PNG`, 무손실 |
| 좌표 원점 | 화면 왼쪽 위 `(0,0)` |
| 런타임 기본 배치 | 원본 크기 `100%`, 화면 원점 `(0,0)` |

화면에 위치가 고정되는 장비, 작업대, 잔과 단계별 재료 이미지는 최종 FHD 화면 좌표를 포함한 투명 캔버스로 직접 만든다. 서로 다른 원본 크기를 런타임에서 제각각 확대·축소해 위치를 맞추는 방식을 신규 음료의 기본 계약으로 사용하지 않는다.

- 배경에는 잔, 재료, 진행 상태, VFX, 설명 문자와 조작 UI를 굽지 않는다.
- 같은 대상의 상태 레이어는 캔버스, 앵커와 정적인 픽셀이 같아야 한다. 조작되는 부분만 달라져야 한다.
- 액체 높이, 따르기, 거품과 넘침처럼 연속적으로 변하는 표현은 기본적으로 실시간 효과로 처리한다.
- 실시간 효과 대신 단계별 PNG가 필요한 음료는 사람에게 단계 수와 전환 방식을 먼저 승인받고 해당 모듈에 명시한다.
- 화면 고정 레이어의 투명 여백을 임의로 잘라 저장하지 않는다. 잘린 파일마다 별도 위치·배율 보정이 생기면 규격 미달이다.

### 13.3 공통 주문 아이콘 규격

| 항목 | 확정값 |
|---|---|
| 캔버스 | `256×256px` |
| 포맷 | `sRGB 8-bit straight-alpha RGBA PNG`, 무손실 |
| 기준 중심 | `(128,128)` |
| 공통 여백 | 각 변 최소 `16px` |
| 재사용 범위 | 주문표, 재고, 제조 완료 목록 |

- 아이콘에는 해당 음료의 완성된 잔과 가장 중요한 식별 요소를 함께 보여준다. 예: 맥주의 거품, 하이볼의 얼음·레몬, 레몬사와의 승인된 장식.
- 잔 종류가 달라도 화면 안에서 비슷한 시각적 무게로 보이게 하되, 키 큰 잔을 억지로 눌러 맥주잔과 같은 실루엣으로 만들지 않는다.
- 메뉴명, 숫자, 등급, 테두리, 슬롯 배경과 상태 배지는 아이콘에 굽지 않는다.
- 현행 맥주 주문 아이콘 `192×192px`은 기존 예외로만 유지한다. 신규 제작·교체본부터 `256×256px`을 적용한다.

### 13.4 공통 손님 제공 음료 규격

| 항목 | 확정값 |
|---|---|
| 캔버스 | `500×500px` |
| 포맷 | `sRGB 8-bit straight-alpha RGBA PNG`, 무손실 |
| 현행 FHD 표시 슬롯 | `165×165px` |
| `1280×720` 표시 크기 | `110×110px` |
| 정렬 기준 | 잔 바닥의 수평 접지점과 메뉴별 `servingAnchor` |

- 제공 이미지는 주문 아이콘이 아니라 손님 테이블에 놓이는 완성 음료다.
- 잔, 내용물, 얼음, 거품과 장식은 해당 제조 화면의 최종 상태와 같은 음료로 읽혀야 한다.
- 키와 폭이 다른 잔의 다양성을 허용한다. 모든 음료의 알파 경계를 똑같이 맞추지 않고, 메뉴별 접지 앵커와 최대 가시 영역을 기록해 같은 메뉴의 변형 상태가 움직이지 않게 한다.
- 접시와 함께 표시될 때는 접시 이미지가 확보한 오른쪽 음료 영역 안에 머물러야 한다. 접시 음식, 옆 좌석 인물과 겹치면 반려한다.
- 그림자, 받침과 장식이 캔버스 밖에서 잘리거나 흰색·검은색 알파 테두리를 만들면 반려한다.

### 13.5 현행 맥주 모듈 — 확정

맥주는 현재 manifest와 실제 소비 코드에 연결된 화면을 정량화한 최초의 `approved-runtime` 음료 모듈이다. 현행의 서로 다른 원본 크기와 런타임 보정값은 신규 제작 시 아래 FHD 화면 고정 레이어로 통합한다.

| 역할 | 신규 계약 | 현행 실제 화면의 목표 가시 영역 |
|---|---|---|
| 제조 배경 | 불투명 `1920×1080` 1장 | 화면 전체 |
| 장비 `neutral` | 투명 `1920×1080` 1장 | 약 `x=838..1114`, `y=228..735` |
| 장비 `beer` | 투명 `1920×1080` 1장 | 장비 공통 영역 유지 |
| 장비 `foam` | 투명 `1920×1080` 1장 | 장비 공통 영역 유지 |
| 잔 보관대 | 투명 `1920×1080` 1장 | 약 `x=356..763`, `y=517..739` |
| 제조 위치의 빈 잔 | 투명 `1920×1080` 1장 | 약 `x=918..1096`, `y=455..668` |
| 실시간 액체 영역 | PNG 산출물 아님 | `x=924..1045`, `y=458..678` |
| 실시간 따르기·거품 영역 | PNG 산출물 아님 | `x=897..1079`, `y=416..778` |
| 주문 아이콘 | 투명 `256×256` 1장 | 13.3 적용 |
| 손님 제공 맥주 | 투명 `500×500` 1장 | FHD `165×165` 슬롯 |

- `neutral`, `beer`, `foam`의 세 장은 장비 본체를 다시 그린 별도 그림이 아니다. 레버와 직접 반응하는 부분 외의 픽셀은 정확히 같아야 한다.
- 액체 높이, 맥주 따르기, 거품과 넘침은 현재처럼 실시간 렌더링을 유지하고 상태 PNG로 중복 제작하지 않는다.
- 배경, 장비, 잔 보관대와 빈 잔에는 영수증, 버튼, 게이지, 목표선과 설명 문자를 굽지 않는다.
- 현재 등록된 별도 `ST-DRINK-BEER-TIER-1` 이미지는 실제 렌더러가 사용하는 레버 상태 레이어와 중복되는 기존 호환 자산으로 취급한다. 신규 맥주 산출물에는 별도 장비 베이스를 한 장 더 요구하지 않는다.
- 현행 `192×192` 맥주 주문 아이콘은 기존 예외다. 다음 교체 시 같은 완성 맥주 정체성을 유지한 `256×256` 아이콘으로 만든다.
- 맥주 모듈의 서로 다른 최종 PNG는 총 `8장`이다: 배경 1, 장비 상태 3, 잔 보관대 1, 빈 잔 1, 주문 아이콘 1, 제공 맥주 1. 실시간 액체와 VFX는 이 수에 포함하지 않는다.

### 13.6 하이볼과 레몬사와 확장 상태

| 메뉴 | 현재 근거 | 현재 판정 | 다음 절차 |
|---|---|---|---|
| 맥주 | 승인된 런타임 화면·자산·소비 코드 존재 | `approved-runtime` | 13.5 계약으로 신규·교체 제작 |
| 하이볼 | 얼음 → 위스키 → 탄산 → 레몬의 기획상 제조 흐름은 존재하나 승인된 런타임 화면은 없음 | `concept-required` | 기존 음료 화면 톤을 참고한 전체 제조 화면 승인 후 모듈 수치 확정 |
| 레몬사와 | 메뉴명 외에 승인된 제조 순서·장비·잔·화면이 없음 | `concept-required` | 메뉴 동작과 제조 순서를 먼저 결정하고 전체 화면 승인 후 모듈 수치 확정 |

- 하이볼은 맥주의 레버 세 상태를 복제하지 않는다. 얼음통, 계량 도구, 위스키, 탄산 장비, 잔과 레몬 중 실제 게임 조작에 필요한 요소를 전체 화면에서 먼저 배치한다.
- 레몬사와는 하이볼의 색상 교체판으로 만들지 않는다. 제조 방식, 잔과 식별 장식이 확정된 뒤 별도 모듈로 만든다.
- 새 음료가 기존 맥주 화면을 공유할지 별도 제조 화면을 사용할지는 전체 화면 콘셉트 승인 시 결정한다.
- 승인 후에는 해당 음료의 각 레이어 `screenBounds`, 접지 앵커, 상태 수, 실시간 효과와 PNG 수를 13.1의 모듈 항목에 기록한다.

### 13.7 음료 파일 승인 조건

- [ ] 음료 모듈에 실제 `screenId`, 기준 상태와 승인 근거가 기록돼 있다.
- [ ] 승인 화면이 없는 신규 음료가 전체 화면 콘셉트와 사람 검수를 먼저 거쳤다.
- [ ] 모든 화면 고정 레이어가 `1920×1080`이며 원점 `(0,0)`, 배율 `100%`로 겹친다.
- [ ] 같은 대상의 상태 전환에서 장비, 잔, 앵커와 정적인 픽셀이 움직이지 않는다.
- [ ] 연속 액체와 순간 VFX를 이유 없이 단계별 PNG에 중복해 굽지 않았다.
- [ ] 주문 아이콘이 `256×256`, 손님 제공 음료가 `500×500` 규격을 지킨다.
