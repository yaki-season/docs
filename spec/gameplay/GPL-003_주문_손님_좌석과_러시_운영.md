## 목적

손님 입장부터 주문, 대기, 서빙, 추가 주문, 퇴장과 좌석 정리까지의 운영 규칙을 정의한다. 플레이어가 여러 손님을 동시에 관리하되 실패 원인을 예측할 수 있고, 품질·팁·만족도·명성이 서로 중복 계산되지 않게 한다.

## 범위

### 포함

- 1인 손님과 2인 그룹의 좌석 배정·퇴장
- 주문·대기·만족도·추가 주문과 팁
- 일반·단골·특수 손님 유형
- 러시아워 주문 파동과 화면 밖 위험 우선순위
- 빈 접시·잔과 좌석 정리

### 제외

- 정확한 손님 생성 간격과 확률 수치
- 개별 캐릭터의 대사와 초상 제작 규격
- 3~4인 일반 그룹과 8인 단일 그룹 표현
- 온라인 대기열 또는 다른 플레이어와의 경쟁

## 상태 모델

### 좌석 상태

```text
비어 있음 → 예약됨 → 착석 → 주문 중 → 식사 중 → 퇴장 대기
→ 정리 필요 → 비어 있음
```

### 손님 상태

```text
입장 → 착석 → 주문 생성 → 대기 → 제공받음 → 식사
→ 추가 주문 또는 계산 → 그룹 퇴장 → 종료
```

### 주문 상태

```text
대기 → 제작 중 → 완성 대기 → 서빙 중 → 제공 완료
                         ↘ 실패·재조리 ↗
```

## 상세 요구사항

### 좌석과 그룹

1. 기본 가게는 카운터 6석으로 시작하고 인테리어 업그레이드로 8석을 거쳐 최대 12석까지 확장할 수 있다.
2. 혼술족은 빈 좌석 하나에만 앉는다.
3. 퇴근 직장인은 2인 그룹으로 생성하며 인접한 빈 좌석 두 개가 있을 때만 함께 입장한다.
4. 2인 그룹의 주문, 대기 게이지와 만족도는 손님별로 관리한다.
5. 2인 그룹은 두 손님이 모두 식사와 추가 주문을 끝냈을 때 함께 퇴장한다.
6. D30의 8인 예약은 현재 작업 가정으로 2인 그룹 네 팀과 공통 예약 식별자를 사용하되 최종 확정 전 데이터에서 교체 가능해야 한다.
7. 퇴장한 좌석에는 손님별 빈 접시·잔이 남고 좌석별 정리 입력이 끝날 때까지 새 손님을 배정하지 않는다.
8. 직원의 홀 자동화가 활성화되면 서빙과 좌석 정리를 대신할 수 있으나 진행 상태는 플레이어 직접 처리와 같은 계약을 사용한다.

### 주문과 식별

9. 주문은 주문자, 좌석, 그룹, 메뉴, 수량, 취향, 생성 시각과 현재 상태를 가진다.
10. 접시·잔과 손님 주문 매트는 같은 `색상+도형+좌석 번호` 표식을 사용한다.
11. 색상만으로 주문을 구분하지 않는다.
12. 직장인 2인은 D1에서 생맥주를 먼저 주문하고 이후 안주를 개별 또는 추가 주문할 수 있다.
13. 같은 메뉴를 묶음 조리하더라도 완성 결과는 주문 식별자별 접시·잔에 연결되어야 한다.
14. 잘못된 손님을 선택하면 완성품을 이동시키지 않고 주문 표식을 재강조하며 첫 실수에는 품질·대기 패널티를 추가하지 않는다.

### 대기·만족도·수익 역할 분리

15. 대기 게이지는 손님별 주문 생성 직후부터 감소한다.
16. 대기 게이지가 0이 되면 해당 손님은 제공받지 못한 주문을 취소하고 매출 0과 명성 하락 원인을 남긴다.
17. 2인 그룹 한 명의 이탈 처리와 그룹 전체 이탈 여부는 미확정이므로 데이터로 분리한다.
18. 대기 게이지 잔량과 손님 유형은 팁에만 직접 영향을 준다.
19. 조리 품질은 판매가에만 직접 영향을 준다.
20. 만족도는 추가 주문 확률과 명성 획득에만 직접 영향을 준다.
21. 동일 결과를 판매가·팁·만족도에 중복 가산하지 않는다.
22. 만족도 기반 추가 주문의 기획 예시는 `80 이상 60%`, `50~79 30%`, 그 미만 0%이나 확정 수치로 사용하지 않는다.

### 손님 유형

| 유형 | 운영 특성 | 캠페인 사용 |
|---|---|---|
| 퇴근 직장인 | 2인, 주문량 많음, 인내심 보통, 생맥주 선주문 | D1부터 핵심 |
| 혼술족 | 1인, 소량 주문, 인내심 높음, 단골화 가능 | D1부터 핵심 |
| 단골 | 기억 주문, 취향, 짧은 에피소드 | D7 이후 핵심 |
| 커플 | 플레이팅 만족 가중 후보 | D16 이후 선택 도입 |
| 관광객 | 추천·오마카세, 높은 팁 후보 | 확장 후보 |
| 리뷰어 | 품질·대기·분위기 분리 평가 | D20 카나모리로 사용 |
| 취객 | 낮은 인내심과 방해 이벤트 | 장기 후보, 기본 캠페인 필수 아님 |

### 단골과 기억 주문

23. 높은 만족도의 반복 서빙 조건을 채운 손님은 단골로 전환할 수 있다.
24. 츠키오카는 D7 종료 시 첫 단골로 기록하고 D8부터 `늘 먹던 걸로` 주문을 사용한다.
25. 첫 기억 주문은 전체 메뉴·소스·음료를 함께 보여 주고 이후에만 일부 또는 전부를 숨긴다.
26. 기억 주문을 틀리면 일반 품질과 분리된 `취향 불일치` 반응을 기록하고 정답 힌트를 제공한다.
27. 같은 기억 주문을 세 번 틀리면 손님이 전체 주문을 다시 말한다.
28. 단골 노트는 광고나 유료 재화 없이 기본 힌트를 제공해야 하며, 힌트 열람의 기본 노출 방식은 미확정이다.

### 러시와 위험 우선순위

29. 주문은 영업일 데이터의 파동 단위로 생성해 회복 구간 없이 지속적으로 몰리지 않게 한다.
30. 화면 밖 공정은 실패 3초 전부터 방향·대상 아이콘·경고음을 제공하고 마지막 1초에는 해당 방향 가장자리를 점멸한다.
31. 여러 위험이 겹칠 때의 잠정 우선순위는 `조리 실패 임박→손님 이탈 임박→일반 주문`이며 최종 순서는 플레이테스트 뒤 확정한다.
32. 같은 우선순위의 조리 위험은 실패까지 남은 시간이 짧은 하나를 크게 표시하고 나머지는 요약 상태로 유지한다.
33. 위험 스테이션으로 복귀하면 대상 공정을 0.4초 동안 자동 강조한다.
34. D30 등 대규모 파동도 시스템이 정한 활성 위험 수 상한을 넘기지 않도록 추가 주문 시점을 지연한다.

## 예외 및 경계 조건

- 인접 좌석이 없으면 2인 그룹은 좌석이 생길 때까지 대기하거나 생성 자체를 지연하며 분리 착석시키지 않는다.
- 손님이 먹는 중 브라우저가 백그라운드로 가면 대기·식사·추가 주문 타이머를 모두 멈춘다.
- 서빙 애니메이션 중 빠른 이중 입력은 한 번의 제공 완료만 만든다.
- 재조리 중인 주문의 원래 손님과 좌석 식별자는 유지한다.
- 특수 손님 유형이 비활성화된 빌드에서는 같은 날짜의 핵심 사건을 혼술족 또는 직장인으로 대체한다.

## 비기능 요구사항

- 좌석·손님·주문은 별도 식별자를 가져 복수 주문 상태가 서로 덮어쓰이지 않아야 한다.
- 손님 생성과 추가 주문 확률은 테스트용 시드로 재현 가능해야 한다.
- 대기 위험은 색상, 형태와 음향 중 최소 두 가지 방식으로 전달한다.
- 손님 유형은 성별·연령·직업과 음주에 대한 고정관념을 실패 연출로 사용하지 않는다.

## 완료 기준

- [ ] 1인 손님과 2인 그룹의 입장·개별 주문·공동 퇴장 흐름이 재현된다.
- [ ] 주문·대기·만족도와 팁이 손님별로 독립 관리된다.
- [ ] 품질, 대기와 만족도의 경제적 역할이 중복 적용되지 않는다.
- [ ] 퇴장 뒤 모든 좌석은 개별 정리 전까지 재배정되지 않는다.
- [ ] 화면 밖 조리 위험과 손님 이탈 위험이 정의된 우선순위로 표시된다.
- [ ] 기억 주문 실패가 캠페인이나 관계 진행을 차단하지 않고 힌트를 남긴다.
- [ ] D30 예약의 2인 그룹 네 팀이 공통 예약으로 동작한다.
