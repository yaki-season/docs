## 목적

D4의 양배추 사라다·하이볼과 D5의 토리카와를 현재 공용 주문·조리·서빙 구조에 구현할 수 있는 수준으로 확정한다. 한 그룹의 구성원도 각자 주문을 가진다는 기존 계약을 유지하면서 날짜별 주문 수, 항목 수, 신규 조작, 품질, 경제와 UI 결과를 서로 모순 없이 연결한다.

## 범위

### 포함

- D4 전용 `사이드 메뉴` 스테이션과 양배추 사라다의 준비·주문·서빙·정산 규칙
- D4 드링크 스테이션의 하이볼 수동 제조와 품질 판정
- D5 토리카와의 조립·양면 굽기·소금·타레 규칙
- D4·D5의 확정 손님 수, 개별 주문 수, 총 주문 항목 수와 첫 주문·2인 그룹·마감 주문
- 주문 카드, 레시피 노트, 테이블 표현과 공용 준비 목록 연결

### 제외

- D6 상세 계약 — `GPL-007`. D7 메뉴, 신규 도구, 주문표, 밸런스와 시나리오 확정
- 부채의 조작·수치·튜토리얼 — D7 이후로 미룬다
- D4·D5의 대사 원고와 컷신 샷 단위 연출
- 에다마메 등 `사이드 메뉴` 스테이션의 후속 메뉴
- 아트 에셋의 최종 파일·애니메이션 제작

## 공통 계약

1. D4와 D5의 2인 그룹은 인접 좌석과 공동 퇴장 규칙만 공유하며, 주문은 구성원마다 한 건씩 생성한다. 그룹 전체를 한 주문으로 합치지 않는다.
2. D4와 D5는 `maxActiveOrders=2`, `maxRiskProcesses=2`, `arrivalPolicy.maxAllSeatsEmptyWaitSec=13`, `arrivalPolicy.autoCloseAfterFinalCustomer=true`를 사용한다.
3. 주문 항목은 공용 준비 목록에서 손님에게 배정하며, 메뉴·조리 방식·미제공 수량이 일치하지 않는 드롭은 아무 상태도 바꾸지 않고 취소한다.
4. D4는 신규 품질 공정 하나라는 캠페인 원칙의 예외로 하이볼과 저복잡도 보조 행동인 사라다 담기를 함께 도입한다. 품질·실패 판단이 있는 신규 공정은 하이볼 하나뿐이다.
5. 실제 영업에서 다음 입력을 강제하는 단계형 튜토리얼, 자동 완료, 스테이션 탭 점멸과 판정 구간 강조를 사용하지 않는다. 양배추 사라다·하이볼·토리카와 조작법은 레시피 노트로 확인할 수 있다.
6. 스테이션 전환 중 영업·손님·그릴 타이머는 계속 흐른다. 브라우저 숨김·포커스 상실, 이야기 대사, 일시정지와 복귀 요약 중에는 기존 공통 정지 계약을 적용한다.

## D4 양배추 사라다

### 메뉴와 주문

7. 사용자 표시명은 `양배추 사라다`, 영구 메뉴 ID는 `cabbage-salad`다. 레시피 노트에는 생양배추에 가벼운 간장 드레싱과 깨를 더하는 무료 곁들임으로 설명한다.
8. 기본 판매가는 `0G`이고 원가·재고·준비 수량 상한이 없다. 제공해도 판매·매출을 만들지 않으며 영업 종료 시 남은 접시는 보상 없이 자동 폐기한다.
9. 양배추 사라다는 단독 주문할 수 없다. 같은 주문에 판매가가 `0G`보다 큰 음식 또는 음료를 최소 한 개 포함해야 한다.
10. 양배추 사라다를 주문하는 손님은 최초 주문에 `1~2접시`를 명시한다. 식사 중 리필·추가 주문으로 사라다를 요청하지 않는다.
11. 주문 카드에는 `양배추 사라다 ×수량`만 표시한다. `무료`, `서비스`, `0G` 표식은 주문 카드에 표시하지 않고 무료라는 사실은 레시피 노트에서만 설명한다.
12. 주문된 사라다는 주문 완료의 필수 항목이다. 미제공 수량이 남으면 전체 주문이 완료되지 않고 기본 팁도 지급되지 않는다.
13. 사라다는 품질 등급과 품질 만족 점수를 만들지 않으며 주문 만족도 분모에서 제외한다. 같은 주문의 유료 품질 항목만 기존 수량 가중 평균을 사용한다.

### 사이드 메뉴 스테이션

화면 표시명은 `사이드 메뉴`다. 데이터와 코드의 station type은 후속 메뉴 공정을 구분하기 위해
`instantService`, 화면 ID는 호환성을 위해 `SCR-SVC-INSTANT`를 유지한다. 내부 용어를 플레이어 UI에 노출하지 않는다.

14. D4부터 독립 상위 탭·화면 `SCR-SVC-INSTANT`를 연다. 스테이션은 주문 수요와 무관하게 항상 활성이고, 플레이어는 원하는 만큼 사라다를 준비할 수 있다.
15. 사라다 메뉴 카드를 `2.5초` 연속으로 누르면 접시 한 개가 완성되어 공용 준비 목록에 들어간다. 진행 중 문구는 `사라다 담는 중`이고 카드 둘레에 원형 진행 게이지를 표시한다.
16. 한 번의 연속 홀드는 한 접시만 만든다. 한 접시 완성 뒤에도 포인터를 계속 누르고 있으면 다음 접시가 자동으로 시작되지 않으며, 다음 접시는 손을 떼고 다시 눌러야 한다.
17. `2.5초` 전에 손을 떼거나 포인터가 카드 밖으로 나가거나 입력이 취소되면 진행을 `0`으로 되돌린다. 스테이션 전환, 일시정지, 브라우저 포커스 상실·숨김도 진행을 취소하고 `0`으로 되돌린다.
18. 취소된 홀드는 접시·비용·재료·부분 진행을 남기지 않는다. 스테이션에 머물며 홀드하는 동안 영업·손님·그릴 타이머는 정상 진행한다.
19. `사이드 메뉴` 버튼의 숫자 배지는 `max(0, 미제공 사라다 총수량 - 공용 준비 목록 사라다 수량)`이다. 값이 `0`이면 배지만 숨기고 버튼과 사라다 준비 입력은 비활성화하지 않는다.

### 서빙과 테이블

20. 사라다 한 접시를 성공적으로 제공할 때마다 해당 손님의 대기 시간을 `10초` 회복한다. 두 접시를 한 번에 제공하면 수량 단위로 `20초`를 회복하되 현재 최대 대기 시간을 넘지 않는다.
21. 사라다가 먼저 제공되면 테이블에 접시를 즉시 놓지만 손님은 다른 주문 항목을 기다린다. 모든 필수 항목이 제공된 뒤 기존 `15초` 식사·음주 상태에서 함께 먹는다.
22. 같은 손님에게 사라다를 한 접시 또는 두 접시 제공해도 테이블에는 사라다 접시 하나만 표시하고 `×2` 배지를 붙이지 않는다. 정확한 주문·제공 수량은 주문 카드와 도메인 상태에서 유지한다.
23. 다른 손님에게 드롭하거나 대상이 이탈하거나 수량 선택을 취소하면 공용 수량·미제공 수량·대기 시간·매출을 모두 보존하고 카드를 원위치로 돌린다.

## D4 하이볼

### 화면과 입력

24. 사용자 표시명은 `하이볼`, 영구 메뉴 ID는 `highball`, 기본 판매가는 `7G`다.
25. 하이볼은 별도 상위 스테이션 화면을 만들지 않는다. `SCR-SVC-DRINK` 한 화면에 기존 생맥주 설비와 하이볼 작업대를 동시에 노출하며 mode tab을 두지 않는다.
26. 생맥주와 하이볼은 각각 한 번에 잔 하나를 둘 수 있는 독립 작업면이다. 두 작업면은 동시에 진행 상태를 보존할 수 있지만 실제 입력은 한 pointer씩 순차 처리한다.
27. 다른 상위 스테이션으로 이동하는 것은 허용하며 현재 잔·재료·액체 누적 상태를 보존한다. 병을 누르는 중 이동하면 흐름은 즉시 멈추고 누적량까지만 보존한다.
28. 제조 순서는 `잔 배치 → 얼음 → 위스키·탄산수 → 레몬`이다. 드링크 화면 진입 시 하이볼 중앙 작업 슬롯은 비어 있어야 하며, 플레이어가 작업대 우측의 하이볼 잔 보관대에서 잔 하나를 선택해야 중앙 슬롯에 빈 잔이 나타난다. 얼음은 한 번 클릭하면 고정량이 들어가며 품질을 판정하지 않고, 잔 내부 높이의 약 `80%` 이상을 큰 각얼음으로 채워 차갑고 충분히 준비된 상태가 즉시 읽혀야 한다.
29. 얼음 뒤에는 위스키와 탄산수 중 어느 것을 먼저 부어도 된다. 각 병 자체를 누르고 있는 동안 병이 잔 쪽으로 기울어 같은 유량으로 따르고, 손을 떼면 즉시 멈추고 원위치로 돌아간다.
30. 레몬을 넣기 전에는 위스키와 탄산수를 원하는 횟수만큼 다시 눌러 보충할 수 있다. 이미 부은 액체는 덜어낼 수 없다.
31. 레몬은 위스키와 탄산수가 모두 `0`보다 클 때만 활성화한다. 레몬을 클릭하면 즉시 최종 품질을 확정하고 공용 준비 목록으로 옮긴다. 얼음 전 액체, 얼음·두 액체 전 레몬 등 순서가 잘못된 입력은 재료를 소비하거나 상태를 바꾸지 않는다.
32. 실시간 작업면에는 잔의 채움과 액체 층만 표시한다. 숫자, 목표 구간, 실시간 비율·판정 게이지를 표시하지 않는다. 작업면의 고정 레시피 표찰은 `얼음 → 위스키 1 : 탄산수 3 → 레몬`이다.

### 넘침과 품질

33. 위스키·탄산수는 각각 초당 `1단위`로 누적하고, 둘의 합이 `4.8단위`를 넘으려는 순간 흐름을 자동 차단해 `넘쳤습니다`를 표시한다.
34. 넘친 잔은 `낮은 품질로 계속`과 `버리고 다시 만들기` 중 하나를 플레이어가 선택한다. 계속을 선택하면 레몬을 넣어 `Fail`로 완성할 수 있고, 폐기를 선택하면 빈 작업면으로 초기화하며 완성품·매출을 만들지 않는다.
35. 넘치지 않은 잔은 아래 세 값을 함께 판정한다.

| 판정값 | Perfect | Good |
|---|---:|---:|
| 위스키 절대량 | `0.8~1.2` | `0.6~1.4` |
| 탄산수 절대량 | `2.55~3.45` | `2.1~3.9` |
| 최종 `탄산수/위스키` 비율 | `2.7~3.3` | `2.4~3.6` |

36. 세 값이 모두 Perfect 범위면 `Perfect`, 세 값이 모두 Good 범위 이상이지만 하나 이상 Perfect 밖이면 `Good`, 넘치지 않았으나 하나 이상 Good 밖이면 `OK`, 넘친 잔을 계속 만들면 `Fail`이다.
37. 판매가는 공통 품질 판매율과 내림 규칙을 사용해 `Perfect=7G`, `Good=4G`, `OK=2G`, `Fail=1G`가 된다.

## D5 토리카와

### 메뉴와 조립

38. 사용자 표시명은 `토리카와`이고 설명에는 `닭껍질 꼬치`를 병기할 수 있다. 기존 영구 메뉴 ID `kawa`는 저장 호환을 위해 유지하며 표시명만 토리카와로 통일한다.
39. 기본 판매가는 `5G`이고 주문 조리 방식은 `salt|tare`다.
40. 토리카와 한 꼬치는 같은 접은 닭껍질 조각을 다섯 번 클릭해 만든다. 클릭할 때마다 다음 빈 칸에 자동으로 끼우며 `0/5`부터 `5/5`까지 진행 상태를 표시한다.
41. D5 첫 토리카와 주문에도 적정 시간대 하이라이트, 탭 점멸과 영업 중 단계형 가이드를 표시하지 않는다. 레시피 노트에는 모모보다 빨리 타므로 더 짧게 살피라는 정성적 단서만 제공하고 정확한 초는 표시하지 않는다.

### 굽기와 마감

42. 토리카와는 앞면·뒷면을 독립적으로 누적하며 각 면 `0~9.999초=덜 익음/익는 중`, `10~13.999초=적정`, `14~17.999초=과다`, `18초 이상=완전 탄`이다.
43. 소금 토리카와는 양면 굽기 뒤 회수한다. 양면 품질 조합은 기존 네기마 공통 규칙을 사용하며 양면 완전 탄만 제공 불가·폐기다.
44. 타레 토리카와는 `조립 → 조립대 타레 1회 붓질 → 그릴 재고 → 기본 양면 굽기 → 회수` 순서로 처리한다. 붓질의 판정 구간·중단·복구는 D3 타레 모모의 공통 데이터를 재사용한다.
45. 그릴 위 도포·재가열과 토치를 사용하지 않는다. 타레는 조립대에서 한 번만 칠하며, 칠하지 않고 보낸 꼬치는 소금으로 확정된다.
46. 타레 토리카와의 최종 품질은 `기본 양면 굽기 품질`을 그대로 쓴다. 양면 완전 탄은 다른 결과와 무관하게 제공 불가·폐기다.

## 날짜별 확정 주문표

### D4

- 총 손님 `8명`, 개별 주문 `8건`, 총 주문 항목 수량 `19개`다.
- 첫 주문은 츠키오카의 `양배추 사라다 ×1 + 하이볼 ×1`이다.
- `×2` 사라다는 마감 파동의 마지막 주문에서 처음 사용한다.

| 순서 | 주문 | 수량 합 | 역할 |
|---:|---|---:|---|
| `D4-ORDER-001` | 양배추 사라다 ×1, 하이볼 ×1 | 2 | 첫 손님·두 D4 기능 소개 |
| `D4-ORDER-002` | 소금 모모 ×1, 생맥주 ×1, 양배추 사라다 ×1 | 3 | 2인 그룹 A |
| `D4-ORDER-003` | 소금 모모 ×1, 생맥주 ×1 | 2 | 2인 그룹 B |
| `D4-ORDER-004` | 소금 네기마 ×1, 하이볼 ×1 | 2 | 그릴·하이볼 교차 |
| `D4-ORDER-005` | 타레 모모 ×1, 양배추 사라다 ×1 | 2 | 타레 복습·무료 곁들임 |
| `D4-ORDER-006` | 소금 네기마 ×2, 생맥주 ×1 | 3 | 다수 꼬치 복습 |
| `D4-ORDER-007` | 소금 모모 ×1, 하이볼 ×1 | 2 | 드링크 교차 |
| `D4-ORDER-008` | 양배추 사라다 ×2, 생맥주 ×1 | 3 | 마감 파동·사라다 2접시 |

### D5

- 총 손님 `9명`, 개별 주문 `9건`, 총 주문 항목 수량 `20개`다.
- 첫 주문은 `소금 토리카와 ×1 + 생맥주 ×1`이다.

| 순서 | 주문 | 수량 합 | 역할 |
|---:|---|---:|---|
| `D5-ORDER-001` | 소금 토리카와 ×1, 생맥주 ×1 | 2 | 첫 토리카와·짧은 굽기 체감 |
| `D5-ORDER-002` | 타레 토리카와 ×1, 하이볼 ×1, 양배추 사라다 ×1 | 3 | 2인 그룹 A |
| `D5-ORDER-003` | 타레 토리카와 ×1, 하이볼 ×1 | 2 | 2인 그룹 B |
| `D5-ORDER-004` | 소금 네기마 ×1, 양배추 사라다 ×1 | 2 | 즉시 제공 복습 |
| `D5-ORDER-005` | 소금 토리카와 ×1, 하이볼 ×1 | 2 | 그릴·드링크 교차 |
| `D5-ORDER-006` | 타레 모모 ×1, 생맥주 ×1 | 2 | 기존 타레 복습 |
| `D5-ORDER-007` | 타레 토리카와 ×1, 양배추 사라다 ×1 | 2 | 토리카와 타레 마감 |
| `D5-ORDER-008` | 소금 모모 ×2, 하이볼 ×1 | 3 | 다수 꼬치·하이볼 |
| `D5-ORDER-009` | 소금 토리카와 ×1, 생맥주 ×1 | 2 | 마감 복습 |

주문 순서는 날짜 안의 진행 순서를 뜻한다. 정확한 입장 시각은 시간대 밀도에 맞춰 데이터로 배치하되 활성 주문·위험 공정 상한과 빈 가게 `13초` 상한을 우선한다.

## 날짜 완료와 다음 날 연결

47. D4는 계획 주문 drain, 모든 손님 퇴장, 좌석 정리와 정산 1회 적용 뒤 완료한다. 완료 저장은 `day-d5`와 토리카와 메뉴를 열며 D5의 주문표를 다음 영업일로 사용한다.
48. D5는 토리카와를 한 개 이상 정상 제공하고 계획 주문 drain, 모든 손님 퇴장, 좌석 정리와 정산 1회 적용 뒤 완료한다.
49. D5 완료 저장은 `day-d5-completed`만 기록한다. D6 기획 승인 전에는 부채 기능·온보딩·보상과 D6 주문 데이터를 해금하거나 활성화하지 않는다.
50. D4·D5 정산과 날짜 완료 저장은 같은 영업일 완료 ID에 대해 한 번만 적용한다.

## 예외 및 경계 조건

- 사라다만 담아 두거나 하이볼 잔을 시작한 상태에서도 주문 수요가 바뀌거나 손님이 이탈할 수 있다. 제작 상태는 자동으로 다른 주문에 배정하거나 삭제하지 않는다.
- 공용 준비 목록의 사라다·하이볼·토리카와는 특정 주문 ID를 보유하지 않으며 일치하는 어느 손님에게나 배정할 수 있다.
- 하이볼의 위스키가 `0`이면 비율을 계산하지 않고 레몬 입력을 거부한다. `0`으로 나누는 품질 판정을 만들지 않는다.
- 하이볼 탭 잠금은 드링크 내부 탭에만 적용한다. 긴급한 그릴·손님 화면 이동을 막지 않는다.
- D6 이후 후보 데이터가 저장소에 남아 있어도 이 문서를 근거로 활성화·노출·확정할 수 없다.

## 비기능 요구사항

- 사라다 홀드와 병 홀드는 포인터 다운·업·취소와 단조 증가 시간을 기준으로 판정하며 렌더 프레임 수에 의존하지 않는다.
- 홀드·액체 입력 뒤 첫 시각 반응은 `50ms` 이내, 완성·넘침·취소 피드백은 `100ms` 이내 시작을 목표로 한다.
- 원형 게이지, 병 기울기, 액체 층, 조립 수량과 품질 결과는 색 외에 문구·형태·움직임 중 하나 이상을 함께 사용한다.
- 날짜·주문·제조·서빙 규칙은 렌더러 없이 고정 시계와 테스트 시드로 자동 검증할 수 있어야 한다.
