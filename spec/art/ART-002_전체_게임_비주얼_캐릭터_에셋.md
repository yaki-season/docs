## 목적

`YAKI SEASON`의 브랜드, 골목·가게, 캐릭터, 음식·도구와 VFX가 하나의 2.5D 픽셀 아트 세계로 읽히는 제작 기준을 정의한다. 조작 대상과 상태는 작은 화면·LOW 모드에서도 구분되어야 하고, 성장 뒤에도 오래된 가게의 생활감을 유지한다.

## 범위

### 포함

- 브랜드·간판·환경·조명·색채
- 2D 배경과 3D 조작 대상의 시각 결합
- 주요 캐릭터의 실루엣·복장·표정·동작
- 음식·스테이션·도구·VFX 상태 세트
- 캠페인 단계별 외관 변화와 기술 규격
- 모든 신규·교체 시각 에셋의 공통 수작업풍 스타일 프로파일과 회귀 기준

### 제외

- 개별 에셋의 최종 제작 프롬프트와 파일 manifest
- UI 텍스트의 최종 폰트 라이선스
- 캐릭터 3D 리깅과 자유 카메라용 전 방향 모델
- 초기 탐색 이미지의 이전 상호와 생성 오류 문자

## 상세 요구사항

상세 규칙은 브랜드, 2.5D 표현, 환경, 캐릭터, 조작 에셋과 VFX 영역을 함께 적용한다.

## 브랜드와 시각 방향

1. 로고는 `YAKI SEASON`과 `炭火やきとり とり暦`를 함께 사용할 수 있어야 한다.
2. 간판은 `とり暦`가 첫 식별 요소이며 초기 `鳥屋/Toriya` 표기는 사용하지 않는다.
3. 공통 분위기는 따뜻한 주황 숯불·제등과 짙은 남색 저녁, 오래된 목재·종이·황동 질감이다.
4. 픽셀 아트는 흐릿한 필터가 아니라 굵은 픽셀 군집, 계단형 윤곽, 제한 팔레트와 무안티앨리어싱으로 표현한다.
5. 밝은 면은 황갈색 숯불광, 그림자는 남색·자주색을 사용하되 화면 전체를 단일 주황 또는 남색으로 덮지 않는다.
6. 생성 이미지의 설명·워터마크·틀린 문자와 콘셉트 시트 테두리를 런타임 에셋에 포함하지 않는다.

#### 적용 규칙

1. 배경·캐릭터·음식·도구·스테이션·UI icon·VFX·노트 illustration과 홍보용 일러스트는 같은 프로파일을 공유한다.
2. 3D 조작물은 과도하게 매끈한 PBR 외형을 피하고 손으로 칠한 base color, 거친 roughness, 제한된 하이라이트와 그림형 접지로 2D 배경에 연결한다.
3. UI icon과 VFX는 선·색·픽셀 리듬을 축약해 계승하되 기능 가독성과 색각 비의존 신호를 질감보다 우선한다.
4. 캐릭터는 헤어스타일만 바꾼 반복 얼굴을 금지하며 얼굴형·눈매·코·입·손·자세와 연령 표현을 함께 다르게 설계한다.
5. 인물의 손은 손가락 수·관절 방향·소품 접촉을 확인하고 감정은 얼굴과 자세 중 두 요소 이상으로 표현한다.
6. 밤 장면도 얼굴·음식·조작 대상의 중간 명도를 확보하고 화면 전체를 주황 필터나 막힌 검정으로 덮지 않는다.
7. 개발용 충돌 mask·hit zone·graybox·비표시 데이터 texture는 회화 마감에서 제외하지만 사용자에게 보이는 placeholder는 프로파일 적용 여부를 명시한다.
8. 기준 세트 밖의 기존 생성물·파생물·테스트 캡처는 이후 생성의 기준 이미지, source, runtime 에셋으로 사용하지 않는다. 이번 정리에서 해당 파일과 그 manifest·provenance 참조를 제거하며, 새 에셋은 기준 세트와 승인된 통합 콘셉트에서만 분리한다.

#### 금지 특성

- 플라스틱 피부, 유광 3D 인물, 사진 같은 PBR 재질과 과도한 렌즈 효과.
- 균일한 벡터 선, 완벽한 대칭, 반복 얼굴·소품과 자동 생성 흔적이 남은 손·접촉 오류.
- 임의 픽셀 노이즈, 흐린 업스케일, 단순 다운샘플을 수작업 픽셀 마감으로 취급하는 결과.
- 모든 영역의 동일한 디테일 밀도, 화면 전체의 단일 주황 tint 또는 저명도 검정.
- 가짜 문자·워터마크·서명·설명문과 특정 스튜디오·작품·작가의 고유 캐릭터·장면 복제.

### 영업 화면 공간 구성

| 깊이·영역 | 필수 시각 구성 |
|---|---|
| 배경 | 손님측 바와 좌석 바로 뒤, 화면 수평 중앙의 단일 가게 대문·문틀·문짝·문턱과 그 너머 밤 골목. 대문 좌우는 화면 끝까지 막힌 측면 목재벽이며 외부 골목은 중앙 대문 개구부를 통해서만 보인다. 측면 벽의 작은 선반·병은 보조 장식일 뿐 별도 출입구나 개방 bay가 될 수 없다. 플레이어가 손님석에서 주방을 보는 역방향 구도로 제작하지 않는다. |
| 손님 정보 화면 | 카운터 건너편의 손님과 빈 좌석, 바 상판, 손님별 제공 음식·음료와 빈 식기. 손님 상태와 주문 데이터를 가장 명확히 읽는 정면 구도다. |
| 조리 화면 | 조립·그릴·주류·서빙 등 독립 작업대와 직접 조작 도구. 각 화면은 상단 주문서와 하단 준비 목록 안전 영역을 비운다. |
| 공통 공간 기준 | 손님은 바 테이블 건너편, 모든 조리 기구는 주인공 쪽 바 테이블에 바로 붙여 배치한다. 화면별 배경은 이 실제 위치 관계를 공유한다. |

7. 손님·조리 화면은 바 안쪽 주인공의 동일한 기준 위치에서 정면, 아래쪽 또는 옆쪽으로 시선을 옮긴 고정 1인칭 프리셋을 사용한다.
8. 3D 오브젝트의 가장자리와 재질은 배경보다 과도하게 매끈하거나 사실적으로 보이지 않아야 한다.
9. 접지감은 그림자 맵 대신 래스터 접지 그림 또는 blob shadow를 사용한다.
10. 손님 화면의 바 테이블 음식과 각 조리 화면의 도구는 해당 화면의 상판·작업면과 동일한 원근·소실점·가림 순서를 유지한다.
11. 손님 정보 화면과 조리 화면을 한 합성 안에 동시에 넣지 않으며 조리 화면에는 참조용 주문서만 남긴다.

## 환경과 캠페인 변화

### 기본 외관·내부

- 외관은 좁은 저녁 골목, 낮은 목조 점포, 노렌, 제등, 화분과 비에 젖은 바닥을 사용한다.
- 내부는 플레이어가 안쪽에 서고 손님이 맞은편에 앉는 6석 바 카운터와 손님측 바 바로 뒤, 화면 수평 중앙의 단일 대문을 중심으로 한다. 대문 너머로 좁은 밤 골목이 이어지고 대문 좌우는 화면 끝까지 막힌 측면 목재벽이다. 어두운 목재·병 선반·종이·황동 조명은 중앙 대문틀과 막힌 측면 벽의 보조 요소로 사용한다.
- 빈 좌석은 카운터 너머의 등받이·좌석 앵커로 표현하고 플레이어 앞에 완전한 스툴 열을 배치하지 않는다.
- 메뉴판과 간판 외 생성 이미지 속 문자는 장식 무늬로 대체하거나 UI에서 다시 그린다.

## 캐릭터 공통 기준

- 성인은 약 6~6.5등신의 현실적 비율을 기본으로 한다.
- 작은 해상도에서 눈썹·눈매·입꼬리와 자세로 감정을 읽게 한다.
- 의상은 현대 일본 골목의 작업복·사무복·생활복을 바탕으로 하고 판타지·과장 전통복을 피한다.
- 동일 인물의 전신·초상·좌석 스프라이트에서 머리, 안경, 대표색과 앵커를 유지한다.
- 연령은 주름뿐 아니라 자세, 동작 속도와 손의 형태로 구분한다.
- 감정은 얼굴색 하나가 아니라 눈·입·고개·손과 자세 중 두 가지 이상으로 표현한다.

## VFX와 애니메이션

- 숯불 불씨는 상시 화력 비례, 최대 80개다.
- 연기는 굽는 동안 최대 6개 큰 쿼드와 UV 스크롤을 사용한다.
- 기름 튐은 뒤집기 순간 최대 30개, 수명 0.5초다.
- 판정은 링·짧은 불씨·윤기와 음식 반응을 사용하고 풀스크린 블룸을 금지한다.
- 관통은 눌림·정지·관통·반동, 뒤집기는 집게·회전·재접촉, 서빙은 카운터 마찰과 2~3px 멈춤을 표현한다.
- 애니메이션은 논리 상태를 지연시키거나 입력 영역을 갑자기 이동시키지 않는다.
- 식사와 음주 루프는 손님 앞 테이블 음식·잔 상태와 맞아야 하며, 퇴장 전 빈 그릇·빈 컵 상태로 자연스럽게 전환한다.

## 파일·에셋 규격

20. 배경은 JPG 또는 WebP, 알파가 필요한 스프라이트는 PNG 또는 검증된 WebP를 사용한다.
21. 픽셀 에셋은 최근접 보간을 사용하고 압축으로 윤곽·알파가 번지지 않게 한다.
22. 배경의 논리 기준은 `16:9`이며 `1920×1080 FHD` Chrome 화면에서 손님 화면의 얼굴·상태·테이블 음식과 조리 화면의 상단 주문서·중앙 도구·하단 준비 목록 안전 영역을 유지한다.
23. 상태 변형은 같은 캔버스 크기·피벗·하단 중앙 앵커를 공유한다.
24. 에셋 manifest는 ID, 경로, 크기, 포맷, 알파, 앵커, 상태, 출처·생성 근거와 해시를 기록한다.
25. 런타임 텍스트, 손 모양, 커서와 콘셉트 번호는 에셋에 굽지 않는다.
26. 모바일 크롭과 모바일 전용 변형은 후순위이며 현재 데스크톱 에셋 승인 조건에서 제외한다.

4. 분리한 요소는 원본의 크기·각도·접촉면·가림 관계를 유지하며, 독립 재생성이 필요한 경우 해당 `sourceMasterId`를 기준 이미지로 사용한다.
5. 가려진 면은 분리 시 복원하되 마스터 합성에 없던 새 장식·문자·기능을 추가하지 않는다.
6. 카메라 높이·화각·회전과 소실점의 사전 수치 확정을 승인 조건으로 삼지 않고, 마스터에서 측정한 anchor·가림선·안전 영역·투영 기준을 companion metadata에 기록한다.
7. 전체 장면 생성만으로 런타임 승인을 대체하지 않는다. 분리본의 알파 경계·접촉면·가려진 면과 `1920×1080 FHD`·`1280×720` 재합성을 통과한 에셋만 manifest에 등록한다.
8. 화면별 구성요소·파일 해시·기계 판독 분리 목록과 프롬프트는 `art-workspace/concept-masters/2026-07-26/README.md`, `master-catalog.json`, `PROMPTS.md`를 제작 인계 기준으로 사용한다.
9. 화면에서 잘라낸 `visible cutout`과 가려진 면까지 복원한 `complete layer`는 서로 다른 승인
   대상이다. cutout 승인은 complete layer나 runtime 승인을 대신하지 않는다.
10. complete layer는 승인 cutout을 실루엣·화풍·원근 reference로 사용하되, 다른 범주의
    사람·음식·UI 조각이나 손님 모양의 구멍을 보존하지 않는다. 온전한 자산을 한 개씩
    생성해 별도 사용자 승인을 받는다.
11. 공식 제작 순서는
    `설정·공간 추론 승인 → visible cutout 승인 → complete layer 개별 승인 →
    FHD/720p 재조립 회귀 승인 → runtime 최적화 → catalog·manifest 등록`이다. 각 단계의
    승인 전에는 다음 단계의 산출물을 runtime 또는 source 정본으로 등록하지 않는다.
12. 기계 판독 게이트와 검증은
    `art-workspace/pipeline/pipeline-contract.json`과
    `node art-workspace/pipeline/validate-pipeline.mjs`를 따른다.
13. 이미지 생성 프롬프트보다 먼저 설정·시나리오·화면 설계와 승인 마스터를 함께 읽고
    `spatial-inference.json`에 화면 ID·게임 상태·플레이어 행동·`semanticOwner`·자산
    의미, 카메라, 앞뒤 순서, 가려진 면의 연속 구조, 불변 요소와 금지 치환을 기록한다.
14. 손님 서비스 화면의 공간 순서는
    `바 안쪽 주인공 카메라 → 단일 바 테이블 → 손님 좌석 → 바로 뒤 가게 대문 → 밤 골목`
    으로 고정한다. 가게 대문은 화면 수평 중앙의 단일 출입구이고 대문 좌우는 화면
    끝까지 막힌 측면 벽이다.
15. 손님과 좌석에 가려진 complete 배경은 대문틀·문짝·문턱·골목으로 이어져야 하며,
    대문 없이 전체 후면을 막은 목재벽·전폭 병 선반·깊은 별실·두 번째 카운터로 바꾸지
    않는다. 반대로 중앙 대문 좌우의 측면 벽을 열어 별도 개구부·출입구·창처럼 만들지도
    않는다.
16. 영업 중 손님 화면에서는 손님 사이 또는 뒤의 중앙 대문을 통해서만 골목의 공간 단서가
    읽혀야 한다. 인물 밀도가 높아져도 중앙 대문의 위치와 가게 출입 동선을 삭제하거나
    좌우로 치우치게 하지 않는다.
17. 텍스트 spec과 승인 이미지가 충돌하거나 공간 관계를 한 문장으로 설명할 수 없으면
    일반적인 이자카야 관습으로 빈칸을 채우지 않고 `unresolvedQuestions`로 기록해 생성을
    중단한다.
18. `spatial-inference.json`이 `approvedForGeneration=true`이고 화면별 topology
    validator를 통과하기 전에는 이미지 생성 도구를 호출하지 않는다.

## 예외 및 경계 조건

- 캐릭터 상태 에셋 누락 시 빈 좌석으로 바꾸지 않고 오류·재시도를 제공한다.
- LOW 모드에서도 안경, 머리띠, 앞치마, 주문과 익힘 단계가 식별되어야 한다.
- 좌우 반전 시 가르마·비대칭 소품의 정체성이 무의미하게 뒤바뀌면 별도 반전 에셋을 사용한다.
- D30 군중에서도 주요 인물의 머리와 대표색을 다른 손님이 완전히 가리지 않게 한다.

## 비기능 요구사항

- 모든 에셋은 게임 화면 크롭·겹침·알파·축소 검수를 통과해야 한다.
- 주류는 과음·경쟁의 상징, 손님 유형은 풍자·고정관념으로 과장하지 않는다.
- 에셋 라이선스와 생성 이력을 manifest에서 추적할 수 있어야 한다.
- 생성형 도구 사용 여부와 관계없이 `YS-HANDCRAFTED-NIGHT-v1`의 선·과슈·색·재료·픽셀 마감이 최종 사용자 노출 결과에 남아야 한다.
- 접근성·입력 가독성과 성능 예산은 표면 질감보다 우선하지만, 질감을 줄인 LOW 모드도 실루엣·따뜻한/차가운 색 관계와 픽셀 리듬을 유지한다.
