## 목적

기존 콘셉트아트의 따뜻한 숯불 이자카야와 저해상도 픽셀 표현을 실제 웹 프로토타입용 에셋으로 재제작하고 적용한다. 콘셉트 시트를 화면에 그대로 붙이는 것이 아니라, 조작 대상과 상태가 분리된 제작 에셋을 만들어 기능 검증 중에도 읽기 쉽고 일관된 화면을 제공한다.

## 범위

### 포함

- 조립, 그릴과 카운터에 필요한 최소 배경·소품·음식·손님 에셋
- 닭다리살, 대파, 빈 꼬치와 조립 단계별 네기마 표현
- 날것, 익는 중, 적정, 과다와 탄 상태를 구분하는 꼬치 표현
- 숯불·연기·윤기·불씨와 클릭 반응용 최소 VFX
- 에셋 최적화, 투명 배경, 픽셀 스케일링과 실제 화면 적용
- 츠키오카의 대기·맛보기·만족·절제된 수용·재조리 반응
- 2.5D 레이어용 공통 배경, 전경 프레임과 공정별 작업대 분리

### 제외

- 가게 외관, 거리, 주방 전체와 영업 종료 화면
- 생맥주 기계, 잔과 드링크 관련 에셋
- 복수 손님, 주요 등장인물 전체 라인업과 표정 시트
- 츠키오카 외 손님과 대화용 대형 초상
- 모모 및 추가 메뉴, 타레 붓, 부채, 집게의 직접 조작 기능
- 완전한 3D 모델링, 리깅, 물리 기반 재질과 고해상도 시네마틱
- 스테이지별 배경 변화, 계절 변형과 장식 업그레이드
- 모바일 전용 크롭, 해상도와 터치 상태 에셋

### 생성·후처리 규칙

1. 생성 도구에는 각 파일에 명시된 로컬 콘셉트 이미지를 참조 이미지로 제공한다.
2. `BG-01`, `ST-01`, `ST-02`, `ST-04`, `FD-01`, `FD-02`, `FD-03`, `PR-01`, `CH-01` 순으로 기준 원근·광원·정체성을 먼저 확정한다.
3. `FD-04`는 생성된 `FD-01`·`FD-02`를 참조하고 `CH-02`~`CH-05`는 생성된 `CH-01`을 편집 참조한다.
4. 투명 파일은 내장 이미지 생성의 평면 크로마키 방식으로 생성한 뒤 로컬에서 `#00ff66`을 제거한다. CLI/API 모델로 임의 전환하지 않는다.
5. 최종 규격 변경은 최근접 보간을 사용한다. 캐릭터와 스테이션 상태 파일은 자동 trim하지 않는다.
6. 생성 도구 기본 저장 위치에 결과를 남겨 두지 않고 최종 검수본을 manifest의 `app` 경로로 복사한다.
7. 생성 원본, 실패본과 임시 크로마키 파일은 런타임 경로에 넣지 않는다.
8. `app/art/gameplay/ASSET-MANIFEST.md`에 ID, 최종 경로, 실제 크기, 바이트, SHA-256, 사용 프롬프트, 참조 이미지와 검수 결과를 기록한다.

### 스타일 요구사항

1. 전체 팔레트는 짙은 목재와 검정 석쇠, 따뜻한 주황 숯불, 닭의 황갈색, 대파의 녹색을 주요 구분색으로 사용한다.
2. 배경은 조작 대상보다 명도와 채도를 낮춰 음식과 주문표가 우선 읽히게 한다.
3. 픽셀 경계는 의도적으로 유지하며 브라우저 확대 시 흐릿한 보간이 생기지 않게 한다.
4. 하나의 에셋 내부에서 픽셀 크기와 광원 방향을 일관되게 유지한다.
5. 광원은 아래쪽 숯불의 주황빛과 위쪽 실내등의 약한 중성광을 기준으로 한다.
6. 닭과 대파는 색뿐 아니라 실루엣, 표면 질감과 단면 형태로 구분한다.
7. 날것은 밝고 윤기가 약한 분홍빛, 적정은 갈변과 윤기, 과다는 짙은 갈색 점, 탄 상태는 확장된 검은 면과 연기로 구분한다.
8. 손님은 전체 콘셉트의 픽셀 인물 비율을 따르되 프로토타입에서는 허리 위 초상과 손 반응만 제작할 수 있다.
9. 콘셉트 이미지의 설명 문구, 번호, 테두리와 예시 커서는 실제 에셋에 포함하지 않는다.
10. 콘셉트 이미지를 단순 축소·크롭해 완성 에셋으로 사용하지 않고, 투명 영역과 상태 분리가 가능한 원본 에셋으로 재구성한다.

### 기술 규격

- 래스터 에셋은 투명 배경이 필요한 경우 `PNG`, 불투명 배경은 품질 손실이 보이지 않는 `WebP` 또는 `PNG`를 사용한다.
- 스프라이트는 정수 배율로 표시하고 CSS와 렌더러에서 최근접 보간을 적용한다.
- 원본 픽셀 그리드는 `1x` 기준으로 보관하고 화면에서는 `2x`, `3x` 같은 정수 배율을 우선한다.
- 개별 텍스처는 위 manifest의 장면 레이어 예외를 제외하면 한 변 `1024px` 이하로 제한한다.
- 투명 에셋은 불필요한 빈 여백을 제거하되 클릭 영역은 렌더링 코드에서 별도로 확장한다.
- 파일명은 영문 소문자와 하이픈을 사용하고 대상과 상태를 식별할 수 있게 한다. 예: `skewer-negima-perfect-front.png`.
- 앱에서 사용하지 않는 중간 생성물과 콘셉트 시트 복사본은 런타임 에셋 디렉터리에 포함하지 않는다.
- 현재 `app/art/skewer-negima.png`는 요구 품질을 충족하면 보완해 재사용하고, 그렇지 않으면 같은 경로 계약을 유지하거나 참조를 함께 갱신한다.

### 적용 요구사항

1. 모든 필수 에셋은 `app` 저장소의 명확한 런타임 에셋 디렉터리에 저장한다.
2. 조립 단계, 조리 판정과 손님 결과 상태가 실제 게임 상태에 따라 대응하는 에셋 또는 셰이더 표현으로 바뀌어야 한다.
3. 조작 대상은 배경 이미지에 합쳐 넣지 않고 독립 클릭·애니메이션이 가능한 레이어로 제공한다.
4. 배경과 상호작용 오브젝트가 서로 다른 해상도 방식을 사용하더라도 최종 화면에서 픽셀 밀도가 이질적으로 보이지 않아야 한다.
5. 숯불 플리커, 연기와 불씨는 게임 상태를 가리지 않고 프레임 드롭을 유발하지 않는 수량으로 제한한다.
6. 에셋 목록과 실제 사용 경로를 `app`의 아트 또는 개발 README에 기록한다.

## 예외 및 경계 조건

- `1280×720`에서 재료가 구분되지 않으면 에셋 자체를 확대하거나 단순화하며 CSS 확대만 반복하지 않는다.
- 적정과 과다 상태가 색각이나 낮은 밝기에서 구분되지 않으면 그을음 면적과 연기 형태 차이를 우선 강화한다.
- 셰이더를 사용할 수 없는 경로에서도 최소한 상태별 래스터 대체 표현을 제공하거나 지원 불가 오류로 명확히 처리한다.
- 이미지 생성 도구를 사용한 결과는 픽셀 크기, 투명 경계와 원근을 사람이 검수하고 콘셉트 시트 그대로의 문구·오류를 제거한다.

## 비기능 요구사항

- 초기 화면에 필요한 에셋의 총 전송 크기는 압축 후 `5MB` 이하를 목표로 한다.
- 2.5D 1차 생성 에셋 전체는 `5MB` 이하, 첫 조립 장면에 필요한 부분은 `2.5MB` 이하를 목표로 한다.
- 에셋 로딩 전후에 작업 영역의 크기가 크게 이동하지 않도록 고정 종횡비를 사용한다.
- 모든 필수 에셋은 외부 URL 없이 로컬에서 로드 가능해야 한다.
- 라이선스가 불명확한 외부 에셋을 포함하지 않는다.
