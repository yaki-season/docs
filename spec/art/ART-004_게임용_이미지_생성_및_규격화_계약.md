## 목적

## 1. 정본과 제작 절차

### 1.1 기준 우선순위

새 이미지의 기준은 다음 순서로 선택한다.

1. 현재 manifest에 승인 등록되고 실제 소비 코드가 사용하는 같은 용도의 런타임 이미지
2. 해당 파일의 manifest 레코드, 캔버스, 앵커와 실제 배치값
3. 현재 런타임 리비전과 일치하는 승인 화면 자료
4. 같은 화면에서 이미 승인된 스타일·조명·공간 기준
5. 위 기준이 전혀 없을 때만 사람에게 승인받은 전체 화면 콘셉트

텍스트로 “츠키오카처럼” 또는 “네기마·모모처럼”이라고만 쓰거나, AI가 임의 재구성한 화면·현재 리비전을 확인하지 않은 캡처·반려 이미지를 기준으로 사용하지 않는다.

### 1.2 승인 참고가 있는 기본 제작 방식

1. 실제 소비 화면과 만들 상태 하나를 먼저 정한다.
2. 같은 용도의 승인 런타임 원본, manifest와 소비 코드의 배치값을 이미지 입력과 작업 계약으로 제공한다.
3. 용도별 최종 캔버스, 앵커와 픽셀 밀도를 처음부터 적용한다.
4. 큰 원화를 먼저 만든 뒤 일괄 축소·자동 픽셀화하지 않는다.
5. 한 번의 생성·검수는 한 자산의 한 상태만 다룬다.
6. FHD 실제 소비 화면과 `1280×720` 축소 화면에서 사람이 확인한 결과만 승인한다.

### 1.3 승인 참고가 없는 예외 제작 방식

1. 기존 게임의 가장 가까운 승인 화면과 `YS-HANDCRAFTED-NIGHT-v1`을 반드시 참고한다.
2. 먼저 해당 용도의 전체 화면 콘셉트를 만든다.
3. 사람이 화풍, 구도, 기능 배치와 게임 적합성을 승인하기 전에는 개별 에셋을 분리하거나 후속 생성 기준으로 사용하지 않는다.
4. 승인된 전체 화면에서 소비 단위별 레이어·앵커·안전 영역을 측정한다.
5. 각 최종 에셋을 실제 소비 캔버스에 맞춰 제작하고 다시 FHD·720p 화면 검수를 받는다.

승인 참고가 없는 화면의 큰 원화는 제한적으로만 허용된다. 새로운 화풍을 자유 탐색하는 원화가 아니라 기존 게임의 시각 언어를 확장하는 화면 기준이어야 한다.

## 2. 공통 화면·스타일·파일 규격

### 2.1 화면 기준

| 항목 | 확정값 |
|---|---|
| 1차 제작·승인 화면 | PC `1920×1080` |
| 추가 축소 검수 | PC `1280×720` |
| 축소 방식 | 전체 논리 화면을 정확히 `2/3` 축소 |
| 한 화면 최대 좌석 | `6석` |
| 모바일 | 별도 규격 확정 전 제외 |

8석·12석 확장에서는 인물을 축소해 한 화면에 모두 넣지 않는다. 카운터를 최대 6석 단위 구역으로 나누고 좌우 화면 전환으로 이동한다.

### 2.2 공통 스타일 프로파일

모든 신규·교체 사용자 노출 이미지는 `YS-HANDCRAFTED-NIGHT-v1`, 작업명 `손끝이 남은 따뜻한 밤`을 사용한다.

- 일부 남은 연필 밑그림과 약간 불균일한 잉크선
- 여러 번 덧칠한 과슈 색면과 제한된 종이 질감
- 호박색·황갈색 실내광과 남색·인디고 밤의 대비
- 인물 피부, 옷, 목재, 음식과 배경이 한 렌더링 체계로 읽히는 마감
- 얼굴·음식·조작 대상의 정보 밀도가 높고 배경은 한 단계 조용한 위계

다음은 금지한다.

- 플라스틱 피부, 균일한 벡터 선, 사진형 PBR 광택과 과한 렌즈 효과
- 특정 작가·스튜디오·작품의 고유 화풍 복제
- 가짜 문자, 워터마크, 서명, 설명 화살표와 의미 UI의 이미지 삽입
- 형태와 무관한 고대비 점 노이즈, 자동 디더링과 흐릿한 자동 축소 흔적
- 고정 제한 팔레트나 단일 저해상도 격자를 모든 용도에 일괄 적용하는 방식

### 2.3 보이는 픽셀 밀도

아래 수치는 원본 캔버스가 아니라 최종 FHD 화면에서 보이는 화면 픽셀 기준이다.

| 표현 | 목표 범위 |
|---|---|
| 주요 윤곽선 | 대체로 `2~4px` |
| 머리카락·옷 주름·과슈 색면 군집 | 대체로 `3~6px` |
| 눈매·안경·입·손가락·표정선 | 필요한 곳에 `1~2px` |
| 종이결·연필 흔적 | 주변과 명도 차가 작은 `1~2px` 재질 정보만 허용 |

`3px 스타일`, `4px 스타일` 같은 숫자만 프롬프트에 넣은 결과를 준수로 인정하지 않는다. 승인 이미지를 같은 소비 화면·같은 표시 크기로 나란히 비교해 선, 얼굴 정보량, 색면과 픽셀 군집이 한 게임으로 읽혀야 한다.

### 2.4 공통 파일 원칙

- 불투명 최종 화면은 `sRGB 8-bit RGB PNG`, 투명 레이어는 `sRGB 8-bit straight-alpha RGBA PNG`를 기본으로 한다.
- 알파가 필요한 이미지에 흰색·검은색 경계가 남으면 반려한다.
- 픽셀 보존이 필요한 래스터는 최근접 보간 또는 동등한 방식으로 표시하고 밉맵을 생성하지 않는다.
- 카운터, 좌석, UI, 문자, 게이지, VFX 등 다른 의미 소유자의 요소를 대상 이미지에 굽지 않는다.
- 같은 대상의 상태 이미지는 캔버스, 앵커, 조명과 정적인 픽셀이 같아야 한다.
- manifest에는 실제 치수, 색 공간, 알파, 앵커, 불투명 경계, 기준 파일, 상태와 SHA-256을 기록한다.

## 3. 영업 화면 좌석 인물

### 3.1 기준 이미지

| 항목 | 정본 |
|---|---|
| 런타임 ID | `D1-TSUKIOKA-WAITING` R3 |
| 기준 파일 | `app/public/assets/core/customer/d1-tsukioka-waiting-r3-b1.png` |
| 캔버스 | `1920×1080` |
| 포맷 | `sRGB 8-bit straight-alpha RGBA PNG` |
| 현재 츠키오카 앵커 | `logical-seat-anchor-fhd: (1086,594)` |
| 공통 제작 앵커 | `seatHipAnchor: (960,594)` |

츠키오카 기준은 얼굴 복제가 아니라 캔버스, 정보량, 좌석 깊이, 하체 가림, 픽셀 밀도, 화풍과 조명의 기준이다.

### 3.2 캔버스·앵커·크기

- 최종 납품본은 `1920×1080` 투명 전체 화면 캔버스다.
- 생성 때 엉덩이가 좌석에 닿는 지점을 `seatHipAnchor: (960,594)`에 둔다.
- 실제 좌석 배치에서는 이미지를 확대·축소하지 않고 앵커의 가로 위치만 좌석 중심으로 이동한다.
- 인물과 손에 든 소품의 불투명 영역은 공통 제작 좌표 기준 `x=820..1100` 안에 둔다.
- 불투명 영역 최대 폭은 `280px`, 앵커 좌우 각각 최대 `140px`이다.
- 최소 좌석 중심 간격 약 `296px`에서 인접 인물 사이 최소 `16px` 투명 간격을 남긴다.
- 머리 꼭대기는 FHD `y=180..300`, 엉덩이 앵커부터 머리까지 높이는 `294..414px` 범위다.
- 최소 폭은 정하지 않는다.
- `seatHipAnchor`와 실제 불투명 경계를 metadata에 기록한다.
- 같은 인물의 모든 상태는 캔버스, 앵커, 화면 속 배율을 유지한다.

### 3.3 신체 다양성과 좌석 확장

- 머리 꼭대기, 눈높이, 키와 전체 배율을 인물 간에 동일하게 맞추지 않는다.
- 키, 앉은키, 머리 크기, 목 길이, 어깨 폭, 몸통 길이와 체형 차이를 유지한다.
- 짧은 인물을 확대하거나 큰 인물을 축소해 머리 높이를 맞추지 않는다.
- 어깨, 외투, 머리카락과 자연스러운 팔 실루엣은 최대 폭 안에서 넓게 허용한다.
- 가장 폭이 넓은 인물끼리 인접 좌석에 놓은 화면 검수를 통과해야 한다.
- 말풍선은 고정 눈높이가 아니라 인물별 머리 경계 또는 별도 `speechAnchor`를 사용한다.
- 먹기·마시기 상태의 손·팔·소품까지 최대 폭 안에 머문다.

### 3.4 자세와 행동

- 기본 대기·주문 상태는 몸통과 얼굴이 정면 중심을 향한다.
- 작은 고개 기울기, 어깨 높이 차이와 표정 변화는 허용한다.
- 옆을 보거나 대각선으로 앉아 좌석 방향이 달라 보이는 자세는 금지한다.
- 기본 상태에서 손, 팔이나 팔꿈치를 카운터·책상 위에 올려두지 않는다.
- 기본 상태의 손은 무릎 위, 몸 가까이 또는 자연스럽게 내린 위치에 둔다.
- 카운터 밖으로 몸을 과하게 내밀거나 다른 좌석으로 팔을 뻗지 않는다.
- 음식·꼬치를 들기, 입으로 가져가기, 맥주잔 들기·마시기, 작은 주문 손짓과 물건 수령은 허용한다.

금지 대상은 손과 팔 자체가 아니라 기본 대기·주문 이미지에서 이를 카운터 위에 기대어 올려놓는 자세다.

### 3.5 상태 제작 순서

1. 인물별 정면 대기 상태 한 장을 먼저 만든다.
2. 실제 영업 화면에서 사람이 기본 상태를 승인한다.
3. 승인된 기본 상태를 직접 편집해 후속 상태를 한 장씩 만든다.
4. 후속 상태를 새 인물처럼 처음부터 다시 생성하지 않는다.
5. 얼굴, 체형, 복장, 앵커, 픽셀 밀도와 광원은 유지하고 행동에 필요한 표정·손·팔·소품만 바꾼다.

최소 우선 상태는 `정면 대기`, `음식 먹기`, `맥주 마시기`다. 나머지는 실제 게임 상태표에 연결된 용도가 확인된 뒤 추가한다.

## 4. 스토리 장면

### 4.1 표현 단위

- 영업 전, 영업 종료 후, 회상과 사건 장면은 장소·조명·인물·행동·감정이 한 화면에 담긴 완성 일러스트로 만든다.
- 좋은 기준은 `IL-D1-PREOPEN-TSUKIOKA`, `app/public/assets/core/s0/story/d1-preopen-tsukioka-full-scene-r1-b1.png`다.
- 일반 배경 위에 독립 전신 인물이나 작은 대화 초상을 얹는 구성은 사용하지 않는다.
- 별도의 미래 UI가 확정되지 않는 한 `CH-*-PORTRAIT` 또는 스토리용 독립 전신 컷아웃을 제작 카테고리로 두지 않는다.
- 대사 한 줄이나 화자 교체마다 새 그림을 만들지 않는다. 장소, 행동, 시간대, 감정 흐름과 카메라가 이어지는 단위를 `storyBeat`로 기록한다.
- 장소 이동, 핵심 행동, 큰 감정 전환, 시간대 또는 카메라 의미가 바뀔 때만 새 `storyBeat`를 만든다.

### 4.2 두 인물 대화 구도

- 두 인물은 같은 공간과 조명 안에 실제로 함께 있는 완성 구도로 그린다.
- 왼쪽 인물은 오른쪽을, 오른쪽 인물은 왼쪽을 바라본다.
- 완전한 옆모습보다 서로를 보면서 관객에게도 표정이 보이는 안쪽 `3/4` 방향을 기본으로 한다.
- 거리, 시선 높이, 주변 소품과 가림은 대화 관계가 자연스럽게 보이게 구성한다.
- 레이어 분리를 위해 두 사람을 부자연스럽게 멀리 떼거나 접촉·가림 관계를 없애지 않는다.

### 4.3 화자 강조

| 상태 | 크기 | 밝기 | 채도 |
|---|---:|---:|---:|
| 말하는 인물 | `103%` | `100%` | `100%` |
| 듣는 인물 | `97%` | `72%` | `90%` |

- `focusAnchor`는 각 인물의 발, 엉덩이 또는 장면 내 접촉점이다.
- 전환 때문에 발이 뜨거나 의자에서 엉덩이가 움직여 보이면 안 된다.
- 화자 전환은 `160~220ms`의 짧고 부드러운 전환을 사용한다.
- 확대된 화자가 상대 인물, 화면 가장자리와 대사 영역을 침범하지 않는다.
- 듣는 인물 레이어만 어둡게 하고 배경이나 화면 한쪽 전체를 함께 어둡게 하지 않는다.
- 화자가 없는 서술 장면은 원래 크기·밝기·채도를 사용한다.
- 이 값은 프로젝트 공통 초기값이다. 사람 화면 검사로 조정한 뒤에는 프로젝트 전체에서 함께 변경하며 장면별 임의값을 두지 않는다.

### 4.4 파일 구성

| 산출물 | 규격 | 역할 |
|---|---|---|
| 완성 장면 기준본 | `1920×1080`, sRGB 불투명 PNG | 화풍·구도·광원 승인 |
| 배경 레이어 | `1920×1080`, 불투명 PNG | 해당 `storyBeat` 고정 공간 |
| 인물 A | `1920×1080`, straight-alpha RGBA PNG | 화자 전환 |
| 인물 B | `1920×1080`, straight-alpha RGBA PNG | 화자 전환 |
| 합성 검수본 | `1920×1080` 2장 | A 화자·B 화자 실제 화면 검수 |

완성 장면을 먼저 승인하고 같은 이미지에서 배경과 인물을 마스크 분리한다. 분리를 위해 인물을 각각 재생성하지 않는다. 빈 배경, 머리카락·옷 가장자리와 접지 그림자를 보정하고, 재합성 결과가 승인 기준본과 같아야 한다. 인물 레이어는 해당 `storyBeat` 밖의 일반 배경에 재사용하지 않는다.

## 5. 꼬치 이미지 계약

### 5.1 기준과 적용

신규 꼬치는 현재 manifest에 승인되고 실제 코드가 소비하는 네기마·모모 그릴·조립 파일을 정본 기준으로 삼는다.

| 용도 | 현행 기준 |
|---|---|
| 네기마 그릴 | `app/public/assets/core/cooking/spr-negima-grill-*-r1-b1.png` |
| 모모 그릴 | `app/public/assets/campaign/d2/spr-momo-grill-*-r1-b1.png` |
| 모모 조립 | `app/public/assets/campaign/d2/spr-momo-assembly-progress-*-r1-b1.png` |
| 주문 아이콘 | 현행 네기마·모모 주문 아이콘 |
| 제공 접시 | 현행 네기마·모모 제공 접시 |

현행 네기마 `128×512` 조립 트레이·`192×192` 아이콘과 현행 모모 `2048×1024` 제공 접시는 기존 결선 예외다. 신규 메뉴부터 아래 규격을 적용한다.

### 5.2 그릴·조립 공통 원본

| 항목 | 확정값 |
|---|---|
| 캔버스 | `109×494px` |
| 포맷 | `sRGB 8-bit straight-alpha RGBA PNG` |
| 제작 배율 | 최종 사용 크기 `100%` 직접 제작 |
| 방향 | 세로, 뾰족한 끝이 위 |
| 길이 중심축 | `x=54` |
| 위·아래 투명 여백 | 각각 `4~6px` |
| 최대 가시 가로 범위 | `x=4..104` 안쪽 |
| 재료 가로 폭 | 메뉴별 실루엣에 따라 자유 |

- 모든 상태는 중심축, 꼬치 끝과 손잡이 위치가 같다.
- 익으면서 재료가 조금 수축하거나 가장자리가 변할 수 있지만 꼬치 전체가 이동·확대·축소되면 안 된다.
- 접시, 트레이, 석쇠, 불, 연기, 집게, 손, UI와 문자를 포함하지 않는다.
- 큰 원화를 축소하거나 후처리 픽셀화하지 않는다.

### 5.3 조립 단계

- 재료가 `N`개면 `0..N`의 `N+1`개 논리 상태를 가진다.
- `0`은 빈 꼬치, `1..N`은 손잡이 쪽부터 재료가 하나씩 추가된 상태다.
- 먼저 꽂힌 재료는 다음 단계에서 이동하지 않는다.
- `조립 N단계 = 조립 완료 대기 = 그릴 raw`이며 같은 PNG를 재사용한다.
- 가로 방향, 기울기, 화면 속 크기와 쌓임은 런타임 배치가 처리한다. 가로 회전 복제본과 별도 트레이 이미지를 만들지 않는다.

### 5.4 그릴 상태와 뒤집기

메뉴 하나의 그릴 상태 PNG는 총 `5장`이다.

| 상태 | 표현 |
|---|---|
| `raw` | 재료 본래색과 촉촉한 표면 |
| `cooking` | 약한 호박색과 초기 갈변 |
| `proper` | 따뜻한 황갈색과 읽을 수 있는 그릴 자국 |
| `overcooked` | 더 어둡고 건조하며 낮아진 채도 |
| `burnt` | 진한 갈색이지만 유지되는 재료 구분과 실루엣 |

- 게임은 양면 조리 시간을 독립 계산하되 현재 보이는 면의 공통 상태 PNG를 사용한다.
- 뒷면은 같은 상태 이미지를 런타임에서 반전하므로 앞뒤 전용 열 장을 만들지 않는다.
- 연기, 불씨, 기름 튐과 순간 윤기는 별도 VFX다.
- 파일명은 `spr-{menuId}-grill-{state}-r{sourceRevision}-b{runtimeBuild}.png` 패턴을 사용한다.

### 5.5 꼬치 전용 픽셀 밀도

- 주요 외곽선은 짙은 갈색 `1~2px`이다.
- 고기 결, 채소 단면과 그릴 자국은 `1~4px`의 읽을 수 있는 덩어리다.
- 고정 제한 팔레트를 강제하지 않고 재료·단면·익힘을 식별할 색을 사용한다.
- 검은 외곽선을 두껍게 두르거나 자동 디더링·고대비 점 노이즈를 만들지 않는다.
- 익힘은 `본래색 → 호박색·초기 갈변 → 황갈색·그릴 자국 → 어둡고 건조함 → 진한 갈색` 순서를 유지한다.

### 5.6 주문·재고·완성품 아이콘

| 항목 | 확정값 |
|---|---|
| 캔버스 | `256×256px` |
| 파생 원본 | 해당 메뉴의 그릴 `raw` |
| 중심 | `(128,128)` |
| 방향 | 손잡이 왼쪽 아래, 끝 오른쪽 위 |
| 회전 | 세로 원본에서 시계 방향 약 `36°` |
| 목표 가시 영역 | 약 `x=40..216`, `y=20..236` |

주문·재고·완성품 목록은 같은 아이콘을 재사용한다. 아이콘을 새로 해석해 그리지 않고 승인 `raw`에서 파생한다.

### 5.7 손님 제공 접시

| 항목 | 확정값 |
|---|---|
| 캔버스 | `1000×600px`, `5:3` |
| 실제 FHD 표시 | `260×156px` |
| 접시·음식 영역 | `x=174..686`, `y=256..414` |
| 접시 중심 | 약 `(430,335)` |
| 꼬치 방향 | 손잡이 왼쪽, 끝 오른쪽 |
| 꼬치 가로 범위 | 약 `x=205..545` |

- 접시는 왼쪽에 두고 오른쪽은 음료 공간으로 비운다.
- 접시, 그림자, 원근, 광원과 위치는 메뉴 간 동일하게 유지하고 음식만 교체한다.
- 제공 꼬치는 `proper`에서 파생한다.
- `served-1`은 중심선 `y=335`에 한 개, `served-2`는 `y=300`, `y=355`에 두 개를 둔다.
- 수량 `0`은 접시를 숨기고, `1`은 `served-1`, `2 이상`은 `served-2`를 사용한다. 정확한 3개 이상 수량은 UI 숫자가 소유한다.

### 5.8 메뉴별 PNG 수

재료가 `N`개인 신규 꼬치 메뉴의 서로 다른 최종 PNG는 `N+8장`이다.

| 묶음 | 수량 |
|---|---:|
| 조립 `0..N-1` | `N` |
| 그릴 상태 | `5` |
| 공통 주문 아이콘 | `1` |
| 제공 접시 | `2` |

`조립 N`, 조립 완료 대기와 그릴 `raw`는 같은 파일이므로 중복 계산하지 않는다.

## 6. 음료 이미지 계약

### 6.1 공통 음료 모듈

음료는 맥주 파일 목록을 복제하지 않고 공통 역할과 메뉴별 상태를 분리한 `drinkModule`로 관리한다.

| 필드 | 내용 |
|---|---|
| `menuId` | 음료 메뉴 식별자 |
| `screenId` | 실제 제조 화면 식별자 |
| `referenceStatus` | `approved-runtime` 또는 `concept-required` |
| `background` | 제조 화면 배경 |
| `stationStates` | 장비 상태 목록 |
| `vesselStates` | 잔 상태 목록 |
| `ingredientStates` | 얼음·주류·탄산·레몬 등 단계별 재료 |
| `liquidRenderMode` | `realtime` 또는 승인된 래스터 단계 |
| `vfx` | 따르기·거품·넘침 등 순간 효과 |
| `orderIcon` | 주문·재고·완료 공통 아이콘 |
| `servedDrink` | 손님 테이블 완성 음료 |
| `screenBounds` | 각 레이어의 FHD 경계·앵커 |

- 같은 카메라와 작업대를 그대로 쓰는 음료만 승인 배경을 공유한다.
- 장비나 작업대가 달라지면 전체 화면 콘셉트와 사람 승인을 먼저 받는다.
- 맥주의 레버 세 상태, 맥주잔과 거품 규칙을 다른 음료에 강제하지 않는다.
- 잔의 높이·폭·실루엣은 메뉴별로 다를 수 있다. 같은 메뉴의 상태 사이에서 캔버스·접지 앵커·안전 영역을 고정한다.

### 6.2 화면 고정 레이어

| 항목 | 확정값 |
|---|---|
| 캔버스 | 모두 `1920×1080px` |
| 좌표 원점 | 왼쪽 위 `(0,0)` |
| 기본 배치 | 원본 `100%`, 화면 원점 `(0,0)` |
| 배경 | sRGB RGB PNG |
| 투명 레이어 | sRGB straight-alpha RGBA PNG |

고정 장비, 작업대, 잔과 단계별 재료는 최종 FHD 좌표를 포함한 캔버스로 직접 만든다. 서로 다른 잘린 원본을 런타임에서 제각각 확대·축소해 맞추지 않는다. 연속 액체 높이, 따르기, 거품과 넘침은 실시간 효과를 기본으로 하고, 단계별 PNG가 필요하면 상태 수와 전환 방식을 먼저 승인받는다.

### 6.3 음료 공통 아이콘·제공 이미지

| 용도 | 캔버스 | 추가 계약 |
|---|---|---|
| 주문·재고·완료 아이콘 | `256×256px` | 중심 `(128,128)`, 각 변 최소 `16px` 여백, 세 용도에서 같은 파일 재사용 |
| 손님 제공 음료 | `500×500px` | 메뉴별 잔 바닥 `servingAnchor`, FHD `165×165`, 720p `110×110` 표시 |

- 주문 아이콘은 완성된 잔과 핵심 식별 요소를 함께 보여준다.
- 메뉴명, 숫자, 등급, 슬롯 배경과 상태 배지를 굽지 않는다.
- 제공 이미지는 손님 테이블의 완성 음료이며 제조 최종 상태와 같은 잔·내용물·거품·얼음·장식으로 읽혀야 한다.
- 잔 종류의 다양성을 허용하되 접시의 오른쪽 음료 영역, 옆 좌석 인물과 UI를 침범하지 않는다.
- 현행 맥주 주문 아이콘 `192×192`는 기존 예외이며 신규·교체본부터 `256×256`을 사용한다.

### 6.4 맥주 모듈

맥주는 현재 실제 런타임과 소비 코드가 존재하는 `approved-runtime` 모듈이다. 신규·교체본은 현재 런타임 보정 결과를 아래 FHD 고정 레이어로 통합한다.

| 역할 | 신규 계약 | 목표 가시 영역 |
|---|---|---|
| 제조 배경 | 불투명 FHD 1장 | 화면 전체 |
| 장비 `neutral` | 투명 FHD 1장 | 약 `x=838..1114`, `y=228..735` |
| 장비 `beer` | 투명 FHD 1장 | 장비 공통 영역 |
| 장비 `foam` | 투명 FHD 1장 | 장비 공통 영역 |
| 잔 보관대 | 투명 FHD 1장 | 약 `x=356..763`, `y=517..739` |
| 제조 위치 빈 잔 | 투명 FHD 1장 | 약 `x=918..1096`, `y=455..668` |
| 실시간 액체 | PNG 아님 | `x=924..1045`, `y=458..678` |
| 실시간 따르기·거품 | PNG 아님 | `x=897..1079`, `y=416..778` |
| 주문 아이콘 | `256×256` 1장 | 공통 아이콘 계약 |
| 제공 맥주 | `500×500` 1장 | FHD `165×165` 슬롯 |

- 세 장비 상태에서 레버와 직접 반응하는 부분 외 정적 픽셀은 정확히 같다.
- 액체 높이, 따르기, 거품과 넘침은 현재처럼 실시간 렌더링한다.
- 별도 `ST-DRINK-BEER-TIER-1`은 실제 레버 상태 레이어와 중복되는 기존 호환 자산이며 신규 산출물에 포함하지 않는다.
- 서로 다른 최종 PNG는 배경 1, 장비 3, 잔 보관대 1, 빈 잔 1, 아이콘 1, 제공 맥주 1의 총 `8장`이다.

### 6.5 하이볼·레몬사와 확장 상태

| 메뉴 | 현재 상태 | 다음 절차 |
|---|---|---|
| 맥주 | `approved-runtime` | 6.4 계약 적용 |
| 하이볼 | 제조 흐름은 기획됐으나 승인 런타임 화면 없음, `concept-required` | 기존 음료 톤을 참고한 전체 제조 화면 승인 후 수치 확정 |
| 레몬사와 | 승인된 제조 순서·장비·잔·화면 없음, `concept-required` | 메뉴 동작과 제조 순서 결정 후 전체 화면 승인 |

- 하이볼은 얼음통, 계량 도구, 위스키, 탄산 장비, 잔과 레몬 중 실제 조작 요소를 전체 화면에서 먼저 배치한다.
- 레몬사와는 하이볼 색상 교체판으로 만들지 않는다.
- 새 음료가 맥주 화면을 공유할지 별도 화면을 쓸지는 전체 화면 콘셉트 승인 때 결정한다.

## 예외 및 경계 조건

- 현행 결선과 크기가 다른 네기마·모모·맥주 파일은 기존 예외로 유지하고 자동 변환하지 않는다.
- 기존 파일 교체와 소비 코드 변경은 별도 구현 작업과 화면 승인을 요구한다.
- 승인 화면이 없는 양배추 제공 화면과 기타 음식은 이 문서의 수치를 임의 적용하지 않고 `concept-required`로 남긴다.
- 새로운 음료·음식·세 명 이상 스토리 구도에서 화면 계약이 부족하면 생성하지 않고 미해결 질문으로 돌린다.
- 에셋 누락을 다른 캐릭터, 빈 좌석 또는 임의 placeholder로 숨기지 않는다.
- 상태 이미지의 실루엣·앵커 변경이 필요하면 새 source revision과 사용자 재승인을 요구한다.

## 비기능 요구사항

- 모든 최종 이미지는 FHD와 720p에서 크롭, 겹침, 알파, 픽셀 밀도와 가독성을 검사한다.
- 이미지 생성 방식과 관계없이 기준 이미지, 프롬프트·제작 지시, 후처리, SHA-256과 사람 승인 결과를 추적한다.
- UI·텍스트·게이지·focus와 접근성 신호는 래스터에서 분리한다.
- 손님 다양성은 얼굴형, 키, 체형, 복장과 자세로 표현하고 연령·직업·음주 고정관념을 과장하지 않는다.
- 상태 차이를 단순 색조 덮기만으로 표현하지 않고 실루엣, 질감, 자세 또는 명암 변화를 함께 사용한다.
- 승인되지 않은 새 캡처나 임의 합성 검수판이 정본 에셋보다 우선하지 않는다.

## 완료 기준

### 공통

- [ ] 실제 소비 화면·manifest·소비 코드 또는 승인 전체 화면 중 하나가 생성 근거로 연결돼 있다.
- [ ] 승인 참고 유무에 맞는 직접 제작 또는 전체 콘셉트 선행 절차를 사용했다.
- [ ] `YS-HANDCRAFTED-NIGHT-v1`과 용도별 픽셀 밀도 회귀를 통과했다.
- [ ] FHD와 720p 실제 소비 화면에서 사람 승인을 받았다.
- [ ] 가짜 문자, UI, 워터마크, 자동 디더링, 흐릿한 축소와 알파 테두리가 없다.

### 좌석 인물

- [ ] `1920×1080`, `seatHipAnchor`, 최대 폭 `280px`과 자세 계약을 지킨다.
- [ ] 키·체형 차이를 유지하고 머리 높이·눈높이를 인물 간 강제 통일하지 않았다.
- [ ] 가장 넓은 인물끼리 인접해도 최소 간격과 UI 가독성을 유지한다.
- [ ] 기본 상태의 손·팔·팔꿈치가 카운터 위에 올라가 있지 않다.
- [ ] 후속 상태가 승인 기본 상태의 얼굴·체형·복장·앵커를 유지한다.

### 스토리

- [ ] 장소, 시간대, 관계와 핵심 상황이 하나의 완성 일러스트로 읽힌다.
- [ ] 일반 배경 위에 독립 전신 초상이나 작은 대화 초상을 얹지 않았다.
- [ ] 두 인물의 안쪽 3/4 시선과 A·B 화자 합성본이 모두 자연스럽다.
- [ ] 화자 전환에서 접지점이 움직이지 않고 배경은 함께 어두워지지 않는다.
- [ ] 분리 레이어 재합성이 승인 완성 장면과 같다.

### 꼬치

- [ ] 그릴·조립 원본이 `109×494`, 중심축 `x=54`, 상하 여백 `4~6px`이다.
- [ ] `조립 N = 완료 대기 = raw`가 같은 파일이다.
- [ ] 다섯 익힘 상태에서 꼬치 위치·크기가 움직이지 않는다.
- [ ] 아이콘 `256×256`, 제공 접시 `1000×600` 두 장이 계약을 지킨다.
- [ ] 신규 꼬치가 현행 네기마·모모와 원본 100% 비교에서 같은 게임으로 읽힌다.

### 음료

- [ ] 모듈에 `screenId`, 기준 상태, 상태 목록과 FHD 경계가 기록돼 있다.
- [ ] 승인 화면이 없는 음료가 전체 화면 콘셉트와 사람 검수를 먼저 거쳤다.
- [ ] 화면 고정 레이어가 FHD 원점·100% 배율로 겹친다.
- [ ] 아이콘 `256×256`, 제공 음료 `500×500` 계약을 지킨다.
- [ ] 맥주 전용 잔·레버·상태 수를 다른 음료에 강제하지 않았다.

2. 양배추 제공 화면과 꼬치 이외 음식의 용도별 규격.
3. 하이볼 제조 화면의 최종 배치·레이어·상태 수.

5. 모바일 전용 이미지 캔버스·크롭·픽셀 밀도.
