## 목적

`SYS-004`의 소스·렌더링 구조가 요구하는 모든 아트 입력을 식별하고, 현재 `app` 에셋의 재사용 범위, D1 통합 프로토타입의 필수 제작물, 30일 캠페인 확장물과 납품 계약을 정의한다. 아트 팀은 이 문서의 안정된 ID와 상태를 기준으로 제작하고 개발 팀은 파일명이 아닌 manifest ID로 에셋을 연결한다.

## 범위

### 포함

- 브랜드, 프롤로그, 환경, 스테이션, 3D 조작물, 음식, 캐릭터, UI와 VFX 에셋
- 현재 `app/art/gameplay` 16종의 재사용·이식·교체 판단
- D1 통합 프로토타입과 S0~D30 전체 게임의 제작 우선순위
- 래스터, 스프라이트 atlas, GLB, 텍스처와 manifest 납품 규격
- 성장 단계, LOW 모드와 `1920×1080 FHD` Chrome 화면 검수
- 후보 메뉴·미확정 인물의 제작 차단 조건
- `YS-HANDCRAFTED-NIGHT-v1` 스타일 기준, 수작업 마감과 시각 회귀 승인 게이트

### 제외

- BGM, 환경음과 SFX 제작 목록
- 대사·UI 문구와 폰트 최종 라이선스 선정
- 실제 에셋 생성·후처리와 런타임 파일 추가
- 아트 담당자 배정, epic, task와 일정 산정
- 현재 단계의 모바일 크롭·모바일 전용 에셋

## 상세 요구사항

상세 규칙은 제작 우선순위, 현행 재사용 판정, D1 필수 목록, 캠페인 확장 목록, 파일·manifest, 납품과 검수 영역을 함께 적용한다.

## 제작 우선순위

| 우선순위 | 제품 게이트 | 의미 |
|---|---|---|
| `P0` | S0+D1 통합 프로토타입 | 첫 주문 네기마 3개·생맥주 1잔의 완전 가이드, 모모 해금·이름 없는 엑스트라 유형, 6석, 정산까지 완주하는 데 필수 |
| `P1` | S0~D30 전체 캠페인 | 단계별 가게, 주요 인물, 직원, 성장, 후속 확정 메뉴와 D30 예약에 필수 |
| `P2` | 품질·확장 | 선택 손님, 시즌 메뉴, 추가 표정·연출과 운영 이후 확장 |
| `BLOCKED` | 기획 결정 필요 | 외형·메뉴·조작안이 미확정이어서 최종 제작을 시작하면 재작업 위험이 큰 항목 |

`P0` 에셋이 없으면 플레이스홀더로 도메인 개발은 가능하지만 D1 통합 완료를 선언할 수 없다. `P1`은 해당 날짜 콘텐츠가 `approved`가 되는 시점에 pack 단위로 제작하며 `P2`는 초기 운영 번들에 넣지 않는다.

## 공통 스타일 품질 게이트

2026-07-25 이후 새로 제작하거나 교체하는 모든 사용자 노출 에셋은 `ART-002 v3.6.1`의 `YS-HANDCRAFTED-NIGHT-v1`을 사용한다. 기존 생성·파생 runtime 에셋은 이번 결정으로 전부 승인 취소하며, 빈 runtime manifest에서 다시 시작한다. 개발용 무표시 graybox는 허용하지만 사용자 노출 placeholder와 이전 생성물은 새 아트의 기준 이미지·source·runtime 파일로 사용할 수 없다.

### 제작 전

1. 에셋별로 기준 review 이미지 2~4개와 적용할 스타일 축을 선택한다.
2. 기능·구도·상태 프롬프트와 공통 스타일 프롬프트를 분리해 기록한다.
3. 같은 화면에 합성될 캐릭터·배경·음식·도구는 승인 통합 원본, 같은 생성 세션 또는 같은 기준 이미지군을 사용한다.
4. 개발용 비표시 mask·hit zone·graybox 이외의 사용자 노출 placeholder는 스타일 적용 여부와 교체 조건을 `review` metadata에 적는다.
5. 스타일 회귀 기준에는 `ART-002 v3.6.1`의 최신 손님·스테이션 기준 세트를 사용하고, 화면 구도·구성요소·분리 범위에는 `art-workspace/concept-masters/2026-07-26/`의 확정 마스터만 사용한다. 과거 통합 원본, 자동 생성 래스터, 이전 review 파생물과 테스트 캡처는 삭제 대상으로 분류하며 재참조를 금지한다.
6. 이미지 생성 프롬프트 전에 설정·시나리오·상세 화면·승인 마스터의 공간 단서를
   `spatial-inference.json`으로 정리한다. 화면 ID·게임 상태·플레이어 행동·
   `semanticOwner`·자산 의미, 카메라, 앞뒤 순서, 문·창·외부의 위치, 가려진 면의
   연속 구조, 불변 요소와 금지 치환을 모두 기록한다.
7. 텍스트와 승인 이미지 사이에 해결되지 않은 충돌이 있거나
   `approvedForGeneration=false`이면 생성 도구 호출을 금지한다.

### 생성·초벌 뒤 필수 마감

- 손·얼굴·관절, 음식·도구의 접촉과 가림 관계를 수정한다.
- 반복 얼굴·반복 소품·완벽한 대칭·자동 복제 패턴을 제거한다.
- 가짜 문자·워터마크·서명·설명과 생성 잔여물을 제거한다.
- 화면 안 광원·그림자·재질과 기존 승인 에셋의 색 관계를 통일한다.
- 과도한 매끈함·플라스틱 피부·사진형 PBR·균일 그라디언트를 연필·잉크·과슈 색면과 제한된 하이라이트로 교정한다.
- 실제 표시 크기에서 얼굴·손·음식·도구 외곽의 픽셀 군집을 형태 중심으로 다시 정리한다.
- 기능 안전 영역, 색각 비의존 신호와 LOW 모드 가독성을 질감보다 우선해 재확인한다.

생성형 도구를 사용하지 않은 에셋도 같은 최종 마감과 회귀 검수를 받는다. 반대로 프롬프트에 스타일 문구가 있다는 사실만으로 게이트를 통과한 것으로 보지 않는다.

### 승인 증빙

각 `review → approved` 전환은 다음 증빙을 provenance 또는 review 인계 문서에 남긴다.

| 항목 | 필수 기록 |
|---|---|
| `styleProfile` | `YS-HANDCRAFTED-NIGHT-v1` |
| `styleRefs` | 사용한 기준 review 경로와 SHA-256 |
| `promptCore` | 공통 스타일 프롬프트 또는 수작업 제작 지시 |
| `promptAsset` | 기능·구도·상태별 지시 |
| `finishPass` | 해부·접촉·반복·문자·광원·재질·픽셀 수정 내역 |
| `regression` | 기준 이미지와 FHD·1280·실제 표시 크기 비교 결과 |
| `exceptions` | 성능·접근성 때문에 질감을 줄인 항목과 유지한 핵심 특성 |

## 에셋 ID와 상태 규칙

### ID 접두사

| 접두사 | 종류 | 예시 |
|---|---|---|
| `BR` | 브랜드·로고 | `BR-LOGO-HORIZONTAL` |
| `BG` | 전체 배경·환경 슬라이스 | `BG-INTERIOR-S1` |
| `ST` | 스테이션 몸체·성장 변형 | `ST-GRILL-TIER-1` |
| `MDL` | GLB 인터랙티브 모델 | `MDL-BEER-GLASS` |
| `TEX` | 모델·셰이더 텍스처 | `TEX-SKEWER-BASE` |
| `FD` | 음식 icon·비조작 sprite | `FD-MOMO-ORDER` |
| `CH` | 캐릭터 sprite·초상 | `CH-EXTRA-COMMUTER-SERVICE` |
| `PR` | 이야기·환경 소품 | `PR-RECIPE-NOTE` |
| `UI` | 기능 icon·atlas | `UI-STATION-ICONS` |
| `VFX` | 이펙트 atlas·mask | `VFX-COOKING-CORE` |

1. ID는 출시 저장·콘텐츠에서 참조한 뒤 재사용하거나 의미를 바꾸지 않는다.
2. 상태는 `planned`, `blocked`, `in-production`, `review`, `approved`, `deprecated` 중 하나다.
3. runtime manifest에는 `approved`만 들어가고 검토·실패본은 `art-workspace/review`에 둔다.
4. 파일 교체는 같은 ID에서 revision과 SHA-256을 올리며 pivot·논리 크기·clip 이름이 바뀌면 호환성 변경으로 기록한다.
5. 좌우 반전 가능한 에셋은 manifest에 명시하고 비대칭 안경·가르마·도구가 중요한 캐릭터는 별도 mirror variant를 사용한다.

5. 분리 에셋은 원본의 크기·각도·접촉면·가림 순서를 유지하고, 독립 재생성 시 해당 마스터를 기준 이미지로 사용한다.
6. 가려진 면 복원과 2D·3D 투영 오차는 `1920×1080 FHD`와 `1280×720` 합성에서 별도 검수한다.
7. 마스터는 화면 구성과 톤앤매너 source이며 그 자체를 runtime manifest에 등록하지 않는다. 분리본의 알파·pivot·anchor·접지·가림·성능·FHD 재합성 증빙이 있어야 `approved`로 전환한다.
8. `visible cutout` 승인은 해당 잘라낸 면만 승인한다. 가려진 면까지 포함한
   `complete layer`는 `semanticOwner` 하나 단위로 다시 제작하고 별도 사용자 승인을
   받아야 한다.
9. complete layer의 review에는 승인 cutout 경로·해시, 생성 프롬프트 또는 결정론적
   방법, FHD PNG·해시, 교차 범주 오염 검사, 승인 상태와 runtime 등록 허용 여부를
   `completion-report.json`으로 기록한다.
10. complete layer가 `pending-user-review` 또는 `rejected-by-user`이면
    `runtimeRegistrationAllowed=false`여야 한다. 승인 complete layer 전부의 FHD/720p
    재조립 회귀가 끝나기 전에는 최적화·catalog·manifest 등록을 금지한다.
11. 중간 반려 이미지는 최종 review·source·runtime 경로에 보존하지 않고 해시와 실패
    사유만 report에 남긴다.
12. 공식 계약은 `art-workspace/pipeline/pipeline-contract.json`이며, 작업공간 루트에서
    `node art-workspace/pipeline/validate-pipeline.mjs`를 사용한다.
13. complete layer마다 프롬프트 작성 전에 확정한 `spatial-inference.json` 경로와
    SHA-256을 `completion-report.json`에 기록한다.
14. `CM-CUSTOMER-SERVICE-R1`은
    `바 안쪽 주인공 카메라 → 단일 바 테이블 → 손님 좌석 → 바로 뒤 가게 대문 → 밤 골목`
    순서를 유지한다. 대문은 화면 수평 중앙의 단일 출입구이고 그 좌우는 화면 끝까지
    막힌 측면 벽이다. 대문 없이 전체 후면을 막힌 목재벽·전폭 병 선반·깊은 별실·
    두 번째 카운터로 치환하거나, 측면 벽을 별도 개구부·출입구로 열면 자동·수동 검수
    모두 실패한다.
15. validator는 `sourceMasterId`별 topology와 공간 추론 파일의 승인 여부·해시를
    검사한다. 공간 추론 증빙이 없거나 설정 불변 요소와 다르면 complete 후보로
    제출할 수 없다.
16. 열 개 마스터의 topology는 `art-workspace/pipeline/topology-registry.json`에서
    관리한다. 현재 `CM-CUSTOMER-SERVICE-R1`만 승인됐으며, 나머지 아홉 마스터는 한
    이미지에 서로 다른 화면·상태가 섞여 있어 각 소비 화면의 카메라·인접·가림 계약을
    사용자 승인하기 전 생성이 차단된다.
17. 제작 프로필은 FHD 장면 좌표를 유지하는 `complete-layer`, 독립 icon·UI skin·
    음식·소품인 `standalone-raster`, GLB·atlas·texture·metadata를 원자적으로 다루는
    `bundle-model` 세 가지다. 각 프로필은 공식 JSON Schema의 승인 report를 가진다.
18. 생성·개별 검수는 `semanticOwner` 하나와 후보 자산 하나만 다룬다. 통합 검수는
    이미 개별 승인된 자산만 소비 화면 하나에 조립한다.
19. spec·승인 이미지의 기록 SHA-256이 실제 파일과 다르면 항상 차단하고 영향 분석을

### 그릴 음식의 station 소비 원근·톤 승인 게이트

그릴 음식의 격리 checkerboard 승인은 모델·node·재질·상태 의미를 확인하는 중간 증빙이며 실제
station 소비 승인을 대신하지 않는다. D1 네기마 보정과 이후 모모·타레·후속 음식은 다음 게이트를
모두 통과해야 한다.

1. `CM-GRILL-STATION-QUEUED-SELECTION R3`의 고정 camera·perspective를 D1 그릴 음식의 유일한
   소비 카메라로 사용한다. 정면 icon, orthographic 상품 컷 또는 격리 검수 카메라를 완료 tray나
   석쇠 소비 화면의 배치 기준으로 사용하지 않는다.
2. raw·첫 면·둘째 면·proper·overcooked·burnt를 같은 3/4 상부 station 시점과 실제 slot/tray
   위치에서 비교한다. 꼬치 두께, 닭·대파의 부피, 잉크 외곽, 석쇠·숯불의 따뜻한 반사광이 승인
   master의 공간과 하나로 읽혀야 한다.
3. proper 닭은 밝고 먹음직스러운 회갈색 속살과 절제된 진갈색 sear, 대파는 익은 녹색을 유지한다.
   raw와 같은 분홍색 또는 평면적인 정면 실루엣으로 읽히면 반려한다.
4. 시각 보정은 기존 `180°` 뒤집기, 면별 시간, `contactFace`, 회수·재투입·저장 복구 계약을
   변경하지 않는다. 별도 음식 raster·중복 texture·GLB 사본을 만드는 근거로도 사용하지 않는다.
5. 새 음식 또는 보정 revision은 먼저 승인 master-derived base 위 실제 station 위치에 한 상태만
   합성해 FHD/720 소비 화면으로 승인받는다. 격리 checkerboard 승인만으로 finalizer·runtime
   handoff를 허용하지 않는다.
6. 완료 상태는 음식 없는 `ST-GRILL-FINISHED-TRAY`가 station 원근·톤을 먼저 통과한 뒤 음식을
   합성한다. tray와 음식 중 하나라도 정면 UI처럼 보이면 두 요소의 소비 화면 승인을 모두 보류한다.

기존 D1 음식 단독 승인은 source 상태 증빙으로 보존하되, 이 게이트를 통과하기 전에는 소비 화면
최종 승인이나 finalizer 입력으로 승격하지 않는다. `CM-GRILL-STATION-EMPTY-BASE R1`은
2026-07-30 사용자 승인을 받은 D1 소비 화면 base이며 runtime 등록 허가는 별도다.

29. 편집 원본은 Aseprite·PSD·Krita·Blender 등 제작 도구 형식을 허용하되
    `art-workspace`에만 두고 `app` Git 저장소에는 넣지 않는다.
30. 런타임 raster는 배경 WebP/JPG, 알파 PNG/WebP, 3D GLB 2.0을 기본으로 한다.
31. 표시용 raster는 sRGB, 데이터 mask는 linear 색 공간을 사용하며 알파 에셋은 straight alpha, 고정 canvas와 nearest 축소 규칙을 적용한다.
32. 16:9 배경은 512x288 논리 pixel grid의 4배인 2048x1152를 기본으로 하며 다른 원본 크기도 같은 pixel density를 유지한다.
33. atlas는 최대 2048x2048, 오브젝트 텍스처는 최대 1024x1024로 제한한다.
34. runtime 파일명은 소문자 ASCII kebab-case로 하고 사람이 보는 한글 이름은 manifest metadata에 둔다.
35. 검토본·실패본·chroma 원본·프롬프트 collage는 `public/assets`에 두지 않는다.
36. `app/art`, `app/captures`는 금지 경로다. 테스트 캡처는 기본적으로 무시되는 테스트
    출력 디렉터리에 생성하고, 장기 증빙만 `art-workspace/evidence`에 보존한다.
37. `art-workspace` 원격에는 승인 자산과 필요한 생성 source·provenance·검수 증거만
    올린다. `pending-user-review` binary는 로컬에만 두고, 반려 binary는 삭제한 뒤
    `REJECTIONS.md`에 SHA-256과 사유만 남긴다. 나중에 deprecated된 승인본은 history를
    rewrite하지 않는다. 비공개 원격 생성·업로드는 별도 사용자 확인 전 수행하지 않는다.

| `provenance` | 외부 작업공간의 승인·생성 근거 식별자 또는 경로 |
| `license` | 제작자·생성 도구·외부 라이선스 |
| `specRefs` | 요구사항 ID와 문서 버전 |
| `reviewedAt` | 사용자 승인일 |

38. `npm run assets:validate`는 URL 존재, SHA-256, byte, raster 치수, 중복 stable ID·URL,
    미등록 payload, 금지 작업용 경로와 URL의 `-r{sourceRevision}-b{runtimeBuild}`를 확인한다.
39. manifest는 stable ID별 활성 runtime build 하나만 가진다. 이전 build는 art 저장소와
    Git history에만 남긴다.
40. 같은 atlas의 frame은 canvas, pivot, pixel density와 조명 방향이 같아야 한다.
41. UI icon·alpha·atlas·pixel art는 무손실만 허용한다. 손실 압축은 불투명 배경에만
    허용하며 자동 회귀와 사용자 시각 승인을 모두 요구한다.
42. provenance와 프로필 승인 report의 `runtimeRegistrationAllowed`는 항상 `false`다.
    소비 화면 FHD/720p 재조립·최적화·최종 사용자 승인을 검증한 finalizer만
    `runtimeRegistrationAllowed=true`인 `runtime-handoff.json`을 파생한다.
43. 승격 dry-run은
    `npm run assets:promote -- --handoff <runtime-handoff.json>`으로 실행한다. 성공 시
    현재 handoff·bundle·manifest에 묶인 30분 유효 일회성 영수증을 만든다.
44. 실제 반영은 같은 handoff에 `--write --receipt <receipt>`를 모두 지정해야 한다.
    파일·manifest 변경 또는 만료는 거부하며 성공한 영수증은 소비한다.
45. 단일 파일도 bundle transaction으로 처리한다. 여러 파일과 manifest 중 하나라도
    실패하면 이전 활성 파일과 manifest를 모두 복구한다.

## 개발자 참조 카탈로그

`app/public/assets/manifest.json`은 런타임과 자동 검증의 단일 원본이고
`art-workspace/ASSET-CATALOG.md`는 제작·검수 중인 ID·상태·용도를 찾는 로컬 사람용
인덱스다. 카탈로그는 app 빌드 입력이 아니며 manifest 내용을 대체하지 않는다.

46. 카탈로그는 에셋 ID, 한글 이름, 상태, 우선순위, runtime 경로, source 경로, pack,
    형식·규격, 대표 사용 화면, 관련 콘텐츠 ID와 마지막 검증일을 기록한다.
47. `blocked`, `planned`, `review` 에셋은 카탈로그에만 남기고 runtime 경로를 비워 두며,
    차단 결정·대체 placeholder와 해제 조건을 명시한다.
48. runtime으로 승격된 항목은 manifest가 유일한 구현 계약이며 개발자는 파일명을
    추측하거나 로컬 카탈로그를 런타임에서 읽지 않고 manifest ID를 사용한다.
49. 새 에셋 승인, 파일 교체, 폐기, pack 이동과 ID 추가가 발생한 작업에서 카탈로그를
    갱신하고, 실제 runtime 승격 시에는 승격 도구가 manifest와 파일을 함께 갱신한다.
50. 각 Artist 작업은 완료 전에 자신이 생성·수정한 모든 작업물이 카탈로그에 반영됐는지
    확인하고 인계 요약에 정확한 provenance·handoff 경로를 기록한다.

## 아트·개발 인수인계 계약

아트 팀은 에셋 ID별로 다음을 함께 전달한다.

- runtime 파일과 편집 원본 경로.
- manifest 레코드와 SHA-256.
- 실제 화면 `1920×1080 FHD`와 `1280×720` 캡처 및 화면별 통합 원본·분리 에셋 비교.
- 투명 경계, pixel density, pivot·anchor와 mirror 검수 결과.
- 생성형 도구 사용 시 최종 프롬프트, 참조, 수정·후처리 내역과 권리 정보.
- 생성 도구와 무관하게 `styleProfile`, 기준 이미지·해시, 수작업 마감 체크와 스타일 회귀 결과.
- GLB의 triangle, material, texture, node·clip 목록.
- 기존 에셋을 교체하는 경우 이전·신규 visual regression 비교.

개발 팀은 에셋 파일명을 코드에 직접 하드코딩하지 않고 manifest ID를 사용한다. anchor·clip 계약이 부족하면 추측한 좌표를 코드에 넣지 않고 검토 상태로 돌린다.

## 검수 기준

### 자동 검수

- raster 규격, alpha, 모서리 투명도, 색 공간, 최대 크기와 해시.
- GLB triangle, material·texture 수, bounds, node·clip 이름과 비어 있는 mesh.

- production pack의 전체 byte, 텍스처 메모리 추정과 누락 참조.
- runtime 경로의 검토본·실패본·읽을 수 없는 생성 문자 여부.

### 화면 검수

- 2D 배경과 3D 대상의 소실점, 숯불 방향, pixel density와 blob shadow 정합.
- `YS-HANDCRAFTED-NIGHT-v1` 기준과 선·과슈 색면·종이/사용 흔적·따뜻한/차가운 색 분리·정보 밀도·픽셀 군집이 이어짐.
- 캐릭터가 반복 얼굴·플라스틱 피부·비정상 손·소품 접촉 오류 없이 얼굴형·연령·자세로 구분됨.
- 3D 대상이 과도한 PBR 광택이나 매끈한 외곽으로 2D 배경에서 분리되지 않음.
- 손님 화면에서 손님·주문 상태·바 테이블 음식·빈 식기의 좌석별 대응과 앞뒤·가림 관계 유지.
- 조립·그릴·주류 화면이 독립적으로 존재하고 상단 주문서·중앙 조리 대상·하단 준비 목록을 가리지 않음.
- 정면 손님, 아래쪽 불판과 옆쪽 주류 장면에서 바 높이·도구 크기·광원·소실점이 같은 가게 공간으로 이어짐.
- `1920×1080 FHD`와 `1280×720`에서 HUD·캐릭터 머리·작업 도구·준비 목록 크롭 없음.
- 주문, 위험, 익힘과 캐릭터 상태가 색각 이상 시뮬레이션과 grayscale에서도 구분됨.
- LOW 모드에서 안경·앞치마·주문 icon·익힘 단계와 위험 신호 유지.
- D30 8인 장면에서 주요 인물과 현재 주문 대상이 가려지지 않음.

## 예외 및 경계 조건

- 기존 12개 재사용 후보가 FHD 화면별 합성·스타일 회귀를 통과하지 못하면 ID만 유지하고 파일을 교체한다.
- 이전 버전에서 승인된 지속형 손님·카운터·스테이션 합성은 독립 화면 분리, 새 anchor와 FHD 합성 검수 전까지 `review`로 되돌린다.
- 주인공 외형 미확정 상태에서는 얼굴·전신을 요구하지 않는 1인칭 구도와 소품 연출을 사용한다.
- 카나모리 성별 표현과 후보 메뉴가 미확정이면 placeholder ID를 운영 콘텐츠에 참조하지 않는다.
- D30 그룹 구성이 바뀌어도 seat·customer anchor 데이터 교체만으로 대응하고 배경에 8명을 고정해 그리지 않는다.
- 좌우 반전으로 캐릭터 정체성이 깨지면 mirror variant가 없을 때 반대 좌석 배치를 사용하지 않는다.
- WebP 알파가 목표 브라우저에서 경계 번짐을 만들면 해당 에셋만 PNG로 전환하고 byte 영향을 기록한다.
- 에셋 누락 시 필수 캐릭터를 빈 좌석으로 숨기지 않고 로드 오류 또는 명시적 개발 placeholder를 표시한다.
