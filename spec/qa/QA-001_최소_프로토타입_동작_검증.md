## 목적

최소 웹 프로토타입이 야키토리 한 주문의 조립, 굽기와 서빙을 실제로 검증할 수 있는 상태인지 판단한다. 기능 유무뿐 아니라 클릭 이해도, 상태 일관성, 반응형 화면과 픽셀 에셋 적용을 함께 확인한다.

## 범위

### 포함

- 핵심 상태 전이와 조리 시간 판정의 자동 검증
- 데스크톱 마우스 클릭의 종단 검증
- 정상, 잘못된 재료, 너무 이른 클릭, 탄 꼬치와 재시작 경로
- 세 기준 뷰포트의 화면 캡처와 겹침·잘림 검수
- 에셋 로딩, 콘솔 오류와 상태별 시각 표현 검수
- 최소 3회의 외부 또는 비개발자 관찰 플레이테스트

### 제외

- 대규모 기기 매트릭스, 장시간 부하, 서버와 네트워크 테스트
- 스테이지 밸런스, 경제, 유지율과 수익화 지표
- 생맥주, 복수 주문과 추가 메뉴 회귀 테스트
- 모바일 브라우저, 터치 입력과 모바일 뷰포트 테스트
- 완성 제품 수준의 보안·침투·접근성 인증

## 상세 요구사항

### 자동 검증 요구사항

1. 조리 상태 로직은 실제 대기 없이 시간을 주입하거나 모의해 다음 경계를 검증한다.
2. `2.499초`, `2.500초`, `5.499초`, `5.500초`, `6.999초`, `7.000초`의 판정이 `GPL-001`과 정확히 일치해야 한다.
3. 레시피 정상 순서, 잘못된 재료 무시, 조립 완료 후 추가 재료 무시를 검증한다.
4. 앞면 적정 뒤집기, 뒷면 적정 회수, 너무 이른 클릭 무시와 탄 상태 실패를 검증한다.
5. 성공과 실패 뒤 재시작하면 레시피 인덱스, 양면 시간, 선택, 결과와 애니메이션 잠금이 초기화되는지 검증한다.
6. 브라우저 종단 테스트는 최소 한 번의 정상 흐름을 마우스 클릭으로 완료한다.
7. 종단 테스트는 빠른 이중 클릭이 재료 두 개 삽입, 이중 뒤집기 또는 이중 서빙을 만들지 않는지 확인한다.

### 수동 검증 시나리오

### A. 정상 품질 서빙

1. 네기마 주문표를 확인한다.
2. 닭, 대파, 닭, 대파, 닭을 순서대로 클릭한다.
3. 완성 꼬치와 대기 꼬치를 차례로 클릭해 그릴에 올린다.
4. 앞면 적정 신호에서 꼬치를 클릭해 뒤집는다.
5. 뒷면 적정 신호에서 꼬치를 클릭해 접시로 회수한다.
6. 접시와 손님 주문 매트를 차례로 클릭한다.
7. 좋은 손님 반응과 다시 하기 기능을 확인한다.

### B. 잘못된 재료와 이른 클릭

1. 첫 재료로 대파를 클릭한다.
2. 조립 진행이 증가하지 않고 닭 칸이 강조되는지 확인한다.
3. 정상 순서로 조립하고 그릴에 올린 직후 꼬치를 클릭한다.
4. 뒤집히지 않고 덜 익음 피드백이 표시되는지 확인한다.
5. 이후 정상 흐름을 계속 완료할 수 있는지 확인한다.

### C. 탄 꼬치와 복구

1. 꼬치를 그릴에 올리고 한 면을 7초 이상 방치한다.
2. 탄 상태, 실패 원인과 다시 만들기 명령을 확인한다.
3. 다시 만들기를 실행한다.
4. 이전 타이머와 결과가 남지 않은 새 주문 상태인지 확인한다.

### D. 중단과 복귀

1. 굽기 중 브라우저 탭을 숨기거나 창 포커스를 변경한다.
2. 7초 이상 기다린 뒤 복귀한다.
3. 숨김 시간이 조리 시간에 누적되지 않았는지 확인한다.
4. 같은 꼬치를 계속 조리해 정상 서빙할 수 있는지 확인한다.

### 시각 검증

- `1280×720`, `1920×1080`에서 각각 조립, 그릴, 카운터 상태의 화면 캡처를 남긴다.
- 각 캡처에서 주문표, 핵심 작업 대상, 상태 피드백과 공정 탭이 서로 겹치거나 잘리지 않아야 한다.
- 캔버스 또는 렌더 영역의 픽셀을 검사해 빈 화면이나 단색 오류 화면이 아님을 확인한다.
- 닭과 대파, 날것과 적정, 적정과 탄 상태가 축소 화면에서도 형태 또는 질감으로 구분되어야 한다.
- 콘셉트 시트의 번호, 설명 문구와 예시 커서가 런타임 화면에 남아 있지 않아야 한다.

### 관찰 플레이테스트

1. 구현에 참여하지 않은 사용자 최소 3명이 별도 설명 없이 첫 주문을 시도한다.
2. 개발자는 사용자의 입력을 대신하거나 정답 순서를 말하지 않는다.
3. 다음 항목을 기록한다.

| 지표 | 목표 |
|---|---:|
| 첫 재료 선택까지 | `5초 이내` 2명 이상 |
| 첫 꼬치 조립 완료 | `30초 이내` 2명 이상 |
| 뒤집기 첫 시도 성공 | 3명 중 2명 이상 |
| 올바른 손님 서빙 성공 | 3명 중 3명 |
| 한 주문 뒤 조작 순서 설명 | 3명 중 2명 이상 |

4. 모든 사용자가 같은 단계에서 막히거나 잘못 이해하면 출시 차단 결함으로 기록한다.
5. 손맛에 대해서는 `재료가 끼워지는 느낌`, `뒤집기 반응`, `적정 순간 인지`, `접시 서빙의 무게감`을 각 한 문장으로 수집한다.

### 결함 등급

| 등급 | 기준 | 처리 |
|---|---|---|
| 차단 | 시작 불가, 정상 경로 완료 불가, 저장소 에셋 누락, 상태 무한 정지 | 완료 불가 |
| 높음 | 판정 경계 오류, 이중 입력으로 상태 손상, 데스크톱 필수 대상 조작 불가 | 완료 전 수정 |
| 보통 | 상태는 완료되지만 피드백 오해, 일부 뷰포트 겹침, 에셋 상태 불일치 | 원칙적으로 수정, 남으면 위험 기록 |
| 낮음 | 기능에 영향 없는 미세 정렬·연출 문제 | 후속 후보 기록 가능 |

## 예외 및 경계 조건

- 실제 시간에 의존하는 자동 테스트는 허용 오차를 두기보다 모의 시계를 사용한다.
- 플레이테스트 참여자가 3명 미만이면 자동·수동 기능 검증은 완료할 수 있으나 관찰 검증은 미완료로 기록한다.
- 외부 폰트나 네트워크 차단이 핵심 흐름을 중단시키면 차단 결함으로 분류한다.

## 비기능 요구사항

- 자동 테스트는 반복 실행해도 순서 의존과 무작위 실패가 없어야 한다.
- 테스트용 우회 입력이 일반 사용자 화면에 노출되지 않아야 한다.
- 검증 명령, 수동 결과, 캡처 위치와 남은 결함을 `app`에 기록하고 요약을 관련 epic에 남긴다.
- 테스트 데이터는 실제 게임 상태와 같은 전이 함수를 사용해야 한다.
