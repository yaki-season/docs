## 목적

메뉴, 공정, 손님, 영업일, 성장과 저장 콘텐츠를 코드 변경 없이 일관되게 작성·검증할 수 있는 데이터 단위를 정의한다. 확정 수치와 기획 예시를 구분하고 잘못된 참조·범위·캠페인 잠금을 런타임 전에 검출한다.

## 범위

### 포함

- 식별자, 데이터 버전과 공통 검증 규칙
- 레시피·공정·품질·손님·영업일·성장·직원·시나리오 데이터
- 확정 상한과 미확정 밸런스 변수
- 저장 참조와 콘텐츠 마이그레이션 조건

### 제외

- 특정 직렬화 언어와 구현 코드
- 최종 밸런스 테이블 값
- 원격 콘텐츠 배포와 라이브 운영 도구

## 상세 요구사항

상세 규칙은 공통 검증, 콘텐츠 단위, 기준선과 저장 참조를 함께 적용한다.

## 공통 규칙

1. 모든 콘텐츠 레코드는 영구 식별자, 스키마 버전, 표시 키, 활성 여부와 변경 이력을 가진다.
2. 영구 식별자는 출시 저장 데이터에서 재사용·변경하지 않는다.
3. 표시 문구와 에셋 경로는 로직 식별자와 분리한다.
4. 모든 참조는 로드 전에 존재·유형·활성 여부를 검증한다.
5. 비율은 `0~1`, 시간은 초, 재화는 음수가 아닌 정수, 화면 좌표는 정규화 값 등 단위를 명시한다.
6. 최소값은 최대값보다 클 수 없고 확률 합과 가중치 정규화 규칙을 명시한다.
7. 캠페인 필수 레코드는 비활성화하거나 삭제할 수 없고 대체 레코드를 가져야 한다.
8. 예시 수치는 `candidate`, 출시 기준은 `approved`처럼 상태를 구분해 미정값이 확정값으로 로드되지 않게 한다.

### 공정·품질

- 공정은 입력 종류, 시작·중단·완료 조건, 시간 구간, 적정 범위, 실패·복구와 접근성 보정을 정의한다. 타레 공정은 제작 중 출처 주문의 `seasoning=tare`를 따르며, 완료품에는 해당 조리 방식만 보존하고 주문 식별자는 보존하지 않는다.
- 그릴 제작물 상태는 `frontElapsedSec`, `backElapsedSec`, `orientationFaceDown=front|back`, `grillPlacementState=staged|active|offGrill`, `contactFace=front|back|null`을 가진다. `active`에서는 `contactFace=orientationFaceDown`인 한 면만 시간이 증가하고 반대 면은 정지한다. `staged|offGrill`과 뒤집기 공중 구간에서는 `contactFace=null`이며 양면이 모두 정지한다. 재투입·저장 복구는 `orientationFaceDown`과 양면 누적 시간을 보존하고 그 방향의 면만 재개한다.
- 본편 그릴 설정은 `slotCount=6`, `slotUpgradeEnabled=false`로 고정한다. D1 첫 주문은 `initialPlacementCount=3`, `initialPlacementSlots=[1,2,3]`, `timerStartPolicy=afterInitialBatchPlaced`를 사용해 세 번째 배치 완료 전에는 세 꼬치를 `grillPlacementState=staged`, `contactFace=null`로 유지하고 완료 시 함께 `active`로 전환한다.
- 그릴 메뉴 데이터는 면별 익힘 곡선, 적정·과다·탄 경계, 재투입 허용 규칙과 선택 강화 입력을 가진다. 네기마 기본값은 각 면 `perfect=8초`, `over=16초`, `burnt=21초`이며 재투입 횟수는 제한하지 않는다. 기본 화력은 시간에 따라 변하지 않는다.
- D5 카와는 `ingredients=[foldedChickenSkin,foldedChickenSkin,foldedChickenSkin,foldedChickenSkin,foldedChickenSkin]`, `seasoningOptions=[salt,tare]`, 면별 `perfect=10초`, `over=14초`, `burnt=18초`를 사용한다. D5 첫 가이드의 `properHighlight=true`는 실제 판정 범위를 넓히는 보정값을 만들 수 없다.
- 부채 강화 데이터는 `boostElapsedSec=4`, `cooldownSec=9`, `scope=allActiveGrillProducts`, `unlockScenarioId="d5"`를 가진다. 강화는 모든 그릴 위 제작물의 현재 면 누적 시간에 즉시 더하며, D5 완료 전에는 해당 입력을 노출하거나 판정하지 않는다. 쿨타임은 영업 타이머와 같은 일시정지 규칙을 따른다.
- 생맥주는 맥주·거품 목표 시간, 각 허용 범위, 총 넘침 범위, 넘침 뒤 플레이어 선택과 첫 잔 보조값을 가진다. 기본값은 `beerTargetSec=3`, `foamTargetSec=1`, `stageToleranceSec=0.7`, `overflowToleranceSec=0.7`, `overflowDecision=playerChoice`다. 두 단계가 모두 허용 범위 안이면 `Perfect`, 한 단계만 벗어나면 `Good`, 두 단계가 모두 벗어나면 `OK`이며, 총 채움 `4.7초` 초과 뒤 `낮은 품질로 제공`을 선택하면 `Fail`이다.
- 품질은 네 등급의 공정 집계 규칙, 판매율·만족 점수와 제공 가능 여부를 가진다. 기본 `qualitySaleRateTenths`는 `Perfect=10`, `Good=7`, `OK=4`, `Fail=1`이며, 메뉴 기본 판매가에 `rate/10`을 곱한 뒤 골드 단위에서 내린다. 기본 `qualitySatisfactionPoints`는 `Perfect=100`, `Good=40`, `OK=10`, `Fail=0`이며 주문의 제공 항목을 수량 가중 평균한 뒤 소수점을 버려 주문 만족도로 사용한다. 제공 가능한 `Fail` 판매가는 계산값이 `1G` 미만이면 `1G`로 보정한다. `Fail`은 제공 가능한 최저 품질이며 `bothFacesBurnt=true`인 완전 탄 제작물은 이 등급과 별도인 제공 불가 상태다.
- 네기마와 카와의 양면 품질 규칙은 `perfect+perfect → Perfect`, `perfect+over → Good`, `over+over|perfect+under → OK`, `over+under|under+under|exactlyOneFaceBurnt → Fail`, `bothFacesBurnt → discard`다.
- `anything` 특수 주문에서 플레이어는 제공 불가 상태가 아닌 모든 공용 완성품 카드를 드래그해 제공할 수 있다. 홀 담당의 자동 서빙 후보도 제공 불가 항목을 제외한 모든 공용 완성품이며, 그중 하나를 균등 무작위로 고른다.
- 완료품은 `inventoryScope=shared`를 가지며 특정 주문 식별자를 보유하지 않는다. 수동 서빙 트랜잭션은 공용 완성품 카드 식별자와 `targetCustomerId`를 받아, 일치하는 손님 접시 위 수량 선택 `serveOne|serveAll`이 확정된 뒤에만 상태를 바꾼다. `serveOne`은 한 개, `serveAll`은 카드 수량과 대상 손님의 일치 미제공 수량 중 작은 값을 배정한다. 이 선택이 열린 `targetCustomerId`는 `manualServeSelectionLocked`로 기록하며, 홀 담당 자동 서빙 후보·예약·확정에서 제외한다. 바깥 클릭·취소 입력은 `cancelQuantityChoice`로, 선택 중 대상 손님 이탈은 `cancelTargetUnavailable`로 카드만 원위치 복귀하고 모든 주문·완성품·대기·품질·판매 상태를 보존한다. 후보가 여러 개면 `orderReceivedAscending`으로 가장 먼저 접수된 항목을 고른다. 일치 후보가 없으면 `invalidDrop`으로 카드만 원위치 복귀하고 모든 주문·완성품·대기·품질·판매 상태를 보존한다. 성공 시 공용 수량과 주문 항목 미제공 수량을 함께 줄이고, 품질·판매·만족 기록은 이 배정 시점에만 주문에 기록한다. 제작물 폐기는 `discarded` 결과와 폐기 시각·원인을 기록하되 주문 취소·제공·판매로 집계하지 않는다.
- 영업일 종료 데이터는 `sharedPreparedItemEndPolicy=autoDiscardNoReward`를 사용한다. 정산 직전 남은 공용 완성품은 판매·팁·명성·재고 레코드 없이 제거하며, `loreDisposition=staffAndFamilyMeal`은 플레이 화면·선택·보상으로 노출하지 않는 설정 메모다.
- 팁·만족도·명성 배율은 품질 배율과 별도 테이블로 유지한다.

12. 2인 그룹은 인접 좌석 두 개와 공동 퇴장 규칙을 가져야 한다.
13. 기억 주문은 정답 조합, 노트 기록 상태, 실패 힌트 단계와 정답·정상 수령 보너스 팁 후보값을 반드시 가진다.
14. 손님 유형의 팁·인내심·추가 주문 수치는 허용 범위를 벗어나면 빌드를 차단한다.
14-1. `patienceSec`는 주문 접수 뒤 대기 게이지의 최대 시간이며 코드 상수 또는 이미지 안 숫자로 중복하지 않는다. 일반·단골 기준값을 바꿀 때는 데이터 레코드와 변경 이력만 수정한다.
14-1-1. 영업일 데이터 `waitRecoverySec`는 항목 하나를 제공할 때 회복하는 대기 시간이며, 현재 후보값은 `10초`다. 메뉴 종류별 보정은 플레이테스트 뒤에만 추가한다.
14-2. 2인 그룹은 `anyMemberTimeout → groupLeave` 정책을 사용한다. 한 명의 대기 게이지가 0이 되면 그룹의 모든 미제공 항목을 취소하고, 이탈 원인·명성 영향은 공통 그룹 ID로 한 번만 기록한다.
14-3. 개별 인물 데이터 `regularThresholdSatisfiedOrders`는 단골 전환에 필요한 만족스러운 전체 주문 완료 횟수이며, 현재 후보값은 `5회`다. 부분 서빙 항목과 2인 그룹 동행의 만족 결과를 중복 합산하지 않는다.
14-4. 기억 주문의 `noteEntryStatus`는 처음에 `hidden`이며, 메뉴·소스·음료가 모두 정답이고 전체 주문이 정상 수령된 경우에만 `recorded`로 전환한다. 오답·대기 시간 초과·세 번째 오답 뒤 재고지 주문은 기록 또는 보너스 팁을 만들지 않는다.
14-5. `memoryOrderBonusTipG=6`은 기억 주문의 전체 정답과 정상 수령을 모두 만족할 때 주문당 한 번만 지급한다. 기본 팁과 원인을 분리해 저장한다.
14-6. 영업일 데이터 `timingSec.eat`은 전량 수령 뒤 식사·음주 애니메이션 시간이며, 모든 손님 유형에 공통으로 `15초`를 사용한다. 종료 시 추가 주문 판정 또는 퇴장으로 전이한다.
14-7. 영업일 데이터 `timingSec.orderThinkMin`과 `timingSec.orderThinkMax`는 주문 전 고민 시간의 하한·상한이며, 현재 `4초`와 `6초`다. 손님은 각 주문마다 두 값을 포함한 균등 무작위 시간을 뽑으며, 검증기는 하한이 상한을 넘으면 오류로 처리한다.
14-8. 영업일 데이터 `urgentThresholdSec`은 손님 이탈 임박 경고의 시작 시점이며, 현재 `15초`다. 이 시점부터 모든 해당 주문 박스에 느린 반복 점등과 남은 시간 게이지를 표시한다.
14-9. 주문의 `hasFailItem`은 제공 완료된 항목 중 `quality=Fail`이 하나 이상일 때 참이다. 이 경우 즉시 `postReceiveOutcome=angryLeave`를 사용해 미제공 항목을 취소하고, 식사·음주, 추가 주문, 팁, 만족도·긍정 명성 보상을 생성하지 않는다. 명성 `-1`을 한 번 기록하며 이미 제공한 항목의 판매 기록은 유지한다. 완전 탄은 제공 불가이므로 `hasFailItem` 계산에 들어오지 않는다.
14-10. 2인 그룹의 한 구성원 주문에 `hasFailItem=true`가 되면 그룹 정책 `anyMemberFailReceive → groupLeave`를 사용한다. 두 구성원의 미제공 항목을 취소하고, 이미 제공한 항목의 판매 기록만 보존한다. 화난 퇴장 명성 `-1`은 그룹 공통 원인으로 한 번만 기록한다.
14-11. 1차 밸런스에서 주문 데이터의 `baseTipG`는 정상 수령으로 완료한 주문당 `2`다. `hasFailItem`, 대기 시간 초과 또는 미제공 취소 주문은 기본 팁을 만들지 않는다. 대기 잔량·손님 유형에 따른 보정 필드는 `0`으로 고정하고, 플레이테스트 이후 후보값으로만 변경할 수 있다.
14-12. 영업일 재주문 데이터 `reorderChanceBySatisfaction`은 `satisfaction=100 → 0.40`, `70<=satisfaction<100 → 0.20`, `satisfaction<70 → 0`을 사용한다. 각 주문의 식사·음주 `15초` 종료 뒤 한 번만 판정하며, 값은 플레이테스트 조정 가능한 `candidate`다.
14-13. 주문 `satisfactionPercent`는 `floor(sum(제공 항목 수량 × qualitySatisfactionPoints) / sum(제공 항목 수량))`으로 계산한다. 예를 들어 Perfect 2개·Good 1개면 `floor((100+100+40)/3)=80`이다. Fail 제공·대기 시간 초과·미제공 취소 주문은 만족도·재주문·명성 보상 계산을 만들지 않는다.
14-14. 기억 주문의 `preferenceMismatch=true`면 품질 평균 대신 `satisfactionPercent=30`을 사용한다. 이 주문은 단골 노트 기록·기억 주문 보너스 팁을 만들지 않으며, 재주문 임계값 `70%`에도 도달하지 않는다.
14-15. 명성 데이터 `reputationBySatisfaction`은 `satisfaction=100 → +3`, `80<=satisfaction<100 → +1`, `satisfaction<80 → 0`이다. 대기 시간 초과 또는 Fail 제공의 `angryLeave` 사건은 만족도와 별도로 명성 `-1`을 한 번 기록한다.
14-16. 가라아게 해금 데이터는 `reputationRequirement=100`, `reputationCost=0`, `eventId=karaage_unlock`, `triggerPhase=postSettlementSameDay`를 사용한다. 이벤트는 구매 항목을 열기만 하며 구매를 처리하지 않는다. 장비 데이터 `fryer_station`은 `purchaseSurface=purchaseMenu`, `goldCost=200`, `reputationCost=0`이며, 구매 완료 전에는 가라아게 메뉴·튀김 스테이션을 활성화하지 않는다.

### 성장·직원

- 구매 카탈로그는 `menu|station|employee|interior` 항목을 함께 가지며, 비용·해금 조건·소유 상태·효과를 공통 필드로 관리한다. 이후 꼬치 메뉴·추가 스테이션은 새 화면이나 로직 분기 없이 카탈로그 레코드로 추가한다.
- 업그레이드는 종류, 단계, 비용, 명성 조건, 선행 단계와 수치 효과 하나 이상을 가진다.
- 메뉴 복원과 판매 준비는 별도 상태·조건으로 저장한다.
- 직원은 역할, 속도, 품질 상한, 경험치 곡선, 실수 후보와 애니메이션 참조를 가진다. 1차 기획에서 고용 뒤 반복 급여는 `0`이며, 월 단위 급여 필드는 장기 운영 확장 전까지 비활성화한다. 현재 구매 항목 `hall_staff`는 `reputationRequirement=70`, `reputationCost=0`, `goldCost=100`, `costTiming=oneTimeHire`, `autoTasks=serve|seatCleanup`, `autoServePriority=orderReceivedAscending`, `anythingAutoServePolicy=randomSharedPreparedItem`, `autoServeDelaySec=1`, `manualServeCancelsAutoReservation=true`, `autoSeatCleanupStart=onCustomerLeave`, `autoSeatCleanupDelaySec=3`이고, `beer_staff`는 `reputationRequirement=70`, `reputationCost=0`, `goldCost=150`, `costTiming=oneTimeHire`, `autoStartOnOrderReceived=true`, `autoPrepareDurationSec=5`, `autoConcurrentTaskLimit=1`, `manualPrepareAllowed=true`, `independentManualProcess=true`, `autoTasks=prepareDraftBeer`, `autoTargetQuantity=remainingSharedDraftBeerDemand`, `inProgressAutoTaskCancellation=false`, `qualityWeights={Good:0.60,Perfect:0.40}`, `stationWorkerVisual=beerStaffWorking`, `sharedDrinkProgressIndicator=circular`이며 `OK|Fail` 결과를 만들지 않는다. `randomSharedPreparedItem`은 제공 불가 항목을 제외한 현재 공용 완성품 중 하나를 균등 무작위로 고른다. `remainingSharedDraftBeerDemand`는 모든 미제공 생맥주 주문 수량에서 공용 완성 생맥주 수량과 자동 제조 중인 잔 수를 뺀 값이며, `0`이면 새 자동 작업을 생성할 수 없다. 이미 시작한 자동 작업은 이 값이 `0`이 되어도 취소하지 않는다.
- 음식 조리 직원 공통 품질 업그레이드는 `qualityUpgradeCostsG=[40,55,75,100,140]`, `perfectProbabilities=[0.20,0.40,0.60,0.80,1.00]`, `baseQualityWeights={Good:1.00}`를 사용한다. 모든 단계에서 Perfect 이외 결과는 Good이며 OK·Fail은 만들지 않는다. 이 규칙은 `workerDomain=foodCooking`에만 적용하고 `workerDomain=drink`인 맥주 담당에는 적용하지 않는다.
- 인테리어 좌석 단계는 실제 좌석 레이아웃과 손님 수용 상한을 함께 갱신해야 한다.
- 그릴 칸 확장은 골드 업그레이드가 아니라 **명성 해금 데이터**(`content/progression/grill-slots.json`)로 둔다. `maxSlots`와 명성 구간 `tiers[].reputation → tiers[].slots`를 가진다(기준선: 명성 `0→2`, `10→4`, `20→6`, `30→8`, 최대 `8`). 명성은 소비하지 않으며(도달값 게이트), 구간을 넘어도 즉시 반영하지 않고 **다음 영업일**에 "해금 가능"을 노출해 **플레이어 클릭**으로 적용한다. 기존 골드 `grillSlots` 업그레이드는 구매 카탈로그에서 제외한다.

## 검증 규칙

- 중복 ID, 누락 참조, 음수 비용, 역전 범위와 도달 불가 날짜를 오류로 처리한다.
- 필수 날짜가 잠긴 메뉴만 요구하거나 대체안이 없으면 오류다.
- 한 날짜의 신규 행동이 하나를 초과하면 경고, 필수 진행을 동시에 둘 이상 요구하면 검토 오류로 처리한다.
- 품질·팁·만족도 효과가 같은 결과에 중복 연결되면 오류다.
- 주문 최종 수익 상한을 넘는 배율 조합은 오류다.
- 에셋·오디오 키가 manifest에 없으면 빌드 전에 오류로 처리한다.
- `grillPlacementState=active`인 제작물의 `contactFace`가 `orientationFaceDown`과 다르거나, `staged|offGrill`인 제작물의 `contactFace`가 `null`이 아니거나, 한 틱에서 양면 누적 시간이 함께 증가하면 상태 검증 오류다.

## 예외 및 경계 조건

- `approved` 상태의 필수 수치가 비어 있거나 `candidate` 값만 있으면 출시용 데이터 로드를 실패시킨다.
- 알 수 없는 열거 값, 순환 선행 조건과 자기 참조는 자동 보정하지 않고 오류로 처리한다.
- 비활성 콘텐츠를 기존 저장이 참조하면 지정된 대체 ID로 마이그레이션하고 대체가 없으면 원본 저장을 보존한 채 복구 오류를 표시한다.
- 선택 콘텐츠의 표시 문구·에셋이 누락되면 해당 콘텐츠만 비활성화할 수 있지만 캠페인 필수 콘텐츠에는 이 완화를 적용하지 않는다.
- 확률 가중치 합이 0이면 무작위 선택을 수행하지 않고 날짜에 정의된 기본 결과를 사용한다.

## 비기능 요구사항

- 콘텐츠는 사람이 diff를 검토할 수 있는 텍스트 기반 형식으로 관리한다.
- 로드 순서에 따라 결과가 달라지지 않아야 한다.
- 데이터 검증 실패는 경로, 레코드 ID, 필드와 원인을 함께 보고한다.
- 확률 콘텐츠는 테스트 시드와 강제 결과를 주입할 수 있어야 한다.
