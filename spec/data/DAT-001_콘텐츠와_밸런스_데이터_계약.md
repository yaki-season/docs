## 목적

메뉴, 공정, 손님, 영업일, 성장과 저장 콘텐츠를 코드 변경 없이 일관되게 작성·검증할 수 있는 데이터 단위를 정의한다. 확정 수치와 기획 예시를 구분하고 잘못된 참조·범위·캠페인 잠금을 런타임 전에 검출한다.

## 범위

### 포함

- 식별자, 데이터 버전과 공통 검증 규칙
- 레시피·공정·품질·손님·영업일·성장·직원·시나리오 데이터
- 확정 상한과 미확정 밸런스 변수
- 저장 참조와 콘텐츠 마이그레이션 조건

### 제외

- 특정 직렬화 언어와 구현 코드
- 최종 밸런스 테이블 값
- 원격 콘텐츠 배포와 라이브 운영 도구

## 상세 요구사항

상세 규칙은 공통 검증, 콘텐츠 단위, 기준선과 저장 참조를 함께 적용한다.

## 공통 규칙

1. 모든 콘텐츠 레코드는 영구 식별자, 스키마 버전, 표시 키, 활성 여부와 변경 이력을 가진다.
2. 영구 식별자는 출시 저장 데이터에서 재사용·변경하지 않는다.
3. 표시 문구와 에셋 경로는 로직 식별자와 분리한다.
4. 모든 참조는 로드 전에 존재·유형·활성 여부를 검증한다.
5. 비율은 `0~1`, 시간은 초, 재화는 음수가 아닌 정수, 화면 좌표는 정규화 값 등 단위를 명시한다.
6. 최소값은 최대값보다 클 수 없고 확률 합과 가중치 정규화 규칙을 명시한다.
7. 캠페인 필수 레코드는 비활성화하거나 삭제할 수 없고 대체 레코드를 가져야 한다.
8. 예시 수치는 `candidate`, 출시 기준은 `approved`처럼 상태를 구분해 미정값이 확정값으로 로드되지 않게 한다.

## 데이터 단위

### 메뉴·레시피

| 필드 그룹 | 필수 내용 |
|---|---|
| 식별 | 메뉴 ID, 표시 키, 카테고리, 활성 상태 |
| 조합 | 재료 ID 순서, 수량, 선택 소스·취향 |
| 공정 | 공정 ID 순서, 필요 스테이션, 예상 시간 |
| 판정 | 공정별 입력 항목, 구간, 가중치, 복구 규칙 |
| 경제 | 원가 후보, 기본 판매가, 품질 배율 참조 |
| 진행 | 복원 조건, 명성 조건, 판매 준비 비용, 메뉴 슬롯 조건 |
| 관계 | 손님 취향, 기억 주문과 시나리오 연결 |
| 표현 | 주문 아이콘, 2D·3D 에셋, SFX·VFX 참조 |

9. 레시피 공정은 존재하는 스테이션 순서로만 구성하고 순환 참조를 허용하지 않는다.
10. 조립 메뉴는 재료 순서와 재료 수가 일치해야 한다.
11. 메뉴가 사용하는 모든 공정에 판정 또는 즉시 완료 규칙이 있어야 한다.

### 공정·품질

- 공정은 입력 종류, 시작·중단·완료 조건, 시간 구간, 적정 범위, 실패·복구와 접근성 보정을 정의한다.
- 그릴은 면별 익힘 곡선, 화력 보정, 적정·과다·탄 경계와 최대 복구 횟수를 가진다.
- 생맥주는 맥주·거품 속도, 이상 범위, 넘침 차단과 첫 잔 보조값을 가진다.
- 품질은 네 등급의 공정 집계 규칙, 판매가 배율과 제공 가능 여부를 가진다.
- 팁·만족도·명성 배율은 품질 배율과 별도 테이블로 유지한다.

### 손님·주문

| 필드 그룹 | 필수 내용 |
|---|---|
| 손님 유형 | 그룹 크기, 인내심, 주문량, 팁, 추가 주문 가중치 |
| 개별 인물 | 유형, 취향, 단골 조건, 초상·대사 참조 |
| 주문 | 메뉴 풀, 수량, 선주문, 추가 주문, 기억 정보 공개 수준 |
| 좌석 | 요구 인접석, 예약 ID, 입장·퇴장 규칙 |
| 반응 | 품질·대기·취향별 반응과 명성 효과 |

12. 2인 그룹은 인접 좌석 두 개와 공동 퇴장 규칙을 가져야 한다.
13. 기억 주문은 정답 조합과 실패 힌트 단계를 반드시 가진다.
14. 손님 유형의 팁·인내심·추가 주문 수치는 허용 범위를 벗어나면 빌드를 차단한다.

### 영업일·시나리오

영업일은 다음 항목을 포함한다.

- 날짜·스테이지·감정 키워드
- 영업 전·후 장면과 스킵 요약
- 사용 가능한 메뉴·스테이션·직원
- 자동 등장 손님과 일반 손님 풀
- 주문 파동, 회복 구간, 활성 위험 상한
- 신규 행동 1개와 복습 상황 1개
- 핵심 목표 1개와 보너스 목표 최대 2개
- 실패·잠금·직원 부재 대체 흐름
- 정산 결과, 해금, 배경·노트 변화와 다음 날

15. D1~D30은 중복 없는 날짜 식별자를 가져야 하고 다음 날짜 참조가 끊기지 않아야 한다.
16. 각 날짜는 캠페인 필수 메뉴·손님이 잠겼을 때 사용할 대체안을 가진다.
17. D30은 운영 경향별 파동을 가지되 공통 결말과 D31 참조를 공유한다.

### 성장·직원

- 업그레이드는 종류, 단계, 비용, 명성 조건, 선행 단계와 수치 효과 하나 이상을 가진다.
- 메뉴 복원과 판매 준비는 별도 상태·조건으로 저장한다.
- 직원은 역할, 속도, 품질 상한, 급여, 경험치 곡선, 실수 후보와 애니메이션 참조를 가진다.
- 인테리어 좌석 단계는 실제 좌석 레이아웃과 손님 수용 상한을 함께 갱신해야 한다.

## 저장 참조와 마이그레이션

18. 저장 데이터는 콘텐츠 전문이 아니라 영구 ID, 단계와 플레이어 결과를 저장한다.
19. 콘텐츠 ID가 폐기되면 기존 저장을 위한 대체 ID 또는 마이그레이션 규칙을 제공한다.
20. 저장된 날짜·메뉴·직원 참조가 현재 콘텐츠에 없으면 임의 삭제하지 않고 복구 가능한 기본값과 진단을 제공한다.
21. 콘텐츠 스키마 버전과 저장 스키마 버전을 독립적으로 관리한다.

## 검증 규칙

- 중복 ID, 누락 참조, 음수 비용, 역전 범위와 도달 불가 날짜를 오류로 처리한다.
- 필수 날짜가 잠긴 메뉴만 요구하거나 대체안이 없으면 오류다.
- 한 날짜의 신규 행동이 하나를 초과하면 경고, 필수 진행을 동시에 둘 이상 요구하면 검토 오류로 처리한다.
- 품질·팁·만족도 효과가 같은 결과에 중복 연결되면 오류다.
- 주문 최종 수익 상한을 넘는 배율 조합은 오류다.
- 에셋·오디오 키가 manifest에 없으면 빌드 전에 오류로 처리한다.

## 예외 및 경계 조건

- `approved` 상태의 필수 수치가 비어 있거나 `candidate` 값만 있으면 출시용 데이터 로드를 실패시킨다.
- 알 수 없는 열거 값, 순환 선행 조건과 자기 참조는 자동 보정하지 않고 오류로 처리한다.
- 비활성 콘텐츠를 기존 저장이 참조하면 지정된 대체 ID로 마이그레이션하고 대체가 없으면 원본 저장을 보존한 채 복구 오류를 표시한다.
- 선택 콘텐츠의 표시 문구·에셋이 누락되면 해당 콘텐츠만 비활성화할 수 있지만 캠페인 필수 콘텐츠에는 이 완화를 적용하지 않는다.
- 확률 가중치 합이 0이면 무작위 선택을 수행하지 않고 날짜에 정의된 기본 결과를 사용한다.

## 비기능 요구사항

- 콘텐츠는 사람이 diff를 검토할 수 있는 텍스트 기반 형식으로 관리한다.
- 로드 순서에 따라 결과가 달라지지 않아야 한다.
- 데이터 검증 실패는 경로, 레코드 ID, 필드와 원인을 함께 보고한다.
- 확률 콘텐츠는 테스트 시드와 강제 결과를 주입할 수 있어야 한다.
