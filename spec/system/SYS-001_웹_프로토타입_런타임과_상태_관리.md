## 목적

1인 개발자가 기존 `app/sources`의 WebGL2 익힘 셰이더 실험을 활용하거나 교체하면서, 별도 서버 기능 없이 브라우저에서 단일 야키토리 주문을 안정적으로 반복 검증할 수 있는 최소 실행 기반과 상태 경계를 정의한다.

## 범위

### 포함

- 로컬 개발 서버에서 실행되는 단일 웹 애플리케이션
- 조리 흐름의 명시적 상태 관리, 경과 시간 기반 그릴 판정과 재시작
- 정적 에셋 로딩, 로딩·오류 상태와 브라우저 백그라운드 처리
- 기존 꼬치 텍스처와 익힘 셰이더 실험의 재사용 가능성 검토
- 자동·수동 검증이 가능한 안정된 요소 식별자와 상태 관찰 지점

### 제외

- 백엔드, 데이터베이스, 인증, 원격 API와 분석 수집
- PWA 설치, 오프라인 캐시, WebView·앱스토어 패키징과 배포 자동화
- 모바일 브라우저 호환성과 터치 입력 처리
- 영구 저장과 세이브 데이터 마이그레이션
- 다국어, 라이브 운영과 원격 콘텐츠 갱신
- 완성 게임 수준의 범용 ECS, 에디터와 콘텐츠 파이프라인

## 상세 요구사항

1. 구현 결과물은 `app` 저장소 안에서 로컬 개발 서버 명령 하나로 실행 가능해야 한다.
2. 애플리케이션은 최소 `loading`, `assembly`, `grillFront`, `grillBack`, `plated`, `served`, `failed` 상태를 명시적으로 구분한다.
3. 각 사용자 입력은 현재 상태에서 허용된 전이 하나만 만들며 상태가 맞지 않는 입력은 데이터 변경 없이 종료한다.
4. 레시피 순서, 현재 조립 인덱스, 앞면 결과, 뒷면 결과, 현재 공정, 선택 대상과 결과 상태를 하나의 일관된 게임 세션에서 관리한다.
5. 조리 시간은 `performance.now()`와 같은 단조 증가 시간을 기준으로 계산하고 렌더 프레임 수에 의존하지 않는다.
6. 브라우저가 숨겨지는 순간 조리 시계를 정지하고 복귀 시 정지 시간을 제외한 시점부터 계속한다.
7. `다시 하기`는 페이지를 다시 불러오지 않고 세션 상태, 타이머, 선택과 일회성 애니메이션 잠금을 초기값으로 되돌린다.
8. 이미지·셰이더·폰트 등 필수 에셋을 모두 불러오기 전에는 핵심 입력을 활성화하지 않는다.
9. 필수 에셋 하나라도 로딩에 실패하면 오류 상태, 실패한 종류와 다시 시도 명령을 표시한다.
10. 개발 모드에서는 현재 공정, 앞·뒷면 경과 시간과 판정 결과를 콘솔 또는 비노출 상태 관찰 API로 확인할 수 있어야 한다.
11. 자동 검증에서 사용할 주요 대상은 역할 기반 쿼리 또는 안정된 `data-testid`와 같은 식별 수단을 가져야 한다.
12. 기존 `app/sources`의 셰이더와 꼬치 텍스처는 품질과 통합 비용을 비교한 뒤 재사용할 수 있다. 재사용하더라도 단일 토글 상태를 면별 독립 익힘 상태로 확장해야 한다.
13. Three.js를 도입하거나 기존 WebGL2를 유지하는 선택은 개발자가 할 수 있으나, 하나의 화면에서 중복 렌더러와 중복 애니메이션 루프를 운영하지 않는다.
14. 조리 판정과 상태 전이 로직은 렌더링·DOM 이벤트 코드와 분리해 시간 조건을 독립적으로 검증할 수 있어야 한다.

## 예외 및 경계 조건

- WebGL을 사용할 수 없고 대체 렌더 경로가 없다면 지원되지 않는 환경임을 표시하고 빈 캔버스를 보여주지 않는다.
- 같은 포인터 이벤트가 중복 전달되어도 상태 전이는 한 번만 발생해야 한다.
- 매우 긴 프레임 뒤 복귀하더라도 한 프레임에서 여러 공정을 건너뛰지 않는다.
- 다시 시도 중 이전 로딩 요청의 늦은 응답이 새 세션 상태를 덮어쓰지 않아야 한다.
- 상태 관찰 기능은 프로토타입 UI에 개발자용 수치를 항상 노출하지 않는다.

## 비기능 요구사항

- 최신 안정판 Chromium 계열 데스크톱 브라우저에서 동작해야 한다.
- `1280×720` 환경에서 조리 중 목표 평균 30 FPS 이상을 유지하고 입력 후 반응이 장시간 정지하지 않아야 한다.
- 정적 에셋은 저장소에 포함하고 외부 서비스의 가용성에 핵심 흐름이 의존하지 않아야 한다.
- 프로토타입 실행에 비밀 키나 사용자별 환경 변수를 요구하지 않는다.
- 개발 시작 방법과 검증 명령을 `app` 저장소의 README에 기록한다.
