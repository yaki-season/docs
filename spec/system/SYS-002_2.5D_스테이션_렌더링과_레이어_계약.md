## 목적

기존 단일 주문 상태 로직을 유지하면서 평면 플레이스홀더 화면을 Three.js 기반 2.5D 영업 장면으로 교체한다. 생성된 래스터 에셋을 깊이가 다른 평면과 기존 익힘 셰이더 대상에 배치해, 카메라 이동·가림·로딩·성능을 예측 가능한 계약으로 만든다.

## 범위

### 포함

- Three.js 단일 렌더러와 고정 원근 카메라
- 배경, 손님·중경, 인터랙티브 작업대, 전경의 깊이 레이어
- 조립·그릴·서빙 스테이션 프리셋과 짧은 카메라 전환
- 정적 JPG, 투명 PNG, 기존 꼬치 익힘 셰이더의 결합
- 레이아웃 안전 영역, 에셋 로딩 게이트, 저사양 폴백
- 기존 DOM 주문·안내·탭 UI와 3D 캔버스의 입력 우선순위

### 제외

- glTF 캐릭터·도구 모델, 스켈레탈 애니메이션과 물리 엔진
- 자유 카메라, 줌·회전 조작과 충돌 처리
- 드링크 스테이션, 복수 손님과 복수 그릴 슬롯
- 실시간 그림자 맵, 풀스크린 포스트 프로세싱과 블룸
- 모바일 터치 최적화와 PWA

## 상세 요구사항

1. 기존 상태 원본과 조리 판정은 렌더러를 import하지 않으며 `SYS-001 v1.0.0`의 전이 함수를 유지한다.
2. 앱은 `origin/agent/yakitori-vertical-slice`의 커밋 `d3fd2c7` 또는 이를 포함한 병합 커밋을 구현 기준선으로 사용한다.
3. 화면 렌더링은 Three.js의 렌더러 하나와 `requestAnimationFrame` 루프 하나만 사용한다.
4. 카메라는 원근 카메라이고 자유 조작을 제공하지 않는다.
5. 조립, 그릴, 서빙은 같은 배경·손님 레이어 위에서 서로 다른 스테이션 프리셋을 사용한다.
6. 프리셋 전환은 위치와 카메라 목표를 0.25~0.45초 `ease-out`으로 보간하되 게임 상태와 조리 타이머를 중단하지 않는다.
7. `1280×720`, `1920×1080`에서 상단 14%는 DOM UI 안전 영역, 중앙 `x 25~75% / y 18~55%`는 손님 안전 영역, 하단 42%는 활성 작업 영역으로 유지한다.
8. 생성 에셋의 논리 기준 캔버스는 `2048×1152`이며 스테이션·캐릭터 에셋은 문서에 정의된 하단 중앙 앵커를 유지한다.
9. 투명 PNG는 알파 테스트나 일반 알파 블렌딩으로 표시하고 불투명 픽셀의 검은·녹색 테두리가 보이지 않게 한다.
10. 배경과 전경은 포인터 이벤트를 받지 않으며 인터랙티브 오브젝트만 레이캐스트 대상으로 등록한다.
11. 재료·접시처럼 작은 그림의 실제 클릭 영역은 시각 바운드보다 확장해 최소 `44×44 CSS px`를 충족한다.
12. 꼬치는 기존 면별 익힘 시간에서 계산한 값으로 텍스처 또는 `uDoneness`를 갱신한다.
13. 손님 텍스처는 `waiting`, `tasting`, `satisfied`, `neutral`, `retry` 상태 이름으로만 교체하고 게임 로직이 파일 경로를 직접 조합하지 않는다.
14. 모든 필수 에셋은 명시적 manifest에서 로드하고 하나라도 실패하면 빈 캔버스 대신 오류와 다시 시도를 표시한다.
15. 로딩 중과 브라우저 숨김 상태에서는 렌더 루프를 정지하며 재개 시 큰 델타를 한 프레임에 적용하지 않는다.
16. 초기 장면은 외부 URL, API 키와 원격 폰트 없이 로드 가능해야 한다.

## 성능 예산

- 기준 데스크톱 `1280×720`에서 평균 30 FPS 이상을 유지한다.
- 드로우콜은 단일 손님·단일 작업대 장면에서 20 이하를 목표로 하고 30을 넘지 않는다.
- 삼각형은 10,000 이하를 목표로 하고 50,000을 넘지 않는다.
- 실시간 광원은 ambient와 숯불 보조광을 합쳐 2개 이하로 제한한다.
- 연기 쿼드는 6장 이하, 동시 파티클은 80개 이하로 제한한다.
- `devicePixelRatio`는 1.5를 상한으로 한다.
- 초기 장면에 필요한 압축 전송 에셋은 2.5MB 이하, 전체 이번 범위 에셋은 5MB 이하를 목표로 한다.
- 실시간 그림자 맵 대신 접지 그림이 포함된 스프라이트 또는 반투명 쿼드를 사용한다.

## 예외 및 경계 조건

- WebGL2 또는 Three.js 초기화에 실패하면 기존 DOM 기능 화면으로 폴백하거나 지원 불가 오류를 명시한다.
- 에셋 비율이 뷰포트와 다르면 중앙 크롭을 사용하되 손님·작업 안전 영역을 자르지 않는다.
- 스테이션 전환 중 새 전환 요청은 마지막 유효 프리셋 하나로 수렴하고 카메라가 중간 위치에 고정되지 않는다.
- 창 크기 변경 중 선택·드래그 상태가 있다면 논리 상태를 보존하고 새 카메라 기준으로 클릭 영역을 다시 계산한다.

## 비기능 요구사항

- 레이어, 프리셋, 에셋 경로와 앵커는 한 설정 모듈에서 조정 가능해야 한다.
- 렌더러 교체가 상태 전이 테스트를 깨뜨리지 않아야 한다.
- 장면의 텍스트는 DOM으로 제공해 생성 이미지의 오탈자에 의존하지 않는다.
- 에셋 라이선스와 생성 근거는 `app/art/gameplay/ASSET-MANIFEST.md`에 기록한다.

## 완료 기준

- [ ] Three.js 단일 장면에 6개 시각 레이어와 DOM UI가 정의된 순서로 표시된다.
- [ ] 조립·그릴·서빙 전환 중 배경과 손님 정체성이 유지된다.
- [ ] 기존 조립·굽기·서빙 판정과 자동 테스트가 회귀 없이 동작한다.
- [ ] 모든 에셋이 manifest 경로에서 로드되고 실패 상태가 검증된다.
- [ ] 두 기준 뷰포트에서 손님, 주문 UI와 작업 대상이 가려지거나 잘리지 않는다.
- [ ] 드로우콜, 삼각형, DPR과 초기 에셋 예산이 기록된다.
- [ ] 캔버스가 비어 있거나 단색인 상태와 처리되지 않은 콘솔 오류가 없다.
