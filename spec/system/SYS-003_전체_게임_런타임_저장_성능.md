## 목적

모바일·PC 브라우저에서 전체 30일 캠페인을 실행하기 위한 런타임 책임, 상태 경계, 2.5D 렌더링, 저장·복구와 성능 예산을 정의한다. 게임 규칙은 렌더러와 분리하고 영업 중 중단이 억울한 시간 경과나 저장 손상으로 이어지지 않게 한다.

## 범위

### 포함

- 정적 웹 애플리케이션과 Three.js 기반 2.5D 렌더링
- 캠페인·영업일·손님·주문·조리 상태 관리
- 로컬 저장, 체크포인트, 스키마 버전과 손상 복구
- 에셋·콘텐츠 로딩, 오류, 저사양 폴백
- PC·모바일 브라우저 성능 예산과 측정
- 테스트용 시간·난수·상태 관찰 지점

### 제외

- 계정, 백엔드, 클라우드 저장과 원격 API
- PWA 설치, WebView와 앱스토어 패키징
- 원격 라이브 콘텐츠와 실제 분석 이벤트 전송
- 멀티플레이와 서버 권위 상태

## 상세 요구사항

상세 규칙은 플랫폼, 책임 경계, 상태, 시간, 저장, 렌더링과 성능 영역을 함께 적용한다.

## 플랫폼 계약

| 항목 | 목표 |
|---|---|
| 실행 환경 | 모바일·PC 웹 브라우저 |
| 렌더러 | Three.js/WebGL 단일 렌더러 |
| PC | Chrome·Edge, 16:9, `1280x720` 이상 |
| 모바일 | 최신 Android Chrome·iOS Safari, 가로 방향 |
| 기준 성능 | 중급 Android 30 FPS 고정, 데스크톱 60 FPS 목표 |
| 배포 | 정적 파일로 제공 가능, 핵심 흐름에 외부 서비스 불필요 |

최소 브라우저 버전과 기준 기기 모델은 검증 뒤 확정하며, 미확정 상태에서 `최신`만으로 출시 호환성을 주장하지 않는다.

## 책임 경계

1. 게임 규칙은 렌더러·DOM을 import하지 않고 순수 상태와 이벤트로 동작한다.
2. 렌더러는 게임 상태를 그리며 판정·경제 값을 직접 계산하지 않는다.
3. 입력 계층은 포인터 좌표를 활성 스테이션의 논리 좌표로 변환해 게임 규칙에 전달한다.
4. 콘텐츠 값은 `DAT-001`의 검증된 데이터에서 로드하고 코드에 메뉴·날짜별 수치를 중복 정의하지 않는다.
5. 오디오·VFX·애니메이션은 단발 게임 이벤트를 구독하되 상태 전이를 직접 발생시키지 않는다.

## 상태 영역

| 영역 | 최소 상태 |
|---|---|
| 애플리케이션 | 부팅, 로딩, 준비, 실행, 일시정지, 오류 |
| 캠페인 | 현재 날짜·스테이지, 해금, 재화, 운영 경향, 이야기 플래그 |
| 영업일 | 준비, 영업, 마감, 정산, 성장, 완료 |
| 손님·주문 | 좌석·그룹·대기·만족·주문·제공·퇴장 |
| 조리 | 제작물·스테이션·공정·면별 익힘·액체·품질 |
| UI | 활성 화면·스테이션, 선택 대상, 비차단 상태 피드백, 접근성 설정 |

6. 각 입력은 현재 상태에서 허용된 전이 하나만 만든다.
7. 같은 포인터 이벤트가 중복 전달되어도 조립·뒤집기·서빙·구매는 한 번만 처리한다.
8. 애니메이션 종료는 이미 확정된 논리 결과를 표현할 뿐 별도 보상·판정을 만들지 않는다.
9. 영업일 강제 파동과 확률 결과는 시드 가능한 난수 원본을 사용한다.
10. 개발·테스트 모드에서 현재 상태, 타이머, 시드, 주문 연결과 경제 원장을 관찰할 수 있어야 한다.

## 시간과 일시정지

11. 조리·대기·식사·연출 시간은 단조 증가 시간을 기준으로 계산하고 렌더 프레임 수에 의존하지 않는다.
12. 브라우저가 숨겨지거나 포커스를 잃으면 단일 런타임 정지 상태로 진입해 영업 시계, 다음 입장 상한, 주문 전 고민, 대기, 식사, 퇴장, 좌석 정리, 그릴 면별 누적, 뒤집기 공중 시간, 입력 잠금, 액체, 공정 쿨타임, 애니메이션·VFX 시간과 `requestAnimationFrame` 루프를 즉시 멈춘다.
12-1. 정지 진입은 중복 호출에 안전해야 한다. 숨김·포커스 상실·이야기·명시적 일시정지 원인을 각각 보존하고, 모든 원인이 해제되기 전에는 어느 하위 시간축도 재개하지 않는다.
12-2. 정지 진입 순간 활성 포인터와 좌석 정리 홀드를 취소한다. 생맥주 레버는 즉시 놓고 현재 액체량을 보존하며 복귀 뒤 사용자가 다시 누르기 전에는 흐르지 않는다.
13. 복귀 시 중단 경과 시간을 게임 상태에 적용하지 않는다. 절대 시각을 저장한 그릴·애니메이션·입력 잠금은 복귀 시각으로 재기준화하고, 상태 요약을 표시하더라도 그 시간 동안 계속 정지한다.
14. 렌더 프레임이 오래 지연되어도 한 프레임에서 여러 논리 상태를 무조건 건너뛰지 않는다. 탭이 활성 상태였던 일반 프레임 지연과 정지 상태 경과를 구분한다.
15. 이야기 대사와 명시적 일시정지 화면도 같은 단일 정지 계약을 사용하며, 화면별 개별 타이머 정지 구현으로 대체하지 않는다.
15-1. 개발 관찰 지점은 현재 정지 여부, 활성 정지 원인, 렌더 루프 예약 여부와 주요 시간축 스냅샷을 제공해 실제 경과 대기 전후 값이 같은지 검증할 수 있어야 한다.

## 저장과 복구

### 체크포인트

16. 영업일 시작 직전 캠페인 상태를 `day-start` 체크포인트로 자동 저장한다.
17. 정산 보상과 성장 선택이 확정된 뒤 `day-complete` 체크포인트를 자동 저장한다.
18. 영업 중에는 전체 진행을 영구 저장하지 않으며 새로고침·종료 후 `day-start`에서 재개한다.
19. UI·접근성·오디오 설정은 변경 즉시 별도 설정 저장으로 보존한다.

### 저장 데이터

20. 저장 데이터는 스키마 버전, 쓰기 시각, 현재 날짜, 캠페인 상태, 경제 원장 요약, 해금, 직원, 이야기·온보딩·설정을 포함한다. 폐기된 실제 영업 순차 가이드 진행도는 새 저장에 기록하지 않는다.
21. 저장은 임시 키에 완전한 새 데이터를 쓴 뒤 검증하고 활성 키를 교체하는 방식으로 중간 쓰기 손상을 피한다.
22. 정산에는 고유 영업일 완료 식별자를 기록해 새로고침 후 보상을 중복 지급하지 않는다.
23. 저장 로드 시 스키마와 참조 식별자를 검증하고 잘못된 데이터로 게임을 시작하지 않는다.
24. 이전 스키마는 순차 마이그레이션하고 지원할 수 없는 미래 버전은 덮어쓰지 않고 오류를 안내한다.
25. 활성 저장이 손상되면 마지막 검증된 백업을 제안하고 백업도 없으면 새 게임과 진단 정보 보존을 제공한다.

## 2.5D 렌더링

### 장면 계층

| 순서 | 레이어 | 내용 |
|---:|---|---|
| 0 | 배경 | 뒷벽·선반·골목·야간 창의 2D 이미지 |
| 1 | 손님 | 좌석 스프라이트·초상 상태 |
| 2 | 고정 바 카운터 | 상판·주문 매트·손님 가림선·전달 anchor |
| 3 | 스테이션 | 플레이어측 조립대·그릴·드링크·서빙 모듈 |
| 4 | 인터랙티브 | 꼬치·석쇠·잔·도구 등 실제 조작 대상 3D |
| 5 | VFX | 불씨·연기·기름·판정·글로우 |
| 6 | 전경 | 양끝 목재·노렌·등불 프레임 |
| 7 | UI | 주문·경고·탭·텍스트 |

26. 배경과 조작하지 않는 환경·손님은 2D를 기본으로 하고 꼬치·석쇠·맥주잔·도구는 Three.js 오브젝트로 구현한다.
27. 카메라는 바 안쪽 주인공 위치에서 카운터 너머 손님을 바라보는 고정 1인칭 3/4 앵글이며 스테이션별 프리셋만 사용하고 자유 회전·줌을 제공하지 않는다.
28. 프리셋 전환은 바 안쪽의 짧은 좌우 이동 또는 작업대 push-in으로 0.25~0.45초 보간하고, 카운터 선·손님 방향·플레이어측 전후 관계를 보존한 채 배경 계층에 제한된 패럴랙스를 적용할 수 있다.
29. 직접 조작 대상은 스테이션별 `InteractionPlane`의 로컬 2D 좌표를 입력 계약으로 사용한다.
30. 꼬치 셰이더는 앞·뒷면 익힘과 타레 값을 받아 날것→적정→탄 상태의 색·그을음·광택을 연속 표현한다.
31. 맥주 표현은 액체 높이, 거품 경계와 자동 잔 기울기를 시각화하며 물리 시뮬레이션을 필수로 하지 않는다.
32. 장면은 렌더러 하나와 `requestAnimationFrame` 루프 하나만 사용한다.

### 영업 장면 불변식

- 손님과 좌석은 고정 카운터 뒤에 있고 손님의 하체는 카운터 상판에 가려진다.
- 고정 카운터는 모든 영업 스테이션에서 유지되며 주문 매트와 전달 anchor를 소유한다.
- 활성 스테이션과 인터랙티브 오브젝트는 카운터의 플레이어측 하단에만 배치한다.
- 주인공 얼굴·몸은 기본 영업 장면에 렌더하지 않고 승인된 손·도구만 선택적으로 플레이어측 레이어에 표시한다.
- 스테이션 전환은 활성 손님·주문을 제거하거나 카메라를 손님측으로 뒤집지 않는다.

## 성능 예산

### 프레임

- 기준 기기 30 FPS, 프레임 `33ms` 안에서 JS 로직 `8ms 이하`, 렌더 `20ms 이하`, 여유 `5ms 이상`을 목표로 한다.
- 데스크톱은 60 FPS를 목표로 하되 모바일 예산 위반을 허용하는 근거로 사용하지 않는다.

37. LOW 자동 판정은 첫 3초 측정과 기기 정보로 결정하되 FPS 임계값은 미확정이다.

## 로딩·오류·호환성

38. 필수 에셋과 콘텐츠 manifest를 검증한 뒤에만 핵심 입력을 활성화한다.
39. 에셋 실패는 종류와 재시도를 표시하고 늦은 이전 요청이 새 로딩 상태를 덮어쓰지 않게 한다.
40. WebGL 초기화 실패 시 가능한 2D 폴백 또는 지원 불가 안내를 표시하고 빈 캔버스를 남기지 않는다.
41. 핵심 실행에 비밀 키, 원격 폰트와 외부 서비스 가용성을 요구하지 않는다.
42. 실제 분석 이벤트 수집은 별도 동의·개인정보 요구사항이 생기기 전까지 비활성화하고 로컬 개발 기록만 허용한다.

## 예외 및 경계 조건

- 저장 공간 부족 시 현재 활성 저장을 지우지 않고 설정과 진단 가능한 오류를 보여준다.
- 마이그레이션 실패 시 원본 저장을 보존하고 새 형식으로 덮어쓰지 않는다.
- 화면 크기 변경 중 선택·드래그 상태는 마지막 유효 논리 상태로 복구한다.
- 전환 중 새 스테이션 요청은 마지막 요청 하나로 수렴하고 카메라가 중간 상태에 고정되지 않는다.
- LOW 모드에서도 주문, 캐릭터 특징과 위험 신호를 제거하지 않는다.

## 비기능 요구사항

- 로직·렌더·입력·오디오·저장·콘텐츠의 경계를 자동 테스트로 대체 가능해야 한다.
- 저장 데이터와 경제 원장은 결정적 직렬화 형식을 사용한다.
- 성능 측정은 실제 기준 기기, Chrome DevTools, Spector.js와 렌더 통계를 함께 기록한다.
- 코드 배포 없이 시즌 콘텐츠를 추가하는 기능은 미확정이며 현재 정적 번들 계약을 우선한다.
