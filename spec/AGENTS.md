# spec AI 작업 지침

## 목적

`inbox/`에서 채택된 변경사항을 구현 가능한 요구사항 상세 설계로 정제한다. `spec/`은 구현 판단의 기준이며 소스코드를 보관하는 위치가 아니다.

## 갱신 규칙

1. 관련 카테고리와 기존 요구사항을 먼저 검색한다.
2. 기존 요구사항의 변경인지 새 요구사항인지 판단한다.
3. 새 문서는 `v1.0.0`으로 생성하고, 기존 문서는 변경 영향에 따라 주·부·수 버전을 올린다.
4. 요구사항 식별자, 문서 버전, 목적, 범위, 상세 요구사항, 예외, 완료 기준, 의존성, 미해결 질문을 작성한다.
5. 근거가 된 `inbox/` 문서 경로와 SHA-256 지문을 연결한다.
6. 변경 이력에 이전·새 버전, 날짜, 변경 유형, 변경 내용과 영향을 기록한다.
7. 변경된 요구사항 식별자와 정확한 문서 버전을 `epic/` 영향 분석에 전달한다.
8. 처리한 원본과 판단 결과를 `meta/inbox_처리_이력.md`에 기록한다.

새 문서는 `template/spec_요구사항_템플릿.md`를 사용한다.
버전 증가는 `template/spec_epic_문서_버전_관리_지침.md`를 따른다.

## 식별자 규칙

카테고리 코드와 세 자리 순번을 조합한다.

- UI: `UI-001`
- 시나리오: `SCN-001`
- 게임플레이: `GPL-001`
- 시스템: `SYS-001`
- 아트: `ART-001`
- 오디오: `AUD-001`
- 데이터: `DAT-001`
- 품질: `QA-001`

식별자는 문서가 이동하거나 제목이 바뀌어도 재사용하거나 변경하지 않는다.

## 금지 사항

- 구현 언어에 종속된 완성 소스코드 작성
- 실행 가능한 스크립트 또는 운영 설정 추가
- 근거와 변경 이력 없이 요구사항 덮어쓰기
- 기존 문서 내용을 변경하고 버전 또는 변경 이력을 그대로 유지
- 미확정 내용을 확정 요구사항처럼 표현
