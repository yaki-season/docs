## 목적

PC와 모바일 웹에서 한 포인터만으로 준비, 조리, 서빙, 정산과 성장까지 전체 게임을 조작하는 화면·입력 계약을 정의한다. 화면 속 물건을 직접 다루는 감각을 유지하면서 정밀 제스처, 색상과 작은 목표점에 의존하지 않는다.

## 범위

### 포함

- 전체 화면 흐름과 각 화면의 진입·이탈 조건
- 영업 HUD, 스테이션 전환과 화면 밖 경고
- 마우스·터치 공통 입력 문법과 선택형 제스처
- PC 16:9와 모바일 가로 반응형 레이아웃
- 튜토리얼, 접근성, 일시정지·중단 복귀
- 로딩·오류·빈 상태·비활성 상태

### 제외

- 최종 카피라이팅과 번역 문자열
- 세로 모바일 플레이
- 키보드 전용 조작과 게임패드 지원
- 광고·결제 화면의 최종 구성

## 상세 요구사항

상세 규칙은 전체 화면 흐름, 공통 입력 문법, 영업 HUD와 접근성 영역을 함께 적용한다.

## 전체 화면 흐름

```text
첫 실행·불러오기
→ 프롤로그 또는 오늘의 영업 전 화면
→ 메뉴·직원·예약 확인
→ 영업 준비
→ 영업 HUD와 스테이션 화면
→ 마감
→ 정산
→ 레시피 노트·업그레이드
→ 다음 목표
→ 다음 날
```

| 화면 | 핵심 정보 | 주 입력 | 이탈 조건 |
|---|---|---|---|
| 프롤로그 | 가게, 열쇠, 노트, 숯 | 대상 클릭·드래그, 건너뛰기 | D1 준비 완료 |
| 영업 전 | 날짜, 메뉴, 예약, 목표, 직원 | 탭·선택 | 영업 시작 |
| 영업 | 주문, 손님, 위험, 작업 대상 | 클릭·탭, 홀드, 선택형 드래그 | 마감 조건 |
| 정산 | 주문·품질·대기·수익·명성 | 순차 확인, 건너뛰기 | 보상 확정 |
| 성장 | 메뉴·장비·인테리어·직원 | 탭, 구매 확인 | 다음 목표 |
| 레시피 노트 | 복원 상태, 취향, 기록 | 페이지·힌트 선택 | 이전 화면 |
| 설정·일시정지 | 입력·소리·진동·도움 | 토글·슬라이더 | 재개·영업 종료 |

## 공통 입력 문법

| 입력 | 의미 | 사용 |
|---|---|---|
| 클릭·탭 | 선택 또는 현재 상태의 대표 행동 | 재료, 꼬치, 잔, 완성품, 정리 |
| 대상 선택→목적지 선택 | 복수 목적지 중 이동 | 접시·잔 서빙, 위치별 그릴 |
| 누르고 유지 | 손을 떼면 즉시 멈추는 흐름 | 생맥주·거품 |
| 드래그 | 빠른 직접 이동 | 재료·접시·잔, 프롤로그 열쇠 |
| 수평 스와이프 | 방향이 있는 빠른 행동 | 꼬치 뒤집기 선택 입력 |
| 스테이션 탭 | 작업 화면 전환 | 조립·그릴·드링크·카운터 등 |

1. 핵심 캠페인은 hover, 우클릭, 휠, 키보드 조합과 두 손가락 입력을 요구하지 않는다.
2. PC의 클릭·누르기·떼기와 모바일의 탭·홀드·릴리스는 같은 의미와 결과를 가진다.
3. 클릭·탭만으로 모든 핵심 조리와 서빙을 완료할 수 있다.
4. 드래그·스와이프는 속도와 회전 방향만 반영하고 품질 보너스를 주지 않는다.
5. 하나의 활성 포인터만 처리하며 동시 다중 터치를 요구하지 않는다.
6. 입력 우선순위는 `조작 물건→선택 목적지→스테이션 전환→배경 연출` 순서다.
7. 애니메이션 잠금 중 같은 대상의 빠른 반복 입력은 한 번만 처리한다.
8. 빈 영역을 누르면 일반 선택을 취소한다. 모바일에서는 선택된 완성품을 다시 눌러도 취소할 수 있다.

## 입력 크기와 피드백

- PC 최소 클릭 영역은 `44x44 CSS px`, 모바일 최소 터치 영역은 `56x56 CSS px` 상당이다.
- 생맥주 레버의 맥주·거품 영역은 각각 최소 `72x72 CSS px`를 확보한다.
- 탭은 누르고 뗀 위치 차이 `12px` 이하를 잠정 기준으로 하며 실제 기기 검증 뒤 조정한다.
- 드래그 시작은 이동 `8px` 이상, 무입력 길게 누르기 힌트는 `600ms`를 잠정 기준으로 한다.
- 입력 뒤 50ms 안에 들림, 외곽선, 그림자 또는 밝기 중 두 가지 이상으로 반응한다.
- 선택 상태는 대상 `1.05배` 들림, 굵은 외곽선과 목적지 맥동으로 표시한다.
- 손가락 아래 설명을 두지 않고 예상 도착점은 손가락보다 `12~20px` 위에 표시한다.

## 영업 HUD

### 항상 보이는 정보

1. 현재 주문과 주문자 표식.
2. 손님별 대기 상태.
3. 현재 스테이션과 다른 스테이션의 진행 상태.
4. 화면 밖에서 3초 안에 개입할 위험의 방향과 종류.
5. 현재 조리 대상의 면별 진행 또는 잔 내부 맥주·거품 층.
6. 일시정지 진입 수단.

### 상황별 정보

- 조작 중에만 스냅 구간, 빈 그릴 칸, 목적지와 레버 방향을 표시한다.
- 결과 직후에만 공정 판정, 비율, 손님 반응과 원인 하나를 짧게 표시한다.
- 공정 소수점, 큰 콤보 팝업, 중복 확인 버튼과 세 개 이상 동시 도움말은 숨긴다.

### 경고

7. 안전 상태는 중립, 3초 전 경고는 방향 아이콘+주황 계열+경고음, 마지막 1초는 방향 가장자리 점멸+강한 아이콘으로 구분한다.
8. 경고는 레버, 잔, 꼬치와 손님 주문표를 가리지 않는다.
9. 잠정 우선순위는 `조리 실패 임박→손님 이탈 임박→일반 주문`이며 최종 순서는 플레이테스트 뒤 확정한다.
10. 복수 위험은 가장 임박한 하나를 크게, 나머지는 상단 스테이션 탭의 상태 배지로 표시한다.

## 스테이션 레이아웃

11. 상단은 주문·대기·경고 안전 영역, 중앙은 손님과 반응 영역, 하단은 작업 대상과 스테이션 탭 영역으로 사용한다.
12. 카운터 화면은 손님 얼굴 대신 하단에 연결된 큰 주문 매트·칩을 서빙 목적지로 제공한다.
13. 조립은 재료통, 중앙 꼬치, 전달 트레이를 한 시야에 배치한다.
14. 그릴은 대기 트레이, 2~6개 그릴 칸과 완성 접시를 한 시야에 배치한다.
15. 드링크는 빈 잔, 중앙 레버·노즐, 완성 트레이를 한 시야에 배치한다.
16. 스테이션 전환은 `0.25~0.45초`의 고정 프리셋 이동으로 표현하고 자유 카메라는 제공하지 않는다.
17. 전환 중 다음 조작 대상은 이동 완료 후 활성화하되 진행 중 타이머는 멈추지 않는다.

## 반응형과 한 손 모드

18. PC는 `1920x1080`을 중심으로 `1280x720`까지 지원한다.
19. 모바일 브라우저는 가로 방향으로 고정하고 최신 Android Chrome과 iOS Safari를 목표로 한다.
20. PC와 모바일은 같은 정보 우선순위와 입력 의미를 유지하고 단순 축소판으로 만들지 않는다.
21. 모바일의 필수 조작 대상은 선택한 손 쪽 하단 70% 도달 영역에 배치한다.
22. 오른손·왼손 모드는 재료통, 트레이, 잔 선반과 주요 도구 위치를 수평 반전한다.
23. 레버의 아래=맥주, 위=거품 의미와 주문 읽기 방향은 반전하지 않는다.
24. 중요한 대상이 양끝에 있으면 `선택 유지→스테이션 또는 목적지 선택`으로 나누고 긴 드래그를 요구하지 않는다.
25. 이미지 비율이 뷰포트와 다르면 중앙 크롭하되 주문·손님·작업 안전 영역을 자르지 않는다.

## 온보딩과 도움

26. 첫 행동은 손 모양 1회와 한 줄 동사 문구로 안내한다.
27. 같은 행동을 한 번 성공하면 손 모양, 두 번 성공하면 텍스트, 세 번 성공하면 강조를 제거한다.
28. 설정에서 전체 도움말을 다시 켤 수 있다.
29. 튜토리얼 1회 실패는 원인, 2회 실패는 목표와 판정 범위 확대, 3회 실패는 시범·자동 완료 선택을 제공한다.
30. 자동 완료를 사용해도 이야기·메뉴·다음 날짜 진행을 제한하지 않는다.

## 접근성

- 익힘은 색+질감+연기+소리+링 형태 중 최소 두 가지를 사용한다.
- 주문 연결은 색+도형+숫자를 사용한다.
- 맥주 비율은 액체층+잔 각인 선+완성 파동을 사용한다.
- 위험은 색+방향+아이콘+음향을 사용한다.
- 큰 터치 영역 옵션은 꼬치 손잡이와 도구의 유효 영역을 넓힌다.
- 초보 모드는 적정 구간 30~40% 확대, 흐름 감속과 제한된 슬로 모션을 제공할 수 있다.
- 소리 없이도 모든 상태를 이해할 수 있고 진동은 완전히 끌 수 있어야 한다.
- 브라우저 확대와 조리 영역 스크롤 방지의 충돌은 실기기 접근성 검증 대상으로 둔다.

## 예외 및 경계 조건

### 중단·오류·복귀

31. `pointercancel`, 포커스 상실과 화면 밖 이동 시 물건을 마지막 유효 위치로 복구하고 액체 흐름을 멈춘다.
32. 브라우저 백그라운드 진입 시 모든 게임 타이머와 렌더링을 멈춘다.
33. 복귀 시 현재 주문과 위험을 2초 동안 요약하고 요약이 끝날 때까지 타이머를 재개하지 않는다.
34. 필수 에셋 로딩 실패는 빈 화면 대신 실패 종류, 다시 시도와 지원 안내를 표시한다.
35. 구매·정산·저장 처리 중 중복 입력은 한 번의 결과만 만든다.

## 비기능 요구사항

- 의미 텍스트는 생성 이미지에 굽지 않고 접근 가능한 DOM 또는 동등한 UI 계층으로 제공한다.
- 중요 텍스트·아이콘은 배경과 충분한 대비를 확보한다.
- 레이아웃 변화로 조작 대상과 텍스트가 겹치거나 화면 밖으로 밀려나지 않아야 한다.
- 영업 중 긴 설명 모달과 전체 화면 점수 연출로 플레이 리듬을 끊지 않는다.

## 완료 기준

- [ ] 마우스와 한 손가락 각각으로 준비부터 정산까지 핵심 흐름을 완료한다.
- [ ] 모든 필수 대상이 플랫폼별 최소 입력 크기를 충족한다.
- [ ] PC 두 기준 해상도와 모바일 가로 화면에서 HUD·손님·작업 영역이 겹치지 않는다.
- [ ] 복수 위험이 정의된 우선순위와 비색상 신호로 전달된다.
- [ ] 왼손 모드, 큰 터치 영역, 무음과 초보 보조에서도 진행이 가능하다.
- [ ] 백그라운드·포인터 취소·중복 입력이 상태 손상을 만들지 않는다.
- [ ] 튜토리얼 안내가 성공 횟수에 따라 줄고 설정에서 복원된다.
