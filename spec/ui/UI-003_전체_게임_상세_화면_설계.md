## 목적

기획의 애플리케이션·영업일·이야기·조리 상태를 실제 런타임 화면과 일대일로 연결한다. 콘셉트아트 한 장에 여러 상태가 합쳐져 화면 수, 진입 조건과 UI 계층이 모호해지는 문제를 해소하고, 개발자는 `screenId`와 `overlayId`로 화면을 구현하며 Artist는 `componentId`와 분리 묶음으로 런타임 에셋을 제작할 수 있게 한다.

## 범위

### 포함

- 부팅부터 D31 진입까지 사용하는 화면·오버레이 식별자
- 화면별 목적, 진입·이탈 조건, 시간 정지, 저장 시점과 입력 잠금
- `1920×1080 FHD` 기준 공통 레이아웃과 서비스 화면 안전 영역
- 시스템·스토리·영업 전·영업·마감·정산·성장 화면의 필수 구성요소
- 로딩·빈 상태·잠금·오류·중단 복귀 상태
- 기존 콘셉트 마스터와 런타임 화면의 일대다 대응
- 향후 에셋 분리를 위한 구성요소 ID와 분리 묶음

### 제외

- 최종 문구, 번역 문자열과 서체 라이선스
- 세로 모바일 전용 레이아웃
- 키보드 전용 조작과 게임패드
- 후반 후보인 사시미·플레이팅의 세부 판정 수치
- 실제 UI·렌더러·상태 머신 구현
- 런타임 이미지·GLB·atlas의 직접 제작

## 정본 관계와 화면 분리 원칙

1. `UI-002`는 입력·HUD·접근성의 상위 계약이고, 이 문서는 실제 화면 ID·화면 내부 구성·전환의 상세 정본이다.
2. `SYS-003`의 애플리케이션·영업일 상태와 `GPL-002`의 날짜 흐름을 먼저 화면 상태로 나눈 뒤, 각 화면 안에 `GPL-003~005`와 `SCN-002`의 구성요소를 배치한다.
3. 콘셉트 마스터는 톤, 구도, 재료감과 구성요소의 시각 참고다. 마스터의 장수·패널 분할·이미지 안 문구로 런타임 화면 수와 전환을 추론하지 않는다.
4. 한 런타임 화면은 하나의 주목적만 가진다. 이야기, 영업 브리핑, 조리, 정산, 구매, 노트와 다음 목표를 같은 주화면에 동시에 펼치지 않는다.
5. `screenId`는 주화면, `overlayId`는 현재 주화면과 논리 상태를 보존한 채 위에 쌓이는 계층, `phaseId`는 같은 주화면 안에서 순차 공개되는 단계다.
6. 의미 텍스트·가격·수치·실시간 게이지·focus·상태 이름은 DOM 또는 동등한 접근성 UI 계층에서 제공한다. 생성 이미지에 굽지 않는다.
7. 상위 gameplay 수치가 `candidate` 또는 후반 후보면 이 문서도 같은 상태를 상속한다. 화면 위치가 확정됐다고 후보 콘텐츠 자체가 확정되는 것은 아니다.

### 기존 합성 오류와 교정

| 합쳐져 있던 단위 | 상세 화면 정본 |
|---|---|
| 프롤로그 한 장 | `SCR-STORY-PROLOGUE`의 열쇠 선택·대문 열기 2개 무실패 phase(점화는 직접 조작 없이 `SCR-STORY-BEAT` 대사로 처리) |
| 영업 전 한 장 | `SCR-STORY-BEAT` → `SCR-DAY-BRIEFING` → `SCR-DAY-PREP` |
| 정산 한 장 | `SCR-POST-CLOSING`과 `SCR-POST-SETTLEMENT` 5개 phase 분리 |
| 성장·구매 한 장 | `SCR-META-PURCHASE`와 `SCR-POST-REVIEW` 분리 |
| 레시피 노트·다음 목표 한 장 | `SCR-META-NOTE`와 `SCR-POST-NEXT-GOAL` 분리 |
| 일시정지·설정 한 장 | `OVR-PAUSE` 위에서 `OVR-SETTINGS`를 별도 계층으로 호출 |
| 오류·복귀가 없는 정상 장면 | `SCR-SYS-RECOVERY`, `OVR-RETURN-SUMMARY`를 독립 상태로 추가 |

## 전체 화면 구조

```text
SCR-SYS-BOOT
└─ SCR-SYS-START
   ├─ 새 게임 → SCR-STORY-PROLOGUE
   └─ 이어하기 → SCR-STORY-BEAT 또는 SCR-DAY-BRIEFING

SCR-STORY-PROLOGUE 또는 SCR-STORY-BEAT
→ SCR-DAY-BRIEFING
→ SCR-DAY-PREP
→ SCR-SVC-CUSTOMERS ↔ 조립 ↔ 그릴 ↔ 드링크 ↔ 해금 스테이션
→ SCR-POST-CLOSING
→ SCR-POST-SETTLEMENT
→ OVR-UNLOCK / SCR-STORY-BEAT
→ SCR-POST-REVIEW
   ├─ SCR-META-PURCHASE
   ├─ SCR-META-NOTE
   └─ SCR-POST-NEXT-GOAL
→ SCR-POST-DAY-COMPLETE
→ 다음 날 SCR-STORY-BEAT 또는 SCR-DAY-BRIEFING
```

`SCR-SYS-RECOVERY`는 부팅·저장·에셋·WebGL 오류가 발생한 화면에서 진입한다. `SCR-SYS-ONBOARDING`은 시작·설정·일시정지의 `조작 설명`에서 별도 화면으로 열며 실제 영업 상태를 조작하지 않는다. `OVR-PAUSE`, `OVR-SETTINGS`, `OVR-RETURN-SUMMARY`, `OVR-STORY-DIALOGUE`, `OVR-SERVE-QUANTITY`, `OVR-UNLOCK`, `OVR-CONFIRM`은 허용된 주화면 위에만 쌓인다.

## 공통 레이아웃 계약

### 논리 좌표

- 기준 캔버스는 `1920×1080`이고 중앙 `contain` 방식으로 축소한다.
- FHD 안전 프레임은 `x=64~1856`, `y=40~1040`이다. 필수 텍스트·입력·상태 표식은 이 안에 둔다.
- `1280×720`에서는 전체 논리 좌표를 `2/3`로 축소하고 정보 순서나 화면 분리를 바꾸지 않는다.
- 비율이 다른 데스크톱 뷰포트는 좌우 또는 상하 여백을 허용한다. 필수 요소를 채우기 위해 scene을 임의 확대 크롭하지 않는다.
- 서체, 숫자, 게이지, focus ring과 도움말은 래스터 source의 해상도와 무관하게 선명한 UI 계층으로 그린다.

### 일반 화면 프레임

| 영역 | FHD 논리 범위 | 용도 |
|---|---|---|
| `globalTop` | `x=64~1856`, `y=40~112` | 뒤로, 날짜·재화, 설정·일시정지 |
| `primaryContent` | `x=128~1792`, `y=128~920` | 화면의 단일 주목적 |
| `primaryAction` | `x=128~1792`, `y=936~1040` | 이전·계속·영업 시작 등 |
| `toastLayer` | `x=1392~1856`, `y=128~360` | 비차단 결과 최대 3개 |

### 공통 구성요소와 에셋 경계

| 구성요소 class | 내용 | 분리 묶음 | 구현 경계 |
|---|---|---|---|
| `scene.background` | 골목·뒷벽·창·선반 | `background` | 비상호작용 래스터 |
| `scene.architecture` | 카운터·좌석·작업면·station body | `architecture` | anchor metadata 포함 |
| `scene.actor` | 손님·직원·이야기 인물 | `actors` | 좌석은 `seatHipAnchor`, 이야기는 장면별 `focusAnchor` |
| `scene.interactable` | 음식·잔·꼬치·도구·노트 | `interactables` | 논리 hit zone과 시각 bounds 분리 |
| `scene.state` | 잠금·예약·정리·품질·자동화 | `state-overlays` | 텍스트 없는 상태 에셋 |
| `scene.vfx` | 불씨·연기·거품·판정 | `vfx` | 논리 결과와 별도 clip |
| `scene.foreground` | 가림선·전경 목재·dim veil | `foreground` | 입력 차단 여부 metadata |
| `ui.frame` | 종이·목재 frame·도장·의미 icon | `ui-art` | 문구·수치 제외 |
| `ui.semantic` | 문구·수치·게이지·focus·상태 이름 | 없음 | DOM 또는 동등 접근성 계층 |

각 분리 에셋은 최소 `componentOwner`, `screenIds`, `sourceMasterId`, `anchor`, `pivot`, `boundsFhd`, `stateVariant`, `styleProfile`을 metadata에 기록한다. 같은 에셋을 여러 화면에서 사용하면 `screenIds`에 모든 사용 화면을 기록하고 중복 파일을 만들지 않는다.

## 상세 화면 설계

### `SCR-SYS-BOOT` 부팅·로딩

- 진입: 앱 실행, 새로고침, 다음 날 pack 전환.
- 이탈: manifest·저장·콘텐츠·필수 렌더러 검증 성공 시 `SCR-SYS-START` 또는 지정 복귀 화면. 실패 시 `SCR-SYS-RECOVERY`.
- 입력: 로딩 중 핵심 입력 잠금. 보조기술에는 현재 단계와 진행 상태를 알린다.

### `SCR-STORY-BEAT` 영업 전·정산 후 이야기

- 진입: 날짜별 story flag가 있고 영업 전 또는 정산 후 허용 지점에 도달.
- 이탈: 모든 대사 확인 또는 스킵 요약 확인.
- 조리 장면을 동시에 노출하지 않는다. `storyBeat`마다 장소·시간·행동·감정을 담은 완성 일러스트를 사용하며, 두 인물 장면은 현재 발화자와 대화 상대를 같은 공간 안에 둔다.
- 일반 배경 위에 작은 대화 초상이나 독립 전신 컷아웃을 얹는 구성을 사용하지 않는다.
- 같은 `storyBeat`에서는 대사마다 이미지를 교체하지 않고 화자 강조만 전환한다. 말하는 인물은 크기 `103%`, 밝기·채도 `100%`; 듣는 인물은 크기 `97%`, 밝기 `72%`, 채도 `90%`를 초기 공통값으로 사용하며 전환 시간은 `160~220ms`다.

| `componentId` | 구성요소 | 계약 |
|---|---|---|
| `story.scene` | `storyBeat` 완성 장면·배경 레이어 | 장소·시간·행동·감정과 성장 상태를 함께 표현 |
| `story.actors` | 같은 완성 장면에서 분리한 인물 레이어 | 안쪽 3/4 시선, 장면별 `focusAnchor`, 독립 초상 재사용 금지 |

### `SCR-POST-DAY-COMPLETE` 저장·다음 날

## 온보딩 상세 설계

### `SCR-SYS-ONBOARDING`

- `onboarding.station=customers|assembly|grill|drink`와 화면별 `stepIndex`를 가진다. 후속 해금 스테이션은 실제 도입 시 같은 계약에 추가한다.
- 실제 게임 화면을 직접 실행하거나 그 위에 오버레이하지 않는다. 배경은 해당 주화면의 축약 모형 또는 정지 예시를 사용하고 설명 대상만 선명하게 강조한다.
- 대상처럼 보이는 버튼·메뉴는 설명 단계 이동과 시범 재생만 수행한다. 손님·주문·조리 타이머·재고·품질·보상·캠페인·저장 상태를 생성하거나 변경하지 않는다.
- 한 단계에는 핵심 동작 하나, 짧은 제목, 이유, 입력 방법, 색 외 번호·테두리·형태 강조만 둔다. 실제 플레이 성공이나 정확한 시간 입력을 완료 조건으로 삼지 않는다.
- 공통 이동은 `이전`, `다음`, `목차`, `나가기`이며 키보드 focus 순서와 현재 단계/전체 단계 수를 제공한다. 나가면 진입 전 시작·설정·일시정지 화면으로 돌아간다.
- 그릴 단계는 대기 카드→첫 빈 칸 배치→배치 즉시 독립 조리→개별 뒤집기→개별 회수→품질별 완성 목록 순으로 설명한다. 두 꼬치 동시 배치·동시 타이머 시작은 설명하지 않는다.
- 이 화면군은 설계만 확정한다. 현행 인게임 가이드의 제거·대체, 목차, 시범과 진입 동선은 현재 코드 변경 범위 밖의 후속 개발이다.

## 오버레이 상세 설계

### `OVR-STORY-DIALOGUE`

- 영업 중 이야기는 한 말풍선 두 줄 이내다.
- 주문·위험 경고와 겹치면 큐에 두고 안전한 때 연다. 열린 동안 영업 시계와 위험 타이머를 멈춘다.
- 발화자 이름, 본문, 다음/닫기만 표시하고 장시간 portrait cutscene으로 바꾸지 않는다.

### `OVR-SERVE-QUANTITY`

- 대상 좌석의 접시 anchor에 붙이고 `1개만 제공`, `다 주기`, 취소를 같은 깊이에 둔다.
- 선택 전에는 공용 수량·주문·대기·품질을 바꾸지 않는다.
- 상자 밖 클릭, 취소, 대상 이탈은 모두 무변경 복귀다.
- 열린 동안 해당 손님은 홀 담당 자동 서빙 후보에서만 제외하고 다른 타이머는 계속 흐른다.

### `OVR-PAUSE`

- 현재 화면 snapshot을 dim 처리하되 주문과 위험 상태를 완전히 가리지 않는 요약을 panel 안에 다시 표시한다.
- 행동은 `재개`, `도움`, `설정`, `영업 종료`다.
- 영업 종료는 `OVR-CONFIRM`에서 현재 영업 진행이 저장되지 않고 day-start에서 다시 시작됨을 알린 뒤 시작 화면으로 이동한다.

### `OVR-SETTINGS`

| category | 항목 |
|---|---|
| 입력 | 단일 포인터 안내, 큰 조작 영역 |
| 소리 | 전체·효과·음악, 무음 상태 |
| 진동 | 켜기/끄기 |
| 도움 | 화면별 온보딩 목차 열기, 설명 진행도 초기화 |
| 초보 보조 | 적정 구간 확대·흐름 감속·임박 슬로 모션·시범 허용 |
| 시각 | 대비, 비색상 표식 preview |

- 설정은 변경 즉시 별도 저장한다.
- 일시정지에서 열었으면 닫을 때 `OVR-PAUSE`, 시작 화면에서 열었으면 `SCR-SYS-START`로 돌아간다.
- `OVR-PAUSE`와 같은 panel로 합치지 않는다.

### `OVR-RETURN-SUMMARY`

- 브라우저 background·포커스 상실에서 돌아오면 2초간 표시한다.
- 현재 station, 미완료 주문 수, 가장 가까운 손님 이탈, 위험 조리 대상과 남은 상태를 요약한다.
- 2초가 끝나기 전 영업 시계·손님·조리·부채 cooldown·액체를 재개하지 않는다.

### `OVR-UNLOCK`

- 유형은 메뉴, station, 직원, 레시피 page, 도구다.
- 이름, 해금 이유, 실제 사용 가능 시점과 다음 행동을 표시한다.
- 해금 이벤트가 구매 item을 열었어도 여기서 비용을 소비하거나 소유 상태를 바꾸지 않는다. 구매는 `SCR-META-PURCHASE`에서만 한다.

### `OVR-CONFIRM`

- 구매, 영업 종료, 기존 저장이 있는 새 게임에만 사용한다.
- 제목, 결과 한 줄, 확정, 취소만 제공한다. 위험한 행동은 취소에 기본 focus를 둔다.
- 중복 입력과 애니메이션 종료는 하나의 commit만 만든다.

## 오버레이 우선순위와 중첩

높은 순서부터 `시스템 복구 > 확인 > 설정 > 일시정지 > 복귀 요약 > 대사 > 제공 수량 > 비차단 toast`다. 온보딩은 overlay stack에 들어가지 않는 별도 주화면이다.

1. `OVR-SETTINGS`는 `OVR-PAUSE` 위에만 한 단계 중첩할 수 있다.
2. `OVR-CONFIRM`은 구매·pause·start에서 한 단계 중첩할 수 있다.
3. 영업 중 대사는 위험 상태와 겹치면 큐에 두며, 온보딩은 영업과 분리되어 대사 overlay와 중첩되지 않는다.
4. 제공 수량 상자가 열린 상태에서 pause하면 수량 선택을 무변경 취소한 뒤 pause를 연다.
5. 시스템 복구 화면에서는 일반 overlay stack을 폐기하고 복구에 필요한 확인만 새로 연다.

## 상태별 공통 표시

| 상태 | 표시 계약 |
|---|---|
| `loading` | 기존 화면을 지우지 않고 대상 영역 skeleton·진행 상태. 핵심 입력 잠금 |
| `empty` | `없음`의 이유와 다음 가능한 행동. 빈 panel만 남기지 않음 |
| `locked` | 구매 카탈로그에서는 조건 표시, 영업 퀵 전환에서는 항목 자체를 숨김 |
| `disabled` | 원인 1줄과 비색상 형태. 클릭해도 상태 변화 없음 |
| `selected` | 1.05배 들림, 굵은 외곽선, 목적지 맥동 |
| `processing` | 구매·정산·저장의 commit 잠금과 진행 표시 |
| `success` | 변화 전·변화량·변화 후 또는 다음 상태를 짧게 표시 |
| `error` | 마지막 정상 상태 보존, 원인·재시도·복구 경로 |
| `focus` | 배경과 구분되는 2px 이상 외곽선, 색만으로 표현하지 않음 |

## 예외 및 경계 조건

- 저장이 없으면 시작 화면의 이어하기는 비활성화하고 빈 저장을 오류로 취급하지 않는다.
- 손상 저장·미래 스키마·저장 공간 부족은 원본을 덮어쓰지 않는다.
- 필수 에셋 또는 WebGL 실패 시 빈 캔버스를 남기지 않고 복구 화면을 표시한다.
- 예약·직원·해금 구매 item이 없으면 해당 영역에 명시적 빈 상태를 표시한다.
- 조리 주문서 6장까지는 스크롤·축약하지 않는다. 6석 초과 확장은 별도 화면 계약 확정 전 P0에 노출하지 않는다.
- 잠긴 station은 영업 퀵 전환·좌우 이동에서 보이지도 열리지도 않는다.
- `pointercancel`, 화면 밖 이동, focus 상실은 드래그 대상을 마지막 유효 위치로 복구하고 액체·정리 hold를 중단한다.
- 화면 전환 중 새 요청은 마지막 요청 하나로 수렴한다.
- 정산·구매·저장·영업 시작의 빠른 반복 입력은 하나의 commit만 만든다.
- 정산 중 중단되면 마지막 완료 체크포인트를 사용하고 같은 영업일 보상을 중복 지급하지 않는다.
- 후반 후보 station은 ID만 예약하며 콘텐츠·에셋이 확정되기 전 잠금 card나 teaser를 영업 화면에 노출하지 않는다.

## 비기능 요구사항

- `1920×1080`, `1280×720` Chrome에서 필수 UI가 겹치거나 안전 프레임 밖으로 나가지 않아야 한다.
- PC 클릭 영역은 최소 `44×44 CSS px`를 지킨다.
- 입력 뒤 `50ms` 안에 들림·외곽선·그림자·밝기 중 두 가지 이상으로 반응한다.
- 화면 ID, overlay stack, phase와 현재 focus를 자동 테스트에서 관찰할 수 있어야 한다.
- 화면 전환 애니메이션은 논리 결과를 만들지 않고 이미 확정된 상태만 표현한다.
- 소리 없이 모든 상태를 읽을 수 있고 위험·품질·잠금은 색 외 신호를 가진다.
- LOW 모드에서도 주문, 손님 특징, 직접 조작 대상과 위험 신호를 제거하지 않는다.
- 콘셉트 마스터 원본을 runtime manifest에 직접 등록하지 않는다.
