## 목적

PC 웹에서 플레이어가 바 안쪽의 주인공 시점으로 카운터 너머 손님을 계속 바라보며, 마우스 클릭만으로 야키토리를 조립, 굽기, 서빙할 수 있어야 한다.

## 범위

### 포함

- 주문, 조립, 그릴, 카운터의 최소 화면 구성
- 마우스 클릭 기반의 단일 입력 의미
- 대상 선택, 자동 이동, 상태 피드백과 오입력 차단
- PC 가로 화면의 작업 영역과 최소 클릭 영역
- 공정 전환 중 유지되는 2.5D 가게 배경과 단일 손님 좌석
- 플레이어측 작업 공간과 손님측 좌석을 나누는 고정 바 카운터
- 접시 전달, 맛보기와 품질별 손님 반응 연출

### 제외

- 드래그·스와이프 전용 기능과 품질 보너스
- 키보드 단축키, 우클릭, 마우스 휠과 hover 필수 기능
- 모바일 브라우저, 터치 입력, 한 손 조작과 모바일 뷰포트 대응
- 설정 화면, 접근성 옵션 화면과 왼손 전용 레이아웃 전환 UI
- 스테이지 HUD, 시간 제한, 점수, 재화, 평판과 다중 주문 큐
- 생맥주 UI와 다른 메뉴의 조작 UI

## 화면 구조

### 영업 기본 화면 공간 계약

| 화면 영역 | 공간·시점 계약 |
|---|---|
| 카메라 | 바 안쪽 주인공 위치에서 카운터 너머 손님을 바라보는 고정 1인칭 3/4 시점. 영업 중 주인공 얼굴·몸은 화면에 등장하지 않고 승인된 경우에만 손·도구 일부를 하단에 표시한다. |
| 상단 | 주문표, 상태 문구와 경고를 두며 손님 얼굴과 겹치지 않는다. |
| 중앙 중경 | 손님이 플레이어를 향해 앉아 있고 카운터 상판 뒤로 하체가 가려진다. 빈 좌석은 손님측 등받이·좌석 앵커로만 보인다. |
| 중앙 경계 | 고정 바 카운터 상판, 주문 매트와 전달 지점이 손님측과 플레이어측을 끊김 없이 나눈다. |
| 하단 전경 | 플레이어가 다루는 조립대·그릴·서빙 트레이와 조작물이 표시된다. 스테이션 전환은 이 영역을 교체하거나 짧게 이동한다. |

플레이어 앞에 완전한 손님용 스툴이 놓이거나, 손님과 고정 카운터가 사라진 빈 방에 독립 작업대만 나타나는 구도는 허용하지 않는다.

1. 화면 상단에는 현재 주문표와 짧은 상태 문구만 표시한다.
2. 중앙 작업 영역은 현재 공정에 따라 `조립`, `그릴`, `카운터` 중 하나를 표시한다.
3. 하단에는 세 공정의 탭을 표시하되, 다음 공정은 선행 공정이 끝날 때까지 비활성 상태로 보인다.
4. 공정 완료 시 다음 탭을 활성화하고 0.3~0.6초의 이동 연출 뒤 자동 전환한다.
5. 이미 완료한 공정 탭은 상태 확인용으로 다시 열 수 있지만 완료 상태를 되돌리지는 않는다.
6. 공정 전환은 서로 다른 페이지처럼 배경 전체를 교체하지 않고 같은 가게·같은 손님·같은 바 카운터 위에서 플레이어측 작업대와 카메라 프리셋만 전환한다.
7. 손님은 고정 카운터 너머 중앙 중경에 계속 표시하고 활성 작업대는 카운터 앞 하단 작업 영역에서 가장 높은 시각 우선순위를 갖는다.
8. 주문 UI는 상단 안전 영역, 손님은 중앙 안전 영역, 활성 작업대와 조작 대상은 하단 안전 영역을 사용한다.

## 상세 요구사항

1. `click`을 모든 핵심 공정의 대표 입력으로 사용한다.
2. 최소 기능은 클릭만으로 완료되어야 하고 드래그, 스와이프, 길게 누르기나 복합 입력을 요구하지 않는다.
3. 상호작용 대상은 포인터를 누르는 순간 `들림`, 외곽선 또는 밝기 변화 중 두 가지 이상으로 즉시 반응한다.
4. 실제 그림이 작더라도 클릭 영역은 최소 `44×44 CSS px`를 확보한다.
5. 겹친 클릭 영역에서는 현재 공정의 핵심 대상이 장식, 배경과 공정 탭보다 높은 입력 우선순위를 갖는다.
6. 조립 화면은 좌우 또는 하단에 닭다리살과 대파 재료통, 중앙에 빈 꼬치, 상단에 주문 순서, 한쪽에 전달 위치를 배치한다.
7. 재료를 클릭하면 재료가 `들림→꼬치로 짧게 이동→0.12~0.18초 멈춤→관통` 순서로 애니메이션된다.
8. 잘못된 재료는 이동하지 않고 재료통과 주문표의 올바른 다음 칸을 0.3초 동안 서로 다른 형태로 강조한다.
9. 그릴 화면은 대기 꼬치, 그릴 1칸, 접시 1개와 현재 면의 익힘 정보를 표시한다.
10. 그릴 위 꼬치 클릭의 의미는 현재 상태에 따라 `뒤집기`, `접시 회수` 중 하나로 결정하며 동시에 두 선택지를 표시하지 않는다.
11. 익힘 상태는 음식 색만으로 전달하지 않고 표면 변화, 연기 세기, 지글거림 또는 형태가 다른 진행 링 중 두 가지 이상을 함께 사용한다.
12. 적정 구간 진입 시 큰 팝업 대신 꼬치 손잡이 링 맞물림, 짧은 윤기와 높은 `치익` 중 구현 가능한 피드백을 조합한다.
13. 너무 이른 클릭은 입력이 무시되었다는 사실과 `조금 더 굽기` 원인을 1초 이내의 비차단 피드백으로 표시한다.
14. 접시 위 꼬치를 클릭하면 접시를 선택 상태로 띄우고 손님 주문 매트를 목적지로 강조한다.
15. 접시 선택 뒤 손님 주문 매트를 클릭하면 접시가 플레이어측 작업대에서 고정 카운터를 가로질러 손님 앞으로 이동하며, 이동 완료 뒤 손님 반응을 표시한다.
16. 선택 상태에서 빈 영역을 클릭하면 선택을 취소한다. 다른 조작 대상을 클릭하면 기존 선택을 해제하고 새 입력을 처리한다.
17. 애니메이션 진행 중 같은 대상의 연속 입력은 잠그되 화면 전체 입력을 차단하지 않는다.
18. 화면 안내 문구는 한 번에 한 줄과 한 가지 행동만 안내한다.
19. 첫 화면은 인트로 없이 츠키오카의 착석·대기 상태와 네기마 주문을 즉시 표시한다.
20. 스테이션 전환은 0.25~0.45초 동안 이동하고, 이동 중인 다음 조작 대상은 전환이 끝난 뒤 활성화한다.
21. 츠키오카의 머리, 주문 UI와 작업 대상은 모든 공정에서 서로 겹치지 않는다.
22. 접시 서빙 이동은 작업대에서 주문 매트까지 연속 경로를 보여 주며 중간에 화면 밖으로 사라지지 않는다.
23. 접시 도착 뒤 `tasting` 반응을 먼저 표시하고 품질에 따라 `satisfied` 또는 `neutral`로 전환한다.
24. 탄 실패는 접시 전달 연출을 재생하지 않고 `retry` 반응과 재조리 안내를 표시한다.
25. 결과 패널은 화면 하단 또는 측면에 두어 손님 얼굴, 접시와 반응 자세를 가리지 않는다.
26. 손님 반응은 눈·입·고개 또는 손 자세 중 두 가지 이상이 달라져 정지 화면에서도 구분되어야 한다.
27. 카메라 이동, 접시 이동과 반응 애니메이션은 상태를 중복 전이시키지 않는 표현 계층으로 구현한다.
28. 이미지에 메뉴명·안내·판정 문구를 굽지 않고 모든 의미 텍스트를 DOM으로 표시한다.

## 데스크톱 화면 요구사항

- 기준 검증 뷰포트는 `1280×720`과 `1920×1080`이다.
- 지원 범위 안에서 주문표, 작업 대상과 공정 선택 항목의 상대적 위치를 유지한다.
- 손님 얼굴을 직접 클릭해야만 서빙되는 구조를 피하고 카운터에 큰 주문 매트를 제공한다.
- 중앙 크롭과 스테이션 전환 뒤에도 고정 카운터의 좌우 연결, 손님의 정면 방향과 플레이어측 작업대의 앞뒤 관계를 유지한다.
- 조리 영역의 기본 이미지 끌기와 텍스트 선택이 클릭 조작을 방해하지 않아야 한다.
- 마우스 버튼을 누른 채 창 밖으로 이동하거나 창 포커스를 잃으면 진행 중 선택을 마지막 유효 상태로 복구한다.
- `1280×720`에서 상단 14%, 중앙 손님 영역과 하단 작업 영역이 겹치지 않아야 한다.
- `1920×1080`에서 배경이 과도하게 확대되거나 조작 대상이 양끝으로 흩어지지 않게 중앙 콘텐츠 폭을 제한한다.

## 예외 및 경계 조건

- 비활성 공정 탭, 장식용 재료와 배경 클릭은 진행 상태를 바꾸지 않는다.
- 애니메이션 중 화면 크기가 바뀌면 최종 대상 위치를 새 레이아웃 기준으로 다시 계산한다.
- 지원 뷰포트 범위에서 주문표, 작업 대상과 하단 공정 선택 항목이 서로 겹치지 않아야 한다.
- 이미지나 셰이더 로딩 실패 시 빈 화면 대신 실패 메시지와 다시 시도 명령을 표시한다.
- 탭 전환이나 브라우저 백그라운드 진입 중에는 조리 입력을 받지 않는다.

## 비기능 요구사항

- 포인터 입력 후 첫 시각 반응은 일반적인 로컬 환경에서 다음 프레임 안에 시작해야 한다.
- 텍스트와 중요 아이콘은 배경 대비를 확보하고 음식 상태를 색상 하나로만 구분하지 않는다.
- 레이아웃 변경으로 버튼, 탭과 작업 대상의 클릭 영역이 화면 밖으로 밀려나지 않아야 한다.
- 입력 가능한 대상은 개발자 도구 없이 시각적으로 구별 가능해야 한다.

## 완료 기준

- [ ] 마우스 클릭만으로 주문 확인부터 서빙까지 완료할 수 있다.
- [ ] 조립, 그릴과 카운터 화면의 진입·이탈 조건이 선행 상태와 일치한다.
- [ ] 모든 필수 클릭 대상이 정의된 최소 크기를 충족한다.
- [ ] 선택, 비활성, 오류, 적정 굽기와 완료 상태가 서로 시각적으로 구분된다.
- [ ] 두 데스크톱 검증 뷰포트에서 UI와 작업 대상이 겹치거나 잘리지 않는다.
- [ ] 빠른 연속 클릭과 창 포커스 이탈이 중복 조립·뒤집기·서빙을 만들지 않는다.
- [ ] 같은 배경과 같은 츠키오카를 유지한 채 조립·그릴·서빙 프리셋이 전환된다.
- [ ] 모든 공정에서 바 안쪽 주인공 시점, 카운터 너머 츠키오카와 하단 플레이어 작업 영역의 앞뒤 관계가 유지된다.
- [ ] 접시 도착 뒤 맛보기와 좋은·낮은 품질 반응이 정의된 순서로 표시된다.
- [ ] 결과 UI가 손님 얼굴과 반응을 가리지 않는다.
- [ ] 생성 이미지의 문자 오류 없이 모든 주문·안내·결과 텍스트가 DOM으로 표시된다.
