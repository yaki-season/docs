# spec

게임 개발에 필요한 요구사항 정의서를 카테고리별 디렉토리 하위에 작성한다.

## 프로젝트 구조와 현재 기준

- `docs/`는 `inbox` 원본, `spec` 요구사항, 템플릿과 작업 계획을 관리하는 독립 Git 저장소다.
- `app/`은 소스코드, 테스트, 에셋 연동과 실행 결과를 관리하는 독립 Git 저장소다.
- 작업공간 루트는 Git 저장소가 아니며 `docs/.git`, `app/.git`이 각각 존재한다.
- 현재 `app/sources/`는 WebGL2 익힘 셰이더 스파이크이고, `app/art/gameplay/`는 첫 네기마 수직 슬라이스용 에셋이다. 전체 게임 구현 완료 상태가 아니다.
- `*-001` 문서군은 현재 첫 손님 네기마 수직 슬라이스의 확정 기준이다.
- `GPL-002~005`, `UI-002`, `SCN-002`, `SYS-003`, `DAT-001`, `ART-002`, `AUD-001`, `QA-002`는 현재 `inbox` 전체를 정제한 30일 캠페인 목표 사양이다.

전체 게임 기획 문서군은 `v1.0.0`, `초안`이며 개발자 인계 카탈로그 계약이 추가된 `ART-003`은 `v1.1.0`이다. `SYS-004`와 `ART-003`은 기획을 구현 가능한 프로젝트 구조와 에셋 생산 단위로 구체화한다. `inbox`에서 합의되지 않은 가격, 시간, 확률, 브라우저 버전, 정책과 인물 설정은 미해결 질문 또는 제작 차단 항목으로 남겼다.

## 원본 해석 우선순위

1. 확정 표기가 있는 `YAKI SEASON 게임 기획서.md`의 브랜드·플랫폼·핵심 루프를 우선한다.
2. 더 구체적인 최신 UX·시나리오·캐릭터 텍스트가 같은 주제의 초기 표현을 보완한다.
3. 콘셉트 이미지는 배치·분위기·형태 참고이며, 텍스트와 충돌하면 텍스트가 우선한다.
4. 이전 상호 `鳥屋/Toriya`, 두 탭 생맥주와 초기 비픽셀 참고 이미지는 구현 기준으로 채택하지 않는다.
5. `기획 확장 아이디어 원본`의 제안은 확정 요구사항이 아니라 후보·검증 질문으로만 정제한다.
6. 서로 충돌하거나 수치가 없는 항목은 임의 확정하지 않고 각 문서의 미해결 질문에 둔다.

## 작성 규칙

각 요구사항 문서는 다음 항목을 포함해야 한다.

- 요구사항 식별자와 상태
- 문서 버전과 최종 변경일
- 근거가 된 `inbox/` 문서
- 근거 원본의 SHA-256 지문
- 목적
- 범위
- 상세 요구사항과 예외·경계 조건
- 비기능 요구사항
- 완료 기준
- 의존성
- 미해결 질문
- 변경 이력과 `epic/` 영향

새 요구사항은 `template/spec_요구사항_템플릿.md`를 사용하며, AI 갱신 규칙은 `AGENTS.md`를 따른다.
새 문서는 `v1.0.0`으로 시작하고 기존 문서 변경 시 `template/spec_epic_문서_버전_관리_지침.md`에 따라 버전을 올린다.

## 기본 카테고리

- `ui/`: 화면, HUD, 메뉴, UX 흐름
- `scenario/`: 세계관, 이야기, 캐릭터, 대사, 퀘스트
- `gameplay/`: 핵심 루프, 규칙, 난이도, 보상
- `system/`: 저장, 데이터 로딩, 상태 관리, 빌드 구조
- `art/`: 그래픽, 애니메이션, VFX, 에셋 규격
- `audio/`: BGM, SFX, 오디오 트리거
- `data/`: 콘텐츠 데이터, 스키마, 밸런스 테이블
- `qa/`: 테스트, 검수, 릴리즈 기준
- `meta/`: `inbox/` 원본 처리 이력 등 요구사항 전반의 정제된 관리 데이터
