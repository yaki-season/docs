## 작업 절차

1. 보류 작업 006의 candidate·schema·fixture를 현행 `GPL-006`과 field별 비교해 재사용 가능 항목과 폐기 항목을 기록한다.
2. D4 release definition 형식을 따라 D5 메뉴·process·orders·arrival·completion을 하나의 명시적 versioned record로 작성한다.
3. recipe·finish policy가 Developer 1 domain에 코드 분기 없이 주입되도록 schema와 loader object를 설계한다.
4. 9개 주문의 손님·order ID·line 수량을 합계 검증하고 2인 그룹 주문을 하나로 합치면 실패하게 한다.
5. `properHighlight=false`, 정확한 초 비노출, D6 fan/menu/order/reward 부재를 교차 검증한다.
6. candidate 파일은 본편 loader가 참조하지 않게 격리하고 필요한 경우 archival 설명만 남긴다.
7. Developer 1·2의 실제 D5 boot가 정본 loader만 소비하는지 확인하고, 사람이 화면 주문표와 해금 결과를 대조한다.
