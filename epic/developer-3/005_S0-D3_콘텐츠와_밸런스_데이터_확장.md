## 목표

기존 성장·직원·시나리오 데이터 골격을 실제 S0~D3 연속 캠페인에서 소비할 수 있도록 날짜·장면·
손님·주문·튜토리얼·정산·D4 예고 데이터를 확장하고 교차 검증한다.

## 사용자 확정 실행 조건

- D1·D2·D3는 각각 전체 영업일이다.
- 아사노 아키와 츠키오카 세이지만 고정 인물이며 나머지 손님은 엑스트라 유형이다.
- S0 세 단계 상호작용은 무실패다.
- D3 완료 뒤 D4는 읽기 전용 예고이고 gameplay·보상 데이터를 만들지 않는다.

## 범위

### 포함

- S0~D3 날짜 chain, 진입·완료·다음 날 개방 조건
- S0 장면·상호작용·skip summary 데이터
- D1~D3 시간대별 손님 수·주문 수·항목 수·활성 상한
- 츠키오카 고정 주문과 엑스트라 손님 유형·기억 플래그
- D2 도움 감소, D3 타레 신규 행동과 복습 조건
- 정산·목표·성장 결과와 D4-preview read-only flag
- JSON Schema·참조·날짜 chain·상한 교차 검증과 fixture

### 제외

- gameplay 로직·화면·저장 구현
- D4 실제 손님·메뉴·영업 데이터
- 고정 인물 추가와 D4 이후 캠페인 데이터

## 작업 절차

1. 기존 `content/`의 scenario·customer·order·balance schema와 S0~D3 부족 필드를 분석한다.
2. 날짜·장면·엑스트라 유형·주문·튜토리얼·정산 데이터를 approved/candidate로 분리한다.
3. D1~D3 손님·주문·위험 공정 상한을 기존 시뮬레이터에서 실행 가능하게 연결한다.
4. D4-preview는 command를 갖지 않는 읽기 전용 콘텐츠로 검증한다.
5. 끊긴 날짜·미정의 참조·중복 고정 인물·상한 위반 fixture를 추가한다.
6. 개발자 1·2가 소비할 ID·필드·기본값을 인계한다.
