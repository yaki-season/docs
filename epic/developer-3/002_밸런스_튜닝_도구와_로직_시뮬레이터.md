## 목표

기획자가 코드 수정 없이 게임 수치를 조절하고 한 영업일을 렌더링 없이 시뮬레이션해 결과를 보는
도구를 만든다. `SYS-005`의 편집 UI와 로직 시뮬레이터를 제공한다.

## 범위

### 포함

- 데이터 파일의 수치를 슬라이더로 조절하는 편집 UI, 범위 검증, 되돌리기, JSON 내보내기
- 한 영업일 루프를 모의 시간으로 실행하는 시뮬레이터
- 결과 지표(총수익·서빙·이탈·평균 대기·품질 분포)와 직전 실행 대비 비교
- 같은 수치·같은 시드의 결과 재현성
- `candidate`/`approved` 상태 표시

### 제외

- 최종 밸런스 수치 결정
- 출시 빌드 포함
- 30일 캠페인 시뮬레이션 (한 영업일부터)

## 1차 구현 완료 (2026-07-23)

착수 게이트(선행 작업 `developer-3/001`, `developer-1/007`)가 아직 없는 상태에서 사용자 요청으로
**1차 버전을 먼저 구현**했다. 정식 데이터 계약·영업일 루프가 없어 시뮬레이터는 조리·손님 판정
규칙만 재사용하고 대기열 모델은 도구에 두었다.

- `app/tools/balance-data.json` — 튜닝 수치 (`candidate`)
- `app/tools/simulator.js` — 순수 영업일 시뮬레이터, 도구·테스트 공유
- `app/tools/balance-tool.html` — 슬라이더 UI, 실행·비교·내보내기
- `app/tests/unit/simulator.test.js` — 재현성·수치 영향 검증 7개
- `app/README.md` — 사용법

검증: `npm run dev` → `/tools/balance-tool.html`. 단위 7개 통과. 브라우저에서 콘솔 오류 0으로
슬라이더 조절·시뮬레이션·이탈률 반응 확인.

## 작업 절차

1. (완료) 편집 UI·시뮬레이터·데이터 파일의 1차 버전을 구현한다.
2. `developer-3/001` 완료 후 데이터 파일을 정식 `DAT-001` 스키마·로더로 교체한다.
3. `developer-1/007` 완료 후 시뮬레이터를 정식 영업일 루프로 교체해 게임과 같은 로직을 재사용한다.
4. 저장 방식(다운로드 / File System Access / 개발 서버)을 `SYS-005` 미해결 확정에 맞춰 정한다.
5. 자동 정책 수준과 시뮬레이터 범위(한 영업일 / 30일)를 확정에 맞춰 확장한다.

## 의존성과 인계 조건

- 선행 작업: 없음 (1차는 독립 구현). 정식화는 `developer-3/001`, `developer-1/007`에 의존
- 후속 작업: 없음
- 다른 개발자에게 제공할 입력·출력: `developer-1`·`developer-3/001`에 시뮬레이터가 요구하는 수치
  항목과 결과 지표 구조를 인계한다. 정식 데이터·루프가 생기면 이 도구가 그것을 재사용하도록 교체한다.
