# 개발자 3 - 001 밸런스 데이터 파일과 로더·검증

- 문서 버전: `v1.0.0`

## 참조 spec

- `spec/data/DAT-001_콘텐츠와_밸런스_데이터_계약.md` - `DAT-001` - `v1.0.0`
- `spec/system/SYS-004_app_프로젝트와_소스코드_아키텍처.md` - `SYS-004` - `v1.0.0`

## 목표

`DAT-001` 계약에 따라 게임 수치를 담는 데이터 파일(JSON)과 그것을 읽어 검증하는 로더를 만든다.
조리 시간·손님 인내심·팁 배율 같은 수치가 코드 상수가 아니라 데이터에서 오고, 잘못된 값이 런타임
전에 검출되며, `candidate`/`approved` 상태가 구분되는 기반을 제공한다.

## 배경

수치가 지금은 코드 상수(`src/config/recipe.js`의 조리 임계값 등)로 흩어져 있어 기획자가 조절할 수
없다. 이 작업이 그 수치를 데이터로 옮겨 후속 게임 로직(`developer-1`)과 튜닝 도구(`developer-3/002`)의
공통 기반을 만든다.

## 범위

### 포함

- `DAT-001` 데이터 단위(메뉴·공정·품질·손님·영업일 등)의 JSON 파일 정의
- 레코드별 영구 식별자, 스키마 버전, 표시 키, 활성 여부, `candidate`/`approved` 상태
- 로드 전 참조·유형·범위·중복·순환 검증 (`DAT-001 §공통 규칙`)
- 단위 명시(비율 `0~1`, 시간 초, 재화 음수 아닌 정수 등)와 최소·최대 관계 검증
- 기존 코드 상수(조리 임계값 등)를 데이터로 이전하고 로직이 데이터를 읽도록 연결
- `approved`만 게임 기본값으로 로드하고 `candidate`는 격리하는 규칙

### 제외

- 편집 UI와 시뮬레이터 (`developer-3/002`)
- 영업일 루프·손님 로직 자체 (`developer-1`)
- 최종 밸런스 수치 결정 (기획자 몫, 값은 `candidate`로 채운다)
- 저장 데이터 마이그레이션의 런타임 구현

## 작업 절차

1. `DAT-001`의 데이터 단위를 JSON 스키마로 정의하고 파일 위치를 단일 원본으로 정한다.
2. 공통 규칙(식별자·버전·상태·활성·변경 이력)과 단위·범위·참조 검증을 구현한다.
3. 순환 참조·중복 식별자·미정의 참조·범위 위반을 로드 전에 검출한다.
4. `candidate`/`approved` 상태를 구분하고 `approved`만 기본값으로 로드하는 로더를 구현한다.
5. 기존 코드 상수(조리 임계값 등)를 데이터로 옮기고 값을 `candidate`로 표시한다.
6. 로더와 검증을 자동 테스트로 검증한다(정상 로드, 각 위반 케이스 거부).

## 의존성과 인계 조건

- 선행 작업: 없음 (아트·장면과 무관하게 착수 가능)
- 후속 작업: `developer-1/007`(영업일 루프 로직)과 `developer-3/002`(튜닝 도구)가 이 데이터·로더를 사용
- 다른 개발자에게 제공할 입력·출력: `developer-1`과 `developer-3/002`에 데이터 파일 경로·스키마,
  로더 API, 검증 규칙과 `candidate`/`approved` 접근 방법을 인계한다.
