## 목표

`DAT-001`의 나머지 데이터 단위 — 성장(업그레이드·재료·인테리어), 직원, 영업일 시나리오 — 를 JSON과
스키마로 정의하고 콘텐츠 검증에 편입한다. 작업 001의 데이터 계층을 게임 전체 콘텐츠로 확장한다.

## 범위

### 포함

- 업그레이드 데이터: 재료 등급·장비·인테리어 좌석. 종류·단계·비용·명성 조건·선행 단계·수치 효과
- 직원 데이터: 역할·속도·품질 상한·급여·경험치 곡선·실수율·애니메이션 참조 (`GPL-005 §15~22`)
- 시나리오 데이터: 날짜·스테이지·감정 키워드·이전/다음 날짜·해금·대체안 (`DAT-001 §15, §16`)
- 스키마 3종과 교차 검증(선행 업그레이드 참조, 시나리오 날짜 체인, 유일 식별자, 상태)
- 로더·전체 검증에 세 단위 편입

### 제외

- 게임 런타임의 실제 소비(업그레이드 적용·직원 자동화·시나리오 진행) — 해당 게임플레이 작업 범위
- 최종 밸런스 수치 결정 (값은 `candidate`)
- 다이아·수익화 데이터 (`GPL-005` 후속 검토)

## 작업 절차

1. (완료) upgrade·staff·scenario JSON Schema를 정의한다.
2. (완료) 대표 데이터를 `candidate`로 작성한다(업그레이드 4·직원 2·시나리오 3).
3. (완료) `rules.js`를 일반화하고 선행 업그레이드·시나리오 날짜 체인 참조 검증을 추가한다.
4. (완료) `validate.js`·`loader.js`에 세 단위를 편입한다.
5. (완료) 검증 테스트(정상·위반)를 추가한다.
