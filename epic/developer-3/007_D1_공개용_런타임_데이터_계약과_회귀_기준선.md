## 목표

현재 D1 정본 콘텐츠를 한 machine-readable runtime 계약으로 투영해 개발자 1의 production runtime·E2E가 과거 하드코딩 상수 대신 같은 계약을 소비하도록 한다.

## 범위

### 포함

- D1 손님·주문·항목·첫 주문·경제·그릴 배치의 단일 runtime 계약 builder
- 정상/오류 fixture와 양면 tick·동시 시작 불변식 검증
- Good 1건·Low 1건 정산을 계약에서 결정적으로 계산하는 fixture
- 개발자 1 import·구조·상수 제거 대상·정산 근거 handoff

### 제외

- D5 카와 및 D2~D4 데이터
- `game.js`, renderer, UI, 아트, manifest 및 개발자 1 E2E 수정
- basePrice 3의 10% 업그레이드 반올림 규칙 변경

## 작업 절차

1. D1 정본 데이터에서 공개 runtime에 필요한 값만 투영한다.
2. builder와 독립 fixture 검증기를 `src/content`에 구현한다.
3. 과거 상수·첫 주문·그릴·접촉면 위반 fixture를 실패시킨다.
4. 정산 기대값을 계약의 경제 필드로 계산해 handoff를 작성한다.

## 의존성과 인계 조건
