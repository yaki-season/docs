## 고정 계약

### 뒤집기

- `active` 꼬치는 공중 회전과 재접촉 뒤 `0.3초` 입력 잠금 외에는 언제든 뒤집을 수 있다.
- 뒤집기에 최소 굽기 시간·적정 도달·조기 확인 조건을 두지 않는다.
- `contactFace`인 한 면의 누적 시간만 증가한다.
- `frontElapsedSec`·`backElapsedSec`는 뒤집기·재투입·화면 전환·저장 복구에서 보존한다.
- 일찍 뒤집은 면으로 다시 돌아와 부족한 시간을 이어 채울 수 있다.
- 중간의 `under` 표시는 품질 결과를 고정하지 않는다. 회수 시점의 최종 양면 누적 시간으로
  품질을 계산한다.
- 양면 준비 전 클릭은 뒤집기이고 양면 준비 뒤 클릭은 회수다.

### 제공

- 플레이어가 선택한 공용 완성품을 플레이어가 선택한 손님에게 제공한다.
- 대상 손님의 미제공 메뉴·조리 방식·수량이 맞으면 제공할 수 있다.
- 손님 입장 순서, 주문 접수 순서와 주문 line 순서로 제공을 막지 않는다.
- `D1-ORDER-001`은 네기마 또는 생맥주 중 준비된 항목을 먼저 제공할 수 있다.
- 같은 손님에게 여러 주문이 있어도 숨은 FIFO를 사용자 입력 거부 규칙으로 사용하지 않는다.
- 내부 장부의 결정적 배정은 허용하지만 유효한 플레이어 선택을 막는 선행 조건으로 쓰지 않는다.

## 최초 실패 재현과 현재 기준

- 계약 작성 직전 구현 대조에서는 `beginFlip()`의 최소 준비 조건이 3초 앞면 뒤집기를
  `reason=not-ready`로 거부했고, D1 guided 주문은 네기마 선제 제공을
  `reason=guided-order-sequence`로 거부했다.
- 공유 작업공간의 Developer 1 구현이 병행 갱신된 뒤 이 별도 계약 파일을 최초 실행한 결과는
  `4/4` 통과다. 즉 네 사례의 기대를 낮추거나 `it.fails`로 고정하지 않고, 현재 구현이
  회귀하지 못하도록 정상 통과 계약으로 유지한다.
- `2026-07-31` 행동 projection 계약을 추가한 최초 실행은 기존 네 계약 `4/4` 통과,
  신규 계약 `1`건 실패다. under 상태의 `frontElapsedSec=3`, `backElapsedSec=0`,
  `contactFace=back`, `flipping=false`, `inputLocked=false`는 모두 일치했으나
  `slotViews()` 결과에 `nextAction` 필드가 없었다. 기대 `nextAction=flip`은 낮추지 않았고,
  양면 `8/8`의 `nextAction=retrieve`도 같은 계약 안에 유지한다.
- Developer 3는 이 과정에서 `app/src` 구현 파일을 수정하지 않았다.
