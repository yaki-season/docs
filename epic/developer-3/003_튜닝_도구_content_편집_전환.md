# 개발자 3 - 003 튜닝 도구 content 편집 전환

- 상태: `완료`
- 담당자: `개발자 3`

## 참조 spec

- `spec/system/SYS-005_밸런스_튜닝_도구와_로직_시뮬레이터.md` - `SYS-005` - `v1.0.0`
- `spec/data/DAT-001_콘텐츠와_밸런스_데이터_계약.md` - `DAT-001` - `v1.0.0`

## 목표

밸런스 튜닝 도구가 별도 평면 파일이 아니라 게임이 실제 로드하는 `content/` 데이터를 직접 편집하게
한다. 도구에서 조절한 값이 곧 게임 값이 되도록 데이터 원본을 일원화한다.

## 배경

작업 002에서 도구를 1차 구현할 때는 정식 데이터 계약(작업 001)이 없어 도구 전용 평면 파일
`tools/balance-data.json`을 편집했다. 이제 `content/` 데이터·로더(작업 001)와 정식 영업일
루프(작업 007)가 완성되어, 도구를 그 실데이터 편집으로 전환한다.

## 범위

### 포함

- 도구가 `content/`의 processes·customers·campaign JSON을 직접 로드·편집
- 슬라이더 상·하한·단위를 JSON Schema에서 읽음(값=content, 제약=schema)
- 손님 유형별 수치(유형마다 다른 인내심·팁 배율) 조절
- 실행 전 `content/rules.js`의 런타임 검증(게임과 동일)
- 변경된 content 파일 내보내기(교체 시 게임에 반영)
- 평면 어댑터(`tools/simulator.js`)·평면 데이터·그 테스트 제거

### 제외

- 저장 방식 확정(다운로드/File System Access/개발 서버) — `SYS-005` 미해결, 현재는 다운로드
- 성장·직원·시나리오 수치 노출(해당 데이터 단위 구현 후)

## 작업 절차

1. (완료) 슬라이더 상·하한을 위해 process·day 스키마에 최대값을 보강한다.
2. (완료) 도구가 `content/` 파일과 스키마를 로드하고, 값=데이터·제약=스키마로 슬라이더를 렌더한다.
3. (완료) 시뮬레이터를 `buildConfigFromContent` + `simulateBusinessDay`로 직접 연결한다.
4. (완료) 실행 전 `checkContentRules`로 검증하고 변경 파일 내보내기를 구현한다.
5. (완료) 평면 어댑터·데이터·테스트를 제거한다.

## 의존성과 인계 조건

- 선행 작업: `developer-3/001`(데이터·로더), `developer-1/007`(영업일 루프) 완료
- 후속 작업: 없음. 성장·직원 데이터가 생기면 도구에 노출 항목을 추가
- 다른 개발자에게 제공할 입력·출력: 기획자에게 "도구로 조절 → content 파일 내보내기 → 교체 →
  게임 반영" 흐름을 인계한다. 도구가 편집하는 파일과 게임이 로드하는 파일이 동일하다.

## 완료 기준

- [x] 슬라이더 상·하한·단위가 JSON Schema에서 온다.
