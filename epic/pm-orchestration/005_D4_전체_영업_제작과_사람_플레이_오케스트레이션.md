## 목표

D3 완료 저장에서 실제 D4로 진입해 `8명/8주문/19항목`을 모두 실제 입력으로 응대하고, 양배추
사라다와 하이볼을 포함한 마감·정산·단일 저장·D5 해금까지 사람이 완주한다. 자동 검증은 개발 중
회귀 신호로만 사용하고, D4 완료는 사용자가 실제 영업을 플레이한 뒤 명시적으로 `PASS`해야 확정한다.

## 작업 절차

1. `app/dev`의 현재 구조를 기준으로 데이터·domain·presentation·art writer 경계를 동결한다.
2. Developer 3은 D4 release data를, Developer 1은 D4 domain과 station controller를 병렬로 만들고 명시적 menu/station ID 계약으로 합친다.
3. Developer 2는 gameplay 상태 머신을 `d1-game.js`에 추가하지 않고 controller를 소비해 사이드 메뉴 화면과 드링크 내부 두 작업면을 실제 입력에 연결한다.
4. 의미 placeholder 상태에서 사용자가 첫 주문의 사라다 1접시·하이볼 1잔과 화면 이동을 플레이해 조작·레이아웃 피드백을 준다.
5. Artist 3은 사용자 제공 샘플과 현재 승인 runtime 화면을 함께 기준으로 콘셉트를 만들고, 승인된 콘셉트에서만 모듈형 asset을 분리한다.
6. Developer 2가 승인 asset을 실제 화면에 연결한 뒤 QA가 D4 8주문 전체를 실제 입력으로 완주한다.
7. 사람 피드백으로 발견된 결함은 원 owner에게 되돌리고 동일 저장·동일 주문 경로를 다시 플레이한다.
8. 사용자가 최종 `PASS`한 뒤에만 D4 stage와 각 producer 작업을 완료 처리한다.

- 다른 역할과 병렬 가능한 범위: Developer 1의 순수 domain/controller, Developer 3의 content/schema, Artist 3의 초기 스타일·소품 연구
- 반드시 순차로 진행할 범위: menu/station 계약 동결 → Developer 2 실제 화면 결선 → 기능 사람 플레이 → 아트 콘셉트 승인·분리 → 최종 사람 전체 플레이
- 동시 writer를 금지할 경로·stable ID·finalizer: Developer 1은 `app/src/domain/**`·`app/src/application/businessDay/**`·신규 `app/src/application/stations/**`·D4 campaign transition, Developer 3은 `app/content/**`·`app/src/application/ports/d4BusinessDayDefinition.js`·D4 content tool, Developer 2는 `app/src/d1-game.*`·`app/src/render/**`·`app/src/config/screenLayout.js`·`app/src/assets/**`, Artist 3은 `art-workspace/review/artist-027/`과 승인 전 source만 단일 writer다. `app/public/assets/manifest.json` 승격은 최종 사용자 승인 뒤 Developer 2가 한 번에 수행한다.
