## 목표

S0·D1 최초 공개 gate 뒤 D2의 영업 준비, 도움 감소, 전체 영업, 정산, 저장과 D3 전환을
하루 단위로 온전히 구동한다. 기능은 명시적 개발 placeholder를 허용해 먼저 검증할 수 있지만
사용자에게 개발 중 상태를 분명히 보이고 사람 전체 영업 플레이테스트를 통과한다.

## 범위

### 포함

- 개발자 1 작업 010의 D2 날짜 runtime·전체 영업·저장 전환
- 개발자 2 작업 004·005·006의 시나리오·shell·통합
- 개발자 3 작업 005의 D2 데이터 계약 소비 확인
- 날짜별 stable ID pack 뒤 Artist 1 작업 026과 Artist 3 작업 024 병렬 활성화
- D2 전체 영업과 도움 감소 이해 여부의 사람 플레이테스트

### 제외

- D3 전체 영업, D4 실제 gameplay, 오디오
- 날짜별 stable ID handoff 전 아트 추측 제작
- 개발 placeholder를 정식 승인 아트처럼 표시

## 병렬·순차 계획

- PM 작업 002 완료 뒤 개발자 1 작업 010의 D2 기능 slice를 먼저 연다.
- 개발자 1이 날짜별 stable ID pack을 고정하면 Artist 1의 모모 음식/shader와 Artist 3의
  서비스·이야기·정산 lane을 병렬로 연다.
- 후보별 승인→finalizer→promotion→QA는 순차다.
- D2 전체 영업·정산·저장·D3 전환 사람 `PASS` 뒤 PM 작업 004를 활성화한다.

## 작업 절차

1. PM 작업 002의 공개 gate와 D1 저장 전환 증거를 확인한다.
2. 개발자 1 작업 010을 D2 slice부터 배정하고 stable ID pack을 받는다.
3. 충돌 없는 Artist 1·3 lane과 개발자 2 통합 lane을 병렬 배정한다.
4. placeholder 상태에 명시적 개발 중 표시가 있는지 QA한다.
5. 실제 정적 URL에서 D2 전체 영업·정산·저장·D3 전환을 사람에게 플레이시킨다.
6. `PASS`와 남은 placeholder backlog를 분리 기록하고 PM 작업 004를 활성화한다.

## 사용자 승인 gate

- 새 아트·시나리오 소비 화면과 D2 공개 slice는 사용자가 최종 승인한다.
- 기능 placeholder 허용은 정식 아트 승인으로 간주하지 않는다.
- spec의 후속 인물 정책 drift는 D2 제작 전에 별도 spec 정합 반영 승인을 받아야 한다.

## 사람 화면 테스트

- 필수 경로: D2 준비 → 도움 감소 안내 → 전체 영업 → 정산 → 저장 → D3 전환·복구.
- 필수 확인: D1과 달라진 도움 수준을 이해할 수 있는지, 개발 placeholder가 오인되지 않는지,
  영업 완주와 저장 보상에 막힘이 없는지.
