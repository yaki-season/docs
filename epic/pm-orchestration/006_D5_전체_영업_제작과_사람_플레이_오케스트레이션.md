## 목표

D4 완료 저장에서 preview 없이 실제 D5로 진입해 토리카와의 5회 조립, 짧은 양면 굽기,
소금·타레·선택적 토치와 기존 D4 메뉴를 함께 운용하고 `9명/9주문/20항목`을 모두 실제 입력으로
응대한다. 자동 검증은 회귀 보조 신호로만 사용하며, D5 완료는 구현자가 먼저 전 구간을 직접
플레이하고 사용자가 같은 일반 UI 경로를 확인해 명시적으로 `PASS`한 때에만 확정한다.

## 작업 절차

1. D4 사람 전체 플레이 `PASS`와 `feature/D4toD5` 기준선을 먼저 고정하고 역할별 writer 경계를 선언한다.
2. Developer 3은 확정 D5 release data를, Developer 1은 메뉴별 조리 정책과 D5 campaign runtime을 병렬 구현한다.
3. Developer 2는 정본 data와 domain command를 소비해 토리카와 5회 조립·그릴·타레 마감을 기존 조리 화면에 결선한다.
4. 기능 graybox에서 구현자가 첫 소금 토리카와와 첫 타레 토리카와를 직접 만들고, 사용자에게 같은 경로의 조작·가독성 피드백을 받는다.
5. Artist 1은 사용자 제공 두 reference와 현재 승인 게임 화면을 함께 비교한 전체 화면 적용안을 먼저 만들고, 사용자 승인 뒤 runtime layer를 분리한다.
6. Developer 2가 승인 asset을 binding한 뒤 구현자가 D5 전체를 무중단 완주하고 QA에 재현·잔여 결함을 인계한다.
7. QA는 사용자가 `D5-ORDER-001~009`를 일반 UI로 플레이하도록 지원하고, 결함을 원 owner에게 반환해 동일 주문을 재플레이한다.
8. 최종 사용자 `PASS` 뒤에만 D5 stage와 producer 작업을 완료 처리한다.
