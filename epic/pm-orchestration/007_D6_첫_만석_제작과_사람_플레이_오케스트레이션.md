## 목표

`GPL-007`을 기준으로 Developer 1·2·3의 D6 작업을 순서대로 연결하고, 사람이 D6 전체 영업을 완주해 첫 만석이 의도대로 읽히는지 확인한다. 만석을 목표가 아니라 결과로 유지하고, D7 콘텐츠가 새어 나오지 않게 한다.

## 범위

### 포함

- Developer 3 → Developer 1 → Developer 2 순서 관리와 인계 조건 확인
- D6 주문표·상한·그릴 칸이 세 작업에서 같은 값을 쓰는지 대조
- 사람 전체 플레이 준비와 피드백 수집·반영 판단
- D6 완료 뒤 D7 기획 착수 조건 정리

### 제외

- 각 역할의 구현 자체
- D7 메뉴·도구·주문표 확정
- 신규 아트. D6는 아트 작업이 없다

## 작업 절차

1. `GPL-007`의 주문표·상한·그릴 칸을 세 개발 작업의 완료 기준과 대조한다.
2. Developer 3의 D6 release를 먼저 동결하고 Developer 1에 인계한다.
3. Developer 1의 도착 정책이 D1~D5 회귀 없이 통과하는지 확인하고 Developer 2에 인계한다.
4. Developer 2의 만석 표시 보정 뒤 전체 플레이 준비 상태를 판정한다.
5. 사람 전체 플레이를 준비하고 피드백을 각 역할에 분배한다.
6. D6 완료 뒤 D7 기획 착수 여부를 판단한다.

## 병렬·순차 계획

- 반드시 순차로 진행할 범위: release 동결 → 도착 정책 → 만석 표시 → 전체 플레이
- 동시 writer를 금지할 경로: PM은 코드를 쓰지 않는다. 각 경로의 단일 writer는 해당 개발 작업이 소유한다.
