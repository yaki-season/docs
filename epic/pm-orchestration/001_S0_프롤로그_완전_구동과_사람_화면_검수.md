## 목표

새 게임이 정적 웹 URL에서 열쇠 선택, 대문 열기, 숯 점화의 짧은 무실패 상호작용과 정식
이야기·건너뛰기·3줄 요약을 거쳐 D1 전체 영업으로 자연스럽게 전환되게 한다. 자동 검증뿐 아니라
사람이 실제 화면을 직접 조작한 `PASS` 증거까지 확보해 S0를 온전히 구동되는 스테이지로 닫는다.

## 병렬·순차 계획

- `CH-AKI-STORY`의 versioned portrait binding 계약은 화로 제작과 파일·stable ID가 겹치지 않으므로
  별도 개발자 2 lane에서 병렬로 고정할 수 있다.
- 차가운 `ST-S0-BRAZIER` 단품 승인 → FHD/720 소비 화면 승인 → finalizer·promotion은 순차다.
- `PR-CHARCOAL-IGNITION`의 off·점화·stable 상태는 화로 primary 승인 뒤 companion 계약 순서로 진행한다.
- 아키 초상과 화로·숯이 모두 exact binding된 뒤에만 S0 전체 QA와 사람 화면 테스트를 시작한다.
- S0와 D1 제작은 병렬로 진행하지만 최초 공개 gate는 PM 작업 002까지 함께 완료돼야 닫힌다.

## 작업 절차

1. PM 부팅 때 실제 epic·파일·SHA·테스트를 다시 확인하고 승인 큐와 실행 가능한 역할 lane을 복구한다.
2. 사용자 승인 불필요한 독립 계약은 역할 서브에이전트에게 즉시 배정한다.
3. 사용자 승인 후보는 후보 ID·revision·FHD/720 증거·고정/변경/제외 범위와 PM 권고를 한 건씩 보고한다.
4. 승인되면 Artist finalizer에서 Developer 2 promotion, exact binding, QA 재검증 순으로 자동 인계한다.
5. S0 placeholder와 오류가 0개가 되면 실제 정적 URL과 build 정보를 고정한다.
6. `template/사람_화면_플레이테스트_피드백_템플릿.md`로 사용자에게 S0 조작 테스트를 요청한다.
7. 사람 `PASS`와 자동 검증을 함께 기록하고 D1 시작 저장 전환까지 확인한 뒤 완료 처리한다.

## 사용자 승인 gate

- 아트 단품·실제 소비 화면·이야기 초상·최초 공개 시각 결과의 최종 승인자는 사용자다.
- `조건부 승인`은 수정 확인 전 최종 승인으로 바꾸지 않는다.
- 승인 전에는 해당 후보의 optimizer·finalizer·runtime promotion과 종속 후보를 진행하지 않는다.
- 승인 대기 lane만 멈추고, 충돌 없는 D1과 S0 독립 계약 lane은 계속 진행한다.

  D1 전환 → 새로고침 복구.
- 필수 환경: 최신 Chrome·Edge, `1920×1080`·`1280×720`, 마우스·키보드.
- 필수 판정: 조작 막힘, 화면 가독성, 이야기 흐름, 무음 상태의 시각 피드백, 저장·전환을 확인한
