## 목표

비활성 손님 시스템을 최신 `GPL-003` 운영 계약으로 재정렬하고, 독립 손님 정보 화면과 조리 화면을
오가는 다중 손님·다중 주문 흐름을 활성화한다. `SCN-001`의 단일 츠키오카 장면은 이 작업의 대상이 아닌
회귀·통합 테스트 화면으로 남기며 `CUSTOMER_SYSTEM_ENABLED=false`를 유지한다.

## 배경과 경계

`app/src/state/customer/`와 `app/src/config/menu.js`에는 초기 비활성 구현이 남아 있다. 이를 그대로
활성화하지 않고, 좌석·그룹·주문 식별·공용 준비 목록·자동 제공과 최신 화면 전환 계약을 기준으로
재설계한다.

| 구분 | 작업 006의 프로덕션 책임 | `SCN-001` 테스트 화면 |
|---|---|---|
| 손님 수 | 6석, 단독 및 그룹, 동시 주문 | 츠키오카 1명 고정 |
| 제공 | 주문 ID에 연결된 준비품의 자동·부분 제공 | 수동 주문 매트 클릭 |
| 화면 | 독립 손님 정보/조리 화면의 상태 보존 | 지속 카운터 구도의 회귀 입력 |
| feature flag | 프로덕션 경로에서만 활성화 조건을 검증 | 계속 `false` |

## 범위

### 포함

- `GPL-003` 상태·용어와 기존 비활성 모듈의 차이 분석 및 재정렬
- 6석, 손님·좌석 배정, 인접 2석 그룹, 주문자·좌석·그룹·메뉴·수량·상태 ID 모델
- 대기 게이지, 주문 취소·명성 원인, 팁·판매가·만족도 역할 분리
- 색상+도형+좌석 번호 표식, 잘못된 대상 선택 처리, 퇴장 후 빈 식기·좌석 정리
- `GPL-004` 공용 준비 목록에서 주문 ID에 맞는 자동·부분 제공
- 독립 손님 정보/조리 화면 전환 중 여러 주문·공정·입력 상태 보존
- 수치의 `DAT-001` 분리와 다중 손님 단위·종단 검증

### 제외

- 단골 전환·기억 주문, 러시 파동, 좌석 8·12석 확장, 직원 홀 자동화, D30 예약, 후속 손님 유형 확장
- `SCN-001` 단일 손님 테스트 화면의 구조 변경 또는 feature flag 활성화

## 착수 게이트 (보류 사유)

1. **`GPL-003 v2.6.0`은 초안이다.** 대기 시간, 부분 서빙 10초 회복, 좌석 정리, 그룹 퇴장과 시간대별 활성 주문·위험 공정 상한은 `DAT-001 v1.4.0`과 `GPL-002/GPL-003 v1.3.0/v2.6.0`의 `candidate` 데이터로 확정됐다. 실제 플레이테스트에서만 수치를 조정한다.
2. **작업 005의 프로덕션 화면 인터페이스가 필요하다.** 독립 손님 정보 화면, 6석/주문 표식,
   공용 준비 목록 렌더 어댑터가 준비되어야 한다. 현재 단일 손님 테스트 화면은 이 조건을 충족하지 않는다.
3. **드링크 공정과 `GPL-004` 연결이 필요하다.** 직장인 2인의 생맥주 선주문과 여러 주문의 자동·부분
   제공을 검증할 수 있어야 한다.
4. 위 조건이 충족되기 전에는 `CUSTOMER_SYSTEM_ENABLED`를 켜지 않고, 테스트 화면도 변경하지 않는다.

## 작업 절차

1. 확정된 운영 수치를 `DAT-001` 데이터로 기록하고, 기존 비활성 모듈과 최신 계약의 차이표를 만든다.
2. 좌석·그룹·주문 ID·준비품 연결 모델을 구현하고 독립 손님/조리 화면 렌더 어댑터에 연결한다.
3. 입장→착석→주문→대기→제공→식사→추가 주문·계산→퇴장→정리 흐름과 대기 게이지를 구현한다.
4. 색상+도형+좌석 표식, 잘못된 선택 무이동·첫 실수 무패널티, 자동·부분 제공을 구현한다.
5. 팁·판매가·만족도의 입력을 분리하고 정리 전 재배정을 막는다.
6. 프로덕션 경로에서만 feature flag를 활성화하고, 단일 손님 테스트 경로의 flag와 회귀 검증을 분리한다.
7. 다중 손님 동시 관리, 화면 전환 상태 보존, 드링크 선주문, 자동 제공과 오류 경로의 단위·종단 검증을 추가한다.

## 의존성과 인계 조건

- 선행: 작업 005의 **프로덕션** 독립 화면·6석·주문 표식·준비품 렌더 인터페이스, 드링크 공정 구현,
  `GPL-003`의 미해결 운영 정책 확정
- 후속: 단골·기억 주문과 러시 파동·위험 우선순위는 별도 작업으로 생성
- 인계: Artist 작업은 손님 유형별 초상, 좌석별 배치 anchor, 빈 식기/정리 상태를 제공한다. 좌석·anchor
  이름은 `SYS-002`와 `ART-002` metadata를 정본으로 하며 임의로 변경하지 않는다.

## 완료 기준

- [ ] 프로덕션 손님 시스템이 최신 `GPL-003` 상태 흐름대로 동작하며, 테스트 화면과 분리돼 있다.
- [ ] 6석·인접 2석 그룹·손님별 다중 주문·대기 게이지·정리 전 재배정 금지가 동작한다.
- [ ] 주문이 색상+도형+좌석 번호 및 주문 ID로 구분되고, 자동·부분 제공이 올바른 주문에만 연결된다.
- [ ] 잘못된 선택, 첫 실수, 취소·명성, 팁·판매가·만족도 역할 분리의 예외가 검증된다.
- [ ] 독립 화면 전환 중 주문·공정·입력 상태가 보존되고, 드링크 선주문을 포함한 다중 손님 종단 검증이 통과한다.
- [ ] `SCN-001` 단일 손님 회귀 화면은 flag와 동작을 유지한다.

## 구현 및 검증 결과

- app 구현 위치: 미구현. 재정렬 후보는 `app/src/state/customer/`, `app/src/config/menu.js`다.
- 현재 상태: `CUSTOMER_SYSTEM_ENABLED=false`; 단일 손님 화면은 테스트 목적에 맞게 유지한다.
- 검증 결과: 미실행. 기존 단일 손님 2.5D 캡처·성능 결과는 이 작업의 다중 손님 완료 증거가 아니다.
- 남은 위험: `GPL-003` 미해결 정책, 프로덕션 화면 인터페이스, 드링크·자동 제공 연결이 모두 착수 전 조건이다.
