## 목표

`app@main`에 비활성 상태로 존재하는 손님 시스템을 `GPL-003`의 운영 계약으로 재정렬하고
활성화한다. 단일 손님 가정을 좌석 기반 다중 손님으로 바꾸고, 대기 게이지를 실제로 가동하며,
팁·판매가·만족도의 역할 분리를 구현해 여러 손님을 동시에 관리하는 1차 운영 흐름을 완성한다.

## 배경

작업 005 이전에 손님 상태 머신·유형·다중 슬롯 재주문이 선행 구현되었으나, 당시 근거로 삼은
설계 초안이 `GPL-003`으로 대체되었다. 코드는 지우지 않고 `src/config/features.js`의
`CUSTOMER_SYSTEM_ENABLED=false`로 비활성화해 두었다. 이 작업이 그 코드를 정본 기준으로
되살린다.

- 비활성 구현: `app/src/state/customer/`, `app/src/config/menu.js`
- 설계 기록(대체됨): `inbox/1.design/2026-07-22_손님_유형과_상태_머신_설계_초안.md`,
  `inbox/1.design/2026-07-22_메뉴_카테고리와_주문_규칙_설계_초안.md`

## 범위

### 포함

- 비활성 손님 모듈을 `GPL-003`의 상태·용어로 재정렬하고 플래그 활성화
- 카운터 6석 좌석 모델과 손님·좌석 배정 (`GPL-003 §1, §2`)
- 퇴근 직장인 2인 그룹 입장·퇴장과 손님별 주문·만족도 관리 (`§3~§5`)
- 대기 게이지 실제 가동과 0 도달 시 주문 취소·명성 하락 원인 기록 (`§15, §16`)
- 주문 식별: 주문자·좌석·그룹·메뉴·생성 시각·상태와 `색상+도형+좌석 번호` 표식 (`§9~§11`)
- 잘못된 손님 선택 시 이동 없이 표식 재강조, 첫 실수 무패널티 (`§14`)
- 역할 분리: 팁=대기 잔량·유형, 판매가=품질, 만족도=추가 주문·명성, 중복 가산 금지 (`§18~§21`)
- 퇴장 좌석의 빈 접시·잔과 좌석별 정리 입력 (`§7`)
- 수치는 `DAT-001` 데이터로 분리하고 코드에 상수로 박지 않음

### 제외

- 단골 전환·기억 주문·단골 노트 (`GPL-003 §23~§28`) — 후속 작업
- 러시 파동과 화면 밖 위험 우선순위 (`§29~§32`) — 후속 작업
- 좌석 8·12석 확장과 인테리어 업그레이드 (`§1`)
- 직원 홀 자동화 (`§8`)
- D30 8인 예약 (`§6`)
- 관광객·리뷰어·취객 유형 (`§손님 유형` 표의 확장 후보)
- 커플 유형의 플레이팅 가중 (플레이팅 스테이션 도입 후)

## 착수 게이트 (보류 사유)

1. **`GPL-003`이 `초안`이다.** 최소한 다음 미해결 질문이 확정되어야 구현할 수 있다.
   - 미해결 1: 대기 게이지 기본 시간과 유형별 보정값
   - 미해결 2: 2인 그룹 한 명 이탈 시 개인·그룹 처리
   - 미해결 3: 좌석 정리가 즉시 입력인지 진행 시간을 갖는지
   - 미해결 5: 동시 활성 주문·위험 공정 수의 상한
2. **개발자 1 작업 005 완료.** 손님이 2.5D 장면에 렌더링되고 좌석 앵커가 확정되어야 한다.
3. **`GPL-004`의 드링크 스테이션.** 직장인 2인의 생맥주 선주문(`GPL-003 §12`)이 성립하려면 필요하다.
   드링크가 없으면 2인 그룹의 주문 흐름을 그대로 구현할 수 없다.
4. 위 조건 미충족 시 착수하지 않고 보류 사유를 이 문서에 갱신한다.

## 작업 절차

1. 착수 게이트를 확인하고 확정된 수치를 `DAT-001` 데이터 단위로 정리한다.
2. 비활성 손님 모듈과 `GPL-003`의 상태·용어 차이를 대조표로 만들고 재정렬 범위를 확정한다.
3. 좌석 모델(6석)과 손님·좌석 배정, 인접 좌석 2인 그룹 규칙을 구현한다.
4. 손님 상태를 `GPL-003`의 흐름(입장→착석→주문 생성→대기→제공받음→식사→추가 주문·계산→그룹 퇴장→종료)으로 재정렬한다.
5. 대기 게이지를 가동하고 0 도달 시 주문 취소·매출 0·명성 하락 원인 기록을 연결한다.
6. 주문 식별자와 `색상+도형+좌석 번호` 표식을 접시·잔·주문 매트에 일관되게 적용한다.
7. 잘못된 손님 선택 처리와 첫 실수 무패널티를 구현한다.
8. 팁·판매가·만족도의 역할 분리를 구현하고 중복 가산이 없음을 검증한다.
9. 좌석 정리 입력과 정리 전 재배정 금지를 구현한다.
10. `CUSTOMER_SYSTEM_ENABLED`를 제거하거나 기본 활성으로 전환하고, 건너뛰던 손님 종단 테스트를 되살린다.
11. 다중 손님 동시 관리의 단위·종단 검증을 추가한다.

## 의존성과 인계 조건

- 선행 작업: `developer-1/005_2.5D_영업_장면과_손님_반응_구현.md` 완료
- 후속 작업: 단골·기억 주문, 러시 파동과 위험 우선순위는 별도 작업으로 생성
- 다른 개발자에게 제공할 입력·출력: Artist 작업에서 좌석별 손님 배치 앵커와 손님 유형별 초상이
  필요하다. 좌석 수·앵커 이름은 `SYS-002` 장면 계약과 일치시키고 임의로 바꾸지 않는다.

## 완료 기준

- [ ] 손님 시스템이 활성화되고 `GPL-003`의 상태 흐름대로 동작한다.
- [ ] 카운터 6석에 손님이 배정되고 인접 빈 좌석 2개가 있을 때만 2인 그룹이 입장한다.
- [ ] 2인 그룹의 주문·대기 게이지·만족도가 손님별로 관리되고 둘 다 끝나야 함께 퇴장한다.
- [ ] 대기 게이지가 주문 직후부터 감소하고 0에서 주문 취소·매출 0·명성 하락 원인이 기록된다.
- [ ] 주문이 `색상+도형+좌석 번호`로 구분되며 색상만으로 구분하지 않는다.
- [ ] 잘못된 손님 선택이 완성품을 이동시키지 않고 첫 실수에 패널티가 없다.
- [ ] 팁·판매가·만족도가 각자 정의된 입력만 반영하고 같은 결과를 중복 가산하지 않는다.
- [ ] 좌석 정리 전에는 새 손님이 배정되지 않는다.
- [ ] 조리 수치와 손님 수치가 `DAT-001` 데이터로 분리되어 코드 상수로 남지 않는다.
- [ ] 건너뛰던 손님 종단 테스트가 되살아나 통과하고 다중 손님 검증이 추가된다.
