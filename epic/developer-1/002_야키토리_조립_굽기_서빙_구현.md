## 목표

플레이스홀더 또는 기존 에셋을 사용해도 좋으나, PC 웹의 마우스 클릭으로 네기마 한 주문을 조립하고 양면을 구워 손님에게 서빙한 뒤 다시 시작할 수 있는 완전한 기능 흐름을 구현한다.

## 범위

### 포함

- 주문표, 재료통, 조립 꼬치와 단계별 자동 배치
- 잘못된 재료 피드백과 조립 완료 전달
- 그릴 배치, 면별 시간, 적정·과다·탄 상태, 뒤집기와 접시 회수
- 접시 선택, 손님 주문 매트 서빙, 품질 반응과 다시 하기
- 조립·그릴·카운터 화면과 자동·수동 공정 이동
- 마우스 클릭 입력, 최소 클릭 영역과 연속 클릭 방어
- 핵심 종단 흐름의 브라우저 자동 테스트

### 제외

- 최종 픽셀 아트 제작과 세부 시각 폴리시
- 생맥주, 추가 메뉴와 복수 주문
- 스테이지 목표, 점수, 경제, 저장과 이야기
- 모바일 브라우저, 터치 입력과 모바일 뷰포트 대응

## 작업 절차

1. 작업 001의 상태 모델을 조립·그릴·카운터 화면에 연결한다.
2. 주문 순서와 현재 재료를 표시하고 재료 클릭의 성공·오류 피드백을 구현한다.
3. 조립 완료 꼬치의 전달과 그릴 자동 배치를 구현한다.
4. 면별 시각 상태, 적정 신호, 너무 이른 클릭, 뒤집기, 과다와 탄 실패를 연결한다.
5. 접시 회수, 접시 선택, 손님 주문 매트 서빙과 결과 반응을 구현한다.
6. 다시 하기로 모든 화면과 상태가 초기화되는지 연결한다.
7. 두 데스크톱 검증 뷰포트에 레이아웃과 최소 클릭 영역을 적용한다.
8. 정상 흐름, 오류 흐름과 빠른 이중 클릭 종단 테스트를 작성한다.

## 구현 및 검증 결과

- app 구현 위치
  - `app/src/index.html` — 조립·그릴·카운터 화면 구조와 공정 탭
  - `app/src/main.js` — 상태 배선, 재료 관통 연출, 익힘 진행 링, 접시 서빙 연출
  - `app/src/style.css` — 화면 배치, 최소 클릭 영역, 상태별 시각 구분
  - `app/tests/e2e/vertical-slice.spec.js` — 정상·오류·탄 상태·이중 클릭·포인터 취소 종단 흐름
  - `app/tests/e2e/layout.spec.js` — 최소 클릭 영역, 화면 내 포함, 겹침 검사
  - `app/tests/e2e/capture.spec.js` — 공정별 화면 캡처 산출
- 구현 기준 spec 버전: `GPL-001 v1.0.0`, `UI-001 v1.0.0`, `SYS-001 v1.0.0`
- 구현 기준 태스크 버전: `v1.0.0`
- 검증 방법
  - `npm run verify` — 단위 테스트와 두 데스크톱 뷰포트 종단 테스트를 연속 실행
  - 최소 클릭 영역 `44×44`와 화면 내 포함은 `boundingBox()`로 뷰포트별 자동 검사
  - 공정별 캡처 10장을 `app/captures/`에 생성해 육안 검수
- 검증 결과: `2026-07-21` 기준 단위 31개, 종단 28개(`1280×720`, `1920×1080` 각 14개) 전부 통과
- 구현 중 발견·수정한 결함
  - 전역 입력 잠금이 서로 다른 대상의 연속 클릭까지 차단해 조립 완료 후 그릴 배치가
    무시되었다. `UI-001 §17`에 맞춰 대상별 잠금으로 변경했다.
  - `.skewer { display: flex }`가 HTML `hidden` 속성을 덮어 굽는 중에도 대기 꼬치가
    남았다. `[hidden] { display: none !important }`를 추가하고 회귀 테스트를 넣었다.
  - 결과 오버레이가 반투명이라 뒤 화면 문구가 비쳤다. 불투명 배경으로 변경했다.
  - 익힘 상태 배지가 진행 링과 겹쳤다. 그릴 칸 바깥 위로 옮기고 겹침 검사를 추가했다.
- 남은 위험
  - 재료·접시·손님·배경이 모두 CSS 도형 플레이스홀더다. 실제 픽셀 아트 적용과
    최종 가독성 검수는 작업 003 범위이며, 그전까지 손맛 검증은 제한된다.
  - 익힘 상태는 색 외에 진행 링의 각도와 연기 세기로도 전달하지만, 연기는 플레이스홀더
    수준이라 작업 003의 VFX 적용 후 다시 검수해야 한다.
