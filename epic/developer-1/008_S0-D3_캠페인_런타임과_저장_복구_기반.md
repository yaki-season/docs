## 목표

S0에서 시작해 D3 정산과 D4 진입 직전까지 이어지는 캠페인 상태를 렌더러와 분리하고, 영업일
체크포인트·저장 검증·백업·복구·마이그레이션을 제공하는 정식 런타임 기반을 완성한다.

## 사용자 확정 실행 조건

- 첫 공개 빌드 전 개발 저장은 초기화할 수 있다.
- 첫 공개 빌드부터 저장 스키마 마이그레이션을 보장한다.
- 1차 저장 어댑터는 `localStorage`이고, 활성 저장과 정상 백업 2개를 유지한다.
- 영업 시작 직전과 정산 완료 뒤 자동 저장하며 영업 중 중단은 `day-start`에서 재개한다.
- 공식 지원은 최신 Chrome·Edge, `1920×1080`과 `1280×720`이다.

## 범위

### 포함

- `S0 → D1 → D2 → D3 → D4-preview` 캠페인 상태와 날짜 전이
- `day-start`·`day-complete` 체크포인트, 중복 정산 방지 식별자
- pending 쓰기·검증·활성 키 교체·백업 회전과 손상 복구
- 저장 envelope, 체크섬, 콘텐츠 버전, 순차 마이그레이션 함수 체인
- 파일 내보내기·불러오기에 사용할 저장 직렬화·검증 application port
- 가짜 저장소·시간·난수로 실행하는 단위·통합 테스트

### 제외

- 화면·대사·설정·파일 선택 UI — 개발자 2 작업 004·005 책임
- D1~D3 손님·조리·정산 규칙 — 개발자 1 작업 009·010 책임
- 클라우드 저장, 계정, PWA, WebView, 원격 텔레메트리

## 작업 절차

1. 현재 전역 상태와 영업일 골격을 캠페인·영업일·설정·진단 저장 영역으로 분리한다.
2. `StoragePort`와 `localStorage` 어댑터, memory test adapter를 구현한다.
3. 체크포인트 생성·검증·백업 회전·복구·중복 보상 방지 로직을 구현한다.
4. 내보내기·불러오기용 envelope 검증과 호환 버전 판정을 제공한다.
5. S0~D4-preview 전이를 콘텐츠 ID와 연결하고 모든 분기를 렌더러 없이 검증한다.
6. 첫 공개 버전의 스키마를 고정하고 이후 마이그레이션 fixture 추가 절차를 문서화한다.

- [x] day-start·day-complete 저장과 중복 정산 방지가 자동 검증된다.
