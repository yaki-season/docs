## 목표

검증된 조립·굽기·서빙 상태 흐름을 Three.js 2.5D 가게 장면에 통합하고, 개발자 2의 최종 에셋을 사용해 접시 전달 뒤 츠키오카의 맛보기와 품질별 반응까지 반복 가능한 1차 실제 게임 장면을 완성한다.

## 범위

### 포함

- `d3fd2c7`의 상태·판정·입력·테스트 계약 보존
- Three.js 단일 캔버스, 고정 카메라와 6개 시각 레이어
- 조립·그릴·서빙 카메라/스테이션 프리셋
- 개발자 2 manifest 기반의 16개 에셋 로딩·배치
- 기존 익힘 셰이더를 Three.js 재질로 통합하거나 동일 표현으로 이식
- 재료 조립, 그릴 배치·뒤집기·회수, 접시 이동의 공간 연출
- 츠키오카 `waiting→tasting→satisfied|neutral`, 탄 실패 `retry` 반응
- 기존 78개 회귀 검증과 2.5D 장면·반응·에셋·성능 검증 추가

### 제외

- 인트로, 외관, 레시피 노트와 숯 점화
- 생맥주, 직장인 A·B, 복수 주문, 대기 게이지와 좌석 정리
- 드래그·스와이프·터치 전용 입력, 모바일 전용 레이아웃
- 자유 카메라, glTF 캐릭터, 리깅, 물리와 실시간 그림자
- 정산, 재화, 저장, 메뉴 해금과 다음 날 진행

## 구현 기준선

1. `app`의 `origin/agent/yakitori-vertical-slice` 커밋 `d3fd2c7` 또는 이를 포함한 병합 커밋에서 시작한다.
2. 시작 직후 `npm run verify`의 기존 단위 32개·종단 46개가 통과해야 한다.
3. 개발자 2 작업 001이 `완료`이고 `app/art/gameplay/ASSET-MANIFEST.md`와 이미지 16개가 존재해야 한다.
4. 위 조건을 충족하지 않으면 구현을 시작하지 않고 보류 사유를 이 문서에 기록한다.

## 작업 절차

1. 구현 기준선과 개발자 2 인계물을 확인하고 실제 에셋 경로·규격·해시를 자동 검사한다.
2. Three.js를 로컬 의존성으로 추가하고 기존 게임 상태 모듈이 렌더러를 import하지 않는 경계를 고정한다.
3. 단일 캔버스, 고정 카메라, 배경·손님·스테이션·인터랙티브·VFX·전경 레이어를 구현한다.
4. `sceneLayout.js`에 `assembly`, `grill`, `counter` 프리셋과 안전 영역을 정의하고 0.25~0.45초 전환을 연결한다.
5. 개발자 2의 배경·작업대·재료·접시·캐릭터 에셋을 manifest 이름 그대로 로드해 지정 앵커에 배치한다.
6. 기존 조립 입력에 재료 들림, 이동, 짧은 정지, 관통과 꼬치 반동을 장면 좌표로 연결한다.
7. 기존 그릴 익힘·뒤집기·회수 상태를 Three.js 꼬치와 익힘 재질에 연결하고 별도 WebGL 캔버스를 제거한다.
8. 접시 선택과 주문 매트 클릭을 장면 핫스팟에 연결하고 접시가 손님 앞으로 이동한 뒤에만 반응을 시작한다.
9. `waiting→tasting→satisfied|neutral`과 탄 실패 `retry` 상태를 연결하고 재시작·탭 숨김에서 잔여 트윈과 타이머를 정리한다.
10. 주문·안내·공정 탭·결과 문구는 DOM으로 유지하고 얼굴·접시·작업 대상을 가리지 않게 배치한다.
11. 로딩 실패, WebGL 실패와 저사양 폴백을 구현하고 비활성 탭에서 렌더 루프를 정지한다.
12. 기존 78개 테스트를 통과시킨 뒤 `QA-001 v1.1.0`의 장면·반응·manifest·성능 검증을 추가한다.
13. `1280×720`, `1920×1080`의 8개 상태 캡처와 렌더 통계를 기록하고 차단·높은 결함을 제거한다.

## 의존성과 인계 조건

- 선행 작업: 개발자 1 작업 001~004 완료 결과인 `app@d3fd2c7`; 개발자 2 작업 001 완료
- 후속 작업: 없음. 1차 실제 게임 장면 검토 뒤 범위 확장은 새 spec·epic으로 생성
- 다른 개발자에게 제공할 입력·출력: 개발자 2는 manifest와 16개 이미지를 제공한다. 개발자 1은 이름·캔버스·앵커를 임의 변경하지 않고, 불일치가 있으면 구현 전에 문서 파이프라인으로 되돌린다.

## 완료 기준

- [ ] `d3fd2c7`의 기존 78개 테스트가 회귀 없이 통과한다.
- [ ] 인트로 없이 츠키오카의 네기마 주문이 있는 2.5D 영업 장면으로 시작한다.
- [ ] 배경·손님·활성 스테이션·인터랙티브·VFX·전경·DOM UI가 정의된 깊이로 표시된다.
- [ ] 같은 배경과 손님을 유지한 채 조립·그릴·서빙 프리셋이 빈 프레임 없이 전환된다.
- [ ] 조립 5단계, 양면 굽기, 뒤집기, 접시 회수와 전달이 기존 판정대로 동작한다.
- [ ] 접시 도착 뒤 맛보기와 `satisfied` 또는 `neutral`, 탄 실패 뒤 `retry`가 표시된다.
- [ ] 다시 시작과 탭 숨김·복귀가 장면·타이머·반응·애니메이션 상태를 함께 복원한다.
- [ ] 두 기준 뷰포트에서 주문 UI, 손님 얼굴, 접시와 작업 대상이 겹치거나 잘리지 않는다.
- [ ] manifest 16개가 정확히 로드되고 에셋 404·셰이더 오류·처리되지 않은 콘솔 오류가 0건이다.
- [ ] 캔버스와 렌더 루프가 각각 하나이며 드로우콜 30, 삼각형 50,000, DPR 1.5 예산 안이다.
- [ ] 8개 상태 캡처와 실제 GPU 평균 30 FPS 결과 또는 미측정 위험이 기록된다.
- [ ] 구현 위치, 실행·검증 방법, 결과와 남은 위험이 app 문서와 이 epic에 기록된다.
