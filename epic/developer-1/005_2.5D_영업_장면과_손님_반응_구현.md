## 목표

검증된 조립·굽기·서빙 상태 흐름을 바 안쪽 주인공이 고정 카운터 너머 츠키오카를 바라보는 Three.js 2.5D 가게 장면에 통합하고, 새 화면 계약으로 승인된 에셋을 사용해 접시 전달 뒤 맛보기와 품질별 반응까지 반복 가능한 1차 실제 게임 장면을 완성한다.

## 구현 기준선

1. **충족됨(2026-07-23).** `d3fd2c7`은 `app`의 `main`에 병합되었다(병합 커밋 `4aced51`, 이후 `f35b4c6`).
   더 이상 `agent/yakitori-vertical-slice`에서 시작할 필요 없이 `app@main`에서 시작한다.
2. 시작 직후 `npm run verify`가 통과해야 한다. 기준선 **종단 46개**는 그대로이고, **단위는 63개**다.
   늘어난 31개는 아래 4항의 비활성 손님 모듈 단위 테스트이며, 기존 단위 32개(`recipe` 7 + `gameState` 25)는
   변경 없이 포함된다. 종단에서 손님 런타임 테스트 8개는 플래그가 꺼져 있어 건너뛴다.
3. 개발자 2 작업 001의 16개 이미지는 존재 여부와 해시만 확인하며 새 화면 계약의 승인 근거로 사용하지 않는다.
4. **`app@main`에는 비활성 손님 시스템이 함께 들어와 있다.** `src/state/customer/`(상태 머신·유형·다중 슬롯
   재주문)와 `src/config/menu.js`가 `src/config/features.js`의 `CUSTOMER_SYSTEM_ENABLED=false`로 꺼져 있다.
   이 작업의 제외 범위(복수 주문, 대기 게이지)를 지키려면 **플래그를 켜지 않는다.** 손님의 정본 요구사항은
   `GPL-003`이며 재작업은 별도 작업으로 만든다. 이 작업에서 다루는 손님 반응은 `SCN-001`의 츠키오카
   `waiting→tasting→satisfied|neutral|retry`이고, 비활성 모듈과 무관하게 구현한다.
5. Artist 작업 002가 변경 범위를 확인하고 `BG-SEATING-6`, `BG-BAR-COUNTER-BASE`, P0 스테이션과 새 anchor metadata를 `ART-003 v2.0.0` 기준으로 승인해야 한다.
6. 위 조건을 충족하지 않으면 구현을 시작하지 않고 보류 사유를 이 문서에 기록한다.

## 진행 상황 (2026-07-23) — 더미 도형 착수

사용자 결정으로 **Artist 002 에셋 승인을 기다리지 않고 더미 도형으로 착수**한다. 승인된 아트가
오면 각 슬롯의 텍스처만 교체한다. 더미는 실제 manifest 에셋 ID·앵커에 매핑돼 있다.

- 착수: 기존 DOM 게임과 테스트를 깨지 않도록 **별도 진입점 `src/scene/`**에서 구현. 정식 승격은 후속.
- 구현: Three.js 단일 캔버스·rAF 루프, 레이어 0~6 더미 평면(배경·손님·고정 카운터·스테이션·인터랙티브·VFX·전경),
  셰프측 원근 카메라와 조립·그릴·카운터 프리셋(0.35초 ease-out), 앵커·가림선 계약,
  레이캐스트 입력, 츠키오카 `waiting→tasting→satisfied|neutral|retry` 반응.
- 검증: 장면 e2e 6개(두 뷰포트) — 렌더·전체 루프·탄 상태 retry. 기존 단위 89·DOM 게임 회귀 무손상.
- 셰프 시점 카메라 적용(2026-07-23): 정면 고정이 시차를 죽이던 문제 해결. 살짝 위·뒤에서 카운터 너머를
  내려다보는 홈 카메라 + 앵커→월드 unproject 진짜 깊이 배치로 교체. 프리셋(조립 좌·그릴 중앙 push-in·
  카운터 우)이 깊이를 통과 이동해 가까운 레이어는 많이·먼 레이어는 조금 밀리고(시차), 카운터가 손님을
  가린다. 더미 바닥 그리드로 깊이 보강. 개념 검증용 `depth-demo.html` 동봉.
- 정식 진입점 승격(2026-07-23): `src/scene/`를 정규 위치로 이동해 `/src/index.html`이 곧 2.5D 장면이
  되게 승격. DOM 뷰 은퇴. e2e를 레이캐스트(`screenPosOf`) 기반으로 통합(`helpers.js`·`vertical-slice`·
  `scene.spec`), DOM 전용 스펙 5개(layout·qa-scenarios·capture·assets·customer) 은퇴 — 로직은 단위 89개가
  유지, 손님 런타임 e2e는 GPL-003 재작업(dev-1/006)에서 장면 기준 재작성. 단위 89·장면 e2e 16(두 뷰포트) 통과.
- 남은 것: 익힘 셰이더를 Three.js 재질로 이식(현재는 더미 색), 8상태 캡처·드로우콜/삼각형 예산 측정,
  손님 하체 가림 등 구도 폴리시, 아트 텍스처 교체.

## 작업 절차

1. 구현 기준선과 개발자 2 인계물을 확인하고 실제 에셋 경로·규격·해시를 자동 검사한다.
2. Three.js를 로컬 의존성으로 추가하고 기존 게임 상태 모듈이 렌더러를 import하지 않는 경계를 고정한다.
3. 단일 캔버스, 셰프측 고정 카메라, 배경·손님·고정 카운터·스테이션·인터랙티브·VFX·전경 레이어를 구현한다.
4. `sceneLayout.js`에 `assembly`, `grill`, `counter` 셰프측 프리셋, 카운터 가림선과 손님측·플레이어측 안전 영역을 정의하고 0.25~0.45초 전환을 연결한다.
5. 승인 manifest의 배경·좌석·고정 카운터·작업대·재료·접시·캐릭터 에셋을 ID 그대로 로드해 지정 앵커에 배치하고, 레거시 결합형 좌석 이미지는 사용하지 않는다.
6. 기존 조립 입력에 재료 들림, 이동, 짧은 정지, 관통과 꼬치 반동을 장면 좌표로 연결한다.
7. 기존 그릴 익힘·뒤집기·회수 상태를 Three.js 꼬치와 익힘 재질에 연결하고 별도 WebGL 캔버스를 제거한다.
8. 접시 선택과 주문 매트 클릭을 장면 핫스팟에 연결하고 접시가 손님 앞으로 이동한 뒤에만 반응을 시작한다.
9. `waiting→tasting→satisfied|neutral`과 탄 실패 `retry` 상태를 연결하고 재시작·탭 숨김에서 잔여 트윈과 타이머를 정리한다.
10. 주문·안내·공정 탭·결과 문구는 DOM으로 유지하고 얼굴·접시·작업 대상을 가리지 않게 배치한다.
11. 로딩 실패, WebGL 실패와 저사양 폴백을 구현하고 비활성 탭에서 렌더 루프를 정지한다.
12. 기존 78개 테스트를 통과시킨 뒤 `QA-001 v1.2.0`의 장면·반응·manifest·성능·화면 방향 검증을 추가한다.
13. `1280×720`, `1920×1080`의 8개 상태 캡처와 렌더 통계를 기록하고 차단·높은 결함을 제거한다.
