## 목표

최신 기획의 **독립 손님 정보 화면·조립·그릴·드링크·서빙 화면**을 같은 플레이어 물리 위치와
공유 상태 위에서 전환할 수 있는 프로덕션 장면 구조로 정렬한다. 동시에 현 구현의 츠키오카 1인·네기마
1주문 장면은 폐기하지 않고 `SCN-001` 회귀·통합 테스트 화면으로 명시적으로 유지한다.

## 계약 분리와 우선순위

프로덕션 동작은 항상 `SYS-002 v3.0.0`, `UI-002 v5.24.0`, `UI-003 v1.0.0`, `GPL-003 v2.0.0`, `GPL-004 v1.1.0`,
`ART-002/003 v3.1.0`을 정본으로 한다. 이전 단일 수직 슬라이스 문서는 테스트 화면의 범위와
검증 절차에만 적용하며, 프로덕션 요구사항을 축소하거나 대체하지 않는다.

## 구현 기준선과 현재 구현 판정

1. `app@main`의 기존 단일 캔버스 구현(`src/index.html`, `src/main.js`, `src/render/sceneRenderer.js`,
   `src/config/sceneLayout.js`)은 **프로덕션 기본 화면이 아니라 `SCN-001` 테스트 화면**이다.
2. 해당 테스트 화면은 `CUSTOMER_SYSTEM_ENABLED=false`를 유지한다. 이 플래그를 켜거나 단일 장면을
   다중 손님 화면으로 확장하지 않는다.
3. 현재의 배경·손님 유지형 카메라 프리셋과 더미 슬롯은 테스트 전용이다. 프로덕션 프리셋은 독립 화면을
   활성화하고 동일한 플레이어 기준 공간에서 필요한 오브젝트만 보여야 한다.
4. 프로덕션용 최종 아트는 Artist 작업 009~021의 사용자 승인 뒤 작업 022가 인계한 manifest와 anchor metadata만 사용한다. 더미 아트로
   테스트 화면을 계속 실행할 수 있으나, 이를 프로덕션 장면 완료로 보고하지 않는다.

## 작업 절차

1. 현재 단일 손님 구현을 `SCN-001` 테스트 모드로 표기하고, 테스트·캡처·성능 결과의 적용 범위를 분리한다.
2. `sceneLayout`과 렌더러에 `UI-003`의 프로덕션 화면 프리셋 레지스트리(`SCR-SVC-CUSTOMERS/ASSEMBLY/GRILL/DRINK`)를 추가한다. 서빙은 별도 주화면이 아니라 손님 화면의 공용 완성품 dock·좌석 anchor·`OVR-SERVE-QUANTITY` 연결로 제공한다.
   프리셋은 같은 플레이어 기준 anchor를 사용하고, 이전처럼 카메라 x 위치를 이동해 장면을 공유하지 않는다.
3. 화면별 배경·고정 오브젝트·핫스팟·HUD 안전 영역을 manifest ID와 metadata로 등록하고, 전환 시 필요한
   레이어만 활성화한다.
4. 좌석 6개와 주문/그룹 표식의 표시 인터페이스, 공용 준비 목록·부분 제공 상태의 렌더 어댑터를 만든다.
   실제 손님 배정·대기·정리·자동 제공 상태 전이는 작업 006과 `GPL-004`에서 연결한다.
5. 좌/우·빠른 화면 전환, 상태 보존, 웹 접근성 입력과 빈 프레임·가림·44px 핫스팟을 검증한다.
6. 승인 아트를 적용한 프로덕션 화면별 캡처·manifest·성능 검증을 추가한다. 승인 전에는 테스트 화면의
   더미 회귀만 실행하고 결과를 분리 기록한다.

## 의존성과 인계 조건

- 단일 손님 테스트 화면은 현재 더미·회귀 에셋으로 계속 실행할 수 있으며 Artist 승인에 의해 중단되지 않는다.
- 프로덕션 화면 인수에는 Artist 작업 009~021의 개별 사용자 승인, 작업 022의 runtime 인계와 `ART-002/003`의
  독립 화면 manifest·anchor metadata가 필요하다.
- 작업 006은 이 작업이 **프로덕션** 손님 화면의 6석·주문 표식·공용 준비 목록 렌더 인터페이스를 제공한 뒤
  연결한다. 단일 손님 테스트 화면 완료는 작업 006의 선행 조건을 충족하지 않는다.
- 드링크의 실제 공정 완료와 최신 `GPL-004`의 자동 제공 계약은 작업 006의 다중 손님 활성화 전에 필요하다.

## 구현 및 검증 결과

- 현재 app 구현은 `SCN-001` 테스트 화면이다. 단일 츠키오카, 네기마, 지속 카운터 구도, 수동 주문 매트와
  `waiting→tasting→satisfied|neutral|retry` 반응을 제공한다.
- 익힘 셰이더가 grill-skewer에 실제로 물려 있다(`src/render/grillMaterial.js`). 절차적 네기마 텍스처 위에
  마이야르·그을음·타레 광택·숯불 반사를 데이터 구동 익힘값으로 렌더하고, 키 G 실시간 튜너로 시각
  파라미터를 조정한다. 판정 시간은 `content/processes/grill.json`이 소유하며 셰이더는 결과만 그린다.
- 테스트 검증 결과: 단위 108 통과, e2e 36(두 기준 뷰포트) 통과. SwiftShader 부하로 `workers 1·retries 1`.
  자동 측정은 드로우콜 11·삼각형 20·DPR 1·평균 58.9 FPS다.
- 로컬 주의: `playwright.config`의 webServer는 `python3`이라 Windows 환경에서는 `python -m http.server 8777`을
  먼저 띄우고 `reuseExistingServer`로 재사용해야 한다(CI·Linux는 그대로 동작).
- **프로덕션 화면 디렉터 증분 1(2026-07-26):** 별도 진입점 `src/game.html`/`game.js`에 독립 영업 화면
  구조 뼈대를 구축했다. 같은 `PLAYER_EYE`에서 파생한 화면별 시선 프리셋(손님=정면·조립/그릴=아래·
  드링크=옆)으로 4개 화면을 전환하고(`src/config/screenLayout.js`, `src/render/productionRenderer.js`),
  전환 상태 머신(`src/render/stationDirector.js`)이 좌·우/퀵 이동·급한 전환 수렴(§104)·전환 중 조작
  잠금(§71)을 담당한다. 조립·그릴은 기존 `gameState`·익힘 셰이더를 재사용하고, 완성품을 그릴 화면에서
  집어 손님 화면 serveMat으로 전달하는 화면 교차 서빙이 동작한다. 조리 job은 화면과 독립 진행한다.
  공용 렌더 순수 함수는 `src/render/sceneMath.js`로 추출해 테스트 화면과 공유한다.
