# 개발자 1 - 017 D3 타레 모모 주문·조리·선택적 토치 정합

- 상태: `대기`
- 담당자: `개발자 1`
- 우선순위: `P0`
- 현재 milestone에 필요한 이유: D3 주문의 `seasoning=tare`가 실제 조리 제작물로 전달되지 않고 모든 모모가 단일 타레 작업으로 합쳐지는 공개 경로 결함을 해소한다.
- 하지 않으면 막히는 stage gate: D3 전체 영업 사람 화면 검수와 정적 URL 공개 판정

## 목표

D3 주문의 `타레 모모` 표시와 `seasoning=tare`를 조립·그릴·반복 도포·재가열·공용 완성품·서빙까지 제작물별로 보존하고, 토치 없이도 적정 타레를 완성하되 선택적 토치로 불향 보너스를 얻는 실제 공개 조리 경로를 완성한다.

## 범위

### 포함

- 주문 카드·대기 제작물·그릴·완성품의 `타레 모모` 표시
- 주문 line의 `menuId`·`seasoning`을 조립 대기물과 그릴 슬롯까지 전달
- 제작물 고유 ID별 타레 도포 횟수·범위·재가열·과열 상태
- 양면 굽기 뒤 타레 붓 활성화, 도포 뒤 그릴 재가열과 반복 도포
- 토치 없는 적정 완료·회수와 선택적 토치 불향 보너스
- 소금 모모·타레 모모 혼합 주문과 복수 타레 모모의 독립 처리
- 화면 전환·일시정지·저장·복구 중 제작물별 상태 보존
- 실제 주문 접수부터 서빙까지의 단위·통합·Playwright 회귀

### 제외

- 네기마·카와 등 다른 메뉴의 신규 타레 조작 확장
- 타레·붓·음식 표면의 최종 아트 제작
- D4 실제 gameplay
- 조리 수치의 장기 밸런스 튜닝

## 작업 절차

1. 실제 D3 주문 접수→조립→그릴 회수 경로에서 `seasoning`이 사라지고 고정 `D3-MOMO-TARE-ACTIVE` ID로 합쳐지는 실패 테스트를 먼저 추가한다.
2. 제작 중 항목과 그릴 슬롯에 고유 ID·`menuId`·`seasoning`을 보존하고 snapshot schema를 호환 갱신한다.
3. 타레 모모만 제작물별 마감 상태로 보내며 소금·무양념 모모는 기존 회수 경로를 유지한다.
4. 타레 도포→재가열 반복과 부족·적정·과열 판정을 데이터 구동으로 구현한다.
5. 기존 필수 토치 판정을 선택적 보너스로 변경하고 토치 미사용 적정 완성품의 회수·서빙을 허용한다.
6. 주문 표시, 비활성 이유, 제작물별 타레 상태와 선택 토치 안내를 실제 UI에 연결한다.
7. 수정 전 구현 또는 결함 주입으로 소금 모모 오처리·두 번째 타레 모모 우회·토치 강제 회수가 각각 실패하는지 확인한다.

## 병렬·순차 계획

- 다른 역할과 병렬 가능한 범위: Artist 1 작업 026의 타레 음식 표면 상태, Artist 3 작업 024의 붓·타레통·상태 신호 제작
- 반드시 순차로 진행할 범위: 제작물 상태 계약과 stable state ID 확정 뒤 아트 runtime 연결, 그 뒤 통합 QA
- 동시 writer를 금지할 경로·stable ID·finalizer: `app`의 조립·그릴 제작물 schema, D3 타레 상태 ID와 snapshot migration은 이 작업이 단일 writer다.

- 필수 경로: 타레 모모 주문 접수→양면 굽기→타레 1회 부족→추가 도포·재가열 적정→토치 없이 회수, 별도 꼬치에서 선택 토치 불향 보너스, 소금 모모 혼합 처리

## 완료 기준

- [ ] 주문을 받을 때부터 `타레 모모`가 표시되고 `seasoning=tare`가 서빙까지 보존된다.
- [ ] 소금 모모는 타레 공정에 들어가지 않고 복수 타레 모모는 고유 ID로 독립 처리된다.
- [ ] 적정 반복 도포·재가열 뒤 토치 없이 Perfect·회수·서빙·영업 종료가 가능하다.

- [ ] 실제 공개 입력 E2E가 기존 강제 디버그 staging 없이 D3 주문부터 타레 모모를 완성한다.
- [ ] 수정 제거 또는 결함 주입 시 양념 누락·고정 ID 충돌·토치 강제가 각각 테스트 실패로 검출된다.
