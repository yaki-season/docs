- 문서 버전: `v1.0.0`
- 최종 변경일: `2026-07-23`
- 상태: `대기`
- 담당자: `개발자 1`

## 참조 spec

## 목표

한 영업일 루프를 렌더링 없이 순수 상태로 구현한다. 영업 시작부터 손님 도착·주문·조리 연결·서빙·
퇴장 반복을 거쳐 영업 종료·정산 지표까지 도는 골격을 만들고, 수치는 코드 상수가 아니라 데이터에서
읽는다. 이 로직은 게임·시뮬레이터·자동 테스트가 함께 쓰는 단일 원본이 된다.

## 배경

아트(작업 005)와 최종 밸런스 수치가 확정되기 전에도 게임 로직은 만들 수 있다. 수치를 데이터에서
읽으면(작업 `developer-3/001`) `GPL-002`·`GPL-003`의 미해결 수치가 코드를 막지 않는다.
placeholder `candidate` 값으로 로직을 짜고 기획자가 도구(`developer-3/002`)로 조율한다.

## 범위

### 포함

- 영업일 루프 상태 모델: 영업 시작 → (손님 생성 → 주문 → 조리 연결 → 서빙 → 결과 집계 → 반복) → 영업 종료
- 렌더링·DOM과 분리된 순수 상태 함수. 모의 시간으로 구동
- 손님 생성과 주문을 데이터의 파동·간격 수치로 제어 (`GPL-002` 러시 파동 골격)
- 서빙 결과의 정산 지표 집계: 매출·팁·실패·이탈·평균 대기·품질 분포
- 기존 조리 상태(`gameState`)와 휴면 손님 로직(`src/state/customer/`)을 이 루프에 최소 연결
- 수치는 `developer-3/001`의 데이터·로더에서 읽음
- 무작위 요소의 시드 고정과 결과 재현성

### 제외

- 좌석 6석·2인 그룹·대기 게이지 가동·러시 우선순위의 완전 구현 (`GPL-003` 상세 → 작업 006)
- 30일 캠페인 진행·성장·해금 (`GPL-002` 캠페인 → 후속 작업)
- 2.5D 렌더링과 장면 (`작업 005`)
- 밸런스 편집 UI·시뮬레이터 (`developer-3/002`)
- 최종 수치 결정

## 작업 절차

1. 영업일 루프 상태 모델과 전이를 렌더링과 분리해 정의한다.
2. `developer-3/001`의 데이터·로더에서 손님 간격·조리 시간·인내심 등 수치를 읽어 연결한다.
3. 손님 생성 → 주문 → 조리 연결 → 서빙 → 결과 집계 반복을 모의 시간으로 구동한다.
4. 기존 조리 상태와 휴면 손님 로직을 이 루프에 최소 범위로 연결한다(완전한 좌석·그룹은 작업 006).
5. 영업 종료 시 정산 지표를 집계한다.
6. 시드 고정으로 결과 재현성을 보장한다.
7. 루프 전체를 모의 시간 자동 테스트로 검증한다.

## 의존성과 인계 조건

- 선행 작업: `developer-3/001_밸런스_데이터_파일과_로더_검증.md` 완료
- 후속 작업: `developer-3/002`(시뮬레이터가 이 루프를 재사용), `developer-1/006`(손님 좌석·그룹 상세),
  `developer-1/005`(이 로직을 2.5D 장면에 연결)
- 다른 개발자에게 제공할 입력·출력: `developer-3/002`에 영업일 루프 실행 API와 정산 지표 구조를,
  작업 005에 렌더링이 붙일 상태 전이 지점을 인계한다.

## 완료 기준

- [ ] 한 영업일 루프가 영업 시작부터 종료까지 렌더링 없이 실행된다.
- [ ] 손님 도착·주문·서빙·퇴장이 반복되고 영업 종료 조건에서 멈춘다.
- [ ] 조리 시간·손님 간격 등 수치가 데이터에서 읽히고 코드 상수로 남지 않는다.
- [ ] 영업 종료 시 매출·팁·실패·이탈·평균 대기·품질 분포가 집계된다.
- [ ] 같은 수치·같은 시드가 같은 결과를 낸다.
- [ ] 루프 전체가 모의 시간으로 자동 검증된다.

## 구현 및 검증 결과

- app 구현 위치: 미구현
- 구현 기준 spec 버전: `GPL-002 v1.0.0`, `GPL-003 v1.0.0`, `DAT-001 v1.0.0`
- 구현 기준 태스크 버전: `v1.0.0`
- 검증 방법: 구현 후 기록
- 검증 결과: 미실행
- 남은 위험
  - `GPL-002`·`GPL-003`이 `초안`이라 루프 구조가 바뀔 수 있다. 미해결은 대부분 수치라 데이터로
    흡수하지만, 러시 파동·정산 구조 등 규칙이 바뀌면 재작업이 있을 수 있다.
  - 좌석·2인 그룹 완전 구현은 작업 006이므로, 이 골격의 손님 모델은 단순화 버전이다.
