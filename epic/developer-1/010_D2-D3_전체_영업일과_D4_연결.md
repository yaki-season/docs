## 목표

D2와 D3를 각각 영업 준비·전체 영업·정산·저장으로 완성하고, D3 정산 뒤 저장을 훼손하지 않는
읽기 전용 D4 개발 예고 상태까지 연결한다.

## 사용자 확정 실행 조건

- D2·D3는 대표 장면이 아니라 각각 전체 영업일이다.
- D2는 D1 도움을 줄이고, D3는 타레 공정과 그릴·드링크 교차 관리를 도입한다.
- 기능이 완성된 날짜는 아트 placeholder가 남아 있어도 단일 공개 URL에 순차 개방한다.
- D4는 경고 확인 뒤 들어가는 읽기 전용 예고이며 보상·주문·저장을 바꾸지 않는다.

## 범위

### 포함

- D2 전체 영업·정산·저장과 D3 개방

- D3 타레 붓 공정, 그릴·드링크 교차 주문과 화면 밖 상태 보존
- D3 정산·저장 뒤 `D4-preview` 상태 개방
- 날짜별 기능 gate와 공개/비공개 상태

### 제외

- D4 실제 영업·보상·정산·콘텐츠
- D2·D3 서비스·이야기·정산 아트 제작 — Artist 3 작업 024
- D2·D3 음식 모델·shader 제작 — Artist 1 작업 026
- D4 이후 메뉴·성장·시나리오

## 작업 절차

1. 작업 009의 영업일 aggregate를 날짜별 콘텐츠로 반복 실행할 수 있게 일반화한다.
2. D2 도움 감소와 복습 상황을 구현한다.
3. D3 타레 공정과 교차 주문을 `GPL-004` 판정에 연결한다.
4. 각 날짜 정산·체크포인트·다음 날 개방을 작업 008에 연결한다.
5. D4-preview를 읽기 전용 상태로 만들고 gameplay command를 거부한다.
6. D2·D3 각 날짜의 독립 종단과 D1→D3 연속 종단을 검증한다.
7. 날짜별 기능이 동결될 때 `screenId/stateId/componentId/requiredAssetId` placeholder inventory를
   Artist 1 작업 026·Artist 3 작업 024와 개발자 2 작업 006에 증분 인계한다.

- 타레 도포·토치 범위·집중 시간·완료 상태와 저장 복원을 구현한다.
- 부족/적정/과다/집중 과열 품질, 화재 위험·안전 자원 소모, 회수·서빙·종료 차단을 연결한다.

- 토치 도구·화염·완성 꼬치 VFX/SFX stable ID를 연결하고 직원 자동 조리에도 같은 판정을 적용한다.

### 구현 증분 1 — 저장 가능한 순수 도메인

- 양면 굽기·타레 선행 조건, 안전 차단, 완료 전 회수 차단을 구현했다.

- 전용 5개와 전체 Vitest 373개를 통과했다. 실제 D3 메뉴·그릴 UI·저장 envelope 연결은 다음 증분이다.

### 구현 증분 2 — D3 메뉴·그릴·런타임 저장 연결

- D3 첫 주문을 확정안대로 `타레 모모 1 + 생맥주 1`로 변경했다.
- 8명·7주문·16항목, 첫 타레 모모, `d4-preview` 전환을 고정한 D3 전체 영업 definition과 loader를 추가했다.
- `?day=d3`가 D3 definition을 소비하도록 실제 영업 화면 진입 분기를 연결했다.
- 양면 조리 완료 메뉴를 seasoning별 후처리로 넘기는 `d3GrillSession`을 추가했다. 타레 모모만 토치를 강제하고 일반·소금 메뉴는 기존 품질로 회수한다.
- 토치 진행 상태를 브라우저 영업 런타임 snapshot에 포함해 새로고침 후 coverage·집중 시간·완료 상태를 복원한다.
- 전용 10개와 전체 Vitest 378개를 통과했다. 실제 토치 조작 UI·게이지·과열 경고와 E2E는 다음 증분이다.

### 구현 증분 3 — 실제 토치 입력 UI와 E2E

- D3에서만 보이는 타레 모모 토치 패널을 추가하고 `타레 바르기 → 토치 홀드·좌우 스윕 → 회수`를 실제 입력으로 연결했다.
- 적용 범위 progressbar, 텍스트 상태, 집중 과열 경고를 제공하며 색만으로 판정을 전달하지 않는다.
- 포인터·터치의 hold/sweep과 키보드 `Space + ←/→` 대체 입력을 지원한다.
- 미완료 회수 버튼을 비활성화하고 적정 완료 시 Perfect·불향 모모를 공용 준비 목록에 추가한다.
- 토치 진행 중 새로고침 후 coverage를 복원하고 완료·회수하는 Chromium 1280×720 E2E 1/1을 통과했다.

### 구현 증분 4 — D1→D3 전체 영업 종단과 D4-preview 재개

- D1·D2·D3의 모든 손님·주문을 처리하고 마지막 좌석 정리 뒤 조기 마감, 숯불, 5단계 정산, 저장까지 연속 검증했다.
- D3 러시 3주문을 `maxActiveOrders=2`로는 한 wave에서 출현시킬 수 없던 오류를 발견해 2주문+1주문 순차 wave로 분리했다. 총 8명·7주문·16항목은 유지한다.
- D3 완료 뒤 `d4-preview/preview` 저장을 브라우저 세션이 완료 상태로 재개하지 못하던 조건을 수정했다.
- D3 중복 finalize가 정산·보상을 다시 적용하지 않고, 재로드 뒤에도 D4-preview가 유지되는 통합 종단 1/1을 추가했다.
- 전체 Vitest 380/380을 통과했다. 남은 핵심은 실제 브라우저에서 8명 영업을 조작하는 Playwright 종단과 D4 gameplay command 거부 확인이다.

### 구현 증분 5 — 브라우저 D3 종단과 D4 명령 거부

- Chromium 1280×720에서 D3 8명·7주문을 처리하고 마지막 좌석 정리, 숯불, 5단계 정산, D4-preview 전환까지 실제 브라우저 종단 1/1을 통과했다.
- campaign runtime이 preview 상태에서 `begin-day`, `enter-settlement`, `complete-day`를 `CAMPAIGN_PREVIEW_READ_ONLY`로 거부하도록 고정했다.
- 거부된 D4 명령에 임의 보상·해금을 포함해도 메모리 상태와 저장소 snapshot이 바뀌지 않는 것을 통합 검증했다.
- 기존 공개 shell D4 읽기 전용 E2E 1/1과 D3 토치·전체 영업 E2E 2/2, 전체 Vitest 380/380을 통과했다.
- 남은 완료 기준은 D2 도움 감소 정책, 화면 전환 중 그릴·드링크 상태 보존, 날짜별 공개 gate 최종 확인이다.

### 구현 증분 6 — 도움 감소·화면 보존·공개 gate 완료

- D1 순차 가이드는 D1에만 유지하고 D2는 기본 접힘 복습 도움, D3는 타레·토치 신규 행동 안내로 분리했다. D2 도움은 `전체 보기`로 언제든 다시 펼칠 수 있다.
