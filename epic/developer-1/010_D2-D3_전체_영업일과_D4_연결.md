## 목표

D2와 D3를 각각 영업 준비·전체 영업·정산·저장으로 완성하고, D3 정산 뒤 저장을 훼손하지 않는
읽기 전용 D4 개발 예고 상태까지 연결한다.

## 사용자 확정 실행 조건

- D2·D3는 대표 장면이 아니라 각각 전체 영업일이다.
- D2는 D1 도움을 줄이고, D3는 타레 공정과 그릴·드링크 교차 관리를 도입한다.
- 기능이 완성된 날짜는 아트 placeholder가 남아 있어도 단일 공개 URL에 순차 개방한다.
- D4는 경고 확인 뒤 들어가는 읽기 전용 예고이며 보상·주문·저장을 바꾸지 않는다.

## 범위

### 포함

- D2 전체 영업·정산·저장과 D3 개방
- D1에서 성공한 안내의 단계적 제거와 도움말 다시 켜기
- D3 타레 붓 공정, 그릴·드링크 교차 주문과 화면 밖 상태 보존
- D3 정산·저장 뒤 `D4-preview` 상태 개방
- 날짜별 기능 gate와 공개/비공개 상태

### 제외

- D4 실제 영업·보상·정산·콘텐츠
- D2·D3 서비스·이야기·정산 아트 제작 — Artist 3 작업 024
- D2·D3 음식 모델·shader 제작 — Artist 1 작업 026
- D4 이후 메뉴·성장·시나리오

## 작업 절차

1. 작업 009의 영업일 aggregate를 날짜별 콘텐츠로 반복 실행할 수 있게 일반화한다.
2. D2 도움 감소와 복습 상황을 구현한다.
3. D3 타레 공정과 교차 주문을 `GPL-004` 판정에 연결한다.
4. 각 날짜 정산·체크포인트·다음 날 개방을 작업 008에 연결한다.
5. D4-preview를 읽기 전용 상태로 만들고 gameplay command를 거부한다.
6. D2·D3 각 날짜의 독립 종단과 D1→D3 연속 종단을 검증한다.
7. 날짜별 기능이 동결될 때 `screenId/stateId/componentId/requiredAssetId` placeholder inventory를
   Artist 1 작업 026·Artist 3 작업 024와 개발자 2 작업 006에 증분 인계한다.

## 의존성과 인계 조건

- 선행 작업: 개발자 1 작업 008·009, 개발자 2 작업 004·005, 개발자 3 작업 005
- 후속 작업: 개발자 2 작업 006, Artist 1 작업 026, Artist 3 작업 024
- placeholder와 승인 아트의 치환은 gameplay 상태 ID를 바꾸지 않는다.
- Artist 작업은 이 태스크 전체 완료를 기다리지 않고 날짜별 stable ID handoff가 나온 pack부터
  병행할 수 있다. 이미 인계한 ID의 의미를 변경해야 하면 새 ID와 호환성 영향을 기록한다.
