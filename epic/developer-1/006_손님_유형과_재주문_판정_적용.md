## 목표

작업 005의 손님 상태 머신 위에 손님 유형 4종을 적용한다. 다중 슬롯 재주문과 유형별 판정 차이,
반응(mood)이 `GPL-002` 정의대로 동작하는 것을 자동 검증한다.

## 범위

### 포함

- 다중 슬롯 순서열 소비와 재주문(식사 후 다음 슬롯 있으면 `Ordering`으로 복귀)
- 퇴근직장인 `[꼬치, 꼬치]`로 다중 슬롯 재주문 검증(음료 슬롯은 드링크 스테이션 도입 시 복원)
- 혼술족(데이터) 유지, 값만 다른 유형은 데이터로 표현
- 미식블로거 판정 파생: 양면 perfect 아니면 낮은 판정, 리뷰 결과값 기록
- 커플 판정 파생: 양면 perfect일 때 팁 보너스
- mood(`happy / meh / angry`)를 판정 결과에 연결해 반응 표시
- 유형별 손님 스폰(고정 또는 순환)

### 제외

- 취객(방해 상태)과 커플 플레이팅 정식 판정, 멀티 손님(2차)
- 인내심 감소와 시간 초과 퇴장
- 리뷰의 다음 영업일 손님 수 반영
- 유형별 팁 배율·판매가의 밸런스 확정 수치

## 작업 절차

1. 작업 005의 순서열 소비를 다중 슬롯로 확장하고 식사 후 재주문 복귀를 연결한다.
2. 퇴근직장인 `[꼬치, 꼬치]` 순서열로 재주문 루프를 검증한다.
3. 미식블로거 판정 파생과 리뷰 결과값 기록을 구현한다.
4. 커플 판정 파생(양면 perfect 보너스)을 구현한다.
5. 값만 다른 유형(혼술족)은 데이터로 두고, 판정이 다른 유형만 파생임을 유지한다.
6. 판정 결과를 mood에 연결하고 반응 연출을 표시한다.
7. 유형별 스폰과 각 유형의 종단 흐름을 자동 검증한다.

## 구현 및 검증 결과

- app 구현 위치
  - `app/src/state/customer/types.js` — 혼술족·퇴근직장인(데이터), 미식블로거·커플(판정 파생), 유형 순환 스폰
  - `app/src/state/customer/customer.js` — 슬롯 종합 판정(`overallSatisfaction`)과 누적 mood
  - `app/src/main.js` — 유형 순환 스폰, 재주문 시 조리만 초기화, 결과 표시 시점 조정
  - `app/tests/unit/customerTypes.test.js` — 유형별 순서열·판정·재주문 모의 시간 검증
  - `app/tests/e2e/customer.spec.js` — 재주문 런타임 검증(꼬치 2개 요구)
- 구현 기준 spec 버전: `GPL-002 v1.0.0`, `DATA-001 v1.0.0`, `GPL-001 v1.0.0`
- 구현 기준 태스크 버전: `v1.0.0`
- 검증 방법
  - `npm run verify` — 단위 63개, 종단 54개(`1280×720`, `1920×1080`)
  - 다중 슬롯 재주문은 단위(모의 시간)와 런타임 종단 양쪽에서 검증. 종단 테스트는 실제로
    꼬치 3개를 구워 첫 서빙 뒤 결과창이 뜨지 않고 조리만 초기화되는지 확인한다.
- 검증 결과: `2026-07-22` 기준 전부 통과
- 설계 반영 사항
  - 재주문이 base 기능이므로 퇴근직장인은 서브클래스가 아니라 **순서열 데이터**로 구현했다.
    실제 파생은 판정이 다른 미식블로거·커플뿐이다 (`GPL-002 §10`).
  - 다중 슬롯 손님은 중간 서빙에서 결과창을 띄우지 않고, 모든 슬롯을 마치고 퇴장할 때만
    결과를 표시하도록 조정했다.
  - mood는 누적 경험을 반영한다(한 슬롯이라도 나쁘면 완전 만족이 아님).
- 남은 위험
  - 드링크 스테이션 부재로 퇴근직장인이 `[꼬치, 꼬치]`로 축약돼 "일단 생맥 → 안주" 손맛은 미검증이다.
  - 취객(방해 상태)·커플 플레이팅 정식 판정·인내심 감소는 2차 범위로 남아 있다.
  - 팁 배율·만족도 수치는 잠정값이며 밸런스 확정이 필요하다.
