## 배경(확인된 개발 갭)

- 배치 메커니즘(`src/render/cookStations.js` `createCookStations({slots, initialBatchSize})`의
  staged → 동시 시작)은 개수 무관하게 파라미터화돼 있다.
- 그러나 D1 첫 손님 슬라이스 `src/d1-game.js`는 구 규격 그대로다:
  `createD1CookStations()` = `createCookStations({slots:6, initialBatchSize:3})`(고정 6칸·batch 3),
  `SLOT_KEYS=D1_GRILL_SLOT_KEYS`(6칸), 튜토리얼 힌트가 "첫 3개 동시 시작 / 3개 동시 조리 시작"으로 하드코딩됨
  (`src/d1-game.js:689-690`, 프로덕션 `src/game.js:336-337`도 동일 하드코딩).
- 가변 슬롯 리팩터는 `game.js`만 이관했고 D1 공개 슬라이스는 미이관이다.

## 목표

D1 첫 손님 슬라이스를 고정 6칸·batch 3에서 `DAT-001 v5.25.0`·`GPL-005 v2.23.0`의 명성 해금
가변 시작 2칸·네기마 2개 batch로 이관하고, "함께 올려 동시 시작" 튜토리얼 힌트를 하드코딩 3 제거·
데이터 구동(`initialBatch.required`)으로 정합해 실제로 구동되게 한다.

## 범위

### 포함

- `src/d1-game.js`: `createD1CookStations()`(6/3) → 개발자 3 작업 012 계약 값 기반
  `createCookStations({slots: 시작 2, initialBatchSize: 2})` 배선(명성 해금 가변 칸 포함)
- 그릴 geometry: 고정 6칸(`D1_GRILL_SLOTS`/`D1_GRILL_SLOT_KEYS`) → 가변 시작 2칸
  (`screenLayout.computeGrillSlots`/`GRILL_SLOT_KEYS` 방식)과 해금 시 재배치
- 튜토리얼 힌트 데이터 구동: `d1-game.js:689-690`·`game.js:336-337`의 "첫 3개/3개"를
  `initialBatch.required`·`remainingForBatch` 실제 값으로 표시("첫 N개 동시 시작 · 꼬치 M개를 더 올리세요")
- `d1-full-first-order-guide` 안내 순서를 2개 배치·동시 시작으로 정합
- 하드코딩 3/6 잔재 제거(주석 `game.js:33` 포함)

### 제외

- D1 첫 주문·contract·release 데이터(개발자 3 작업 012)
- 아트·placeholder, 손님/좌석/정산 로직

## 병렬·순차 계획

- 개발자 3 작업 012(데이터·계약)가 선행이며, 그 계약 값을 소비해 런타임을 배선한다.
- `cookStations.js` 순수 로직은 변경 불필요(파라미터만 2로 전달). 필요 시 최소 확장만 한다.

## 작업 절차

1. 개발자 3 작업 012의 계약 값(placementCount 2, placementSlots [1,2], 시작 2칸)을 수신한다.
2. `d1-game.js`의 조리 스테이션 생성을 시작 2칸·`initialBatchSize=2`로 배선한다.
3. D1 그릴 geometry를 가변 시작 2칸으로 이관하고 명성 해금 시 재배치를 연결한다.
4. 튜토리얼 힌트를 `initialBatch.required`·`remainingForBatch` 데이터 구동으로 교체한다.
5. 첫 손님이 네기마 2개를 두 칸에 staged 후 동시 active로 시작하는 경로를 FHD/720 E2E로 검증한다.
6. 하드코딩 3/6 잔재를 제거하고 전체 회귀를 통과시킨다.
