# 개발자 1 - 020 D6 겹치는 파동 도착과 만석 운영

- 상태: `대기`
- 담당자: `개발자 1`
- 우선순위: `P0`
- 현재 milestone에 필요한 이유: 현재 `spawnEligibleWaves`는 파동마다 앞 주문 완료를 기다리므로 동시 착석이 최대 2명이다. 좌석은 6석인데 만석이 구조적으로 발생하지 않는다.
- 하지 않으면 막히는 stage gate: D6 첫 만석, 활성 주문 3건 동시 운영, D6 완료와 D7 해금

## 목표

파동이 앞 파동의 주문 완료를 기다리지 않고 시각으로 겹쳐 도착하게 만든다. 첫 파동 보호와 활성 주문 상한은 유지해, 만석이 "먼저 온 손님이 식사하는 동안 새 손님이 앉는" 방식으로만 발생하게 한다. D6 완료를 `day-d6-completed`로 한 번만 저장하고 D7을 해금한다.

## 범위

### 포함

- `spawnEligibleWaves`의 도착 판정을 파동 시각 기반으로 일반화. 첫 파동 배타 규칙은 유지
- 도착이 활성 주문 상한과 빈 좌석 부족으로 미뤄지고, 조건이 풀리면 미도착 파동이 들어오는 규칙
- 그룹의 인접 좌석 요구를 만석 근처에서도 지키고 흩어 앉히지 않는 처리
- 6석 동시 점유 상태의 좌석·주문·인내심 snapshot과 복구
- `arrivalsClosed` 이후 미도착 파동을 들이지 않는 처리와 계획 drain 판정
- D6 완료 조건과 `day-d6-completed` 멱등 저장, D7 해금

### 제외

- D6 release 데이터 — Developer 3 작업 016
- 좌석 표시·말풍선 겹침 — Developer 2 작업 017
- 신규 조리 규칙. D6는 조리를 바꾸지 않는다
- 부채 — D7 이후

## 작업 절차

1. 현재 도착 판정(첫 파동 배타, 완료 게이트, 상한 게이트, 인접 좌석)을 characterization test로 고정한다.
2. 완료 게이트를 데이터가 비어 있으면 건너뛰도록 바꾸고 D1~D5 정의의 기존 동작이 그대로인지 회귀로 확인한다.
3. 도착이 미뤄진 파동이 사라지지 않고 조건 충족 시 들어오는지 시뮬레이터 테스트로 고정한다.
4. 6석 동시 점유 상태에서 정리·퇴장·재도착이 순환하는지 확인한다.
5. 만석 중 일시정지·화면 전환·새로고침 복구를 snapshot 테스트로 고정한다.
6. D6 완료 predicate와 저장을 추가하고 중복 적용이 없는지 확인한다.
7. Developer 2에 좌석 점유 view model을 인계하고 구현자가 graybox에서 만석 구간을 직접 플레이한다.
