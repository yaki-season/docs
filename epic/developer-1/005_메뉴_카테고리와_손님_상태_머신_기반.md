## 목표

메뉴 카테고리 데이터와 검증 규칙을 정의하고, 요리사와 분리된 손님 상태 머신 기반을 구현한다.
혼술족 손님 1명이 입장부터 퇴장까지 전체 상태를 돌고, 서빙 판정을 손님이 소유하며, 재시작으로
초기화되는 것을 자동 검증한다.

## 범위

### 포함

- `DATA-001` 카테고리 5종·스테이션 대응·중복 규칙을 단일 데이터로 정의하고 순서열 검증 구현
- 요리사(조리 리듀서)와 분리된 손님 엔티티 도입, 공유 상위 클래스 없음
- 손님 상태 `Entering / Ordering / Waiting / Eating / Leaving`와 시간 구동 전이
- 카테고리 순서열 소비: 단일 슬롯(`[꼬치]`) 기준 `Ordering→Waiting→Eating→Leaving`
- 서빙 접점에서 손님이 만족도·mood·팁을 계산(판정 소유). 요리사는 판정하지 않음
- 서빙 카테고리와 대기 슬롯 불일치 시 무시
- 인내심 게이지 골격 표시(감소 비활성)
- 재시작 시 손님 상태·슬롯·mood·판정 초기화
- 상태·판정을 렌더링과 분리해 모의 시간으로 검증

### 제외

- 다중 슬롯 재주문과 손님 유형별 판정 차이(작업 006)
- 취객·커플 정식·멀티 손님·좌석·인내심 감소(2차)
- 드링크·튀김·사시미·즉시제공 스테이션 조리 구현
- 팁·판매가 밸런스 수치, 리뷰의 다음 날 반영

## 작업 절차

1. `DATA-001` 카테고리·스테이션·중복 규칙을 한 위치의 데이터로 정의한다.
2. 주문 순서열 검증(미정의 카테고리·중복 불허 위반)을 런타임 전 검출로 구현한다.
3. 손님 엔티티와 5개 상태, 시간 구동 전이를 조리 리듀서와 분리해 구현한다.
4. 단일 슬롯 순서열 소비와 `Waiting`의 외부 서빙 이벤트 전이를 연결한다.
5. `gameState`의 서빙 지점에서 카테고리 포함 payload로 `onServed`를 호출하고, 손님이 판정하도록 배선한다.
6. mood와 인내심 게이지 골격(비활성)을 화면에 연결한다.
7. 재시작이 손님 상태를 초기화하도록 `SYS-001` 재시작과 정합시킨다.
8. 카테고리 검증과 손님 상태·판정을 모의 시간으로 자동 검증한다.

  - `app/tests/e2e/customer.spec.js` — 런타임 생명주기·게이지 검증

- 구현 기준 태스크 버전: `v1.0.0`

  - `npm run verify` — 단위 63개, 종단 54개(`1280×720`, `1920×1080`)
  - 손님 상태 전이·판정·숨김 복귀는 모의 시간 주입으로 브라우저 없이 검증
- 검증 결과: `2026-07-22` 기준 전부 통과
- 설계 반영 사항
  - 요리사가 판정하지 않도록 `gameState`에서 `servedQuality`를 제거하고, 원면 결과만 손님에게
    전달해 손님이 만족도·mood·팁을 계산하도록 옮겼다 (`GPL-002 §5`).
- 구현 중 발견·수정한 결함
  - 인내심 게이지 요소를 `id`로 조회했으나 HTML에 `id`가 없어 손님이 대기 상태가 되는 순간
    `render()`가 예외로 중단되고 이후 화면이 전혀 갱신되지 않았다(e2e 15건 실패로 발견).
    `id` 부여로 수정하고, 같은 유형의 누락을 부팅 시점에 크게 실패시키는 UI 참조 검증을 추가했다.
- 남은 위험
  - 손님이 주문(Waiting)하기 전에도 조리를 시작할 수 있다. 조리 시간이 손님 주문 시간보다
    충분히 길어 실사용 문제는 없으나, 엄밀한 게이팅은 하지 않았다.
  - 인내심 감소·멀티 손님은 2차 범위라 골격만 있다.
