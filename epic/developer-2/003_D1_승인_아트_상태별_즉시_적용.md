## 목표

Artist 000에서 사용자 승인된 D1 개별 상태를 스테이션 묶음 완료까지 기다리지 않고, 승인·해시·anchor·
승격 게이트를 충족하는 즉시 해당 gameplay 상태에 안전하게 적용한다.

## 사용자 확정 실행 조건

- 생 네기마·익는 중처럼 개별 상태가 승인될 때마다 바로 runtime 적용한다.
- 아직 승인 아트가 없는 상태는 명시적 단순 도형과 `개발 중` 라벨로 표시한다.
- 구형 아트나 가장 가까운 승인 상태를 미완성 상태의 대체물로 사용하지 않는다.
- 조립·그릴·드링크 클릭 조작에서 플레이어 신체 부위를 표시하지 않는다.

## 범위

### 포함

- 승인 상태별 runtime handoff 검증, dry-run, 일회성 영수증과 명시적 write
- manifest ID·URL·SHA·anchor·bounds·상태 ID 연결
- 정확히 일치하는 상태에만 승인 에셋을 표시하는 렌더 어댑터
- 미승인 상태 전용 개발 placeholder와 정식 manifest ID 분리
- `1920×1080`·`1280×720` 상태별 시각·입력 회귀

### 제외

- 에셋 생성·수정·재승인 — Artist 000 책임
- 프로덕션 독립 화면 구조 — 개발자 1 작업 005 책임
- 조리 판정·타이머·품질 상태 변경
- review 파일·원본 파일의 직접 복사 또는 manifest 수동 편집

## 작업 절차

1. Artist 000의 승인 bundle과 finalizer 결과를 상태별 인수 목록으로 만든다.
2. 각 항목을 promotion dry-run으로 검증하고 영수증 확인 뒤 원자적으로 승격한다.
3. gameplay 상태 ID와 manifest ID를 1:1 또는 명시적 합성 계약으로 연결한다.
4. 미승인 상태에는 별도 개발 placeholder component만 렌더링한다.
5. 승인 항목 추가마다 manifest·FHD/720·회귀 테스트를 실행한다.
6. 모든 D1 사용자 노출 상태가 승인 아트인지 공개 게이트에서 집계할 수 있게 한다.
