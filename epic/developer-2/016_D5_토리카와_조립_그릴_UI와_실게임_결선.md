# 개발자 2 - 016 D5 토리카와 조립·그릴 UI와 실게임 결선

- 상태: `진행 중`
- 담당자: `개발자 2`
- 우선순위: `P0`
- 현재 milestone에 필요한 이유: D5 토리카와는 기존 조립·그릴 화면을 재사용하지만 같은 재료 5회, 더 짧은 굽기, 소금·타레 마감과 신규 asset을 실제 입력·화면 상태에 연결해야 한다.
- 하지 않으면 막히는 stage gate: 토리카와 실제 조작, 준비 목록·테이블 표시, D5 전체 영업 사람 플레이

## 목표

현재 조립·그릴·타레 화면을 날짜 중립 component로 유지하면서 토리카와의 `0/5~5/5`, 소금·타레,
짧은 양면 굽기와 선택적 토치를 실제 포인터 입력에 연결한다. 주문 카드, 준비 목록, 손님 테이블과
정산까지 `kawa`를 일관된 `토리카와` 표시명·승인 asset으로 보여 주고 D5 전체 영업을 플레이 가능하게 한다.

## 범위

### 포함

- `kawa` 표시명 `토리카와`, 설명 `닭껍질 꼬치`, 소금·타레 recipe 선택 UI
- 접은 닭껍질 한 종류 클릭과 다음 빈 위치 자동 배치, `0/5~5/5` 진행 표시
- 기존 조립 screen shell·station navigation·공용 prepared dock을 재사용한 날짜 중립 결선
- 메뉴별 굽기 view model을 소비하는 토리카와 raw/cooking/proper/over/burnt 상태 binding
- 타레 도포·재가열 2회, 토치 선택/시작 후 완료, 토치 없이 회수 가능한 행동 UI
- 정확한 초·적정 하이라이트·탭 점멸 없이 정성적 레시피 노트와 현재 행동 피드백만 제공
- 주문 카드·완성품 dock·손님 테이블·식사·정산의 토리카와 아이콘과 소금/타레 구분
- D4 완료→D5 pre-open→영업→정산의 일반 UI 전환과 FHD·1280×720 레이아웃
- Artist 028 승인 pack의 requiredAsset/component contract, promotion과 manifest binding

### 제외

- 조리 품질·완료 조건·snapshot 판정 — Developer 1 작업 019
- D5 release data·schema·loader — Developer 3 작업 015
- source 아트 생성과 수정 — Artist 1 작업 028
- 단계형 튜토리얼·적정 시간대 하이라이트와 D6 부채 UI

## 작업 절차

1. `d1-game.js`·`cookStations.js`·조립/그릴 renderer의 메뉴별 하드코딩과 현행 component/asset contract를 실제 호출 경로로 목록화한다.
2. Developer 1의 command/view model과 Developer 3의 definition만 소비하도록 UI adapter를 만들고 날짜·메뉴 판정을 대형 진입 파일에 추가하지 않는다.
3. 의미 placeholder로 recipe selector, 5개 조립 슬롯, 굽기 상태, 타레/토치 행동, prepared/table icon을 먼저 결선한다.
4. 구현자가 첫 소금·타레 토리카와를 실제 pointer 입력으로 플레이해 입력 순서·가독성·station 왕복 결함을 수정한다.
5. 같은 graybox 경로를 사용자에게 보여 기능 배치 승인을 받은 뒤 Artist 028 전체 화면 적용안을 요청한다.
6. 승인 asset을 component별로 binding하고 조립 0~5·그릴·타레·완성 상태의 형태 연속성을 실제 화면에서 확인한다.
7. D5 9주문 전체를 구현자가 직접 완주해 준비 목록·테이블·정산과 save 전환을 확인한 뒤 QA에 인계한다.
