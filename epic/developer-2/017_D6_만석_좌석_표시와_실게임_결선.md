# 개발자 2 - 017 D6 만석 좌석 표시와 실게임 결선

- 상태: `대기`
- 담당자: `개발자 2`
- 우선순위: `P1`
- 현재 milestone에 필요한 이유: 지금까지 동시 착석은 최대 2명이라 여섯 좌석의 말풍선·게이지·서빙 대상이 한 화면에 함께 놓인 적이 없다. 만석에서 겹치거나 잘리면 플레이가 불가능하다.
- 하지 않으면 막히는 stage gate: D6 만석 구간의 조작 가능성, 두 기준 뷰포트 통과

## 참조 spec

- `spec/gameplay/GPL-007_D6_영업일_상세_계약.md` - `GPL-007`
- `spec/ui/UI-002_전체_게임_화면_입력_접근성.md` - `UI-002`
- `spec/ui/UI-003_전체_게임_상세_화면_설계.md` - `UI-003`

## 목표

여섯 좌석이 동시에 점유된 상태에서 손님 액터, 말풍선, 인내심 게이지, 서빙 대상, 정리 게이지가 서로 겹치지 않고 안전 영역 안에서 읽히게 한다. 신규 아트나 신규 UI 요소를 만들지 않고 기존 좌석 표현의 배치와 우선순위만 조정한다.

## 범위

### 포함

- 6석 동시 점유 시 좌석별 말풍선·게이지·서빙 대상의 겹침 제거
- 요리 서빙대 좌석 버튼 6개가 한 줄에서 읽히는지 확인과 필요한 배치 보정
- 만석 상태에서 두 기준 뷰포트(1920×1080, 1280×720) 안전 영역 준수
- 도착이 미뤄진 파동에 대한 화면 표현 결정과 적용
- 만석 구간의 프레임 저하 여부 확인

### 제외

- 도착 판정 — Developer 1 작업 020
- D6 release 데이터 — Developer 3 작업 016
- 신규 아트 제작. D6는 기존 좌석·손님 아트를 그대로 쓴다
- `만석` 배지·축하 연출. `GPL-007` 8항이 금지한다

## 작업 절차

1. Developer 1의 좌석 점유 view model로 6석 동시 점유 화면을 재현한다.
2. 두 뷰포트에서 말풍선·게이지·서빙 대상의 실제 사각형을 측정해 겹침과 안전 영역 위반을 찾는다.
3. 겹치면 좌석 배치가 아니라 표시 요소의 크기·앵커·우선순위를 조정한다.
4. 요리 서빙대 좌석 버튼 6개의 가독성을 확인하고 필요하면 줄바꿈·폭을 조정한다.
5. 도착 지연 손님의 표현을 `GPL-007` 미해결 질문 1에 따라 사용자와 정하고 적용한다.
6. 만석 상태에서 프레임 저하가 없는지 확인한다.

## 병렬·순차 계획

- 다른 역할과 병렬 가능한 범위: Developer 3 작업 016의 데이터 확정
- 반드시 순차로 진행할 범위: Developer 1 도착 정책 → 만석 재현 → 표시 보정 → 전체 플레이
- 동시 writer를 금지할 경로: 이 작업은 `app/src/d1-game.*`과 `app/src/render/**`의 단일 writer다. `app/content/**`는 Developer 3, `app/src/domain/**`은 Developer 1이 소유한다.
