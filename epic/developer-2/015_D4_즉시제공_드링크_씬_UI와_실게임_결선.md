## 목표

Developer 1의 D4 controller를 현재 단일 Three.js renderer와 실제 영업 shell에 연결한다.
`SCR-SVC-INSTANT`는 메뉴 등록형 scene으로 만들고, `SCR-SVC-DRINK`는 기존 생맥주와 신규
하이볼을 동일 상위 화면의 내부 작업면으로 전환한다. gameplay 상태 머신을 2,879줄
`d1-game.js`에 다시 작성하지 않고 composition과 event binding만 남긴다.

## 범위

### 포함

- 현재 정적 `SCREENS/OBJECTS`를 해금 날짜와 station descriptor를 소비하는 service scene registry로 점진 분리
- `SCR-SVC-INSTANT` 상위 quick-nav, 메뉴 card rail/grid와 공용 완성 tray. 수요 숫자 badge는 사용자 지시로 표시하지 않는다.
- instant item descriptor가 label·icon·prepared art·hold copy·duration·badge policy를 제공하는 확장 구조
- 사라다 카드 pointer hold, `사라다 담는 중`, 원형 progress와 모든 취소 입력의 controller 결선
- `SCR-SVC-DRINK` 한 화면에 동시에 보이는 생맥주 설비와 하이볼 독립 작업면
- 하이볼 우측 보관대 glass 선택→ice→whiskey/soda hold→lemon, 병 기울기·액체·overflow·폐기/제공 UI
- 화면에는 고정 placard `얼음 → 위스키 1 : 탄산수 3 → 레몬`만 표시하고 실시간 수치·목표 gauge는 표시하지 않음
- 공용 준비 dock의 `menuId/zone/qualityMode` 렌더링, 사라다·하이볼 선택·서빙
- 주문 card와 테이블의 사라다 1접시 표시, 하이볼 제공 visual, 비법노트 항목
- FHD·720 입력 안전 영역, 키보드 동등 입력, pause·blur·전환 취소
- Artist 027의 component/requiredAsset ID 동결, 승인 asset binding과 manifest 승격

## 작업 절차

1. 현재 `screenLayout.js`·`productionRenderer.js`·`d1-game.html`·`d1-game.js`의 scene/object/DOM 결선을 component별로 기록하고 D4가 소비할 최소 interface를 고정한다.
2. 기존 screen ID와 camera pose를 보존하는 registry factory를 만들고, 날짜별 해금 station만 quick-nav에 노출한다.
3. instant scene shell과 menu descriptor renderer를 구현한다. card·hold ring·copy는 DOM, 배경·작업대·음식은 분리 asset으로 두어 에다마메 추가 시 scene 코드를 고치지 않는다.
4. drink scene에 생맥주와 하이볼 work-surface host를 나란히 두고, mode tab 없이 각 controller를 독립 입력면에 연결한다. 하이볼은 생맥주 받침과 같은 counter 높이에 맞추며 진입 시 중앙 슬롯은 비우고 우측 잔 보관대 선택 뒤 작업 잔과 충분한 얼음 layer를 표시한다.
5. 두 작업면의 미완성 잔 상태를 독립 보존하고 side/quick navigation 왕복 뒤 같은 잔을 렌더한다.
6. 공용 dock의 한글 label·정규식 추론을 제거하고 Developer 1 inventory view의 `menuId`·`zone`·`quality`를 그대로 소비한다.
7. 통합 draft로 D4 첫 주문을 실제 pointer 입력으로 플레이하고 사용자에게 scene 이동·공간 배치·hold 조작 피드백을 받는다.
8. draft 승인 뒤 Artist 027의 최종 screen/component bounds를 확정하고 requiredAsset ID·pivot·anchor handoff를 제공한다.
9. 승인 pack만 resolver와 manifest에 원자적으로 연결하고 실제 FHD·720 화면에서 사람 재검수한다.
