## 목표

D1 아트 제작과 병행해 S0~D3의 정식 한국어 대사·연출 순서·건너뛰기·3줄 요약과 화면 레이아웃을
임시 UI로 먼저 완성하고, 승인 아트가 도착하면 상태·입력 계약을 바꾸지 않고 교체한다.

## 사용자 확정 실행 조건

- 주인공은 `아사노 아키(浅野 秋)`, 29세, 중성적으로 표현되는 고정 인물이다.
- 외형은 짧은 흑갈색 머리·피곤한 눈매·마른 체형·걷어 올린 셔츠·짙은 남색 앞치마다.
- 첫 손님은 `츠키오카 세이지(月岡 誠司)`, 68세, 퇴직한 시내버스 기사다.
- S0~D3의 나머지 손님은 이름 없는 엑스트라 유형과 기억 플래그로 처리한다.
- S0는 `열쇠 선택 → 대문 열기 → 숯 점화`의 짧은 무실패 클릭 상호작용이다.
- 이야기·정산에는 아키 초상을 표시하지만 영업·조리에는 신체 부위를 표시하지 않는다.
- 오디오는 이번 범위에서 제작하지 않고 모든 의미를 시각적으로 전달한다.

## 범위

### 포함

- S0~D3 영업 전·정산 후 정식 대사와 장면 순서
- 모든 이야기 장면 건너뛰기와 최대 3줄 맥락·신규 행동·목표 요약
- S0 세 단계 무실패 상호작용과 D1 영업 준비 연결
- 날짜별 이야기·튜토리얼·정산 UI의 semantic DOM/CSS 임시 레이아웃
- 아사노 아키·츠키오카와 엑스트라 유형의 안정 ID·표시명·대사 규칙
- 승인 아트 교체를 위한 `sourceMasterId`·component·safe area 연결

### 제외

- 실제 영업일 gameplay·저장 — 개발자 1 작업 008~010
- S0·D2·D3 아트 생성 — Artist 작업 023·024
- BGM·SFX·보이스
- 하루·카나모리와 D4 이후 고정 인물 세부 설정

## 작업 절차

1. S0~D3 장면 ID·대사 ID·flag·skip summary를 콘텐츠 데이터와 연결한다.
2. S0 세 클릭 장면을 무실패 상태 흐름과 접근 가능한 버튼으로 구현한다.
3. D1~D3 영업 전·중 짧은 대사·정산 후 장면을 우선순위 규칙에 맞게 구현한다.
4. 임시 UI를 FHD/720 안전 영역에 배치하고 `개발 중` 표시를 분리한다.
5. 승인 아트 도착 시 DOM 의미·상태 ID를 유지한 채 manifest 에셋으로 교체한다.
6. 건너뛰기·재시작·저장 재개·키보드 입력을 E2E로 검증한다.

## 구현 및 검증 결과

- app 구현 위치:
  - `src/scenario/s0-d3-content.js`: S0~D3 scene/state/dialogue ID, 정식 한국어 대사,
    고정 인물·익명 엑스트라, 최대 3줄 skip summary
  - `src/s0-d3.html`, `src/s0-d3.css`, `src/s0-d3.js`: semantic DOM/CSS 임시 UI,
    S0 무실패 3클릭, 건너뛰기·요약·재시작, 영업·정산 placeholder
  - `src/scenario/s0-d3-campaign.js`: Developer 1의 공개 `CampaignRuntime`·
    `CampaignSaveRepository`·storage port를 소비하는 presentation bridge
  - `tests/unit/s0D3ScenarioContent.test.js`, `tests/integration/s0D3CampaignUi.test.js`,
    `tests/e2e/s0-d3-scenario.spec.js`
- 구현 기준 spec 버전: 위 참조 spec
- 구현 기준 태스크 버전: `v1.1.1`
- 콘텐츠 결과:
  - 고정 인물은 `CHAR-AKI` 아사노 아키와 `CHAR-TSUKIOKA` 츠키오카 세이지 두 명뿐이다.
    나머지는 `EXTRA-COMMUTER`, `EXTRA-SOLO`, `EXTRA-OFFICE-PAIR`의 이름 없는 유형이다.
  - S0는 `S0-KEY-SELECT → S0-GATE-OPEN → S0-CHARCOAL-IGNITE`의 정확한 세 버튼으로
    구성하고 실패·점수·오디오 상태를 만들지 않는다.
  - 이야기에는 scene·dialogue ID와 최대 3줄 요약을, 임시 시각 영역에는
    `sourceMasterId`와 `개발 중` 표시를 제공한다. 임시 이미지는 생성하거나 runtime
    manifest에 등록하지 않았다.
  - 영업·조리 placeholder에는 플레이어 신체를 표시하지 않고, 이야기·정산에서만 아키의
    글자형 임시 초상을 표시한다. 오디오 요소 없이 텍스트·형태·현재 단계 표식으로 의미를
    전달한다.
  - 공개 campaign port의 `S0 → D1 → D2 → D3 → D4-preview` node chain을 소비한다.
    독립 검증 페이지는 D4 UI를 구현하지 않고 D3 완료에서 멈추며, localStorage key를
    `yaki-season.dev2-scenario.*`로 격리해 실제 캠페인 저장과 충돌하지 않는다.
  - 영업 시작 전 `day-start`와 정산 뒤 `day-complete`를 공개 repository로 저장한다.
    영업 중 새로고침은 해당 날짜의 영업 전 장면으로 복귀하며 정식 영업 보상은 만들지 않는다.
- 검증 결과:
  - 관련 Vitest 4개 파일·22개 통과
  - S0 무실패 3클릭, 키보드 입력, day-start 새로고침 재개, S0~D3 전체 건너뛰기,
    FHD/720 안전영역과 D1 회귀를 포함한 관련 Playwright 16개 통과
  - 최신 병행 작업 포함 전체 Vitest 26개 파일·215개 통과
  - runtime asset 8개와 참조 이미지 36장 검증 통과
- 후속 인계:
  - 실제 D1~D3 gameplay 결과·보상은 Developer 1 작업 009·010이 bridge에 전달한다.
    이 작업은 보상 수치나 영업 aggregate를 소유하지 않는다.
  - 공개 shell·저장 파일 UI·D4 예고는 지시대로 시작하지 않았으며 Developer 2 작업 005에
    남긴다.
  - 사용자 확정 인물 설정의 SCN-002·ART-002 정합화는 후속 spec 작업에서 수행한다.
