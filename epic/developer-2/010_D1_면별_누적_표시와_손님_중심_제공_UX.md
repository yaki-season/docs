## 목표

Developer 1이 공개한 면별 누적 조리 snapshot과 손님별 주문·제공 domain contract를
`d1-game` semantic DOM으로 소비한다. 그릴 6칸에서 접촉면·양면 누적·회전 정지·현재 행동을
색에 의존하지 않고 읽을 수 있게 하고, 공용 완성품 카드 선택 뒤 일치하는 모든 손님 중 원하는
대상을 마우스와 키보드로 선택해 제공할 수 있게 한다.

## 범위

### 포함

- `d1-game.js/html/css`의 6칸 compact 면별 상태 DOM과 FHD/720 안전 배치
- 앞/뒤 모양 아이콘·텍스트·면별 누적 초·뒤집기/회수 행동 표시
- 조기 뒤집기 뒤 이전 면 누적 보존과 0.3초 공중 회전 중 양면 정지 안내
- `d1BusinessDayUiPort.js`의 좌석별 남은 주문과 선택 메뉴별 제공 가능 projection
- 공용 완성품 카드 선택→원하는 손님 클릭/키보드 제공
- `D1_GUIDED_ORDER_SEQUENCE` UI 오류·문구·테스트 기대 제거
- 관련 integration·Playwright 접근성·FHD/720 회귀

### 제외

- Developer 1 소유 영업 domain·그릴 판정·renderer·저장 schema 변경
- 자동 손님 선택, 첫 주문·첫 order line 강제, 생맥주 우선 강제
- 아트 생성·manifest 수동 편집·유효 finalizer 없는 promotion
- D2~D4, shell, Edge 비필수 작업

## 작업 절차

1. Developer 1의 `slotViews()`와 business-day view model/intent 공개 필드를 대조한다.
2. 작업 010을 진행 중으로 dashboard와 동기화한다.
3. 그릴 슬롯별 compact semantic DOM과 live 상태를 구현한다.
4. 선택 완성품에 일치하는 좌석을 모두 제공 가능 대상으로 투영하고 포인터·키보드 입력을 연결한다.
5. guided sequence 오류·문구·E2E 기대를 제거하고 네기마 선제 제공을 회귀 검증한다.
6. FHD/720 6칸 비겹침, 회전 중 정지, 좌석별 남은 주문, 키보드 제공을 검증한다.

## 의존성과 인계 조건

- 선행 작업: Developer 1 작업 005 `v3.22.0`, 작업 009 `v1.8.1`
- 후속 작업: Developer 2 작업 006, 통합 QA·릴리스 작업 001
- Developer 1 입력: `slotViews()`의 `contactFace`, `frontElapsedSec`, `backElapsedSec`,
  `flipping`, `flipProgress`; business-day `SERVE_ITEM`이 메뉴 일치 손님을 직접 받는 계약
- Developer 2 출력: semantic DOM 구조·접근성 이름·FHD/720 배치·Playwright 소비 계약
- domain에 `guided-order-sequence`가 남아 있으면 Developer 1 소유 blocker로 기록하고 우회하지 않는다.
- Developer 3 작업 011 `v1.0.0`의 네 계약 ID를 인수한다. UI는 조기 뒤집기에 최소 시간 문구를
  만들지 않고, 선택 완성품→선택 손님 intent를 그대로 전달하며 입장·접수·line·숨은 FIFO를
  좌석 비활성 조건으로 쓰지 않는다.
