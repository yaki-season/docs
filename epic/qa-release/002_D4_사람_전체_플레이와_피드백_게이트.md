# 통합 QA·릴리스 - 002 D4 사람 전체 플레이와 피드백 gate

- 상태: `진행 중` (하이볼·사이드 메뉴 실화면 피드백 반영 완료·D4 8주문 전체 플레이 대기)
- 담당자: `통합 QA·릴리스`
- 우선순위: `P0`
- 현재 milestone에 필요한 이유: 현재 프로젝트 자동 검증 파이프라인은 테스트가 통과해도 실제 인게임에서 신규 scene·입력·아트·저장 전이가 정상 적용됐는지 증명하지 못한다.
- 하지 않으면 막히는 stage gate: D4 완료 판정과 D5 제작 인계

## 목표

자동 테스트 결과를 제품 완료 근거로 사용하지 않고, 사용자가 실제 공개 진입 경로에서 D4
8주문 전체를 직접 플레이하고 피드백을 제공하는 반복 gate를 운영한다. 발견 결함은 주문·화면·입력
시점과 함께 원 owner에게 되돌리고, 같은 경로를 다시 플레이해 사용자의 명시적 `PASS`를 받는다.

## 범위

### 포함

- 기능 graybox의 첫 주문 사람 플레이 세션 준비와 피드백 기록
- 최종 아트 적용본의 D3 완료 저장→D4 진입→8주문→정산→D5 해금 전체 플레이
- 공개 shell·일반 UI·실제 pointer/keyboard 입력만 사용하는 재현
- FHD 주 플레이와 1280×720 입력·겹침 추가 확인
- 사라다 hold 취소/완료, highball 정상/넘침/폐기, station 왕복과 pause/blur
- 2인 그룹 개별 주문·공동 식사, 부분 제공, 대기 회복, 테이블 사라다 한 접시 표시
- 정산 단일 적용, 새로고침·이어하기와 D5 pre-open 경계
- 피드백의 blocker/개선 분류, owner 배정, 수정본 재플레이와 최종 사용자 `PASS`

### 제외

- 자동 테스트 수·스크린샷 비교·debug state를 단독 `PASS` 근거로 사용
- QA가 gameplay·data·UI·아트를 직접 수정하거나 manifest를 승격하는 행위
- D5 실제 영업과 D6 이후 콘텐츠 검수
- 사용자가 플레이하지 않은 경로를 추정으로 승인

## 작업 절차

1. Developer 2가 제공한 `app/dev` 실행 경로와 D3 완료 save setup을 확인한다. setup fixture는 진입 준비에만 쓸 수 있고 D4 gameplay 입력을 대신할 수 없다.
2. 기능 graybox에서 사용자가 `D4-ORDER-001`을 직접 완료하도록 안내하고 scene 이동·hold·drink tab·병 조작 피드백을 기록한다.
3. P0 입력·가독성 결함은 해당 owner에게 즉시 반환하고 첫 주문 경로를 다시 플레이해 기능 승인을 받는다.
4. Artist 027 적용 뒤 공개 shell에서 D4를 시작하고 `D4-ORDER-001~008`을 순서대로 실제 입력으로 처리한다.
5. 각 주문의 접수·제공·식사·정리, 준비 목록, 사라다 수량, 하이볼 품질과 경제 결과를 화면에서 기록한다.
6. 마감·정산 5단계·단일 save·D5와 토리카와 해금을 확인하고 새로고침 뒤 결과가 중복되지 않는지 확인한다.
7. 자동 suite는 크래시·명백한 회귀를 찾는 보조 진단으로 실행할 수 있지만, 실패/성공 모두 사람 판정을 대체하지 않는다고 보고서에 적는다.
8. 사용자가 `PASS`하지 않으면 상태를 완료로 바꾸지 않고 결함 수정→동일 주문 재플레이를 반복한다.

## 병렬·순차 계획

- 다른 역할과 병렬 가능한 범위: 기능 graybox 준비 중 자동 보조 진단과 플레이 안내서 작성
- 반드시 순차로 진행할 범위: Developer 1·2·3 기능 결선 → graybox 사람 승인 → Artist 적용 → 최종 전체 플레이 → 결함 수정·재플레이 → 사용자 `PASS`
- 동시 writer를 금지할 경로·stable ID·finalizer: QA는 `app`·`art-workspace`의 producer 파일과 manifest를 수정하지 않는다. 플레이 피드백 문서와 재현 증거만 단일 writer로 관리한다.
