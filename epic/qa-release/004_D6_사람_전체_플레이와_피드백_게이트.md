# 통합 QA·릴리스 - 004 D6 사람 전체 플레이와 피드백 게이트

- 상태: `대기`
- 담당자: `통합 QA·릴리스`
- 우선순위: `P0`
- 현재 milestone에 필요한 이유: D6는 자동 테스트로 "만석이 읽히는가"를 판정할 수 없다. 좌석이 다 찬 화면에서 사람이 조작 대상을 구분하지 못하면 기능이 통과해도 플레이가 불가능하다.
- 하지 않으면 막히는 stage gate: D6 완료 판정, D7 기획 착수

## 참조 spec

- `spec/gameplay/GPL-007_D6_영업일_상세_계약.md` - `GPL-007`
- `spec/ui/UI-002_전체_게임_화면_입력_접근성.md` - `UI-002`

## 목표

사람이 D6 전체 영업을 실제 입력으로 완주하고, 첫 만석이 부담스럽되 감당 가능한지 판정한다. 결함을 등급별로 기록하고 차단·높은 등급이 남아 있으면 D6를 완료로 표시하지 않는다.

## 범위

### 포함

- D6 10명·10건·22항목 전체 플레이를 두 기준 뷰포트에서 각각 수행
- 만석 도달 여부와 그때의 조작 가능성 판정
- 도착 지연 구간에서 손님이 사라져 보이지 않는지 확인
- 만석 중 일시정지·화면 전환·새로고침 복구 확인
- 결함 등급별 기록과 회귀 여부 판정

### 제외

- 구현·수정 자체
- D7 콘텐츠 검증

## 작업 절차

1. Developer 1·2·3 작업이 인계 조건을 만족했는지 확인한다.
2. FHD에서 D6를 완주하며 만석 구간의 조작을 기록한다.
3. 1280×720에서 같은 경로를 반복한다.
4. 만석 중 복구와 도착 지연 표현을 확인한다.
5. 결함을 등급별로 기록하고 차단·높은 등급을 각 역할에 분배한다.
6. 재검증 뒤 D6 완료 여부를 판정한다.

## 병렬·순차 계획

- 반드시 순차로 진행할 범위: 세 개발 작업 인계 완료 → 전체 플레이 → 결함 분배 → 재검증
- 동시 writer를 금지할 경로: QA는 코드를 쓰지 않는다.

## 사용자 승인 gate

- 승인 대상: D6 전체 플레이 결과와 남은 결함 목록
- 승인 전 금지: D6 완료 표시
- 승인 뒤 자동 인계: PM 작업 007의 D7 기획 착수 판단

## 사람 화면 테스트

- 필수 경로: 두 뷰포트 각각의 D6 완주, 만석 구간, 정리 회전, 정산
- 환경: 일반 UI, Chrome FHD와 1280×720
- `PASS` 증거: 뷰포트별 완주 기록과 결함 목록

## 의존성과 인계 조건

- 선행 작업: Developer 1 작업 020, Developer 2 작업 017, Developer 3 작업 016
- 후속 작업: PM 작업 007
- 제공할 입력·출력: 등급별 결함 목록, 완주 기록

## 완료 기준

- [ ] 두 기준 뷰포트에서 D6를 각각 완주했다.
- [ ] 만석 구간에서 여섯 손님의 조작 대상을 구분할 수 있었다.
- [ ] 도착 지연 구간에서 손님이 사라진 것처럼 보이지 않았다.
- [ ] 만석 중 복구가 좌석과 인내심을 유지했다.
- [ ] 차단·높은 등급 결함이 0개다.
- [ ] 남은 중간·낮은 결함이 기록되었다.

## 구현 및 검증 결과

- 진행 상황: 미착수
