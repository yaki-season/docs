## 목표

동시에 진행 중인 개발자·Artist 산출물을 기능이나 승인 아트의 의미를 바꾸지 않고 하나의 검증 가능한
기준선으로 통합하고, S0·D1 최초 공개 gate의 회귀·에셋·handoff 상태를 자동 보고한다. 추가로
S0·D1 범위의 재생성 가능한 ignored 임시 산출물과 obsolete 후보를 안전하게 분류·감사하여, 승인
evidence·runtime provenance·진행 중 변경을 보존한 저장소 위생 기준선을 관리한다.

## 사용자 확정 실행 조건

- 최신 Chrome·Edge, 마우스·키보드, `1920×1080`과 `1280×720`을 검증한다.
- S0·D1 최초 공개의 사용자 노출 placeholder는 0개여야 한다.
- 자동 테스트와 제작자 수동 검수만 공개 gate로 사용한다.
- 원격 플레이 기록을 수집하지 않고 진단 정보에도 저장 payload·개인정보를 포함하지 않는다.

## S0+D1 아티팩트 위생 안전 정책

- QA는 Playwright·Vitest·로컬 캡처 서버·asset promotion·art finalizer의 실행 여부를 먼저 확인한다.
  하나라도 실행 중이면 해당 process가 사용할 `test-results`, staging, receipt를 건드리지 않고 inventory만 갱신한다.
- `git ignored`이고 도구가 자동 재생성하며, live process·approval·provenance·handoff가 참조하지 않고
  사용자 source가 아닌 정확한 경로만 SAFE-TRANSIENT로 삭제할 수 있다. 와일드카드·저장소 루트 재귀 삭제는 금지한다.
- superseded/rejected binary는 상태 문자열만으로 삭제하지 않는다. 명시적 상태, 최신 사용자 승인 successor,
  manifest/finalizer/runtime-handoff/provenance 및 세 저장소 정본 참조 0건, Artist의 묶음 삭제 확인을 모두
  충족한 뒤에만 DELETE-APPROVED로 바꾼다. README·provenance·승인/반려 evidence와 유일 source는 보존한다.
- `app/assets` 심볼릭 링크, `app/public/assets/**`, manifest, promotion receipt/staging, LFS tmp,
  `node_modules`, reference image, 승인 review·GLB·texture, finalizer·handoff·provenance·completion·optimization
  report, `REJECTIONS.md`, 현재 후보와 D1 release definition/콘텐츠 정본은 자동 삭제 대상이 아니다.

## 작업 절차

1. 세 저장소의 branch·HEAD·dirty 경로와 역할별 소유자를 고정된 시각에 기록한다.
2. 현재 전체 verify 실패를 재현해 제품 결함·테스트 드리프트·환경 flaky로 분류한다.
3. 개발자 1 tray/6칸 계약, 개발자 2 그릴 UI 안전영역, Artist 1 master parity의 동일 bounds를 대조한다.
4. Artist 1의 그릴 tray·음식 handoff는 checkerboard·단독 승인이 아니라
   `CM-GRILL-STATION-QUEUED-SELECTION R3` 실제 위치의 FHD/720 원근·톤 승인 증빙이
   있는지 확인하고, 음식 없는 tray R2 승인이 음식 검수보다 먼저인지 감사한다.
5. Artist 1·2·3 handoff의 승인·재조립·finalizer 상태와 공개 placeholder를 owner별로 집계한다.
6. 역할별 수정이 끝난 뒤 충돌 없는 통합 순서와 최소 회귀 묶음을 실행한다.
7. 최초 공개 gate의 통과·차단·남은 위험을 재현 명령과 증빙 경로로 보고한다.
8. cleanup 전후에 assets/reference/pipeline/runtime binding/placeholder/manifest SHA/D1 정적 URL/FHD·720
   evidence가 보존됐는지 감사하고, 실행 중 병행 작업이 있으면 전체 verify 결과를 확정하지 않는다.

## 구현 및 검증 결과

- app 구현 위치: read-only audit만 수행, 소스 변경 없음
- 구현 기준 spec 버전: 위 참조 spec
- 구현 기준 태스크 버전: `v1.1.0`
- 검증 방법: 저장소 상태·cleanup manifest 감사, 병행 process 확인, assets/reference/pipeline/runtime
  inventory, static URL, Chrome·Edge FHD/720 smoke
- 현재 runtime 기준: 승인·binding `9`, 전체 placeholder `33`, drink placeholder `3`.
  `BG-WORKSPACE-DRINK@R2-B1` promotion과 `drink.scene` binding은 완료됐으며 두 D1 진입점의 해당
  missing ID는 제거됐다.
- hygiene 후 target audit: `npm run assets:validate`는 runtime asset `9`개, `npm run visual:references:validate`는
  reference `36`장을 통과했다. runtime inventory는 binding `9`·placeholder `33`·drink `3`·unbound approved `0`이고,
  manifest SHA-256은 `417d2be0584e620450ebd90e0e58b31dca49881b5f86884a06d5380c124c4b57`다.
- art pipeline은 현시점 `29` 오류로 실패한다(현행 spec SHA `4`, S0 sourceMaster topology `2`, legacy provenance
  schema `23`). 이 실패는 cleanup으로 생성되거나 숨겨진 것이 아니며 공개 gate 차단 항목이다.
- 테스트 상태: 과거 Vitest·Playwright 결과는 현재 결과가 아니라 **stale**이다. 이번 hygiene 감사 시점에는
  다른 역할의 `npm run verify`가 실행 중이므로 전체 결과를 확정하지 않는다.
- 공개 준비 상태: Developer 1은 정적 D1 release artifact 입력 대기, Developer 2는 tray R6 DOM reserved
  계약 정합화, Developer 3은 실제 정적 release artifact 제작, Artist 1은 raw 네기마 station 소비 검수,
  Artist 3은 `ST-DRINK-BEER-TIER-1` 제작 재개를 각각 소유한다.
- 남은 위험: 세 저장소의 병렬 dirty 변경과 placeholder 33개, Artist finalizer 잔여 항목, Chromium/Chrome/Edge
  FHD·720 및 static host의 최신 증빙 부재가 공개를 차단한다. cleanup은 이 증빙을 대체하지 않는다.
