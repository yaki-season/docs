## 목표

## 필수 gate

1. CI의 필수 명령은 `npm run verify` 하나이며 `verify:d1-core`와 동일하다.
2. 내부의 `d1:release:check`는 영업창·입장·마감 정책의 source→artifact drift를 차단한다.
3. 내부의 `test:d1:core:unit`는 영업 도메인·UI port·정지 하위 시간축·안내 제거 계약을 검증한다.
4. 내부의 `test:e2e:d1-core`는 공개 `d1-game.html`에서 실제 조립·그릴·드링크·선택 제공 입력, 통합 정지, 정적 release 부팅을 FHD/720으로 검증한다.
5. 각 필수 gate는 잘못된 영업창·13초 변조, 정지 미구현, 순차 안내 재도입 중 하나에서 실패하는 음성 사례를 가진다.

## 판정 규칙

- `제품 회귀`: 현재 공개 화면의 사용자 경로가 spec 결과와 다르다. 공개를 차단한다.
- `테스트 계약 낙후`: 제품은 현재 spec대로이나 구형 파일명·DOM·renderer 내부 구조를 검증한다. 테스트를 교체하고 제품을 되돌리지 않는다.
- `환경 실패`: 브라우저 설치·host·GPU·포트로 인한 실패다. 제품 실패와 분리해 재현 환경을 고친다.
- placeholder·binding·manifest 수치는 사용자 화면의 실제 누락·오표시를 설명할 때만 blocker다.
- 사람 플레이는 자동화가 놓치는 조작감과 가독성을 찾는 진단이다. 명시적 릴리스 결정이 아니면 단독 blocker가 아니다.

## 작업 절차

1. `npm run verify:d1-core`로 release·핵심 단위·공개 실제 입력을 먼저 판정한다.
2. `npm run verify:full-diagnostic`로 전체 Vitest·Playwright를 돌려 나머지 회귀를 세 분류로 나눈다. 이 결과는 D1 제품 결함과 연결되기 전까지 비차단이다.
3. 낙후된 기대값은 현재 스펙과 실화면을 근거로 고친다. 필요성을 설명하지 못하는 테스트는 차단 gate에서 제외한다.
4. 제품 회귀는 실제 입력·상태 스냅샷으로 재현하고 원래 owner에게 돌린다.
5. gate 명령어·실패 분류·현재 위험만 PM 대시보드에 반영한다.
