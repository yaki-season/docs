# 통합 QA·릴리스 - 003 D5 사람 전체 플레이와 피드백 gate

- 상태: `대기`
- 담당자: `통합 QA·릴리스`
- 우선순위: `P0`
- 현재 milestone에 필요한 이유: 현재 자동 검증 파이프라인은 토리카와의 실제 화면 적용, 짧은 굽기 체감, 타레/토치 입력, 전체 영업·저장 전이가 정상인지 증명하지 못한다.
- 하지 않으면 막히는 stage gate: D5 완료 판정과 이후 D6 기획 인계

- `spec/gameplay/GPL-006_D4-D5_영업일_상세_계약.md` - `GPL-006`

- `template/사람_화면_플레이테스트_피드백_템플릿.md` - 사람 플레이 기록

## 목표

자동 테스트를 제품 완료 근거로 사용하지 않는다. 구현자가 먼저 실제 D5 전체 영업을 일반 UI로
완주해 handoff한 뒤, 사용자가 D4 완료 저장부터 D5 9주문·정산까지 직접 플레이하고 피드백을
제공하는 반복 gate를 운영한다. 같은 경로 재플레이와 사용자 명시적 `PASS` 전에는 D5를 닫지 않는다.

## 범위

### 포함

- 구현자의 기능 graybox 소금·타레 경로와 최종 D5 전체 완주 증거 확인
- 최종 아트 적용본의 D4 완료 저장→D5 진입→9주문→정산 전체 사용자 플레이
- 공개 shell·일반 UI·실제 pointer/keyboard 입력만 사용하는 재현
- FHD 주 플레이와 1280×720 입력·겹침 추가 확인
- 5회 조립, 짧은 양면 굽기, 한 면 탄·양면 탄 폐기, 소금 회수
- 타레 도포·재가열 2회, 토치 미사용, 시작 토치 완료, 불향과 최종 낮은 품질
- 2인 그룹 개별 주문, D4 사라다·하이볼 복습, 그릴·드링크 위험 공정 상한
- 준비 목록·손님 테이블·식사·좌석 정리·마감·정산·새로고침
- `day-d5-completed` 단일 저장과 D6 부채·주문·보상 비노출

### 제외

- 자동 테스트 수·스크린샷 비교·debug state를 단독 `PASS` 근거로 사용
- QA가 gameplay·data·UI·아트를 직접 수정하거나 manifest를 승격하는 행위
- D6 gameplay와 부채 후보의 기능 검수
- D5 대사·컷신의 샷 단위 평가

## 작업 절차

1. Producer들의 완료 보고 전에 Developer 2가 구현자 D5 전체 완주 기록과 실제 실행 경로를 제공했는지 확인한다.
2. D4 완료 save setup은 진입 준비에만 사용하고 D5 주문·조리·제공 입력은 fixture/debug API로 대체하지 않는다.
3. 사용자가 `D5-ORDER-001`을 직접 완료하며 5회 조립·짧은 굽기·생맥주 교차와 첫 인상을 기록한다.
4. `002/003/007`에서 타레 2회, 토치 미사용/사용, 하이볼·사라다 교차와 2인 그룹 개별 주문을 확인한다.
5. `004~009`에서 기존 메뉴 복습, 다수 꼬치, 준비 목록·테이블 배치, 마감 주문을 실제 입력으로 처리한다.
6. 마감·정산·단일 save를 확인하고 새로고침 뒤 중복 보상·주문 재생성이 없는지 확인한다.
7. D6 부채·메뉴·주문·보상이 노출되지 않고 `day-d5-completed`만 남는지 일반 UI와 저장 결과에서 확인한다.
8. blocker를 owner에게 반환하고 같은 주문·입력·save 경로를 재플레이해 사용자의 최종 `PASS`를 받는다.

## 병렬·순차 계획

- 다른 역할과 병렬 가능한 범위: 기능 graybox 준비 중 자동 보조 진단과 사람 플레이 체크리스트 작성
- 반드시 순차로 진행할 범위: D4 최종 `PASS` → D5 producer 결선 → 구현자 전체 완주 → 사용자 전체 플레이 → 결함 수정·재플레이 → 사용자 `PASS`
- 동시 writer를 금지할 경로·stable ID·finalizer: QA는 `app`·`art-workspace` producer 파일과 manifest를 수정하지 않는다. 플레이 피드백과 재현 증거만 단일 writer로 관리한다.

## 사용자 승인 gate

- 승인 대상: 첫 소금·타레 기능 graybox와 최종 아트 적용 D5 전체 영업
- 승인 전 금지: D5 producer task 완료, D5 stage 완료, D6 구현 착수
- 승인 뒤 자동 인계: PM 작업 006 완료 판정과 별도 D6 기획 작업

## 사람 화면 테스트

- 필수 경로: 공개 shell→D4 완료→D5, 첫 소금 토리카와, 그룹 타레 주문, 토치 미사용/사용, 기존 메뉴 교차, 마감·정산·D6 비노출
- 환경: Chrome FHD 실제 플레이, Chrome 1280×720 추가 확인. 공개 build와 같은 asset manifest를 사용한다.
- 진단 결과 또는 명시적 필수 gate인 경우의 `PASS` 증거: 구현자 전체 완주 기록, 작성된 feedback template, 사용자 전체 플레이 화면/영상, blocker 수정·재확인 결과, 사용자의 명시적 최종 `PASS`

## 구현 및 검증 결과

- app 구현 위치: 해당 없음. D5 실행 결과를 검수
- 구현 기준 spec·태스크: `GPL-006`, PM 작업 006과 producer 작업 019·016·015·028
- 검증 방법: 구현자·사용자의 실제 전체 플레이가 정본, 자동 검증은 비차단 보조 진단
- 검증 결과: QA 전체 플레이는 아직 시작하지 않았다. producer 구현은 app `efde7ea`, dev 통합은 `3baeda3`에 있으며 자동 보조 진단으로 Vitest 519개·브라우저 8개·build가 통과했다. D4 후일담 마지막 장면에서 실제 D5 영업 진입까지는 브라우저에서 확인됐다.
- 남은 위험: D4 최종 사람 `PASS`, 구현자의 D5 9주문 전체 일반 UI 완주, manifest 정식 토리카와 에셋과 1280×720 적용본이 선행되지 않았다. 자동 검증과 조립 부분 화면 확인만으로 QA `PASS` 또는 D5 완료 판정을 내리지 않는다.
