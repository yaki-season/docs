## 목표

0차 목표는 D1 첫 주문의 완전한 한 흐름을 실제 `app`에서 검증하는 것이다. 손님
`REGULAR_TSUKIOKA`가 입장해 `네기마 3개 + 생맥주 1잔`을 주문하고, 플레이어가 조립·그릴·드링크를
직접 조작해 결과물을 만든 뒤 생맥주 부분 제공과 네기마 최종 제공까지 완료해야 한다.

이 목표의 우선순위는 다음과 같다.

1. 현재 `app` 구현과 테스트를 먼저 실행해 통과·실패·미검증 상태를 기록한다.
2. 기획 계약을 테스트로 먼저 고정하고, 실패하는 기능만 순서대로 보완한다.
3. 기능 계약이 검증되면 화면 기획·정의·규칙·컨셉에 맞는 전체 장면을 한 장씩 제작·승인한다.
4. 승인된 전체 장면에서 필요한 에셋을 분리·개발·개별 승인한다.
5. 소비 화면 재조립과 최종 승인 뒤에만 app runtime으로 인계한다.

## 아트·에셋 인계 규칙

아트 생성 규칙은 기존과 동일하게 유지한다.

1. 화면 기획·정의·규칙·컨셉으로 전체 장면의 의미·카메라·공간 순서를 확정한다.
2. 전체 장면 한 장을 제작하고 사용자 승인을 받는다.
3. 승인된 장면에서 필요한 complete layer, standalone raster, bundle을 분리한다.
4. 각 자산은 격리 검수와 사용자 승인을 거친다.
5. 승인 자산만 FHD/720p 소비 화면에 재조립·승인하고, pipeline finalizer와 명시적 promotion으로만
   `app`에 전달한다.

전체 화면을 새로 만들기 전에는 기존 승인 전체 화면을 `screenId`·카메라·상태·필수 구성요소로
먼저 대조한다. 동일 화면 계약을 충족하는 승인본이 있으면 재생성하지 않고 그 화면을 source로
분리·조립한다. 새 전체 화면 생성은 기존 승인본으로 해당 상태를 만들 수 없다는 근거를 기록한
경우에만 허용한다.

`app`의 현재 테스트 참조 이미지와 `art-workspace`의 기존 승인 증거는 삭제 대상이 아니다. 이들은
새 0차 수직 슬라이스의 비교·이관 입력으로만 사용하며, 미승인 아트는 runtime에 등록하지 않는다.

### D1 츠키오카 손님 + 좌석 — 승인 상태

기존 `Artist 010 customer-seat-01 R2`는 Artist 009 기준 화면의 왼쪽 회사원으로, D1
`REGULAR_TSUKIOKA`가 아니다. 사용자 정정에 따라 잘못된 재사용 연결과 순서 검토판을 삭제했고,
해시와 사유만 `.../reuse/customer-seat-01/REJECTIONS.md`에 남겼다. 원래 승인 자산은 다른 손님
용도로 보존한다.

D1 츠키오카는 기준 화면의 **녹색 가디건·회색 머리·안경을 쓴 노인 손님**으로 별도 complete
layer를 제작한다. 대기와 수령(식사)은 서로 다른 의미 상태이므로 한 번에 만들지 않는다. 먼저
음식·음료가 없는 대기 R2 한 장은 사용자 승인됐다. R1은 의자가 옆을 향해 superseded 처리했으며,
R2는 정면 카메라를 똑바로 향하는 의자로 확정했다. 사용자는 D1 전량 수령 뒤 식사·음주를 하나의
2프레임 bundle로 확정했다. 프레임 A는 네기마를 먹고 프레임 B는 생맥주를 마시며, 두 프레임은
같은 정면 의자·인물·FHD 좌표를 유지한다. bundle R1은 사용자 승인됐고 provenance와 bundle
승인 보고서에 기록했다. D1 기획상 다음 미분리 시각 상태는 **생맥주만 부분 제공되고 네기마 3개는
여전히 대기인 상태**다. 이 상태는 전량 수령 식사·음주와 다르다. 사용자 지시에 따라 생맥주 한
