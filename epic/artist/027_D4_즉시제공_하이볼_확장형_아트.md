# Artist 3 - 027 D4 사이드 메뉴·하이볼 확장형 아트

- 상태: `진행 중` (하이볼·사이드 메뉴 실화면 1차 사용자 승인 반영·finalizer/manifest 승격 대기)
- 담당자: `Artist 3`
- 우선순위: `P0`
- 현재 milestone에 필요한 이유: D4의 신규 사이드 메뉴 scene과 하이볼 작업면에는 승인 runtime asset이 없으며, 사용자 제공 샘플을 현재 게임의 실제 화면 톤과 결합한 제작 기준이 필요하다.
- 하지 않으면 막히는 stage gate: D4 최종 화면 적용, 사람 전체 플레이와 사용자 아트 승인

## 목표

사용자가 제공한 양배추 사라다 접시, 큰 각얼음·레몬이 든 하이볼 잔, 생·구운 모모 샘플의
픽셀 밀도와 따뜻한 조명을 참고하되 현재 manifest 승인 runtime 화면을 최우선 정본으로 삼는다.
사이드 메뉴는 향후 에다마메를 추가해도 배경과 UI를 다시 만들지 않는 scene shell+menu pack으로,
하이볼은 기존 생맥주 scene 오른쪽에 동시에 보이는 modular work surface로 제작한다.

## 범위

### 포함

- 사용자 제공 샘플 4종의 형태·재질·전후 상태 일관성 분석
- 현재 `SCR-SVC-DRINK`, `BG-WORKSPACE-DRINK`, `MDL-BEER-*`와 실제 FHD 소비 화면 비교
- 승인 화면이 없는 `SCR-SVC-INSTANT`의 1920×1080 전체 화면 콘셉트
- instant 공용 shell, 작업대, 메뉴 card 안전 영역, 준비 중 손/접지 영역과 완성 tray 구도
- `FD-CABBAGE-SALAD-*`의 검은 타원 접시, 양배추·가벼운 드레싱·깨, 주문 icon·비법노트 visual
- 기존 drink 배경과 생맥주 설비를 유지한 `ST-HIGHBALL` 동시 노출 work-surface 콘셉트
- `FD-HIGHBALL-*`의 우측 복수 잔 보관대, 선택 뒤 중앙에 나타나는 긴 잔, 잔의 80% 이상을 채우는 큰 각얼음, 위스키·탄산수 병, 레몬, 액체·넘침 layer와 주문 icon
- 병 sprite의 `pourPivot`·목/주둥이 anchor를 제공해 click/hold 동안 코드가 자연스럽게 기울일 수 있는 구조
- FHD·720 실제 component bounds에 맞춘 straight-alpha runtime layer, provenance·catalog·finalizer handoff

### 제외

- 카드 문자, `사라다 담는 중` 문구, 원형 progress, 실시간 수치·품질 gauge를 이미지에 굽는 작업
- instant scene 전체를 사라다 전용 한 장으로 굽거나 에다마메 자리를 미리 음식 그림으로 채우는 작업
- 하이볼을 별도 상위 scene/background로 만드는 작업
- 모모 샘플을 이용한 기존 모모 runtime 재제작
- 사용자 콘셉트 승인 전 개별 asset 대량 생성·분리·manifest 승격

## 작업 절차

1. 사용자 제공 샘플은 `양배추 사라다 접시`, `하이볼 잔`, `생 모모`, `구운 모모`의 네 reference role로 기록한다. 모모 두 장은 음식 상태 간 앵커·실루엣·조명 일관성 기준으로만 사용한다.
2. 같은 화면 용도의 현재 승인 runtime asset과 FHD 배치값을 먼저 읽고, 샘플의 순수 흰/검 배경이나 checkerboard는 최종 게임 배경으로 복제하지 않는다.
3. 사이드 메뉴 scene은 D4의 사라다 tray·접시를 왼쪽에 두고 오른쪽 counter를 후속 메뉴용으로 비운 통합 draft를 먼저 실제 화면에 적용한다.
4. highball은 현재 drink scene 캡처 오른쪽에 work surface를 동시에 노출하고 생맥주 받침과 같은 counter 높이에 맞춘다. 진입본은 중앙 슬롯을 비우고 우측 잔 보관대만 노출하며, 기존 생맥주 설비·조작 영역·가독성을 훼손하지 않는다.
5. 실제 화면 통합 draft에서 화풍·구도·조작 대상 크기를 사용자가 승인한 뒤 최종 asset slicing과 manifest 승격을 확정한다.
6. 승인 화면에서 instant 공용 shell과 사라다 pack, highball의 glass/ice/bottle/lemon/liquid를 독립 layer로 분리하고 Developer 2의 component bounds·pivot에 맞춘다.
7. 병은 기본 upright sprite 하나를 `pourPivot`으로 회전하는 방식을 우선한다. 가림 보정이 꼭 필요한 경우에만 동일 앵커의 tilt companion 한 장을 추가한다.
8. Developer 2 semantic placeholder에 layer를 한 종류씩 넣어 FHD·720에서 투명 경계·접지·클릭 영역·텍스트 안전 영역을 사람이 확인한다.
9. 최종 사용자 승인 뒤에만 provenance·catalog·finalizer pack을 Developer 2에 전달하며 Artist가 manifest를 직접 수정하지 않는다.
