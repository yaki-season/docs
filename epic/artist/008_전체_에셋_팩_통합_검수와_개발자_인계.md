## 목표

Artist 작업 001~007의 결과를 하나의 검증된 runtime asset library로 통합하고, 개발자가 화면·스테이션·캐릭터·메뉴·콘텐츠 ID로 즉시 경로와 사용 계약을 찾을 수 있는 최종 카탈로그와 인계 보고서를 완성한다.

## 범위

### 포함

- P0, P1과 승인된 P2 에셋의 누락·중복·상태·경로·해시 전수 검증
- core, S0-D1, S2-S4, S5-S7, optional pack 구성과 지연 로드 경계 검수
- `app/public/assets/manifest.json` 최종 정합성 검증
- `app/art/ASSET-CATALOG.md`의 화면·module·콘텐츠별 개발자 조회 표 완성
- GLB node·pivot·anchor, atlas clip, texture 색 공간과 companion metadata 전수 검증
- PC·모바일·LOW, S0, D1, 성장, 러시, D20, D30, D31 합성 검수
- 초기 로드·texture·triangle·drawcall 기여 예산과 중복 파일 정리
- 미확정·차단·deprecated 에셋과 개발 placeholder의 잔존 위험 기록

### 제외

- 새로운 기획·메뉴·캐릭터 상태 추가
- 게임 소스의 에셋 로더·장면·UI 구현
- 승인되지 않은 P2 항목을 완료 수량에 포함하는 처리

## 개발자 카탈로그 필수 조회 표

| 조회 축 | 카탈로그에 기록할 내용 |
|---|---|
| 화면 | boot, prologue, pre-open, business station별, settlement, growth, notebook, recovery |
| Three.js module | background, customers, barCounter, stations, interactives, materials, vfx, foreground |
| 콘텐츠 | day, recipe, process, customer, staff, story flag별 에셋 ID |
| 입력 대상 | model node, interaction proxy, pivot, anchor, hit zone metadata |
| 상태 | character clip, station tier, cooking/VFX state, LOW 대체 |
| 파일 | runtime URL, source, provenance, companion metadata, SHA-256, pack |

## 작업 절차

1. `ART-003`의 P0·P1 목록과 승인된 P2 콘텐츠를 실제 manifest ID와 대조한다.
2. 모든 runtime URL, 파일 해시, 상태, pack, source·license, pivot·anchor·clip을 자동 검증한다.
3. content manifest의 recipe·process·customer·day·story·staff asset key가 실제 승인 에셋을 가리키는지 확인한다.
4. `ASSET-CATALOG.md`를 화면, Three.js module, 콘텐츠, 캐릭터, 메뉴와 pack 기준으로 교차 조회 가능하게 완성한다.
5. 각 표의 경로를 `app` 루트 기준 링크로 열어 실제 runtime/source/provenance 파일과 일치하는지 검사한다.
6. S0·D1·8/12석·D20·D30·D31, 각 station과 LOW 모드 대표 합성을 desktop·mobile로 검수하고 셰프측 카메라·고정 카운터·손님 가림선·플레이어 작업 bounds를 별도 체크한다.
7. core+D1 5MB, texture 64MB, scene 50,000 triangles와 active pack 예산에 대한 에셋 기여분을 기록한다.
8. review·실패본·원본·중복·미사용 파일이 runtime pack에 없는지 확인한다.
9. blocked·deprecated·placeholder 항목의 대체 ID, 해제 조건과 영향을 카탈로그의 위험 표에 남긴다.
10. 개발자 인계 보고서에 manifest·카탈로그 경로, 검증 명령, pack 사용법과 남은 위험을 기록한다.
