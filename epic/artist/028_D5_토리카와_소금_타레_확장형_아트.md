# Artist 1 - 028 D5 토리카와 소금·타레 확장형 아트

- 상태: `진행 중`
- 담당자: `Artist 1`
- 우선순위: `P0`
- 현재 milestone에 필요한 이유: D5 토리카와는 사용자 제공 생 상태·완벽 직전 굽기 참고 이미지는 있으나, 현재 게임의 조립·그릴·준비·테이블 화면에서 일관되게 소비할 승인 runtime asset family가 없다.

## 목표

사용자가 제공한 연한 생 토리카와와 그을음 있는 완벽 직전 토리카와 이미지를 상태 reference로 사용하되,
현재 승인된 야키토리 조립·그릴·서빙 화면의 픽셀 밀도·따뜻한 조명·비율을 최우선 정본으로 삼는다.
같은 닭껍질 접힘 구조가 조립 0~5, 굽기, seasoning, 완성 접시까지 이어지는 모듈형 asset family를 만든다.

## 범위

### 포함

- 사용자 제공 두 이미지의 닭껍질 접힘, 대나무 꼬치, 생/완벽 직전 표면 차이 분석
- 원본을 `art-workspace/source/artist-028/`에 읽기 전용 보존하고 출처·용도를 provenance에 기록
- 현재 승인 네기마·모모 조립/그릴/준비/테이블 화면과 실제 FHD 소비 크기 비교
- `FD-TORIKAWA-*`의 접은 닭껍질 단일 조각과 조립 `0/5~5/5` 상태
- raw/cooking/proper/over/burnt의 면 상태와 소금·타레 표면 variant
- 타레 도포·재가열 전후와 선택 토치의 불향 companion layer
- 조립대, 그릴 슬롯, 공용 준비 목록, 주문 icon, 손님 테이블 완성 접시의 동일 silhouette
- straight-alpha PNG, pivot·anchor·bounds, provenance·catalog·evidence·finalizer handoff
- 실제 D5 화면에 올린 전체 화면 적용안 선검수와 승인 뒤 runtime slicing

### 제외

- reference의 검정 배경·후광·독립 상품사진 구도를 runtime에 복제하는 작업
- 진행 숫자, 소금/타레 문자, 정확한 초, 품질 gauge와 도움말을 raster에 굽는 작업
- 기존 네기마·모모·D4 사라다·하이볼 승인 asset 교체
- D6 부채와 D5 컷신·스토리 이미지
- 사용자 적용안 승인 전 개별 asset 대량 생성·manifest 승격

## 작업 절차

1. 대화에 첨부된 두 원본이 로컬에 없으면 작업 시작 전에 사용자에게 재첨부를 요청하고, 원본 그대로 source namespace와 provenance에 보존한다.
2. 밝은 reference는 생 상태, 그을음 있는 reference는 타레가 아닌 완벽 직전 굽기 단계의 형태·재질 기준으로 사용하고 현재 실제 게임 캡처의 조명·채도·선 두께·화면 밀도를 우선한다.
3. 접은 닭껍질 한 조각, 5개가 꽂힌 소금/타레 꼬치, 접시 완성본을 한 장의 비교판과 실제 조립·그릴 화면 적용안으로 만든다.
4. 사용자에게 실제 화면의 크기·접지·톤·네기마/모모와의 구분을 승인받고, 수정 피드백을 적용한다.
5. 승인된 silhouette와 anchor를 고정해 조립 0~5, 굽기 5상태, seasoning·타레·불향 layer를 분리한다.
6. Developer 2의 component bounds에 한 상태씩 결선해 FHD·720에서 슬롯 이탈·겹침·투명 경계·상태 점프를 사람이 확인한다.
7. 조립 5/5와 raw 그릴, 그릴 회수와 prepared/table 접시가 같은 꼬치 비율로 이어지는지 연속 재생으로 검수한다.
8. 최종 사용자 승인 뒤 provenance·catalog·finalizer pack을 Developer 2에 전달하며 Artist가 manifest를 직접 수정하지 않는다.
