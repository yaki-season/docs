## 목표

S0의 열쇠·대문과 이야기 화면을 `YS-HANDCRAFTED-NIGHT-v1` 정식 아트로 제작·승인·분리하고,
최초 공개 빌드에서 S0 placeholder를 0개로 만든다.

## 사용자 확정 실행 조건

- S0는 `열쇠 선택 → 대문 열기 → 숯 점화` 세 단계의 무실패 클릭으로 이어진다.
- 주인공 아사노 아키의 이야기 초상은 표시하지만 상호작용 화면에는 신체 부위를 표시하지 않는다.
- 아키는 29세, 짧은 흑갈색 머리·피곤한 눈매·마른 체형·걷어 올린 셔츠·짙은 남색 앞치마다.
- S0는 D1과 함께 최초 공개되며 사용자 노출 placeholder를 허용하지 않는다.

## 작업 절차

1. 개발자 2 작업 004가 이미 구현한 S0 screen/state/component ID·topology·카메라·클릭 안전
   영역을 확인하고, 작업 007이 제공할 required asset·bounds·layer 표와 대조한다.
2. 첫 승인 단위는 `S0-STATE-KEY / exterior-key`의 공간·카메라 topology contract 한 건이다.
   승인 뒤 첫 시각 후보는 `PR-SHOP-KEY`의 `놓임` 상태 한 개로 제한한다.
3. 통합 master를 한 장씩 사용자 승인받고 임의의 다음 장면을 병행 생성하지 않는다.
4. 승인 master에서 배경·대문·열쇠·초상을 분리한다.
5. checkerboard·FHD/720 재조립·alpha·해시·anchor를 검증한다.
6. 상태 하나가 승인될 때마다 소비 화면 FHD/720 재조립·최적화·최종 승인·finalizer를 마치고
   개발자 2 작업 007·006에 즉시 인계한다.

## 의존성과 인계 조건

- 선행 작업: 없음. 공간·카메라 topology preflight는 즉시 시작한다.
- 병행 작업: Artist 1 작업 000, Artist 3 작업 025, 개발자 2 작업 007
- 아트 분리·finalizer 입력: 완료된 개발자 2 작업 004의 구현 ID와 개발자 2 작업 007의
  component/requiredAsset/bounds/layer inventory
- 후속 작업: 개발자 2 작업 007의 binding·재조립 검증, 작업 006의 공개 gate
- 승인 전 결과와 review 파일은 app runtime에 등록하지 않는다.
- 아사노 아키 초상 stable ID는 Artist 2만 수정하며 다른 날짜의 이야기·정산 화면은 이 ID를
  복제하지 않고 manifest 참조로 소비한다.

## 구현 및 검증 결과

- app 구현 위치: 해당 없음. runtime 인계만 app에 승격
- 구현 기준 spec 버전: 위 참조 spec
- 구현 기준 태스크 버전: `v3.0.0`
- 검증 방법: 사용자 단일 승인·카탈로그·재조립·finalizer·promotion 원자적 write (v8 3게이트)

  `pending-user-review`이며 승인 전 optimizer·finalizer·runtime handoff 대상이 아니다.
