## 목표

모든 후속 Artist 작업이 같은 ID·폴더·manifest·검수 규칙을 사용하도록 런타임 에셋 구조와 개발자용 통합 카탈로그를 구축한다. 현재 `app/art/gameplay/`의 16개 파일을 12개 재사용 후보와 4개 3D 교체 대상으로 등록해 기존 결과물을 잃지 않고 정식 파이프라인으로 이전한다.

## 범위

### 포함

- `app/art/source`, `review`, `provenance`와 `app/public/assets` pack 구조 생성
- 기계 판독 `app/public/assets/manifest.json`의 스키마와 초기 레코드 작성
- 개발자용 `app/art/ASSET-CATALOG.md` 작성
- 현재 이미지 16종의 ID·해시·규격·출처·상태·재사용 판단 이전
- manifest와 카탈로그의 ID·경로·해시 동기화 검증 도구
- source/review/runtime 경계와 에셋 추가 절차를 `app/art/README.md`에 기록

### 제외

- P0 신규 로고·배경·캐릭터·GLB·UI·VFX 제작
- 현재 4개 음식 PNG를 최종 3D 모델로 승인
- 게임 소스에서 에셋을 실제 로드·배치하는 작업

## 작업 절차

1. `ART-003 v1.1.0`의 ID, 상태, pack, 파일·manifest 필드를 그대로 스키마화한다.
2. `app/art/gameplay/ASSET-MANIFEST.md`와 실제 16개 파일의 규격·바이트·SHA-256을 다시 측정한다.
3. `BG-01~02`, `ST-01~04`, `PR-01`, `CH-01~05`는 검수 뒤 `approved` 또는 `review`로 판정하고, `FD-01~04`는 3D 교체 전 `deprecated` 카탈로그 항목으로 이전한다.
4. 파일을 runtime pack으로 옮기거나 복제할 때 원본·검토본과 최종 파일이 섞이지 않도록 경로를 분리한다.
5. `manifest.json`에는 검수를 통과한 `approved` 파일만 ID, revision, pack, kind, URL, 해시, 규격, 색 공간, alpha, pivot, source, license와 spec 참조를 기록한다.
6. `ASSET-CATALOG.md`에는 승인·검토·폐기 상태를 모두 포함해 화면·스테이션·캐릭터·메뉴별 조회 표와 실제 runtime/source/provenance 링크를 작성한다.
7. `blocked`·`planned` 항목도 카탈로그에 등록하되 runtime 경로는 비우고 차단 조건을 기록한다.
8. manifest와 카탈로그의 ID·상태·경로·해시, 실제 파일 존재와 승인 상태를 비교하는 검증 명령을 만든다.
9. 신규 Artist가 같은 구조로 에셋을 추가하는 절차와 금지 경로를 `app/art/README.md`에 기록한다.

## 완료 기준

- [x] 승인된 재사용 파일은 실제 해시·규격과 함께 manifest·카탈로그에 등록되고 3D 교체 대상 4개는 카탈로그·review 경로에만 등록된다.
- [x] 12개 재사용 후보와 4개 최종 3D 교체 대상이 명확히 구분된다.
- [x] runtime, source, review, provenance 경로가 서로 섞이지 않는다.
- [x] 카탈로그의 모든 runtime/source 링크가 실제 파일 또는 명시적 미생성 상태와 일치한다.
- [x] manifest와 카탈로그 불일치, 누락 파일, 잘못된 해시와 승인되지 않은 runtime 파일을 자동 검출한다.
- [x] 개발자가 ID 또는 사용 화면으로 필요한 에셋과 경로를 찾을 수 있다.
- [x] 후속 Artist 작업이 추가할 파일명·ID·pack을 새로 추측할 필요가 없다.
