# spec·epic 문서 버전 관리 지침

## 목적

`inbox/` 원본의 추가·갱신으로 `spec/` 요구사항과 `epic/` 태스크가 생성되거나 변경될 때 문서별 버전과 변경 이력을 일관되게 관리한다.

## 적용 대상

- `spec/`의 요구사항 상세 설계 문서
- `spec/meta/`의 AI 관리 문서
- `epic/pm-orchestration/`, `epic/developer-1/`, `epic/developer-2/`, `epic/developer-3/`, `epic/artist/`,
  `epic/qa-release/`의 태스크 문서
- `epic/작업_현황.md`

`README.md`와 `AGENTS.md`는 운영 지침이므로 문서 버전 적용 대상에서 제외한다.

## 버전 형식

`v주.부.수` 형식을 사용한다.

예: `v1.0.0`, `v1.1.0`, `v2.0.0`

### 주 버전

기존 구현이나 작업 계획과 호환되지 않는 변경에 사용한다.

- 핵심 동작 또는 계약 변경
- 기존 범위의 제거·대체
- 완료 기준 변경으로 대규모 재작업 필요
- 담당 영역이나 태스크 목표의 근본적 변경

`v1.4.2 → v2.0.0`

### 부 버전

기존 방향을 유지하면서 기능이나 범위가 추가되는 변경에 사용한다.

- 새 기능 요구사항 추가
- 예외·경계 조건 추가
- 기존 태스크에 독립적인 작업 단계 추가
- 검증 기준 추가

`v1.4.2 → v1.5.0`

### 수 버전

구현 의미를 바꾸지 않는 정정이나 관리 변경에 사용한다.

- 문장 명확화와 오탈자 수정
- 링크, 출처, 상태 또는 담당자 갱신
- 구현·검증 결과 기록
- 대시보드 집계 갱신

`v1.4.2 → v1.4.3`

## 공통 규칙

1. 새 문서는 `v1.0.0`으로 시작한다.
2. 기존 문서의 내용이 변경되면 최소 수 버전을 반드시 올린다.
3. 한 번의 파이프라인 실행에서 같은 문서를 여러 번 수정해도 최종 영향 중 가장 높은 단계로 한 번만 올린다.
4. 실제 내용이 바뀌지 않았다면 버전을 올리지 않는다.
5. 버전을 올린 같은 변경에서 문서의 변경 이력에 새 행을 추가한다.
6. 과거 변경 이력은 수정·삭제하지 않고 아래에 계속 추가한다.
7. 변경 이력에는 이전 버전, 새 버전, 날짜, 변경 유형, 근거 원본, 변경 내용과 후속 문서 영향을 기록한다.
8. 여러 문서를 변경하면 각 문서의 버전을 독립적으로 판단한다.

## inbox 원본 버전 식별

`inbox/` 파일 자체에는 AI가 문서 버전을 추가하지 않는다. 사람이 같은 경로의 파일을 갱신할 수 있으므로 AI는 파일 내용 전체의 SHA-256 지문을 계산해 원본 리비전을 구분한다.

- 같은 경로, 같은 지문: 이미 처리한 동일 원본
- 같은 경로, 다른 지문: 사람이 갱신한 새 원본 리비전
- 새 경로: 새 원본

처리한 경로와 지문은 `spec/meta/inbox_처리_이력.md`에 기록한다.

## spec 생성·갱신

### 새 문서

1. 버전을 `v1.0.0`으로 설정한다.
2. 최종 변경일을 기록한다.
3. 변경 이력에 최초 생성 행을 추가한다.
4. 근거 `inbox/` 경로와 SHA-256 지문을 기록한다.

### 기존 문서

1. 변경 전 버전을 확인한다.
2. 원본의 추가·갱신 내용과 기존 요구사항의 차이를 분석한다.
3. 주·부·수 중 가장 높은 변경 단계를 결정한다.
4. 문서 버전과 최종 변경일을 갱신한다.
5. 변경 이력에 이전 버전과 새 버전, 근거 원본과 `epic/` 영향을 추가한다.

## epic 생성·갱신

### 새 태스크

1. 버전을 `v1.0.0`으로 설정한다.
2. 생성 근거가 된 `spec/` 경로, 요구사항 식별자와 정확한 문서 버전을 기록한다.
3. 변경 이력에 최초 생성 행을 추가한다.

### 기존 태스크

1. 변경된 `spec/` 버전이 태스크에 미치는 영향을 분석한다.
2. 목표, 범위, 작업 절차, 의존성 또는 완료 기준이 바뀌면 태스크 문서 버전을 올린다.
3. 상태, 담당자 또는 검증 결과만 바뀌어도 수 버전을 올린다.
4. 변경 이력에 참조한 `spec/`의 이전·새 버전과 재작업 영향을 기록한다.
5. 완료된 태스크는 수정하지 않고 `v1.0.0`의 새 후속 태스크를 생성한다.

## 작업 현황과 처리 이력

- 태스크 변경으로 `epic/작업_현황.md`를 갱신하면 해당 문서의 수 버전을 올리고 변경 이력을 추가한다.
- `spec/meta/inbox_처리_이력.md`에 행을 추가하면 해당 문서의 수 버전을 올리고 변경 이력을 추가한다.
- 새 문서 생성과 기존 문서 변경은 가능하면 하나의 커밋에서 원자적으로 반영한다.

## AI 완료 점검

- [ ] 새 `spec/`·`epic/` 문서가 `v1.0.0`인가?
- [ ] 변경된 모든 기존 문서의 버전이 증가했는가?
- [ ] 각 변경 이력에 이전·새 버전과 근거가 있는가?
- [ ] `spec/` 변경 버전이 관련 `epic/`에 정확히 연결됐는가?
- [ ] `epic/작업_현황.md` 버전과 집계가 갱신됐는가?
- [ ] `spec/meta/inbox_처리_이력.md`에 원본 지문과 처리 결과가 기록됐는가?
