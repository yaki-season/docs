# 원본자료 정제 지침

이 문서는 `inbox/`의 원본 자료를 `spec/`과 `epic/`으로 정제할 때 적용하는 기준이다.

## 정제 단계

1. 사람이 넣은 `inbox/` 원본은 변경하지 않고 AI가 분석에 필요한 대목을 추출한다.
2. 발췌한 내용을 주제별 `spec/` 디렉토리에 배치한다.
3. 요구사항 문서에는 목적, 범위, 기능 요구사항, 비기능 요구사항, 완료 기준을 명시한다.
4. 확정된 `spec/`만 `epic/`의 개발자별 태스크로 분해한다.
5. 처리 판단과 반영 경로를 `spec/meta/inbox_처리_이력.md`에 기록한다.
6. `epic/` 태스크는 독립적으로 수행 가능해야 하며, 관련 `spec/` 경로와 요구사항 식별자를 반드시 포함한다.
7. 개발 중·개발 후 변경사항은 `AI_변경사항_반영_파이프라인.md`에 따라 기존 요구사항과 작업에 다시 반영한다.

## AI 사용 규칙

AI에게 작업을 요청할 때는 `inbox/`가 아니라 `spec/` 또는 `epic/` 문서를 기준으로 지시한다.

좋은 요청 예시:

```md
spec/ui/UI-001_결과_화면.md의 정확한 문서 버전과 epic/developer-2/NNN_결과_화면_UI.md의 정확한 태스크 버전을 기준으로 app 저장소에 결과 화면 UI 태스크를 구현하라.
```

피해야 할 요청 예시:

```md
inbox에 있는 아이디어를 보고 알아서 구현하라.
```

`inbox`는 사람이 넣은 미정제 원본이자 판단 재료일 뿐 구현 지시서가 아니다. AI는 정제 결과를 원본에 되쓰지 않는다.

## 정제 판단 기준

- 반복해서 등장하는 아이디어인가?
- 실제 플레이 경험에 영향을 주는가?
- 구현 범위를 정할 수 있는가?
- 다른 시스템과 의존성이 있는가?
- 테스트 또는 검수 기준을 만들 수 있는가?

위 질문에 답할 수 없으면 `spec/`에 정제 결과를 반영하지 않는다. `inbox/` 원본은 판단과 관계없이 항상 그대로 보존한다.
