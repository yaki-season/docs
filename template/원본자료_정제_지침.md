# 원본자료 정제 지침

이 문서는 `inbox/`의 원본 자료를 `spec/`과 `epic/`으로 정제할 때 적용하는 기준이다.

## 정제 단계

1. `inbox/`에서 쓸만한 대목만 발췌한다.
2. 발췌한 내용을 주제별 `spec/` 디렉토리에 배치한다.
3. 요구사항 문서에는 목적, 범위, 기능 요구사항, 비기능 요구사항, 완료 기준을 명시한다.
4. 확정된 `spec/`만 `epic/`의 개발자별 태스크로 분해한다.
5. `epic/` 태스크는 독립적으로 수행 가능해야 하며, 관련 `spec/` 경로를 반드시 포함한다.

## AI 사용 규칙

AI에게 작업을 요청할 때는 `inbox/`가 아니라 `spec/` 또는 `epic/` 문서를 기준으로 지시한다.

좋은 요청 예시:

```md
spec/ui/README.md와 epic/developer-2/001_UI_콘텐츠_기반.md를 기준으로 결과 화면 UI 태스크를 구현하라.
```

피해야 할 요청 예시:

```md
inbox에 있는 아이디어를 보고 알아서 구현하라.
```

`inbox`는 판단 재료일 뿐 구현 지시서가 아니다.

## 정제 판단 기준

- 반복해서 등장하는 아이디어인가?
- 실제 플레이 경험에 영향을 주는가?
- 구현 범위를 정할 수 있는가?
- 다른 시스템과 의존성이 있는가?
- 테스트 또는 검수 기준을 만들 수 있는가?

위 질문에 답할 수 없으면 `spec/`으로 승격하지 않고 `inbox/`에 남겨둔다.
